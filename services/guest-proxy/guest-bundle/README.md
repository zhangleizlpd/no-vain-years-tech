# NVY 访客通道 —— 安装手册

> **这份文档的读者是大模型（AI coding agent）。** 拿到本包的人只需把整个目录连同这份
> README 一起交给模型，模型按下面的步骤执行即可装好。人只在两处需要介入，文中都标了
> 🙋 **需要你本人操作**。

## 本包**不含**能力清单，这是刻意的

通道开了哪些端点、每个端点收什么参数、限频多少、有哪些坑 —— 全部由通道在运行时下发，
装好后随时可以亲眼看一眼：

```bash
curl -sS -m 20 -H "Authorization: Bearer $(cat ~/.config/nvy-futu/token)" \
  http://10.90.0.1:8811/capabilities
```

**本包只负责一件事：把你的机器接到这条通道上。** 能力说明不进包，是因为它会变 ——
以前每加一个端点都要重新打包、线下发一次，而访客手里那份必然滞后；滞后的形态最阴：
模型照着旧清单告诉用户「做不到」，其实对方早就开了。现在装一次就不用再动了。

🚨 **不要凭猜测探测路径。** 白名单之外一律 404 —— 包括对方服务器上**确实存在但没给你开**
的那些。看到 404 就去猜别的路径名**不是探索，是噪音**，也会让对方的访问日志难看。
要知道有什么，读上面那份目录，不要试。

---

## 0. 先读这段：这个通道的形状与边界

你（模型）将要接入的不是一个公开 API，而是**别人自建服务器上的一条受限通道**。它的每一条
限制都是机器强制的，不是口头约定 —— 越界会直接被拒，且**会给对方造成真实成本**。

```text
你的机器                      对方服务器 (endpoint 由对方给出)        香港机器
┌──────────────┐             ┌───────────────────────────┐        ┌──────────────┐
│ WireGuard    │  UDP 51822  │  10.90.0.1  受限代理      │        │ futu-shim    │
│ 10.90.0.3    │════════════►│    ↓ 换成真凭证           │═══════►│   ↓ 常驻运行 │
└──────────────┘             │  只放 8811 一个端口       │        │ 富途 OpenD   │
   AllowedIPs                └───────────────────────────┘        └──────────────┘
   只有 10.90.0.1/32
```

四条硬边界，装之前就要知道。**这里只写不随能力增删而变的那部分** —— 具体放行了哪些
端点、哪个池每分钟几次、哪些市场可用，全部以 `/capabilities` 下发的目录为准，
本文不复述（复述了就会漂）：

| 边界                 | 具体表现                                                                                                                         |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **端点是白名单制**   | 只有目录里列出的那些可用，打别的一律 **404**，不要探测。对方服务器上确实存在但没对你开的端点也是 404 —— 那是有意的，不是配置漏了 |
| **每个端点都有限频** | 超了 **429**。退避后重试，**不要并发刷**。各池的额度不同、且**都是从对方生产采集的池里切出来的** —— 你打满哪个，他那侧就少哪个   |
| **额度还按证券计**   | 除了每分钟的限频，历史行情另有**按证券**的滚动窗配额：同一只票反复查免费，**查一只新票就占一个槽位**，要等窗口滚过才释放         |
| **越界不是软约束**   | 上面每一条都是机器强制的，越界会直接被拒。做不到就如实告诉用户，**不要换端点或改参数试探** —— 试错本身就在消耗对方的额度         |

🚨 **最容易犯的错：批量扫标的。** 一个 loop 扫几百只票 = 吃掉对方几百个槽位。用户要多只
时逐只确认清单，**不要自作主张扩展**。

🚨 **第二容易犯的错：目录里没有就编。** 用户要的东西这条通道给不了时，说「查不到」——
**不要拿你自己的知识凑一个答案**。编出来的行情 / 报价 / 日期看起来会非常像真的，
用户没有任何办法分辨。

## 1. 你需要向本人索取的两个值

**这两个值不在本包里，也无法自己生成。** 现在就问，不要往下猜、不要留空跑：

| 值              | 长什么样                      | 用途                                      |
| --------------- | ----------------------------- | ----------------------------------------- |
| `SERVER_PUBKEY` | 44 字符 base64，形如 `xTIB…=` | 对方服务器的 WireGuard 公钥，填进隧道配置 |
| `GUEST_TOKEN`   | 48 位十六进制                 | 你调接口时的 bearer                       |

🙋 **需要你本人操作**：向把这个包给你的人索取上面两个值。

> ⚠️ 如果对方还没给，说明**服务端那侧还没给你开通** —— 那就先只跑第 2 步（生成密钥并
> 把公钥发回去），拿到值之后再跑第 3 步。这是正常流程，不是出错。

---

## 2. 生成你的密钥对，把公钥发回去

```bash
./setup.sh keygen
```

这一步做三件事：检查依赖 → 在 `~/.config/wireguard/` 生成 `wg2.key` / `wg2.pub`
（**已存在则不覆盖**）→ 打印公钥。

- **verify**：命令最后打印出一行 44 字符 base64 公钥。
- 🙋 **需要你本人操作**：把打印出来的**公钥**发回给对方（微信发都行 —— 公钥不是秘密）。
  **`wg2.key` 是私钥，永远留在本机，不要发给任何人、不要贴进聊天窗口。**

> 依赖缺失时脚本会打印安装命令并退出非零。macOS 是 `brew install wireguard-tools`，
> Debian/Ubuntu 是 `sudo apt install wireguard-tools`。装完重跑本步。

---

## 3. 填入两个值并落配置

拿到第 1 步那两个值之后：

```bash
SERVER_PUBKEY='<对方给的公钥>' GUEST_TOKEN='<对方给的 token>' ./setup.sh configure
```

这一步生成 `~/.config/wireguard/wg2.conf`（0600）并把 token 存到
`~/.config/nvy-futu/token`（0600）。

- **verify**：脚本自证「配置里无未填占位、无空值字段」并打印两个文件的权限，均应为 `600`。

> 🚨 **不要把 token 写进 shell 历史以外的任何地方** —— 不要写进笔记、不要贴进 issue、
> 不要 echo 进日志。脚本已经把它直接落到 0600 的文件里，你后续从那个文件读即可。

---

## 4. 起隧道 🙋 需要你本人操作

```bash
sudo wg-quick up ~/.config/wireguard/wg2.conf
```

🚨 **模型不要自己跑这条。** 它需要 sudo 密码，在非交互环境下会把你挂死。请把这条命令
交给用户，让他在自己的终端里执行，然后回来告诉你结果。

（macOS 也可以用 WireGuard.app：把 `~/.config/wireguard/wg2.conf` 导入后点激活。）

- **verify**：见第 5 步 —— 不要用 `wg show` 判断，理由见下。

> 🚨 **不要用 `wg show wg2` 判断隧道通没通。** macOS 上它 ① 需要 sudo ② 接口真名是
> `utun<N>` 不是 `wg2`（`wg-quick` 在 macOS 走 utun 设备）。不带 sudo 只会得到
> `Unable to access interface`，**必然误报「隧道没起」**。
>
> 🚨 **也不要用 `ping 10.90.0.1`。** 隧道只放 8811 端口，ICMP 本来就不通 —— ping 不通
> 是设计如此，不是故障。

---

## 5. 验通路

```bash
./setup.sh check
```

它只做一件事：带 token 打 `/healthz`，把 HTTP 状态码翻译成人话。

| 得到         | 含义                 | 怎么办                                |
| ------------ | -------------------- | ------------------------------------- |
| `200`        | 通了                 | 继续第 6 步                           |
| `000`        | 隧道没起             | 回第 4 步，让**用户**跑 `wg-quick up` |
| `401`        | token 不对           | 回第 1 步找对方核对 `GUEST_TOKEN`     |
| `403` / 其他 | 对方那侧还没给你开通 | 联系对方，不要重试                    |

## 6. 全套闸验证（可选但建议）

```bash
GUEST_TOKEN="$(cat ~/.config/nvy-futu/token)" \
  BASE=http://10.90.0.1:8811 ./verify-guards.sh --from-guest
```

这个脚本**每道闸都配了一条应当被拒的输入** —— 只跑正例等于没验。**期望末行的失败数是 0。**

> ℹ️ 这里**刻意不写通过数**：断言条数会随通道开放的端点增减而变（本脚本会先拉一次
> `/capabilities`，再对目录里的每个端点各断言一条）。写死一个数就又造出一处会漂的记录，
> 正是本包这次改造要消灭的东西。不带 `--from-guest` 时会少几条 —— 那是只有从你机器上
> 才验得了的端口封堵，不是失败。
>
> ⚠️ 它最后会真打一次上游（`US.PEP`）。那只票已占着对方的配额槽，**重复查不额外消耗
> 配额**，所以拿它做正例是安全的 —— 别改成别的票。
>
> ⚠️ 正常情况**首发就是 200**。脚本对每条正例都保留了「首发非 200 就退避重试一次」的兜底
> 并会**如实打印首发状态**。看到 `↻ … 首发 429` 是限频闸在干活 —— 本套件自己要从那个
> 每分钟 20 次的共享池里取 4 发，**连着跑两遍就会撞上自己的脚印**，隔一分钟再跑即可。

## 7. 装 OpenClaw skill

```bash
./setup.sh install-skill
```

等价于：

```bash
openclaw skills install ./openclaw-skill --as nvy-futu-kline
```

- **verify**：`openclaw skills info nvy-futu-kline` 应显示 **✓ Ready**、
  **Visible to model: yes**，且依赖 `curl` / `wg` 两项均为 ✓。

> 🚨 **不要手工把文件拷进 `~/.openclaw/plugin-skills/`。** 那个目录是 OpenClaw 独占的
> （其 dist 里明写 "fully owned by OpenClaw"），手放的东西会被覆盖掉。用户 skill 的正确
> 落点是 `~/.openclaw/workspace/skills/`，**由 `openclaw skills install` 管理** ——
> 用上面的命令，不要自己搬文件。
>
> ℹ️ 已装过再跑会被拒绝覆盖 —— 重装 / 升级用 `FORCE=1 ./setup.sh install-skill`。
>
> ℹ️ OpenClaw 迭代很快、文档常滞后。若 `skills install` 的参数与此处不符，以
> `openclaw skills install --help` 的实际输出为准，**不要照搬网上的旧写法**。
> （本包写作时验证于 OpenClaw `2026.6.8`：`--as <slug>` 与 `--force` 均存在。）

## 8. 装完之后：怎么用，以及什么算正常

装好后**直接说人话就行**，skill 会被自动调用，它会先去拉一次能力目录、再照目录发起真正的
调用。你不需要告诉它有哪些端点，也不需要在这份 README 里查 —— 那正是目录存在的意义。

想自己看一眼当前开了什么：

```bash
curl -sS -m 20 -H "Authorization: Bearer $(cat ~/.config/nvy-futu/token)" \
  http://10.90.0.1:8811/capabilities
```

目录里写清楚了每个端点收什么参数、限频多少、哪些坑会让你白跑、每个错误码怎么处置。
**照它写的调，不要照直觉调** —— 这个通道上不同端点的参数形态互不相同，猜必然被 400 拒，
而反复改参数试错会烧掉对方的限频额度。

### 什么算正常

| 现象                           | 含义                                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------------------------------------ |
| 模型先打了一发 `/capabilities` | ✅ 正常，每个新会话一次。它在读当前能力，不是在浪费调用                                                |
| 模型说「这个通道没这个能力」   | ✅ 正常判断 —— 前提是它**先拉了目录**。目录里确实没有就是没有，不要逼它换个路径试                      |
| 拿到 **429**                   | ✅ 限频闸在干活，不是坏了。退避重试即可，**不要并发刷**                                                |
| 拿到 **404**                   | ⚠️ 它打了目录之外的路径。让它重新读目录，**不要陪它猜路径名**                                          |
| 拿到 **401**                   | ⚠️ token 不对（或漏了 `Bearer` 与 token 之间那个空格）。找对方核对，**不要重试**                       |
| 连着 **502**                   | ⚠️ 对方上游暂时不可用。隔 30 秒重打一次；仍是 502 就如实告诉用户并停手 —— 不要连续重试、不要当正常吞掉 |

> 每个端点还有自己专属的错误码（比如写端点的一整套 4xx/5xx 语义），全在目录里，
> 本文不复述。

## 9. 卸载 / 吊销

```bash
sudo wg-quick down ~/.config/wireguard/wg2.conf   # 🙋 需要你本人操作
rm -rf ~/.openclaw/workspace/skills/nvy-futu-kline
rm -rf ~/.config/nvy-futu ~/.config/wireguard/wg2.conf
```

> ℹ️ **`openclaw skills` 没有 `uninstall` / `remove` 子命令**（验证于 `2026.6.8`：只有
> check / info / install / list / search / update / verify / workshop）。卸载就是删掉
> workspace 里那个目录 —— 上面第 2 条即是。别去找一个不存在的子命令。

对方那侧可以随时单独吊销你的 token 或删掉你的 peer，**不影响其他任何人**。
