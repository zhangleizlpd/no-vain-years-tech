# Playbook：送估值锚

> **给谁**：持有本通道访客凭证的人。
> **什么时候用**：你的估值流程跑完、产出了某只票的内在价值 V，要把它送到对方的待审箱。
> **怎么用**：把下面「Prompt」一节**整段**拷进你的 agent 会话（`$nvy-futu-kline` 是 OpenClaw 的
> skill 引用语法；换别的 agent 就把那一行删掉，改成让它先读 NVY 通道的能力目录）。

## 三层分工 —— 别把纪律写错地方

| 层       | 在哪                           | 管什么                                                                       | 改了谁受影响                           |
| -------- | ------------------------------ | ---------------------------------------------------------------------------- | -------------------------------------- |
| skill    | `openclaw-skill/SKILL.md`      | **什么时候**该走这个通道                                                     | 装了 skill 的访客，需重发 bundle       |
| 能力目录 | `capabilities/capabilities.md` | **接口契约**：路径、参数放 query 还是 body、编码规则、限额、错误码、应答形态 | 所有访客，运行时拉取，**改完立即生效** |
| **本文** | `playbooks/anchor-submit.md`   | **业务字段语义**：每个字段什么意思、歧义怎么消、什么时候必须停下来问         | 拷了这段 prompt 的人                   |

判据：**凡是"接口怎么调"的，写进能力目录**（它是唯一真相源，且运行时下发）；**凡是"这个数
是什么意思、取哪个"的，写进本文**。写反了会漂 —— 目录里塞业务语义会随端点变更被改掉，
prompt 里塞接口细节会在端点调整后过期而无人知道。

## Prompt（整段拷走）

````text
$nvy-futu-kline

刚跑完的这次估值要送到 NVY 通道的待审箱。请从我们这段对话的上下文里取出下面五个字段，
按定义核对后提交。**不要从你自己的知识里补任何数值。**

## 第一步：拉能力目录

先按 skill 说的取 token、验 `/healthz`、拉 `/capabilities`。端点路径、参数放 query 还是 body、
限频、错误码**一律以目录为准**，不要按下面的描述猜路径。

## 第二步：按定义取五个字段

### ticker —— 这次估值算的是哪一只可交易证券
- 格式：`市场:代码`。市场**只能是 `us` 或 `hk`**；本通道不收 A 股（`cn:`）。
- 代码段保持原样大小写，冒号**不要** percent-encode。
- 🚨 **禁止从公司名推导代码。** 两地上市的公司在两个市场是**两只不同的证券**：
  价格不同、货币不同、代码不同（中国平安 A 股 `cn:601318` / H 股 `hk:02318`；
  腾讯音乐 美股 `us:TME` / 港股 `hk:01698`）。推错了不会报错，会静默落成另一只票的估值。
- **上下文里没有明确指出是哪个市场 → 停下来问我，把候选列出来。**
  遇到 A 股标的直接告诉我这个通道送不了，不要改送别的市场。

### v —— 每股内在价值
- 格式：正数。
- 语义：**每一股**的内在价值，币种 = ticker 所在市场的交易货币（`us:` → 美元，`hk:` → 港元）。
- 🚨 一次估值经常同时产出**多个都叫"内在价值"的数**：总额（如"9,673 亿元"）、
  每股人民币、每股港元。**必须选与 ticker 市场匹配的那个每股值。**
  送 `hk:` 就用港元每股值，送 `us:` 就用美元每股值。
- 🚨 **不要自己按汇率换算。** 上下文里只有别的币种的值 → 停下来问我。
- 🚨 计价单位随行情口径：按 ADS 计价的美股（如 `us:PDD`，1 ADS = 4 普通股）要送**每 ADS** 值。

### asof —— 这个 V 基于哪一天的市场状态
- 格式：`YYYY-MM-DD`。
- 语义：**我算这个 V 时取的那个收盘价，对应的交易日。**
- 🚨 **以下四个日期都不是它**，一个都不要拿来顶替：
  - ❌ 估值跑批 / 生成的那一刻
  - ❌ 报告标题或文件名里的日期
  - ❌ 财务数据基线日（"基于 2025 年报 / Q2 8-K"那种）
  - ❌ 今天
- 🚨 **它必须是交易日。** 你填之前先判一下星期几 —— **落在周六周日就一定是错的**，
  说明你取的是跑批日而不是口径日。
- 上下文里找不到"收盘价 + 其日期"这组信息 → 停下来问我，**不要拿最接近的日期凑**。

### method —— 估值方法名
- 短字符串，能自解释（如 `dcf` / `5-method-weighted` / `sotp`）。系统不解析，
  但它是日后回看"这个 V 怎么来的"唯一线索。

### confidence —— 置信度
- 格式：**10 分制**闭区间 `[0, 10]`，可带小数。
- 🚨 上下文里如果是百分制（`60%`）或 0-1 制（`0.6`），**换算成 10 分制再送**（→ `6.0`），
  并在复述里写出你的换算过程。直接送 `60` 会被拒。

### note —— 附言（可选，≤512 字符）
- 估值理由 / 数据来源 / 已知不确定性。对方靠它判断采不采纳，写清楚能少一轮来回。

## 第三步：发送前必须复述

**应答不会回显任何数值**，发出去就没有第二次核对机会。发送前把这张表念给我，我确认后再发：

```
标的     hk:02318      ← 市场对吗？两地上市的选对边了吗？
V        61.40 港元     ← 币种与市场匹配吗？每股还是每 ADS？
口径日   2026-08-14    ← 是收盘价那天吗？星期几？是交易日吗？
方法     5-method-weighted
置信度   6.0/10        ← 从 60% 换算而来
附言     ...
```

上面任何一条你是"推断"出来而不是"上下文里明写"的，在复述时标出来。

## 第四步：发送

**用「提交待审」那个口，不是直写口。** 我是访客不是持有者本人，打直写口会拿 `403`。
拿到 `403` 就换提交口重发一次，**不要重试直写口、不要改参数试探**。

## 第五步：读应答

`201` 回来的是收件回执（条目 id / 提交方 / 标的 / 状态 `PENDING` / 收件时刻）。

- ⚠️ 回执**不含 V、口径日、方法、置信度** —— 它只证明"收到了"，不证明"收对了"。
  别拿 201 当数值正确的证据。
- ⚠️ 这只是进了待审箱，**锚表零变化**，采不采纳由对方判断。
  告诉我"已提交待审"，不要说"已生效"或"已写入"。
- 🚨 **提交没有幂等**，同一标的送两次 = 两条待审记录要人手工清。
  拿到 `201` 就是成了，**不要因为"不确定成没成"重发**。`429` 是超限频，退避后再发一次。
````

## 为什么这些纪律必须写在 prompt 里（实测依据，别删）

2026-08-18 用 MiniMax-M3 做过 A/B：同一个模型、同一份完整能力目录、同一份带陷阱的估值上下文
（中国平安：只给公司名不给市场 / 三个都叫"内在价值"的数 / 置信度 60% / 跑批日是周日
2026-08-16 而真口径日是周五 2026-08-14），唯一变量是有没有这段 prompt。

| 检查点                       | 只有能力目录                              | 加上本 prompt                                         |
| ---------------------------- | ----------------------------------------- | ----------------------------------------------------- |
| 端点选对（提交口而非直写口） | 1/5                                       | 9/10                                                  |
| **`asof` 取到口径日**        | **0/5**（全填跑批日，且那天是周日）       | 7/10 明确填对，其余全部主动标为待确认，**零静默填错** |
| 币种与市场一致               | 2/5 踩坑（`hk:02318` 配了人民币值 53.42） | 零踩坑                                                |
| 置信度百分制换算             | 4/5                                       | 10/10                                                 |

`asof` 这一项在另一组实验里（8 份真实研报 × 3 轮）也是 **8/8 全错**，两组合计 **13/13**。
它的错法是**"收敛地错"** —— 每次都错成同一个值，所以重复采样看方差**发现不了**。
⇒ 这条纪律不能靠模型自觉，必须写死在 prompt 里。
