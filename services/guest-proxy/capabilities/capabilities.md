# NVY guest channel — 能力目录

> 本文由通道在**运行时**下发（`GET /capabilities`）。访客手里那份 skill 是**薄壳**，
> 不含任何端点清单 —— 本文是这条通道能力的唯一真相源。
>
> 🚨 **加端点时只改这里，不要再去改访客手里的 skill。** 目录声明的端点集合与 nginx
> 实际放行的集合由 `deploy/install.sh` 的 Gate A 机器强制相等，写漏一个部署会红。

Base URL：`http://10.90.0.1:8811`，所有请求都要带 `Authorization: Bearer $TOKEN`。

**三件互不相干的事**：

1. **读行情** —— 美股日线历史 + 美股期权（到期日阶梯 / 合约链 / 实时报价含 greeks / 标的级 IV
   分位）。代理背后是港机上的 futu-shim → 富途 OpenD。**只放美股**，别当通用行情 API。
2. **投研报** —— 把一份研报 PDF 交给对方归档（A股 / 港股 / 美股都收）。代理背后是 NVY 的
   服务端。**只写不读**：你放得进去，但**永远看不到库里有什么**，包括你自己刚放的那份。
3. **送估值** —— 把一只标的的估值锚（V / 口径日 / 方法 / 置信度）送过去（美股 / 港股）。
   两个口，**你手里的 token 决定你能用哪一个**：
   - `/anchor-import` **直接改库里的锚** —— 只有持有者本人能用，其他人打它是 403。
   - `/anchor-submit` **进待审收件箱** —— 谁都能用，锚表零变化；采不采纳由对方逐条判断。
     ⚠️ 同样**只写不读**：送进去之后你看不到它的下落，也查不到任何锚。

## 端点一览

| 端点                  | 干什么                                                                 | 关键参数                           |
| --------------------- | ---------------------------------------------------------------------- | ---------------------------------- |
| `/capabilities`       | 本文自身（能力目录）                                                   | 无                                 |
| `/healthz`            | 通路探针                                                               | 无                                 |
| `/kline`              | 日线历史 OHLC                                                          | `code` `ktype` `start` `end`       |
| `/option-expirations` | 某标的**有哪些到期日**                                                 | `code`                             |
| `/option-chain`       | 某到期日窗上**有哪些合约**（静态属性，无报价）                         | `code` `start` `end` `option_type` |
| `/option-snapshot`    | 一批合约**现在多少钱**（报价 + greeks + OI）                           | `codes`（复数，逗号分隔）          |
| `/overview`           | 一批**标的**的 IV 分位（`iv` / `iv_rank` / `iv_percentile` + HV 梯队） | `codes`（复数，≤500）              |
| `/research-report`    | **投递**一份研报 PDF（只收 POST）                                      | `symbol` `reportDate` `title`      |
| `/anchor-import`      | **直接写**一只标的的估值锚（持有者本人专用，只收 POST）                | `ticker` + JSON body               |
| `/anchor-submit`      | **提交**一条待审估值（谁都能用，只落收件箱，只收 POST）                | `ticker` + JSON body               |

**只有上面这些。** 打别的路径一律 404 —— 上游确实有、但没对访客开的端点（财报日历、
IV 历史一类）也是 404，那是有意的，不是配置漏了。

## 日线

```bash
curl -sS -m 90 -H "Authorization: Bearer $TOKEN" \
  "http://10.90.0.1:8811/kline?code=US.PEP&ktype=K_DAY&start=2026-07-01&end=2026-07-31"
```

| 参数            | 说明                                                           |
| --------------- | -------------------------------------------------------------- |
| `code`          | **必须 `US.` 前缀**（`US.PEP` / `US.AAPL`）。非美股会被 400 拒 |
| `ktype`         | `K_DAY` 日线（还有 `K_WEEK` / `K_MON`）                        |
| `start` / `end` | `YYYY-MM-DD`，可省（省略取默认区间）                           |

## 期权：**三步一条链，顺序不能跳**

期权链和报价是**两个接口**，不存在「一发拿到带报价的整条链」。照下面三步走：

```bash
# ① 先问有哪些到期日（便宜，随便调）
curl -sS -m 90 -H "Authorization: Bearer $TOKEN" \
  "http://10.90.0.1:8811/option-expirations?code=US.PEP"

# ② 再按到期日窗取合约。🚨 窗口跨度**最多 30 天（含首尾）**，超了直接 400。
#    要覆盖更长的阶梯就自己切成多个窗 —— 但先读下面的限频，这一步很贵。
curl -sS -m 90 -H "Authorization: Bearer $TOKEN" \
  "http://10.90.0.1:8811/option-chain?code=US.PEP&start=2026-08-15&end=2026-09-13"

# ③ 拿 ② 返回的合约 code 去取报价。一次最多 400 个 code。
#    💡 把**标的自己的 code** 也放进同一批，它的 last_price 会一起回来 —— 这样拿
#       现货价不用多打一次。
curl -sS -m 90 -H "Authorization: Bearer $TOKEN" \
  "http://10.90.0.1:8811/option-snapshot?codes=US.PEP,US.PEP250815P00150000,US.PEP250815C00150000"
```

几个会让你白跑的点：

- **`/option-chain` 返回的是静态属性**（行权价 / 到期日 / 认购认沽），**没有任何报价**。
  要价格必须走第 ③ 步。看到返回里没有 bid/ask 不是出错。
- **`option_type` 默认 `ALL`**（认购 + 认沽都返）。只要认沽就自己在结果里筛，别以为漏了。
- **`codes` 里每一段都必须是 `US.`**，混一个港股整发被 400 拒（不是只丢那一个）。
- **greeks 可能整块缺失**，那种行**照常返回**并带 `greeks_complete: false`。这是实值腿的
  数学固有现象（报价跌破内在价值 ⇒ IV 无解），**不是数据坏了**，别把这些行丢掉或重试。
- 返回信封统一是 `{"as_of": …, "count": N, "rows": [...]}`。`as_of` 是**采集时刻**，
  不是行情时刻。字段名直接透传富途 SDK，**不要假设它做过归一化**。

## 标的级 IV 分位（`/overview`）—— 挑票的第一步用它，不是用链

```bash
curl -sS -m 90 -H "Authorization: Bearer $TOKEN" \
  "http://10.90.0.1:8811/overview?codes=US.PEP,US.KO,US.VICI"
```

一发最多 **500 个标的**，返回每个标的的：

- `iv` —— 富途的**标的级聚合 IV**（不是某张合约的 IV，也没锁 30 天 / 平价，富途未文档化其口径）
- **`iv_rank` / `iv_percentile`** —— 当前 IV 在过去一年里的位置（0-100）。**这是卖方最常看的读数**：
  分位高 = 期权贵 = 适合卖；分位低 = 便宜 = 卖了不划算
- HV 梯队（30/60/90/120/365 天，各带自己的百分位）

用法上的建议：**先用这条在一批自选票里挑出 IV 分位高的，再去对那几只拉链**。反过来做
（先拉一堆链再挑）会把 `/option-chain` 那个每分钟 10 次的紧池打爆。

⚠️ `codes` 的规则与 `/option-snapshot` 完全一样：**每一段都必须 `US.` 前缀**，混一个港股整发被拒。

## 投递研报（`/research-report`）

把一份 PDF 交给对方归档。**一条命令搞定**，不需要先申请凭证再上传再确认：

```bash
PDF=./reports/pepsico-2026h1.pdf # 换成你要投的那份

curl -sS -m 300 -X POST \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@$PDF;type=application/pdf" \
  "http://10.90.0.1:8811/research-report?symbol=us:PEP&reportDate=2026-08-01&title=PepsiCo%20H1%20review"
```

成功返回 `201` + 八个字段：

```json
{
  "reportId": "9",
  "symbol": "hk:02318",
  "objectKey": "research/…",
  "deduplicated": false,
  "title": "平安 2026 中期回顾",
  "reportDate": "2026-08-01",
  "version": 3,
  "instrumentName": "中国平安"
}
```

怎么读这八个字段、以及**它们没告诉你什么**，见下面「读应答」一节 —— 尤其
`instrumentName` 那段盲区，不读会把「名字对上了」误当成「投对了」。

| 参数         | 必填 | 说明                                                                                   |
| ------------ | ---- | -------------------------------------------------------------------------------------- |
| `symbol`     | ✅   | 标的。**必须 `cn:` / `hk:` / `us:` 字面开头**（`cn:600519` / `hk:00700` / `us:PEP`）   |
| `reportDate` | ✅   | 研报日期 `YYYY-MM-DD`。取你声明的值，系统不会去 PDF 里反推，也不与投递时刻做一致性校验 |
| `title`      | ✅   | 标题                                                                                   |
| `source`     | —    | 来源，不填按「自研」记                                                                 |
| `file`       | ✅   | multipart 字段名固定叫 `file`，必须是真 PDF                                            |

🚨 **后缀式 `00700.HK` / `600519.SH` 在本通道走不通** —— 服务端的归一器确实认它们，但**通道
层有一道先于服务端的闸**：`symbol` 的值必须以 `cn:` / `hk:` / `us:` **字面**开头，否则连转发
都不会发生，你拿到的是代理层的 400（体里没有 `code`，见下面「研报专用错误码」第一行）。
⇒ 这不是"服务端不支持"，是**这条通道只放行前缀式**。照上面表里那三种写法写就行。

### 投之前：`symbol` 必须有据，不能由公司名推出来

🚨 **不要从公司名推证券代码。** 很多公司两地上市 —— 中国平安 A 股是 `cn:601318`、H 股是
`hk:02318`；阿里港股 `hk:09988` 之外还有美股。**推错了没有任何东西会拦你**：代码与公司名
是否对应，这条链上一层校验都没有，投错只会**静默成功**。

> 应答会回显标的名称（`instrumentName`），能让你**自己**发现「投成了另一家公司」——
> 但它**只抓得到这一半**，市场投错（A 股 / H 股互换）抓不到，因为两地上市的票同名。
> 详见下面「读应答」一节。**它是事后的弱信号，不能替代这里的取值纪律。**

取值顺序：**用户明确给了代码就用它；没给就从 PDF 里取** —— 研报的标的代码几乎都在首页抬头：

```bash
pdftotext -layout -f 1 -l 2 "$PDF" - | head -40
```

缺 `pdftotext` 就装 poppler（macOS `brew install poppler` / Debian
`sudo apt install poppler-utils`）。它**不是必需依赖**，只在这一步有用；装不了就直接问用户
要代码，**别猜**。

⚠️ **用户说的市场与 PDF 里写的对不上时，停下来指出分歧、让用户裁决**，不要自己选一个 ——
用户顺口说的「A 股」撞上研报封面的 `02318.HK`，是这里最常见的形态（2026-08-16 实际踩过）。

### 四件会让你白跑的事

🚨 **`symbol` 里的冒号绝对不要做 percent-encode。** 写 `symbol=us:PEP`，**不要**写
`symbol=us%3APEP` —— 代理这一层不解码，编码过的值撞不上市场白名单，你会拿到 400 且怎么改
参数都没用。

🚨 **`title` / `source` 的编码交给 curl 算，你不要自己拼百分号转义。** 它们含空格 / 中文时
确实必须编码，但**手搓 UTF-8 字节是本端点已经实测翻车过的一条**（2026-08-16：`深度研报`
被编成 `%E6%B7%B1%E5%BA%A6%E7%A0%94%E7%BA%A2`，前三个字全对、末字错一个字节 ⇒ 落库成了
「深度研**红**」）。用 `--url-query`，让 curl 去编：

```bash
curl -sS -m 300 -X POST \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@$PDF;type=application/pdf" \
  --url-query "title=PDD 深度研报" \
  --url-query "source=自研" \
  "http://10.90.0.1:8811/research-report?symbol=us:PDD&reportDate=2026-08-11"
```

- **`symbol` / `reportDate` 留在 URL 里原样写**，别塞进 `--url-query` —— 它会把冒号一起编掉，
  正好撞上上一条。只有 `title` / `source` 走 `--url-query`。
- 空格会被编成 `+` 而不是 `%20`，**服务端照样还原成空格**（2026-08-16 实测），不用担心。
- `--url-query` 要 curl ≥ 7.87（2022-12）。`curl --version` 比这老就用下面这个兜底，
  **仍然不要手算**：

  ```bash
  enc() { python3 -c 'import sys,urllib.parse;print(urllib.parse.quote(sys.argv[1]))' "$1"; }
  curl … "http://10.90.0.1:8811/research-report?symbol=us:PDD&reportDate=2026-08-11&title=$(enc 'PDD 深度研报')"
  ```

⚠️ **编错了只能靠 201 回显的 `title` 自己发现。** 应答里那个 `title` 是**落库值**（见下面
「读应答」一节），把它跟你想投的标题**逐字比一遍**，编码翻车会在这里显形。但 `title`
**不在去重键里**（见下面「去重」那条）⇒ **发现了也改不掉**：这个回显是用来**如实汇报**的，不是用来
改正的。⇒ 向用户报标题时报**落库的那个**，不要报你脑子里想的那个。

🚨 **判据是文件内容不是扩展名。** 把 PNG 改名成 `.pdf` 会被 422 拒。

🚨 **去重认「你 + 标的 + 文件字节」三者。** 同一投递方、同一标的、同一份文件重投返回
**首次那条记录**（`deduplicated: true`），不会产生第二份；上传超时后**原样重投**就是正确
做法。`title` / `reportDate` / `source` **不在键里** —— 换个标题重投一样命中去重，**不会**
变成"新的一份"。而 `symbol` **在键里**：同一份文件换个标的投，会**各自成为一条独立记录**
（对方那边文件仍只存一份，两条记录指向同一份）。

**参数写错了怎么办 —— 分两种，别混：**

- ✅ **`symbol` 投错了：用正确的 `symbol` 重投同一份文件即可补救。** 标的在去重键里 ⇒
  这次**不会**命中去重，会新建一条挂在正确标的下的记录（`deduplicated: false`），你不用
  去申请什么，也不用找用户开权限。原来那条错记录**留在库里**（本通道没有 `DELETE`），
  所以如实说清楚：「已按正确标的补投一条，错的那条要请你去服务端清」。
- ❌ **`title` / `reportDate` / `source` 写错了：重投改不掉。** 它们不在去重键里 ⇒ 带新
  参数重投同一份文件，你拿到的是 `deduplicated: true` 加**库里那条旧记录**的值，一个字段
  都不会更新。这条通道对研报没有 `GET` / `PUT` / `DELETE`（见下节），只能请用户去服务端改。

⇒ 拿到 `deduplicated: true` 时**务必核对返回的 `symbol` / `title` / `reportDate` 是不是你
这次想投的那套**，不一致就照上面两条分别处理，别当成功汇报。

### 读应答：版本号、名称回显，以及它们的盲区

| 字段                   | 怎么读                                                                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `reportId`             | 这次归档记录的标识。报给用户时给它就够了                                                                                        |
| `objectKey`            | 文件在归档区的路径。**同一份文件不管挂在几个标的下，这个值都一样**（文件只存一份）                                              |
| `symbol`               | **归一后落库的**标的：你写 `hk:700`，这里回 `hk:00700`（港股补零到 5 位、A 股补到 6 位、美股转大写）                            |
| `title` / `reportDate` | 同上，回的是**落库值**                                                                                                          |
| `version`              | 这份是「**你 + 这个标的**」这条线上的第几份。首投是 `1`，之后每新建一条记录 +1（重投同一份文件不会 +1，你拿到的是原来那条的号） |
| `instrumentName`       | 对方行情目录里这个代码的名称；查不到是 `null`（见下面的盲区）                                                                   |
| `deduplicated`         | `false` = 新建了一条；`true` = 命中去重、没有新建                                                                               |

**两条规则记死：**

1. 🚨 **版本号最大的那份就是最新，而你刚投的这份就是最大的那份。** 服务端**不回**「谁是
   最新」这个信息，也没有任何端点能查到 —— 只能靠这条规则推。用户问「我这份是第几版」答
   `version`；问「最新的是哪份」答「你刚投的这份」。
   ⚠️ 版本号只保证**递增且唯一**，**不保证连续** —— 中途失败的投递会占掉一个号且不回收，
   所以看到 `version: 5` 不代表库里有 5 份，别拿它当计数器报给用户。
2. 🚨 **拿到 `deduplicated: true` 时，回显的全部是「库里那条」的值，不是你这次请求里写的。**
   这正好可以用来核对：回来的 `symbol` / `title` / `reportDate` 与你这次想投的不一致，说明
   这份文件之前就是按那套参数投进去的（处理办法见上一节两条）。

🚨 **`instrumentName` 的盲区 —— 名字对上不等于投对了。**

名称对上**只证明**「不是投成了另一家公司」，**不证明市场选对了**。两地上市的公司在目录里
**同名**：`cn:601318` 与 `hk:02318` 都叫「中国平安」。你把 H 股研报投成 `cn:601318`，回显
照样是「中国平安」，看起来完全正常 —— 这个回显对**你最容易犯的那类错**恰好是瞎的。

⇒ **不要把「`instrumentName` 对上了」当成投对了的确认，更不要据此跳过核对。** 市场
（`cn` / `hk` / `us`）那一半仍然只能靠上面「`symbol` 必须有据」那节保证：代码从用户或 PDF
拿，**不从公司名推**。

`instrumentName` 是 `null` 时**什么都不代表**，尤其**不是错误信号**：可能是对方目录里还
没有这只票（研报常常先于标的入库，是正常态），也可能是名称查询这次没查成。两者对外**故意
不可区分**，因为你的正确动作一样：**照常继续、不当作错误、不要因此重投**。投递本身已经
`201` 成功了。

### 限额

- **限频是漏桶 `2r/m` + 1 格突发，不是"每个日历分钟给你 2 次"。** 桶**每 30 秒补一格**，
  另有 1 格突发余量。实际手感：**连打 2 发都过、第 3 发立刻 429**，此后大约每 30 秒才放行
  1 发 —— 不存在"到了下一分钟就又有 2 次"这回事。
  🚨 **超额是当场拒、不排队**（`nodelay`）：429 就是真被拒了，那一发**没有**在队列里等着，
  重试完全由你负责。⇒ 拿到 429 就**退避约 30 秒再发一发**，别并发、别原地紧打。
  研报是人工产出物，这个额度对正常用法毫无束缚；它挡的是"循环打"。
- **单份 16MB。** 超了返回 413。
- 你名下累计有配额上限，撞到会返回 507 —— 那不是你这份有问题，是总量到顶了，找用户。

### 你**看不到**库里有什么

这条通道对研报是**单向**的：`GET` / `DELETE` 这个路径会被 403 拒，服务端也没有任何列表 /
下载 / 预览接口。用户问"我之前投过哪些"时，**直说这个通道查不了**，别去试别的路径。

### 研报专用错误码

**先看有没有 `code`：有 `code` 的来自服务端，没有的来自代理层。** 400 这一个状态码**两边都会
给**，形状不一样，别按一种去解析。

| 码  | `code`                            | 怎么办                                                                                                                                                                     |
| --- | --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 400 | —（代理层，**无 `code`**）        | `symbol` 不是 `cn:`/`hk:`/`us:` **字面**开头 —— 含没带 `symbol`、写成后缀式 `00700.HK`、或把冒号编成了 `%3A`。体是 `{"error":"bad_request","detail":…}`。改参数重发        |
| 400 | `FORM_VALIDATION`                 | **来自服务端**：缺 `reportDate` / `title`，或 multipart 里没有 `file` 字段。体里带 `invalidAttributes`，**逐项列出缺的是哪个**，照着补齐重发（别逐个参数试）               |
| 401 | —                                 | token 不对。找用户要，别重试                                                                                                                                               |
| 403 | —                                 | 你用了 POST 以外的方法。这个端点**只收 POST**（通道层 `deny` 返 403，不带 `Allow` 头）                                                                                     |
| 413 | —                                 | 文件超过 16MB。别切片重传，这个端点不支持分片                                                                                                                              |
| 422 | `RESEARCH_FILE_NOT_PDF`           | 内容不是 PDF（判据是文件头，不是扩展名）                                                                                                                                   |
| 422 | `RESEARCH_SYMBOL_INVALID`         | 市场前缀过关了，但整体形态不认：`us:`（冒号后是空的）、`cn:ABCDEF`（A 股要 1-6 位数字）、`hk:123456`（港股至多 5 位）、一次给了多个标的。按该市场的代码规则改              |
| 422 | `RESEARCH_SYMBOL_ENCODED`         | **双重编码**：`symbol` 仍以 `cn:`/`hk:`/`us:` 字面开头，但后半段里带了 `%25`（服务端解码后仍留着 `%`）。注意**单次**编码整个值是上面那条 400，不是这条。别自己拼百分号转义 |
| 422 | `RESEARCH_REPORT_DATE_INVALID`    | 日期要 `YYYY-MM-DD`                                                                                                                                                        |
| 429 | —                                 | 撞了投递限频。语义见上面「限额」那条（漏桶，不是每分钟重置）：退避约 30 秒再发一发，别并发                                                                                 |
| 502 | `RESEARCH_STORAGE_REJECTED`       | 归档存储明确拒绝了。**重投同一份不会改变结果**，如实告诉用户并停手                                                                                                         |
| 502 | `RESEARCH_STORAGE_INDETERMINATE`  | 结果未知（可能已经存进去了）。**重投是安全的**，会就地续做不产生第二份                                                                                                     |
| 503 | `RESEARCH_STORAGE_NOT_CONFIGURED` | 对方还没接通归档存储。停手，告诉用户                                                                                                                                       |
| 507 | `RESEARCH_QUOTA_EXCEEDED`         | 你名下累计用量到顶了。停手，找用户                                                                                                                                         |

> ℹ️ 服务端另有一个 422 `RESEARCH_SYMBOL_MARKET_UNSUPPORTED`（市场不在 `cn` / `hk` / `us` 内），
> 但**本通道拿不到它** —— 任何非这三个市场字面开头的值，都在通道层就被上面第一行那个 400 挡下来了，
> 压根到不了服务端。列在这里只是让你别去等一个永远不会来的码：市场写错，你收到的是 **400**。

## 送估值（`/anchor-import` / `/anchor-submit`）

把一只标的的估值锚送过去。**两个口同形，差别只在你手里的 token 能开哪一个**：

| 口               | 谁能用             | 效果                                                   |
| ---------------- | ------------------ | ------------------------------------------------------ |
| `/anchor-import` | **只有持有者本人** | 直接写库：没有这只锚就新建，有就按模型语义刷新         |
| `/anchor-submit` | 谁都能用           | 只进待审收件箱，**锚表零变化**；采纳与否由对方逐条判断 |

打错口的表现很清楚：非本人打 `/anchor-import` → **403**（不是 401，401 是 token 本身不对）。

```bash
curl -sS -m 60 -X POST \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"v":"50.0000","asof":"2026-06-30","method":"dcf","confidence":"8.00"}' \
  "http://10.90.0.1:8811/anchor-import?ticker=us:AOS"
```

| 字段         | 位置  | 必填 | 说明                                                                   |
| ------------ | ----- | ---- | ---------------------------------------------------------------------- |
| `ticker`     | query | ✅   | `us:AOS` / `hk:00700`。**只收美股 / 港股**；冒号不要百分号编码         |
| `v`          | body  | ✅   | 估值 V（数值串）。**必须 > 0**                                         |
| `asof`       | body  | ✅   | 估值口径日 `YYYY-MM-DD`。**服务端不会替你回落成「今天」**              |
| `method`     | body  | ✅   | 估值方法名（自由短字符串，如 `dcf`）                                   |
| `confidence` | body  | ✅   | 置信度，**10 分制闭区间 [0, 10]**（可带小数）                          |
| `note`       | body  | —    | 仅 `/anchor-submit`：给对方看的附言（估值理由 / 数据来源），系统不解析 |

🚨 **`ticker` 必须写在 query 里**（不是 body）——通道那道市场闸读的就是它；写进 body 会
直接 400。

🚨 **`ticker` 绝对不要走 `curl --url-query`。** 那个选项会把冒号编码成 `%3a`（实测
`--url-query "ticker=hk:02318"` → `ticker=hk%3a02318`），而通道那道闸**不解码**就拿它去比对
市场前缀 ⇒ 必然 400，且你怎么改参数都过不去。**原样写进 URL** 就对了。

> ⚠️ 上面「投递研报」一节让 `title` / `source` 走 `--url-query`，那是**那一节专有的**（它们含
> 中文、手搓百分号编码翻过车）。**不要把那条经验搬到这里** —— 2026-08-18 实测，模型正是这么
> 泛化的，产出的命令必炸。

成功返回 `201`。`/anchor-import` 的应答有两个字段要读：

```json
{
  "action": "update",
  "anchor": { "ticker": "us:AOS", "v": "60.0000", "confidence": "9.50", "…": "…" },
  "fallbackEntries": [
    { "ticker": "us:AOS", "slot": "lLevel", "manualValue": "L3", "fallbackValue": "L1" }
  ]
}
```

- **`action`**：`create`（新建了一只锚）/ `update`（刷新了既有锚）/ `noop`（值与库里完全一样，
  **什么都没写**）。
  🚨 `create` 意味着对方当天的行情采集要为这只新标的多做一整轮历史回填 —— **别循环建一堆新锚**，
  要建多只先跟用户确认清单。
- **`fallbackEntries`**：这次导入**冲掉了对方哪些人工调整**（哪一项、原值、回落成了什么）。
  不为空时**必须原样转述给用户** —— 那是对方手动调过的判断被你这次覆盖了。清单为空是正常的。

⏰ **时机（这条是运维约束，不是代码约束，系统不会拦你）**：导入要赶在对方**当日的行情采集轮
开始之前**。赶上了，当天新建的锚在**当轮**就被纳入采集；错过了，那只新锚要等下一轮才有行情。

`/anchor-submit` 的应答是**收件回执**，形状与上面完全不同：

```json
{
  "id": "3",
  "submitter": "guest-a",
  "ticker": "us:AOS",
  "status": "PENDING",
  "createdAt": "2026-08-16T12:00:00.000Z"
}
```

- 🚨 **回执里没有 `v` / `asof` / `method` / `confidence`。** 它只证明「收到了」，**不证明
  「收对了」** —— 数值送错了没有任何东西会告诉你。**核对必须发生在发送之前**，别指望应答兜底。
- 🚨 转述给用户时说「**已提交待审**」，**不要说「已生效」/「已写入」** —— 锚表这时候一个字节
  都没动，采不采纳由对方逐条判断。
- 🚨 **提交没有幂等。** 同一标的送两次 = 收件箱里两条待审记录，要对方手工清。拿到 `201` 就是
  成了，**不要因为「不确定成没成」重发**；`429` 是超限频，退避后再发一次。
- ℹ️ **你没有读取面** —— 看不到对方库里有什么，**也看不到自己刚提交的那条**。别去找「查询提交
  状态」的端点，没有那个东西，探它等于打白名单外的路径。

### 错误对照（送估值）

| 码  | 含义                                                                               | 怎么办                                        |
| --- | ---------------------------------------------------------------------------------- | --------------------------------------------- |
| 400 | `ticker` 不是 `us:` / `hk:` 开头，或不在 query 里，或冒号被编码了                  | 照上表改写，别换端点试                        |
| 400 | `INVALID_IMPORT_TICKER` —— 写法不规范（缺市场前缀 / 代码段小写 / 后缀式 `PEP.US`） | **一律不归一，就是要你改自己的输出**          |
| 400 | `INVALID_IMPORT_MARKET` —— 市场不在白名单（如 `cn:`）                              | 本通道的估值口只收美股 / 港股                 |
| 400 | `INVALID_IMPORT_CONFIDENCE` —— 置信度不在 [0, 10]                                  | 检查你的量表是不是百分制                      |
| 400 | `INVALID_ANCHOR_V` —— 估值 ≤ 0                                                     | 检查取数，别送 0 占位                         |
| 401 | token 不对或没带                                                                   | 找用户要，别重试                              |
| 403 | 你在打 `/anchor-import` 但你不是持有者本人                                         | 改打 `/anchor-submit`（同样的字段，进待审箱） |
| 404 | 目标锚在你这次请求处理途中被删了                                                   | 重打一次即可（会走新建那条路）                |
| 429 | 超了限频（直写 6 次/分，提交 2 次/分，两个口**各自独立计**）                       | 退避后重试，别并发刷                          |

## 错误对照（照着判，别猜）

| 码      | 含义                                                                                                         | 怎么办                                                                                          |
| ------- | ------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| **502** | 上游行情网关暂时不可用（多半正在重启）。**注意：这不是「冷启，等等就好」** —— 网关是常驻的，正常首发就该 200 | **隔 30 秒重打一次**。仍 502 就**如实告诉用户上游有问题**并停手 —— 别连续重试、别当正常现象吞掉 |
| 400     | `code` / `codes` 不是 `US.` 前缀；或到期日窗 > 30 天；或 `codes` 超过 400 个；或参数格式不对                 | 看返回体的 `detail`，它说得很具体。**港股/A 股本通道一律不可用**，直说做不到，别换端点试        |
| 401     | token 不对，或缺 `Bearer` scheme（`Bearer` 与 token 之间要有一个空格）                                       | 找用户要 token，别重试                                                                          |
| 404     | 你打了白名单外的端点                                                                                         | **只有上面那张表里的**，别探别的。财报日历、IV 历史一类的端点上游有、但**没对访客开**           |
| 429     | 超了限频（**期权链那条只有 10 次/分，见下**）                                                                | 退避后重试。**别并发刷**                                                                        |

## 硬约束（违反会给对方造成真实成本）

- 🚨 **`/option-chain` 每分钟只有 10 次 —— 这是全通道最紧的一条。** 它对应的上游官方限额
  本身就只有 10 次/30 秒（= 20 次/分），而那个池**与对方每天早上的生产采集共用** ——
  给你的 10 次/分是**从中对半分出来的**，你打满他那轮就只剩一半速度、会真的跑不完。
  ⇒ **不要循环扫多只票的整条到期日阶梯。** 用户要看某只票时，先问清楚要哪几个到期日，
  只取那几个窗。
- 🚨 **期权其余三条每分钟 20 次，且是共享的** —— `/option-expirations` · `/option-snapshot` ·
  `/overview` **三条合起来 20 次**，不是各 20 次。
- ℹ️ `/kline` 宽松得多（**110 次/分**）：那个池对方自己用得很少。但**额度按证券计**那条
  仍然适用（见下一条），别因为限频宽就去批量扫票。
- 🚨 **不要批量扫标的。** 历史 K 线额度按**证券**计、7 天滚动窗；**同一只票反复查免费，
  查一只新票就占一个槽位、七天才释放**。一个 loop 扫几百只票 = 把对方的额度吃掉。
  用户明确要多只时，逐只确认清单，不要自作主张扩展。
- 🚨 **行情读取只有美股。** 港股 / A 股的**行情**不在此通道 —— 按**最小权限**开，只放行实际
  需要的市场。做不到就直说，不要换端点或改参数试探。
  ⚠️ **这条只管上面那六个读端点。** `/research-report` 收 `cn` / `hk` / `us` 三个市场，
  `/anchor-import` 与 `/anchor-submit` 收 `us` / `hk` 两个 —— 三处判据本来就不是同一个，
  别因为这条就拒绝投递港股 / A 股的研报、或拒绝送港股的估值。
- 🚨 **`ping 10.90.0.1` 不通是设计如此**（隧道只放 8811/tcp），别用它判断连通性 ——
  用 `/healthz`。
