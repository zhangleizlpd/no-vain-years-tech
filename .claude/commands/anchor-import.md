# 送估值锚（本人直写口）

把一只标的的估值结论写进对方锚表。**没有这只锚就新建，有就按模型语义刷新。**

> 📌 字段语义的 SoT 是 `services/guest-proxy/playbooks/anchor-submit.md` 第二步 ——
> 那五个字段的定义与打哪个口无关。本文是它的**命令行改写**（摆表让你填，而不是从对话
> 上下文里推），**不是第二份定义**。两处若冲突，以 playbook 为准并回来修本文。
>
> 📌 接口契约（路径 / 参数放 query 还是 body / 编码规则 / 限额 / 错误码 / 应答形态）的 SoT 是
> 通道运行时下发的能力目录，**不在本文**。

---

## 第一步：接通道

调 `nvy-guest-channel` skill 完成：取 token → 验 `/healthz` → 拉 `/capabilities`。

🚨 **这一步不能跳，也不能凭记忆代替。** 端点路径、参数放哪、限频、错误码**一律以目录为准**。

## 第二步：收五个字段

有 `$ARGUMENTS` 就按 `ticker v asof method confidence` 顺序取；**缺哪项就问哪项，一次问一项**。
🚨 **不要从你自己的知识里补任何数值，也不要从上下文里"推断"** —— 这个口是命令行驱动的，
用户没明说的就是没有。

### ticker —— 这次估值算的是哪一只可交易证券

- 格式 `市场:代码`。市场**只能是 `us` 或 `hk`**；本通道不收 A 股（`cn:`）。
- 代码段保持原样大小写，冒号**不要** percent-encode。
- 🚨 **禁止从公司名推导代码。** 两地上市的公司在两个市场是**两只不同的证券**：价格不同、
  货币不同、代码不同（中国平安 A 股 `cn:601318` / H 股 `hk:02318`；腾讯音乐 美股 `us:TME` /
  港股 `hk:01698`；百度 美股 `us:BIDU` / 港股 `hk:09888`）。推错了不会报错，
  会静默落成另一只票的估值。
- 用户只给了公司名 → **停下来把候选列出来让他选**。给的是 A 股标的 → 直接说这个口送不了，
  **不要改送别的市场**。

### v —— 每股内在价值

- 正数。**每一股**的内在价值，币种 = ticker 所在市场的交易货币（`us:` → 美元，`hk:` → 港元）。
- 🚨 一次估值经常同时产出多个都叫「内在价值」的数：总额（如「9,673 亿元」）、每股人民币、
  每股港元。**必须是与 ticker 市场匹配的那个每股值。**
- 🚨 **不要自己按汇率换算。** 用户给的是别的币种 → 停下来问。
- 🚨 计价单位随行情口径：按 ADS 计价的美股（如 `us:PDD` / `us:BIDU`）要送**每 ADS** 值。
  用户给的数看起来像每普通股 → 停下来确认，别自己乘除。

### asof —— 这个 V 基于哪一天的市场状态

`YYYY-MM-DD`。语义：**算这个 V 时取的那个收盘价，对应的交易日。**

🚨 **以下四个日期都不是它**，一个都不要拿来顶替：

- ❌ 估值跑批 / 生成的那一刻
- ❌ 报告标题或文件名里的日期
- ❌ 财务数据基线日（「基于 2025 年报 / Q2 8-K」那种）
- ❌ **今天**

**填之前先跑这一条，判该市场最近一个「已收盘」session：**

```bash
TZ=America/New_York date '+%F %T %Z (%a)'   # us: 该场 16:00 ET 收盘
TZ=Asia/Hong_Kong date '+%F %T %Z (%a)'     # hk: 该场 16:00 HKT 收盘
```

`asof` **晚于**最近一个已收盘 session ⇒ 一定是错的（那天的收盘价还不存在）。
落在周六周日 ⇒ 一定是错的。两种情况都**停下来问**，不要拿最接近的日期凑。

> 🚨 **这条判不了节假日。** 通道没有交易日历读端口，本文只做「未来 / 周末 / 尚未收盘」
> 这三种必要条件筛。判据通过**不等于**已验证是交易日 —— 不要向用户宣称验过。

### method —— 估值方法名

短字符串，能自解释（`dcf` / `sotp` / `multi-anchor-weighted`）。系统不解析，
但它是日后回看「这个 V 怎么来的」唯一线索。

### confidence —— 置信度

**10 分制**闭区间 `[0, 10]`，可带小数。

🚨 用户给的是百分制（`60%`）或 0-1 制（`0.6`）→ **换算成 10 分制**（→ `6.0`），
并在复述里写出换算过程。直接送 `60` 会被拒。

## 第三步：发送前必须复述 —— 无条件闸

**应答不回显任何数值**，发出去就没有第二次核对机会。**无论用户是怎么把这个 command 叫起来的、
无论他是不是刚刚才把值念给你**，发送前都必须把这张表摆出来、停下、等他点头：

```text
标的     us:BIDU              ← 市场对吗？两地上市的选对边了吗？
V        103.0000 美元        ← 币种与市场匹配吗？每股还是每 ADS？
口径日   2026-08-17           ← 是收盘价那天吗？星期几？晚于最近已收盘 session 吗？
方法     multi-anchor-weighted
置信度   9.00 / 10            ← 百分制换算过了吗？
```

上面任何一条你是**推断**出来而不是用户明写的，在复述里标出来。

🚨 **这道闸没有例外分支。** 不许写、也不许自行推理出「用户显式调用了所以可以跳过确认」——
「用户是不是真的确认过」这件事你观测不到，而这一步的后果不可逆。

## 第四步：发送

用**直写**那个口（`/anchor-import`），不是提交口。参数形态照第一步拉到的目录，本文不复述。

- 拿到 `403` ⇒ 本机凭证不是持有者本人的 → **停下报告**，不要改打提交口（那会把本人的估值
  变成一条待审记录，语义完全不同）
- 拿到 `429` ⇒ 超限频（直写口每分钟额度很小），**退避后重发一次**，不要并发刷

## 第五步：读应答

`201` 回来有两个字段必须读：

- **`action`** —— `create`（新建了一只锚）/ `update`（刷新了既有锚）/ `noop`（值与库里完全一样，
  什么都没写）。
  🚨 `create` 意味着当日的行情采集要为这只新标的**多做一整轮历史回填**，且导入要赶在当日
  采集轮开始之前才会被当轮纳入。**照实告诉用户是哪一种。**
- **`fallbackEntries`** —— 这次导入**冲掉了哪些人工调整**（哪一项、原值、回落成了什么）。
  非空时**必须原样逐条转述** —— 那是用户手动调过的判断被这次覆盖了。为空是正常的。

另外照实说清楚的：

- 🚨 **这个口没有幂等。** 同一标的送两次 = 库里被写两次、痕迹表多一条。拿到 `201` 就是成了，
  **不要因为「不确定成没成」重发。**
- 🚨 通道**没有读取面** —— 发完看不到库里有什么，也查不到刚写的那条。别去找「查询锚」的端点，
  没有那个东西，探它等于打白名单外的路径。
- ⚠️ `confidence` 一旦经本口写入，该锚的来源会翻成 `model`，**此后在 App 里改不动置信度**，
  只能再走本口重放。第一次对某只锚用本 command 时把这条告诉用户。
