# 替身「形状」与恒真检查：2026-08-04 五例实证

> 自 `docs/conventions/testing.md` §7 迁出的时点实例（2026-08-27 conventions 审计：ops 事故放在「测试是哪一类」的文档里，做部署自检的人永远读不到）。原则留在 testing.md §7：**替身数据的形状含长度 / 网络模式 / 链路位置**；**恒有输出 = 恒无输出，判据必须能区分「过」与「不过」**。

## 形状不对，测试绿是运气（三例，全是本机全绿、真环境当场崩）

1. **长度**：假 token 12 字符 vs 生产 48 ⇒ nginx `map_hash` 桶宽不够、起不来。
2. **网络模式**：本机 bridge + 端口映射 vs 生产 `network_mode: host` ⇒ 镜像自带 `default.conf` 抢 80 端口。
3. **链路位置**：只拦 `iptables INPUT` vs docker 发布端口走 `FORWARD` ⇒ 宿主服务挡住了、容器端口完全没挡住 —— **只有从对端真打才看得见**。

## 恒真检查（两例）

1. 部署自检断言「401 = 路由存在」，而未注册路径也返 401 ⇒ 永远通过。
2. 模板占位自检 `grep '__FILL_'`，而注释里也含该字样 ⇒ 永远有输出。

两例的修法相同：先构造一个「应该失败」的输入，确认检查真的红，再拿它当门。
