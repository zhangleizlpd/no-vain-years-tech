# 监控判据的三种静默失效：2026-08-27 一次排查里的三例实证

> 从 [#199](https://github.com/zhangleizlpd/no-vain-years-tech/issues/199) 一条「网关偶发 502」查下去，连着撞出三种**判据失效但不报错**的形态。三例的共同点：表现是「一直绿」或「什么都没查到」，而不是异常。
>
> 原则留在 [`testing.md` §7](../../conventions/testing.md#7-规范自身怎么验不靠通读)（可证伪性 + 两臂对照 + 恒有输出 = 恒无输出），本文只存实例与数据。

---

## 一、期望源取自被监控数据自身 ⇒ 对象消失时判据一起消失

### 现象

`marketdata-snapshot-integrity` 的分母取「**全局**最近一个有快照行的 `session_date`」。一只票连缺两轮时，它在基线日也没有行 ⇒ 不进分母 ⇒ 聚合产不出这一组 ⇒ 判据对它**无输出** ⇒ ✅ 绿。

同一判据被 `option-snapshot-coverage.check.ts` 复用（② 级盘前兜底的目标集），所以**告警与自动补救同时失明**。

### 实测（prod，`us:ALB`，三个交易日）

| session    | 现行（全局基线）判红               | 逐票基线判红      |
| ---------- | ---------------------------------- | ----------------- |
| 2026-08-24 | 3（`us:ALB` `us:APTV` `us:CMCSA`） | 3（同）           |
| 2026-08-25 | **0**                              | **1（`us:ALB`）** |
| 2026-08-26 | **0**                              | **1（`us:ALB`）** |

逐票基线在这三天**零假阳性**：健康票上 `expected` / `covered` 与全局口径逐值相同，分母只多出 ALB 一只（110 → 111）。

### 代价已兑现

本单根因于 2026-08-27 15:59 随 migration 修复。当天 18:00 的 ② 级盘前兜底**本可补回 08-26**（`sessionDate = 上一交易日`、`source = premarket_backfill`，与 `eod` 行不冲突，正是 FR-046 的用途），但 `resolveBaselineDate(08-26) → 08-25`，而 ALB 在 08-25 已是 0 行 ⇒ 不进 `expected` ⇒ 零外呼。⇒ `us:ALB` 的 08-24 / 08-25 / 08-26 三个交易日快照**永久缺失**（已按登记制录入 `ops/runbook/scheduled-tasks.md`）。

### 修法与被否掉的那条

修法是**把缺席检测的期望源换成名册**（工作集 = `need_sync` ∧ 有未到期合约），比例问题才用历史基线（[#232](https://github.com/zhangleizlpd/no-vain-years-tech/issues/232)）。

🚫 **被实测否掉的方向：把历史窗口拉宽**。prod 实测同一分母查询：

| 方案                             | 分母合约数 |       耗时 |                buffers |
| -------------------------------- | ---------: | ---------: | ---------------------: |
| 现行单日 + `need_sync` 闸        |     89,758 | **159 ms** |                      — |
| 近 21 自然日窗（≥10 交易日）+ 闸 |     91,231 | **382 ms** | **342,755（≈2.7 GB）** |

多出的 1,473 个合约**正好只是缺席那一只票的**。另测「取最近 10 期 distinct session」的自包含写法：**全表扫**（456k 行索引项、无早停），直接出局。宿主可用内存约 580 MB、探针每 4h 一轮 —— 2.4× 耗时换一只票的信息不划算，而名册一次索引扫就够。

### 业内同构

[Prometheus / Robust Perception](https://www.robustperception.io/absent-alerting-for-jobs/)：实例从服务发现消失后 `avg by (job)(up) < 0.5` 会 _returning nothing rather than alerting_；「Prometheus can't know which sets of labels are meant to exist」。正解 `absent(up{job="…"})` 里的 `up` 取自**服务发现** —— 独立于被监控指标、且在指标消失时依然存在。

## 二、判据「能红」不等于「测对了」—— 前提失效时它照样会响

### 现象

IVP 双算对表（自算 IV 分位 ↔ vendor 直读值）长期对不上，[#218](https://github.com/zhangleizlpd/no-vain-years-tech/issues/218) 逐条证否 11 条假说后结论是「像某个有界机制，但机制未知」。

判据本身**可证伪、也确实会红** —— 所以 §7 的可证伪性测不出它有问题。真问题在**前提**：它默认「两侧可复算」。

### vendor 书面答复给出的机制

[py-futu-api#257](https://github.com/FutunnOpen/py-futu-api/issues/257)（2026-08-27）：

- `get_option_underlying_his_volatility` 对 **IV 为空的日期前向填充**（取最近一个有效 iv），且**客户端无法仅凭返回序列区分真实日与被填充日**；
- `iv_percentile` 的分母取**实际有效天数**（不含空值日），我们取固定 252；
- 该字段**盘中分钟级更新**，我们拿日线收盘序列比。

⇒ 逐票偏移 = 该票窗口内的**空值日数**，三条成因客户端一条都消不掉。

### 数据如何印证

| 观察（2026-08-26，110 只可算标的）             | 机制解释                                           |
| ---------------------------------------------- | -------------------------------------------------- |
| 偏移**恰为 0** 的 65 只（59%）                 | 窗口内没有空值日 ⇒ 两侧分母都是 252                |
| 其余偏移**有界在 10 样本内、`> 10` 样本 0 只** | 偏移样本数 = 空值日数（1 样本 = 1/252 = 0.3968pp） |
| 同一标的偏移**随时间漂移**                     | 空值日随 252 日窗口滚入滚出                        |
| 偏移**恒为正**                                 | 分母更小 ⇒ 直读值偏高                              |

🚨 **调阈值是在错误的维度上找答案**：10 样本 ≈ 3.97pp，所以原「> 5pp 判硬门」那一档**结构上根本触发不了**——降它等于降了个空档；而真正会响的是 2–5pp 那带。且偏移**没有上界**，放宽到今天的经验上界，明天就会被一只空值日更多的票越过。

### 修法

逐票判据整体退场，改批级一条汇总；只留**一条**自动判据：**可算样本 ≥ 10 且恰合数为 0**。填充机制下无空值日的票必然恰合，连它们都不合 ⇒ 是自算侧塌了（[#211](https://github.com/zhangleizlpd/no-vain-years-tech/issues/211) 历史序列停更 23 天正是这个形状）。

🚨 **最小样本闸不是保守裕度，是判据的前提**：该判据默认样本里**存在**无空值日的票；样本太小时抽到的几只本来就可能全带空值日。取 10 的依据 —— 若每只独立地有 ~41% 概率带空值日，10 只全带约 `0.41¹⁰ ≈ 1e-4`。

🚫 已否决的替代：「连续相同 IV 值 = 填充日」这个启发式会把**真实平盘日**一并误判，属于用一个静默错误换另一个。

## 三、探针自己坏了，返空与「真的没有」不可区分

两例都发生在**探针**上，而不是被查的东西上；两次都是**负控制**（那个「本该命中」的对照）暴露的。

### 例 1：查询串没活着穿过嵌套引号

在 `ssh … 'docker exec … sh -c "…"'` 里 grep 中文串，多层转义后 grep 恒空。表现成「新代码不在运行镜像里」。

**负控制救回**：同一轮里查的**旧**字符串也返空 —— 而旧代码若还在必然命中 ⇒ 断定是管道坏了，不是发现。换 ASCII 标识符（`summarizeIvpDivergences` / `IVP_DIVERGENCE_HARD_PP`）后正反两臂都给出预期结果。

### 例 2：`2>/dev/null` 把 SQL 报错咽成「那一行没有数据」

夜间守候脚本里一段 `GROUP BY 1` 指向了含 `count(*)` 的拼接表达式，PG 直接报错；而管道里的 `2>/dev/null` 让它表现成「那只票没有数据」。

**冒烟时才发现**：正控制（另一只票）有输出、这一段恒空 ⇒ 不是数据问题。修法两条：去掉 `2>/dev/null`（**过滤放分析端，采集端全开**）+ 改正 `GROUP BY`。

### 顺带一条守候类脚本的纪律

长时守候**超时也要输出** —— 「等不到」是结果。安静退出会被读成「一切正常」，而这次的守候进程还真被外部清理杀过一次（换 `nohup` 脱离 + 文件落盘 + 独立哨兵三层后才稳）。
