## 1. 背景与定位

为解决国内 A 股**无法通过 API 获取持仓**的痛点，portfolio 需要一个「券商账户归属字典池」：用户把自己在各券商的账户登记进来，作为后续**导入股票资产数据时的归属标记底座**（per Master §3.2）。

- 券商账户**不是底层业务主键**（业务主键 = 市场 + 代码），仅作外部 Excel 导入 / 系统对接时的**归属映射字段**，并在自选列表页作为下拉过滤筛选器。
- 一个用户可绑定**多券商、多账号**。

---

## 2. 用户故事（User Scenarios）

1. 新用户首次进入：列表只有一个系统生成的「默认账户」（不可删），尚无真实券商。
2. 用户点右上角「新建」→ 选择券商（如中国银河证券）→ 输入客户号 → 点「绑定」→ 列表新增该券商。
3. 用户在券商列表里左滑某条已绑券商 → 删除。
4. 用户左滑「默认账户」：无删除操作（系统账户，不可删）。
5. 用户尚未绑定任何真实券商时导入资产：数据默认归属到「默认账户」（背后 = 当前账号 id）。
6. 用户绑定了多个券商后导入资产：在导入流程中**逐次选择**本批数据归属哪个券商（不设常驻默认券商）。

---

## 3. 页面结构与交互

整体三页流转：**A 列表页 → （右上角新建）→ B 绑定表单页 → （点选择券商）→ C 券商选择弹层 → 回 B → 绑定 → 回 A**。

### 3.1 页 A — 股票账户列表页（图一）

1. **标题**：「股票账户」（已定，见 §6 决策）。
2. **右上角**：「新建」按钮 → 进入页 B。
3. **列表内容**（从上到下）：
   1. **默认账户**（置顶，系统生成）：背后 id = 当前账号 id；**不可删除**（无左滑删除操作）；无客户号或显示「本账号」。
   2. **已绑券商**（用户登记）：每条左滑可删除（删除前二次确认，见 §3.4）。
4. **每行结构**：券商 logo + 券商名 + 状态标签 +（脱敏）客户号。
   - 状态标签：已绑券商显示「已绑定」；默认账户显示「系统默认」。
   - 客户号脱敏展示，如 `3119****2466`（前 4 + 后 4，中间打码）。
5. **不迁移**图一中国银河行右侧的勾（✓）——不设「当前默认/激活券商」概念（导入时逐次选，见 §6 决策）。

### 3.2 页 B — 绑定券商表单页（图二红批注改造）

| 原图二元素                   | 改造为                                                                                     |
| ---------------------------- | ------------------------------------------------------------------------------------------ |
| 顶部标题「盯盘范围」         | 「绑定券商」                                                                               |
| 行1「证券市场 → 马来西亚 >」 | 「选择券商」→ 点击进入页 C；**选中后券商 logo + 名内联显示在本行**（替代原"马来西亚"位置） |
| 行2「货币单位：MYR」         | **去掉**（券商已在行1内联显示，无需独立回显行）                                            |
| 行3「价格范围」+ 双输入框    | 「客户号」+ 单个**文本输入框**，让用户手动输入客户号                                       |
| —（新增）                    | 底部「绑定」按钮 → 校验通过后保存，回页 A                                                  |

1. 「绑定」按钮触发保存：需已选券商 + 已填客户号方可提交（校验见 §4）。
2. 同一券商可绑定多个账户（不同客户号）；唯一性 = 券商 + 客户号（见 §4 FR7）。

### 3.3 页 C — 选择券商弹层（图三，follow 本项目样式）

1. **标题**「选择券商」+ 返回；**去掉右上角「开户」按钮**。
2. **搜索框**：按券商名称 / 首字母简拼过滤。
3. **券商列表**：每行 = 券商 logo + 券商名。**去掉**同花顺的「支持 两融｜港股通｜云条件单」交易能力标签（本项目为归属字典、不做真实交易，标签无意义）。
4. **A-Z 索引**：右侧字母快速定位（按券商名首字母简拼分组）。
5. 选中某券商 → 回传页 B 行1 内联显示。

### 3.4 删除交互

1. 已绑券商左滑出现「删除」→ 点击弹二次确认 → 确认后移除。
2. 删除已绑券商 → 其名下已导入的历史归属数据**转移到「默认账户」**（数据不丢，见 §6 决策）。
3. 默认账户无删除入口。

## 4. 功能需求（Functional Requirements）

| #    | 需求                                                                                               |
| ---- | -------------------------------------------------------------------------------------------------- |
| FR1  | 列表页置顶展示不可删除的「默认账户」（背后 id = 当前账号 id），随账号自动生成。                    |
| FR2  | 列表页展示用户已绑券商，每条支持左滑删除（二次确认）。                                             |
| FR3  | 右上角「新建」进入绑定表单；表单含「选择券商」+「客户号」+「绑定」按钮。                           |
| FR4  | 「选择券商」打开券商选择弹层：内置券商字典 + 搜索（名称/简拼）+ A-Z 索引；无「开户」「能力标签」。 |
| FR5  | 客户号为用户手动输入文本；**明文存储**，列表展示脱敏（前4+后4）。                                  |
| FR6  | 「绑定」保存前校验：券商已选 + 客户号非空（去首尾空格；不强制格式，各券商客户号格式不一）。        |
| FR7  | 同券商可多账号；唯一性键 = 券商 + 客户号；重复绑定需拦截并提示。                                   |
| FR8  | 无任何真实券商绑定时，资产导入 / API 默认归属到「默认账户」。                                      |
| FR9  | 已绑 ≥ 1 真实券商时，导入流程逐次选择归属券商（不设常驻默认券商）。                                |
| FR10 | 券商账户作为自选列表页的下拉过滤筛选器数据源（Master §3.2 / §3.3）。                               |

## 5. 数据模型（PRD 级，非最终 schema）

### 5.1 券商字典（系统静态）

`{ brokerCode, 券商名, pinyinInitials, logoAsset }`——内置国内主流券商清单（华泰、中信、招商、东财、银河、平安、广发、东方……）。**V1 硬编码静态清单**（含 logo 打包），清单变动需发版。

### 5.2 用户券商账户（per user，用户登记）

`{ id, userId, brokerCode, clientNo（客户号）, createdAt }`——唯一性 = `userId + brokerCode + clientNo`。

### 5.3 默认账户（系统语义，非用户登记）

- **中文显示名**：默认账户　**英文 business name**：`default`
- 背后 id = 当前账号 id（account id）；随账号自动存在；不可删除；不可编辑客户号。
- 语义：无真实券商归属时的兜底归属桶。

### 5.4 边界澄清（bounded context）

- 本 PRD 的「券商账户」= portfolio 内的**持仓归属字典**，与 `account` 模块（用户身份 / auth / displayName 等）是**两个独立 context**。
- 「默认账户」虽背后引用 account id，但它是 portfolio 侧的归属语义，**不向 `account` 模块写入任何东西**——只读引用 account id 作种子。
- 英文命名建议（待 /speckit-specify 锁定，per Master「技术命名仅参考」）：券商实体 `broker`、绑定账户 `broker-account`、默认 `default`。

## 6. 关键产品决策

| 决策点                    | 结论                               | 理由                                                                                                                      |
| ------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 页面结构（列表 vs 表单）  | 拆两页，不合并为单页 master-detail | 非高频操作；手机端 drill-down 比 master-detail 更 idiomatic；避开表单双模（新建/编辑）+ dirty 切换 + 手势共存等中等复杂度 |
| 默认账户命名              | 默认账户 / `default`               | 直白；系统生成兜底归属                                                                                                    |
| 表单行2（原货币单位）     | 去掉，券商内联显示                 | 行1已内联展示选中券商，独立回显行冗余                                                                                     |
| 已绑券商「默认/激活」概念 | **不设**                           | 导入时逐次选归属券商，避免常驻默认歧义                                                                                    |
| 图三能力标签              | 去掉                               | 归属字典不做真实交易，两融/港股通等无意义                                                                                 |
| 图三「开户」按钮          | 去掉                               | 本项目不承接开户业务                                                                                                      |
| 列表页标题                | 「股票账户」                       | 对齐 Master §3.2                                                                                                          |
| 客户号存储                | 明文存储 + 展示脱敏                | 归属标记非登录凭证，敏感度中；列表前4+后4打码                                                                             |
| 删券商后历史归属数据      | 转移到「默认账户」                 | 数据不丢，归属回落兜底桶；导入特性落地时再细化                                                                            |
| 券商字典来源              | V1 硬编码静态清单（含 logo 打包）  | 最快；清单变动需发版，后端可配置 V2+ 再议                                                                                 |
| 券商列表市场约束          | 不约束                             | 券商纯归属标记，不随激活市场过滤                                                                                          |

## 8. 边界与非功能 + 剩余延后

### Out of Scope（V1 本特性不做）

1. 真实券商 OAuth / API 直连拉取持仓（A 股本就拉不到；本特性只做手动归属登记）。
2. 实际的资产导入流程（Excel 解析 / 字段映射）——本特性只提供「归属券商」这一维度，导入特性单独 PRD。
3. 海外券商（富途/老虎/IB 等）——V1 券商字典聚焦国内主流券商。

### NFR

1. 券商账户写入 / 删除需稳定持久化；删除已绑券商后，其名下历史归属数据转移到「默认账户」，不丢数据（见 §6 决策）。
2. 客户号明文存储，属敏感信息，列表脱敏展示。

### 剩余延后（SDD / impl 解）

1. **「绑定」保存错误态展示**：重复绑定 / 保存失败的提示形态（Toast / 行内）→ SDD plan / mockup。
2. **券商 logo 资产来源**：各券商品牌 logo（SVG/PNG）从何获取 → impl 阶段处理。
