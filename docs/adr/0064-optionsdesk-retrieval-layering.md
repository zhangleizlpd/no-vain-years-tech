# ADR-0064: optionsdesk 选约检索五层架构 — 召回 / 粗排 / 特征加工 / 精排 / 表达，与可插拔精排

- Status: Accepted (2026-08-12)
- Deciders: @zhangleizlpd
- Tags: optionsdesk / retrieval / ranking / architecture
- Relates: [ADR-0043](0043-server-flat-module-paradigm.md)（扁平 / 贫血 / 护城河 / 零-class；本 ADR 在其 §4 Port 三分法上追加第四类）· [ADR-0062](0062-optionsdesk-bounded-context.md)（optionsdesk bounded context）· [ADR-0032](0032-backend-bounded-context.md)（module 边界）· [ADR-0053](0053-cross-context-pure-rules-import.md)（跨 ctx 纯函数 import 禁令，本 ADR 不触发）

## Context

选约表要从一条期权链里挑出「值得看的那几张」。这条路径在 `050` 已经被做成召回 + 打标 + 精排三段，但**层与层的边界只活在代码里，没有被显式定义**。由此产生三个必须一次性定掉的问题：

1. **层的职责与顺序不明** ⇒ 「先筛再排名」这类改动写出来能跑、数字齐全、只是分母错了，且不会红。
2. **一个视角缺了成色门槛不会被发现**。实证（2026-08-12，`us:KBR`，spot `37.56`）：收租视角按折算年化降序的前 14 行**全部是实值**，含 `K = 105`（相对 spot `+179.6%`）排在第 3 位、年化 `384%`。成因是公式在实值区退化——深度实值 put 的 `bid ≈ K − spot`，故准备金 `K − bid ≈ spot` 恒定而分子随 `K` 增长；那 13 行准备金**同为 `39.60`**，经济上是同一笔交易（花 39.60 买入现价 37.56 的股票）。**再完美的精排也修不了它**，因为按公式它们确实是年化最高的一批。
3. **特征算在哪、检索要不要接缝** —— 两个问题会互相牵制：把特征下沉到存储层能减少读取，但若同一特征在两处各算一份，就落进业界称为 training-serving skew 的失败模式。

⇒ 本 ADR 定义分层、跨层不变量、以及三个此前无归属的架构选择。

## 决策 1 · 五层及各层职责

```text
召回层   → 粗排层 → 特征加工层 → 精排层 → 表达层
```

| 层             | 职责                                                                   | 禁止                                        |
| -------------- | ---------------------------------------------------------------------- | ------------------------------------------- |
| **召回层**     | 硬门槛（成色 / 期限 / 流动性 / 权利金）+ 用户筛选 + 截到**候选上限 K** | MUST NOT 用用户可见的条数当 K（见不变量 ①） |
| **粗排层**     | 多路候选的合并 / 去重 / 粗筛。**当前为 no-op**（单路召回）             | MUST NOT 在此引入与精排不同口径的打分       |
| **特征加工层** | 由候选集算出精排所需的全部特征（含标的**值**）                         | MUST NOT 被跳过或部分前移到精排层内联计算   |
| **精排层**     | 排序。**可插拔**：今日为单键降序，将来可为加权评分或模型               | MUST NOT 直接读原始腿（见不变量 ②）         |
| **表达层**     | 呈现截断到用户可见 N、文案、着色、格式化、标的**呈现**                 | MUST NOT 重新计算任何特征或标的值           |

📌 **「标」不是一层的产物，是两件事**：标的**值**（算不算得上）归特征加工层，算一次；标的**呈现**（画不画、什么颜色、什么文案、什么位置）归表达层。把「标」整体划给表达层会让人在表达层重算一遍判定 —— 那正是不变量 ③ 要禁的。

## 决策 2 · 五条跨层不变量

**① 截断分两级，两个 K 语义不同，且 `K ≫ N`。**
召回层的 `K` 是**候选集上限**，作用是给下游限流；表达层的 `N` 是**用户可见条数**。二者必须是两个数。
🚨 理由是检索系统的硬约束：**下游的召回天花板由上游设定，上游漏掉的候选，下游永远捞不回来。** 当精排是「按某个可在召回层复现的单键降序」时两级截断结果重合，问题看不出来；一旦精排换成模型或多因子，召回层若还按旧口径截到 `N`，模型能看到的就只有旧口径的前 `N` 条 —— 而条数与数值全部正常，不会红。

**② 精排层只读特征集，不读原始腿。**
否则切换排序策略时会发现某个量拿不到。特征集**存归一化后的值**，字典序比大小不受归一化影响，加权时零改动。

**③ 每个特征恰好一个计算地点。**
skew 来自**重复**，不来自**分布**：特征分散在不同层是允许的，同一特征在两处各算一份是禁止的。

**④ 召回层的每一道门槛 MUST 下发被挡下的计数，且该计数在界面上可见。**
硬门槛砍掉的候选默认不可见 ⇒ 「漏了就回召回层修」这条纪律缺少触发信号。计数是让召回遗漏可发现的最低成本手段。外部扫描工具是**额外**的 double check，不替代本条。

**⑤ 每个视角的召回门槛必须表达该意图的经济语义；缺失即缺陷。**
`Context` §2 的深度实值案例是本条的实证：一个视角若只有期限与流动性门槛而没有成色门槛，它会稳定地把「公式退化产物」排在最前，且任何下游层都救不回来。

## 决策 3 · 不设重排层

检索系统的第四段通常是重排（re-ranking），用于平衡多样性 / 公平性 / 商业化。**本系统不设该层。**

理由：本系统是**单人自用的决策辅助**，不存在多方撮合 —— 没有商家、没有广告位、没有平台侧收益需要与用户收益权衡，**重排层要优化的那个目标函数在这里不存在**。

📌 唯一形态相近的候选是「每到期日限 N 条」（用于压制短期限腿霸榜），已否决，理由是它新增一层不可解释性，而本系统的可解释性要求是「用户要能从屏幕反推为什么它排前面」。

## 决策 4 · 检索层立 port —— ADR-0043 §4 Port 三分法的第四类

[ADR-0043 §4](0043-server-flat-module-paradigm.md) 按场景三分：自有 ctx 的 DB 表**无 port**；外部 3rd-party SDK **保留**薄 port + adapter；跨 ctx 发布契约**保留** port。

期权链检索属**第四类：跨 ctx 只读查询** —— 数据在他 ctx 的 schema，当前走只读直查。本 ADR 追加该类的处置：**保留 port**。

🚨 **存在理由是「跨 ctx 只读的显式接缝 + 可 mock」，不是「为了换存储引擎」。** 后者正是 ADR-0043 §决策依据 1 判死的动机（_「不需要 Port-Adapter 做换库的虚无隔离」_）—— 换存储只是这个接缝的副产品，不是它的存在理由。接缝的直接收益是召回判据可以脱离真库单测。

**接口只暴露业务语义**：入参是「视角 + 筛选条件 + 候选上限」，出参是候选集。MUST NOT 出现 SQL 片段、游标、分页 token 或任何存储侧概念 —— 漏进去的话，换实现时接口照样要重写，接缝就白留了。

## 决策 5 · 特征计算位置与不变量解耦

**不变量（③）是「每特征恰好一处」；「哪一层」是可迁移的实现选择。** 两者解耦：

- 全部特征在应用层纯函数 —— 满足不变量 ✅
- 全部特征在检索层实现 —— 同样满足 ✅
- **混着来（同一特征两处各算一份）—— 违反** ❌

**当前位置：应用层纯函数。** 迁移到检索层的触发条件（任一命中即重审）见 frontmatter `sunset_trigger` 第三条。

代价必须在迁移时一并承担，不得只搬公式：判定语义中心从纯函数移到查询实现，会与 ADR-0043「业务不变量落纯函数 `*.rules.ts`」冲突；且公式的边界分支（除零、缺值、部分字段缺失仍应进候选）会从毫秒级单测降级为需要容器的集成测试。

## 候选与否决

| 候选                                      | 否决理由                                                                               |
| ----------------------------------------- | -------------------------------------------------------------------------------------- |
| 召回层直接截到用户可见条数（单级截断）    | 违反不变量 ①；当精排换成模型后会静默封顶且不会红                                       |
| 特征在检索层与应用层各算一份 + 配等价测试 | 业界对该形态的处置是**消除重复**而非测试重复；等价测试昂贵且脆，drift 时两边都算得出数 |
| 把标整体划归表达层                        | 会诱导在表达层重算判定，违反不变量 ③                                                   |
| 设重排层备用                              | 目标函数不存在（决策 3）；空层会被后来者填入不可解释的启发式                           |
| 检索层不立 port，继续只读直查             | 召回判据无法脱离真库单测；跨 ctx 读缺显式接缝                                          |
| 立 port 且理由写「为换存储引擎」          | 与 ADR-0043 §决策依据 1 正面冲突，会被正确地驳回                                       |

## 后果

- **正面**：层职责显式化后，「先筛再排名」「视角缺成色门槛」这两类不会红的缺陷都有了可断言的判据；精排可插拔使排序策略演进不触碰其余四层；port 让召回判据可脱离真库测试。
- **负面**：分层带来一次性的重构成本（现有实现需按五层重新切分并补断言）；port 引入一层间接，单实现期间它的收益只有「可 mock」。
- **中性**：粗排层长期为 no-op。它的存在是为了让多路召回落地时**有位置可放**，而不是现在就有活干。
