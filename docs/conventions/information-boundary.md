# 信息边界约定 —— 代号 ↔ 物理绑定解耦

> 本仓面向**公开**。本文定「什么可以进仓、什么必须留在仓外」的判据。
>
> 机器强制：`scripts/checks/check-identifier-boundary.ts`（`pr-validation.yml` 的 `gate-checks` + lefthook `pre-commit` + lefthook `commit-msg`）。

核心原则一句话：**仓内只出现代号，代号 → 物理绑定的映射在仓外。** 换物理机 = 改仓外一行，仓内零改动。

这不是为了藏东西才这么做 —— 把「这台机器是什么角色」和「这台机器现在是哪台」耦合在一起，本来就是设计缺陷。公开只是让这个缺陷变得有代价。

## 三层归属：一个东西该放哪

| 归属               | 判据                                                                                                                                                                            | 载体                                                                                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **公开**           | 泄漏它不降低任何主机的攻击成本。协议常量、角色代号、**ssh-config alias**、**主机上的仓路径**、**公开构建服务的 project ID**、RFC1918 地址、业务逻辑、架构决策、限频值、测试用例 | 仓内                                                                                                                                                  |
| **仓外运行时解析** | 它**标识或定位**某台真机 / 某个云账号。公网 IP、`user@host` 串、ECS 实例 ID、云账号 UID、VPC/vSwitch/安全组 ID、容器镜像仓实例 ID、CDN/DNS 账号 ID                              | `ops/host/fleet.env.example` 声明变量名（公开契约）；真值在 `~/.nvy/fleet.env`（dev 机）/ `/etc/nvy-fleet.env`（各主机）/ GitHub Actions repo secrets |
| **私有散文**       | 内容**本身**即情报，脱敏个别字段也救不回来。主机清单、RAM 用户 ↔ 权限集 ↔ 凭据文件路径映射、实盘系统的已知脆弱窗口、自然人的物理位置（如把家庭出口 IP 当 SSH 白名单）           | `docs/private/`（gitignored，per [`docs-organization.md`](docs-organization.md)）；公开侧按需留 stub 保入链                                           |

### 三条容易判错的边界

**RFC1918 地址（`10.x` / `172.16-31.x` / `192.168.x`）留公开。** 私有段地址在没有 VPN 公钥**且**没有公网 endpoint 时是惰性的，而 endpoint 属第二层、已经出仓。硬要脱敏它，代价是把它从代码默认值、单测 fixture、部署脚本里连根拔起 —— 大面积回归风险换零安全收益。只参数化 `Endpoint = <公网IP>:<port>` 那一行。

**限频值、CORS 白名单、反枚举逻辑留公开。** 这些设计经得起公开（Kerckhoffs 原则）—— 一个只在别人不知道时才安全的限频阈值，本来就不安全。若某条防护**依赖**其细节不被知道，那是设计缺陷，改设计，不要靠不发布来兜。

**ssh alias 与主机上的仓路径也留公开** —— 这条初版划错过，2026-08-08 首次启用 L2 值层时当场暴露（它们制造了一大批假阳性，而假阳性会教人忽略 L2 告警、等于把这一层废掉）。判据：

- **alias 本身就是一种代号。** 有识别性的是 alias → IP 的**映射**，不是 alias。把它划进仓外层，等于既拿不到安全收益，又逼所有 shell 与 systemd unit 去 env 化一个本来可读的名字。
- **仓路径是文件系统路径，不是标识符。** systemd `WorkingDirectory=` 必须字面量、env 化不了；且没有访问权时知道目录名什么也不是。

**移动构建服务（Expo / EAS）的 `projectId` 留公开** —— 它是公开 API 可查的项目标识，不授予任何权限（构建 / 推送都要另外的 access token），`app.json` 直接 tracked；env 化它得改 `app.config.ts` + build 期 env，代价换零收益。初版划进仓外层是划错（2026-08-27 降级）。

一般化的判据：**先问「泄漏它是否降低攻击成本」，再问「它能不能被 env 化」。** 两个答案都是「否」时，把它塞进仓外层只会制造假阳性 —— 而假阳性的代价是整层守门失去可信度，比漏一个低价值信息严重得多。机器侧对应 `NON_IDENTIFIER_KEY`（`scripts/checks/check-identifier-boundary.ts`）。

## 代号纪律

主机在仓内只以**角色代号**出现。代号说明它**是什么**，仓外的 `fleet.env` 说明它**现在是哪台**。

- 代号是角色化的、稳定的；物理机换了代号不变。
- **永不用 IP 段号给主机起外号。** 那等于把标识符编进了词汇表，此后每次口头讨论、每条 commit message 都在泄漏。
- **角色代号与 ssh alias 并存，两者都公开**，各管一头：alias 给 shell / systemd 用（`ssh "$NVY_APP_SSH_ALIAS"`），角色代号给散文用。这样不必改本机 `~/.ssh/config` 就能让文档说清「它是什么」。
- 历史误名（alias 与真实角色不符，如带 staging 字样却是生产）因此**不是安全问题、是可读性问题**：散文里一律用角色代号，别拿 alias 指代主机 —— 否则读者会照字面误判它是预发环境。alias → 物理绑定的映射仍在仓外。

## 新增任何东西时的 5 问自检

新主机 / 新服务 / 新 runbook / 新 env var / 新 spec / 新 plan —— 走同一套：

1. **这里面有没有能定位到一台真机或一个云账号的字符串？** 有 → 第二层，进 `fleet.env`，仓内用 `${NVY_*}` 引用。
2. **如果只脱掉那些字符串，剩下的内容还安全吗？** 不安全 → 第三层，整篇进 `docs/private/`，别试图逐字段脱敏。
3. **这份文档是某台机器的唯一重建路径吗？** 是 → 它进 `docs/private/` 的代价是「丢了就重建不了」，要么留公开 stub 指明本体位置，要么确认冻结副本在私有归档里。
4. **我要写的是状态还是判据？** 「当前还有 N 处未脱敏」是状态，进 plan；「标识符不进仓」是判据，进本文。
5. **这条信息会不会经 auto-memory 反向流回公开仓？** 见下。

## auto-memory 是通往公开仓的写放大器

`~/.claude/.../memory/*.md` 每个 session 起手自动装载，其字节此后每一轮都在模型工作集里 —— 可被原样复现进 commit message、PR body、plan、代码注释，而这些都落**公开**仓。

所以 memory 里**只放指针，不放标识符**：代号表 + 「真值去哪取」+ 非标识符的耐久坑。这条没有机器强制能兜（见下节 gitleaks 的能力边界），唯一可强制的不变式是那串字符根本不进 context。

## 机器强制的分工与能力边界

| 层                                           | 在哪跑                  | 判什么                                                                                                     | 承重         |
| -------------------------------------------- | ----------------------- | ---------------------------------------------------------------------------------------------------------- | ------------ |
| **L1 结构层** `check-identifier-boundary.ts` | CI，每个 PR，**无条件** | 判**形状**：公网形状 IPv4、云实例/镜像仓/网络资源 ID 前缀、裸 16 位数字、32 位 hex。**不需要知道任何真值** | ✅           |
| **L2 值层** 同脚本，pre-commit + commit-msg  | dev 机                  | 从 `~/.nvy/fleet.env` 的值**派生**精确模式                                                                 | 纵深         |
| gitleaks                                     | pre-commit + CI         | 凭据（靠熵与厂商前缀）                                                                                     | 不覆盖标识符 |

三条设计纪律，每条都有反例撑着：

1. **L1 必须在 CI，不能只在 pre-commit。** 只挂本地钩子的守门在 CI 上永远 skip，而 CI 才是唯一拦得住 PR 的路径；本地钩子还结构上可被 `--no-verify` 绕过。
2. **采集端全开，过滤放分析端。** detector 扫 `git ls-files` 全集、**零 skip-dirs**。反例：仓内的文件树 CVE 扫描器 trivy-fs **至今**配着 `skip-dirs: docs,…`（对 CVE 扫描合理），而 `docs/` 正是所有基础设施标识符的所在地 —— 标识符 detector 若也这么配，反例就永远看不见。
3. **allowlist 登记「已知良性」，不是「已知恶性」。** 新出现的任何公网形状标识符默认红，直到有人显式登记理由；登记在 `ops/host/identifier-allowlist.json`，**按值、永不按路径**（路径豁免 = gitleaks 那条 skip-dirs 教训的复现，见 ADR-0037 §1）。denylist 做不到这件事，而且把真标识符写进 denylist 等于再发布一遍。

**gitleaks 抓不到标识符**：裸 IPv4、云账号 UID、实例 ID 都没有熵特征，内置规则集里没有对应 rule。别把「gitleaks 绿」当成标识符边界的证据（per [ADR-0037](../adr/0037-security-credentials-governance.md) §1）。

## 验证纪律：能不能看见反例

守门改动后，声称「有效」之前必须先能回答：**如果反例存在，我的管道能看到吗？**

机械化的答法是两级验证，第二级才算验证：

1. **detector 单测** —— 正例必红；**负控制必绿**（RFC 保留段 / 文档保留段地址按结构排除；≥ 5 段或含 >255 八位组的点分数字；公共 DNS、语言常量、业务 ID 形状的长数字走 allowlist 条目）。**恰好 4 段的版本号刻意判红**（fail-closed —— 结构上与公网 IP 不可分），撞上按值登记 allowlist，不加上下文抑制。detector 在负控制上误报就会被人关掉，等于零保护，所以负控制比正例更重要。
2. **管道演练** —— 在真分支上埋已知的坏串，逐一确认被哪一道拦住；并断言 detector 的扫描集**等于** `git ls-files`。埋的探针自身要先经「零豁免配置」确认能触发规则，否则拿假阴性当通过。

已知拦不住的三处（明说而非掩盖）：**PR body**（无 git 侧钩子能看到，只能靠 CI 读 PR 事件体）、**`--no-verify`**（本地钩子结构性可绕，靠 CI 那层兜）、**二进制（截图等）**（正则无从下手，「像素里的 PII」没有扫描器能抓 —— 故 `specs/*/design/` 整体不入库，`.gitignore` + sdd-authoring rule）。
