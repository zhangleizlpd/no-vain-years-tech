# Feature Specification: 意图 Tab 选约表 + 期权链逐日快照管道（M2b）

**Feature Branch**: `047-optionsdesk-chain-leg-picker`
**Created**: 2026-08-04
**Status**: Draft
**里程碑**: sell-put 可视化决策系统 p4 第三片 = **M2b**（[p1 §8](../../docs/private/plans/2026-07/07-23-sellput-viz-p1-requirements.md)）

## 背景：为什么切在这里

前两片已 ship：**045**（M1 = 锚管理 + P1 雷达标的视图）、**046**（M2a = P2 详情页上半：锚卡 + 个股温度计区块 + 区间时序图，外加 P7 温度计整页）。本片接着往 **同一张 P2 详情页**下方追加「意图 Tab 选约表」核心区块，并落它背后的**期权链数据管道**。

三条把边界钉在这里的理由：

1. **数据粒度的天然切口**（08-02 拍板）：M2a 全是**标的级**数据（正股日线 / 标的聚合 IV / 指数），M2b 全是**合约级**（链发现 + 逐日快照）。依赖面零交叉，所以 M2a 能先走。
2. **不可逆性把本片的优先级顶到最高**：三家 vendor（富途 / 嘉信 / IBKR）**均不提供期权 EOD 历史**（[p3b §6.5](../../docs/private/plans/2026-07/07-30-sellput-viz-p3b-data-architecture.md)）⇒ **今天没采的快照，将来任何手段都补不回来**。这条把「完整性告警」从 nice-to-have 变成本片**优先级最高的一道防线**，也是把管道排在 UI 之前（US1 先于 US2）的唯一理由。
3. **不含跨标的聚合**（08-04 拍板）：P1 雷达顶部四视图 seg 的其余三视图（机会 / 建仓腿 / 收租腿）**已切给 M2c** —— 它们与本片用同一份快照，但风险性质不同（本片扛不可逆的数据管道风险，M2c 扛可反复调的排序 / 档位口径）。045 `FR-020` 当初 defer 它们时，p1 §8 里程碑表四片一格都没收，08-04 对账时补上。

| **V-A** ✅ | **盘前窗口能否用于补昨日快照** —— 在北京次日 16:00–21:30 重拉某票全链，与昨日收盘后落库的快照**逐字段比对**（不只 bid/ask，含 greeks / OI / Vol / vendor 时间戳） | FR-046 第 ② 级补救整条挂在它上面。已有证据（E32）只证了「盘前重拉与前收逐字节相同」这个**观察**，**没证**「可拿它当昨日快照落库」这个**用法** —— 两者差一个 `session_date` 归属判断，且 OI 这类日结字段是否已翻新未知 | FR-046 退回一级补救（当日重试 + 只告警、人工补采），完整性告警的时效风险由人承担 |

> ✅ **V-A 已于 plan 期结清，实测不再单跑**（2026-08-04 定案，plan D-DATA-4）。原计划是「收盘后落一份 + 次日盘前再拉一份逐字段 diff」；结清的理由不是省事，而是**官方文档 + E32 合起来已经把答案给全了，再跑一次只会复述文档已说的话**：
>
> 1. **bid/ask 与 `update_time` 逐字节相同** —— E32 实测 2148/2148，这一半本就成立。
> 2. **`OI` 会翻新** —— 富途官方 get-option-chain 页原文「Open interest (OI) 数据每日更新，更新时点取决于具体交易所。**美股期权在盘前时段更新**」（`openapi.futunn.com`，2026-08-04 复核）⇒ 盘前重拉拿到的 OI 是 **T 日**的真值，而不是被补的那天（T−1）的。
> 3. **greeks / IV 依赖盘前活跃的正股 spot** —— E32 自己实测 6/7 只标的有盘前成交（PEP 已 +0.45%），而 E32 **没有**比对过 OI 与 greeks 这两组字段。
>
> ⇒ 「盘前重拉能原样当昨日快照落库」这个用法，**在 `OI` 与 greeks 两个字段上本就不成立**。故不走「退回一级补救」那条退路，改为**按已知漂移设计**：FR-046 第 ② 级补救**保留**，代价是字段级语义必须显式化 —— 快照行除 `session_date`（归属交易日）外另存 **`oi_as_of`**（OI 的归属交易日）与 **`quote_as_of`**（本行报价的实际采集时刻），正常路径 `oi_as_of` = 上一交易日、盘前补采路径 `oi_as_of` = `session_date`，两条路径各自自洽且可区分。<br>🎁 顺带解掉了一个此前无人处理的**既有**偏差：收盘快照的 OI 恒滞后一日。<br>🚫 **MUST NOT 为「对齐」把 OI 归到 `session_date`** —— 那是拿标签掩盖真实 vintage，正是本仓反复吃亏的那类静默。

## Clarifications

### Session 2026-08-04（specify 阶段 · 起 spec 前对账四份 plan 时随拍板一并定的范围边界）

- **Q: P1 雷达的机会 / 建仓腿 / 收租腿三视图归本片吗？** → A: **不归**，已切为独立的 **M2c**。切口 = 风险类别：本片扛「漏采即永久缺口」的不可逆数据管道风险，M2c 扛可反复调的排序 / 档位口径；且 M2c 零新增维度、纯消费本片落的快照。合片估 45+ task（M1=28 / M2a=29），会让不可逆的那半被可调的那半拖住。
- **Q: 选约表的链行情取实时还是 EOD？** → A: **EOD 快照 + 显式 `asOf`**，盘中实时不进本片。依据是实测而非取舍偏好：北京 16:00–21:30（ET 盘前）**期权不交易**，对同一批 2150 个合约重拉，bid/ask 与前收**逐字节相同**、决策带内 PUT 474/474 全等（p3b E32）⇒ p1 §2 场景 A 的**盘前决策主场景零信息损失**。连带：与 V10（港股臂）/ OpenD 常驻改造彻底解耦，且请求路径不碰 vendor ⇒ 不存在网关冷启打穿端点预算的问题。
- **Q: 意图双 Tab 形态由谁定？** → A: **本片定形**（p1 §10-3 已把它从落空的「→ p2」改指到 M2b 的 clarify）。M2c 的三个腿视图**沿用本片定下的形态与档位口径**，不重新开问。
- **Q: 采集要不要设 strike 带以省成本？** → A: **不设，采全链**。策略是锚轴 + 市场轴双轴（收租看 `K ≤ W = 0.8V`、CC 看 `K ≥ 愿卖锚`），spot 显著偏离 V 时这些 K 会掉出任何固定带外。链接口本就返回窗内全部合约，带过滤只省 snapshot 批次（7 票约 2100 行 = 6 批，成本可忽略），却会引入「带定错 → 腿静默消失」这一整类 bug。

### Session 2026-08-04（specify 阶段第二轮，3 问全部收敛）

- **Q1 · 仓位水位档没有数据面，意图 Tab 默认落位怎么定？** → A: **手选 chip**（FR-017）。三选一控件按标的持久化，未选之前 Tab 停「全腿」+ 显式提示，**不静默假设档位**。被否的两条：「按最保守档（≥2/3）假设」与 046 立下的「禁显 0、显未知」处置直接相悖 —— 在没数据时替人做方向性假设；「默认恒停全腿、不提供输入」则让 US3 的自动落位本片等于没启用。选手选的决定性理由 = **它与 v1「现金手工录入」是同一类降级路径**（p1 §5 P3 已有先例：现金未录 → 「不可计算」而非 0%），不是为本片临时造的 hack，M3 到位后自然升级为真数据。
- **Q2 · 单票数百行时「全量呈现不截断」的具体形态？** → A: **虚拟化渲染**（FR-005）。理由 = 它是唯一**零语义妥协**的解：逻辑集合 / 滚动条 / 导出口径三者都是全量，只是不渲染视口外的行；且 RN 原生列表即可，零新依赖（守 SC-008）。<br>📌 **写这条时先厘清了一个事实**：p1 其实已给两个意图 Tab 各自的带（建仓腿 ATM 带 × 短 DTE / 收租腿锚轴邻域或 OTM Δ 档），**真正会爆行数的只有「全腿」Tab**，所以虚拟化的适用面比一开始设想的窄。被否的「按到期日分组折叠」代价 = 引入第二套折叠语义，与 p1「死档不折叠」容易被下游读混（那条约束的是**档位**不是到期日）。

## User Scenarios & Testing

### User Story 1 — 逐日快照开始积累，且漏采当天就被发现（Priority: P1）

每个美股交易日收盘后，白名单标的的**全链期权合约与当日行情快照自动落库**；任何一票的当日行数异常（整票缺席 / 行数骤降）先由**两级自动补救**兜住（当日重试 → 次日盘前窗口重采），两级都救不回才叫醒人 —— 而不是等到某天想复盘时才发现半年前缺了一段。

**Why this priority**：这是全片唯一**不可逆**的部分。三家 vendor 都不提供期权 EOD 历史 ⇒ 今天没采的，将来花钱也买不回来。UI 晚一周做只是晚一周看，管道晚一周上线就是**永久少七天数据**。它也是后续所有片（选约表 / M2c 聚合视图 / M4 归因与逐日 greeks 时序）的共同地基。

**Independent Test**：完全不碰 UI 也能验 —— 触发一轮采集，检查各票落库行数、逐票比对上一交易日、注入「某票整票缺席」与「行数腰斩」两类故障看是否 ERROR。

**Acceptance Scenarios**：

1. **Given** 白名单有 N 只已建锚标的，**When** 当日采集跑完，**Then** 每只票的全链合约与当日快照均已落库，且同日重跑不产生重复行。
2. **Given** 某票有一批上一交易日在、当日仍未到期的合约当日没拿到快照，**When** 完整性核对运行，**Then** 产生 ERROR 级告警并指明是哪一票、缺了哪些合约，**且** 不因其他大票覆盖正常而被掩盖。
3. **Given** 某票当日整票缺席，**When** 完整性核对运行，**Then** 同样产生 ERROR（逐票汇总，不看全局总数）。
4. **Given** 当日是大到期日次日（上一交易日有一批合约集体到期），**When** 完整性核对运行，**Then** **不**产生告警 —— 已到期合约不进分母，行数骤降属正常态。
5. **Given** 某行数据违反落库前自洽硬门（如 `bid > ask`），**When** 采集写库，**Then** 该行不入库并 ERROR，**且** 已落的历史数据不被破坏。
6. **Given** 锚表为空（无票开闸），**When** 采集触发，**Then** 该轮跑绿、对 vendor 的请求数为 0，**且** 不产生假红告警。
7. **Given** 某日收盘后采集失败，**When** 次日盘前窗口的兜底重采跑通，**Then** 该日快照被补齐、不升 ERROR，**但** 留下「本日数据来自兜底补采」的痕迹。
8. **Given** 当日重试与次日盘前兜底**均**失败，**When** 补救链走完，**Then** 升 ERROR 告警并指明缺的是哪一票哪一天。

### User Story 2 — 单票选腿：这只票哪条腿最肥（Priority: P2）

盘前打开某票详情页，往下划就能看到这只票**全部可卖 put 腿**的一张表：每条腿的行权价 / 到期、报价、费率档位、有效成本相对 W 的位置、Δ 与 σ 距离、流动性三件套（OI / Vol / 成交额）与活跃度，按档位排好序、按费率着色分档，**不做 top-N 截断**。

**Why this priority**：这是本片的用户面主价值 —— p1 §3 七层链路的第 4 层（选约层）第一次数据化。但它依赖 US1 的数据，故排 P2。

**Independent Test**：造一批快照数据即可端到端验证呈现与排序，无需真跑 vendor。

**Acceptance Scenarios**：

1. **Given** 某票有当日快照，**When** 打开其详情页并划到选约区块，**Then** 该票全部适格腿呈现在表内，**无**静默截断，腿多时靠滚动而非分页丢弃。
2. **Given** 表内含费率低于最低档的腿，**When** 渲染，**Then** 这些「死档」**默认摊开**（不折叠）、灰底、排在列表底部、动作列标「死档剔除」且不提供后续动作入口。
3. **Given** 某腿的 greeks 缺失，**When** 渲染，**Then** 该行**仍在表内**并显式标「数据不全」，**MUST NOT** 因缺 Δ 而被筛掉。
4. **Given** 快照非当日（陈旧），**When** 渲染，**Then** 全表照常呈现，**且** 区块带显式「数据截至 X · 收盘」标注。
5. **Given** 该票从未采过快照（刚建的锚），**When** 打开详情页，**Then** 显式提示「链数据未就绪」，**非**空白页、**非**错误页。
6. **Given** 表格列数超出屏宽，**When** 用户横向滑动，**Then** 可看到隐藏列，且纵向滚动仍在详情页内正常工作。

### User Story 3 — 这一格该干什么：意图判定与三 Tab（Priority: P3）

选约表分三个 Tab（**全腿 / 建仓腿·周化 / 收租腿·年化**）。打开时**自动停在**当前这只票该有的意图上 —— 由 L 层 × 五区间 × 仓位水位的意图判定矩阵决定（水位这一维本片靠手选 chip 补，未选则停「全腿」并提示）；两个腿族**各按自己的口径**算档位（建仓腿看周化、收租腿看年化），**禁跨腿族直接比折年数**。每行给一个动作建议标签，但**建议非拦截**，页脚常驻「触发 ≠ 开仓 —— 人工终决」。

**Why this priority**：把「读出数据」升级为「读出这格的意图」。US2 已经可用（默认停全腿即可），故本条排 P3。

**Independent Test**：固定锚与 spot 造出五区间 × L 层的组合，断言 Tab 默认落位与档位着色，不依赖真数据。

**Acceptance Scenarios**：

1. **Given** 某票**已手选**水位档且 L 层 / 区间 / 水位组合对应「收租」意图，**When** 打开选约区块，**Then** Tab 默认停在收租腿·年化。
2. **Given** 某票**尚未选**过水位档，**When** 打开选约区块，**Then** Tab 停在「全腿」并显式提示选一次水位，**且** 三个 Tab 全部可正常进入读表 —— MUST NOT 因缺水位而挡住看数据。
3. **Given** 用户手选了水位档，**When** 重新进入该票详情页，**Then** 选择被记住，**且** 界面能看出这个值是人工输入而非系统已知。
4. **Given** 某 Tab 下零适格腿，**When** 切到该 Tab，**Then** Tab **可进入**并显示空态文案，面板**不隐藏**、不置灰。
5. **Given** 该票处于不动区（矩阵输出「不开新仓」），**When** 渲染，**Then** 警示注置顶，**且** 腿数据照常全量展示（全量可见原则）。
6. **Given** 同一屏同时有周化行与年化行（全腿 Tab），**When** 渲染，**Then** 每行显式标注所属腿族口径，**且** 排序用统一的档位键而非直接比数值。
7. **Given** 任一腿处于「好」或「可接受」档，**When** 渲染动作列，**Then** 两档**合并**显示为同一个「挂 OCO」标签，靠费率着色区分档位，不用文字区分。

### User Story 4 — 别踩在财报上：意图分域打标（Priority: P4）

收租腿旁边显示财报关系：**长腿**看「已知利空是否出清覆盖」（覆盖 ✓ / 缓冲不足 +Nd），**短腿**看「是否跨财报」（提醒 ⚠）；**建仓腿无标**（建仓意图本就想接货，财报跌反而是折扣）。全部是提醒语义，**无拦截**。

**Why this priority**：第三章「意图分域」的呈现面，是选腿的重要输入但非必需 —— 没有它前三个故事仍完整可用。

**Independent Test**：造财报日期与到期日的相对位置组合，断言三种打标与「无数据」态。

**Acceptance Scenarios**：

1. **Given** 某收租长腿的到期日在下一个财报日之后且缓冲天数充足，**When** 渲染，**Then** 标「利空出清覆盖 ✓」。
2. **Given** 缓冲天数不足，**When** 渲染，**Then** 标「缓冲不足 +Nd」并给出还差几天；**且** 缓冲只约束「最后利空 → 到期」这一侧。
3. **Given** 某收租短腿跨越财报日，**When** 渲染，**Then** 标「跨财报提醒 ⚠」，**且** 该腿仍可被选中（提醒非拦截）。
4. **Given** 某建仓腿跨越财报日，**When** 渲染，**Then** 该行**无**财报标注。
5. **Given** 该票无财报日数据，**When** 渲染，**Then** 该列显式呈现「无日期」，**且** 可与「已确认不跨财报」区分开，**MUST NOT** 假设总有日期。
6. **Given** 某票的财报日相较昨日快照发生了变更，**When** 当日采集跑完，**Then** 系统记录变更前日期与变更时刻（自建 PIT），并进复核名单。

### Edge Cases

- **单票腿数极多**（实测 PEP 一天 730 行）：全腿 Tab 走虚拟化（FR-005）。**残留风险 = 纵向虚拟化列表嵌在详情页纵向滚动内的手势争用**，plan 阶段必须显式处置。
- **仓位水位档在本片没有数据面**（持仓规模属 M3/M4）：靠手选 chip 补齐矩阵输入（FR-017）。**未选态是常驻分支不是过渡态** —— 新建锚的票天然处于未选，必须能正常读表。
- **vendor 当日不可用但次日盘前恢复**：两级补救的第 ② 级救回，不升 ERROR 但留痕（否则「一直在靠兜底续命」会被静默掉）。
- **非标合约**（调整后 root，如 `VICI1`）：采集端全采落库留证据，但选约表一行都不出现；若它出现在未来的持仓 / 挂单回拉里，派生值应置空而非算出一个看起来正常的错数。
- **深实值腿 greeks 被 vendor 整块置 0**（实测 227/2150 行，其中 99.5% 是「bid 跌破内在价值 → IV 无解」的深实值腿，**虚值区零缺失**）：这属数学固有现象，不应为它设常态告警；只有**虚值区**出现 greeks 缺失才是异常。
- **IV 离群**（>500%，实测 3/2150 全部 DTE=1 宽价差）：离群判定须结合 DTE，不能一刀切。
- **某白名单票发生并购类公司行为** → 出现新的非标 root，应进复核名单。
- **vendor 当日整体不可用**：快照缺口不可回补，重试与告警策略见 Q3。
- **US 半日市**：收盘时点提前，采集触发时点与「当日」归属需按交易日历判定而非固定时钟。

## Requirements

### Functional Requirements — 选约表呈现（P2 下半）

- **FR-001**: P2 详情页 MUST 在既有区块（锚卡 → 温度计区块 → 区间时序图）**下方**新增「意图 Tab 选约表」区块，MUST NOT 改动 046 已 ship 的三个区块版式。
- **FR-002**: 选约表 MUST 提供三个 Tab：**全腿 / 建仓腿·周化 / 收租腿·年化**。
- **FR-003**: 表格列集 MUST 含：行权价/到期 · **bid/ask 合并一列**（bid 主着色 + ask 小字常显）· **费率（本行口径）** · 有效成本 vs W · **Δ（|Δ| 真值）** · **σ 距离** · OI · Vol · 成交额 · 活跃度（独立列）· 标注 · 动作。表格 MUST 支持横向滑动查看隐藏列。<br>📌 **费率列 MUST 随行口径切换主数字**（08-04 mockup review 定案）：收租腿行主显年化、建仓腿行主显周化，折年恒为小字副标并标「参照·不排序」；全腿 Tab 在同一列内**逐行**切换。MUST NOT 对周化族的行主显折年 —— 否则**屏幕上的数字不是档位的判定值**（折年 111% 的周化行与年化 17.6% 的行并排同标「好」，正是 FR-004 要防的跨 DTE 直比）。<br>📌 **Δ 列 MUST 显 |Δ| 真值，MUST NOT 只显符号**（同上定案）：本片只含认沽（见 Assumptions）+ FR-043 硬门保证 `PUT Δ ≤ 0` 才入库 ⇒ 符号恒为负，该列信息量退化成「有 / 无」1 bit，而这 1 bit 标注列的「数据不全」已在表达。更关键的是 FR-005 的建仓腿带**由 |Δ| 定义**（0.40–0.55Δ），不显真值则用户无从核对某行凭什么在带内。列头 MUST 标副标「带判据」以抑制跨期限横比 —— 跨期限可比的坐标是 σ 距离不是 Δ。
- **FR-004**: 「折年」列 MUST 仅作**周化行的参照**，MUST NOT 作为短腿的决策变量或排序键（年化 ∝ 1/√T，跨 DTE 直比会系统性偏向短腿）。
- **FR-005**: 系统 MUST 按**全量呈现原则**渲染 —— 按排序逻辑呈现符合条件的全部腿，MUST NOT 做 top-N 截断或静默丢弃。**「全腿」Tab MUST 用虚拟化渲染**（只渲染视口内的行），使**逻辑集合、滚动条长度、任何导出或统计口径三者均为全量**；MUST NOT 用「先加载前 N 行、划到底再加载」这类**会改变逻辑集合**的分页。<br>📌 **只有全腿 Tab 需要虚拟化**：两个意图 Tab 的行数由 p1 给定的带天然收窄（建仓腿 = 市场轴 ATM 带 0.40–0.55Δ × DTE ≤2 周；收租腿 = 锚轴 K≤W 邻域 或 市场轴 OTM Δ 档），不是全链规模。<br>⚠️ 已知实现风险留给 plan：**纵向虚拟化列表嵌在详情页纵向滚动内**是 RN 上的已知坑（嵌套滚动手势争用），plan MUST 显式给出处置方案，MUST NOT 留到 impl 阶段临场发挥。
- **FR-006**: 死档腿 MUST **默认摊开不折叠**、灰底展示、排在列表底部，动作列标「死档剔除」，且 MUST NOT 提供后续动作入口。<br>📌 **标注列 MUST 照常按 FR-023 打财报标**（08-04 mockup review 定案），MUST NOT 因死档而留空或改显占位符 —— 死档是**费率档**，与到期日 / 财报日**正交**，其财报关系本就存在。特殊化的代价是让占位符「—」同时承载「建仓腿按设计无标」与「死档不显」两义，把 FR-026 好不容易拆开的「无日期 / 不跨」又糊回一起。
- **FR-007**: greeks 缺失的腿 MUST 保留在表内并显式标注「数据不全」，MUST NOT 被筛除（决策带由 |Δ| 定义，缺 Δ 即被筛没且无人知晓 —— 实测 227/2150 行会命中）。<br>📌 **该类行 MUST NOT 判档**（08-04 mockup review 定案）：MUST NOT 参与四档着色、费率列 MUST 显缺失占位而非数值、动作列 MUST 标「无法判档」。理由 = 费率**算得出来但会骗人** —— 实测该类 99.5% 是深实值腿（bid 跌破内在价值 ⇒ IV 无解），以 `145 P` / bid 12.30 / 准备金 132.70 为例折年算出来是 307%，可卖它本质是**变相接股**、被指派几乎必然。把 307% 染成绿色「好」档，比留空危险得多。
- **FR-008**: 非标合约（调整后 root）MUST NOT 出现在选约表任何 Tab 中，MUST NOT 参与任何派生计算。
- **FR-009**: 表尾 MUST 显示 DTE 两段式提示（结构先行：覆盖已知利空出清 + 方向性缓冲），MUST NOT 呈现「跨 DTE 年化最大化」类建议。
- **FR-010**: 每行 MUST 呈现动作建议标签；「好」与「可接受」两档 MUST 合并为同一个「挂 OCO」文案，靠费率着色区分档位。<br>📌 **「薄」档 MUST 标「暂不挂」**（08-04 mockup review 定案）——「暂」字承时间性，与死档的永久性剔除区分。四态梯度 MUST 为：**挂 OCO**（好 / 可接受 —— 去做）→ **暂不挂**（薄 —— 暂不做）→ **死档剔除**（死档 —— 永不做）→ **无法判档**（greeks 缺失，见 FR-007）。四者全为建议语义，per FR-011。<br>📌 **薄档行的费率列 MUST 同屏显出该行的 `ask` 口径值**（形如 `7.2% (ask 11.4%)`；plan D-SOT-2 期新增，此处补写为 spec 正文）。**理由 = 动作列在薄档这一格上是有意的信息损失，必须由费率列补回**：策略 SoT 的「尴尬区」实为**按 `ask` 二分且随意图分叉**的两态（`ask` 够高时接货意图可「挂多个卖一 OCO 碰运气」，否则两种意图都是跳过继续等），而那个输出属**执行层的挂单方式** —— FR-012 明禁挂单入口、FR-011 定死动作标签为建议语义，呈现面承载不了它。⇒ 动作列保持四态、薄档一律「暂不挂」，但把二分所需的那个数**摆到屏幕上**，让人能自行套用 SoT。<br>🚫 这**不是**「`ask` 参与判档」的口子 —— 分档口径恒为 `bid`（FR-018），`ask` 只作同屏参照；SoT 那个第五态记入 M3 兑现清单（plan § M3 兑现清单），不是丢弃。
- **FR-011**: 区块页脚 MUST 常驻「触发 ≠ 开仓 —— 人工终决」，且全部动作标签 MUST 为**建议语义、非拦截**。
- **FR-012**: 本片 MUST NOT 提供「选腿 → 创建许愿单」入口（属 M3）。
- **FR-013**: 选约表全部读数 MUST 带显式 `asOf`；陈旧时 MUST 呈现「数据截至 X · 收盘」，MUST NOT 静默当作当日实时值。
- **FR-014**: 该票从无快照时，MUST 显式呈现「链数据未就绪」并说明何时会有，MUST NOT 呈现空白页或错误页。
- **FR-015**: 选约区块 MUST 随期权台 tab 一并受 markets 合规开关门控（路由级 guard），与 045 / 046 同构。

### Functional Requirements — 意图判定与档位

- **FR-016**: 系统 MUST 由**意图判定矩阵**（L 层 × 五区间 × 仓位水位）判定当前标的的意图，并让 Tab 默认停在该意图对应的 Tab。
- **FR-017**: 仓位水位档在本片**无数据面**（持仓规模属 M3 / M4）。详情页 MUST 提供一个**三选一手选控件**（`<1/3` · `1/3–2/3` · `≥2/3`）作为矩阵的水位输入，选择 MUST 按标的持久化。<br>🚫 **未选之前 MUST NOT 假设任何档位** —— 此时 Tab 默认停「全腿」并显式提示「选一次水位档以定位意图」；MUST NOT 显 0、MUST NOT 按最保守档静默假设（承 046 对水位档「禁显 0、显未知」的既定处置）。<br>📌 **该控件是降级路径而非终态**：与 v1「现金手工录入」同形态（p1 §5 P3 先例）。手选值 MUST 标注为人工输入；M3 持仓数据到位后 MUST 由真实水位取代，且 MUST 在本片就把「数据来源」表达出来，以免 M3 上线时分不清哪些是人填的。
- **FR-018**: 建仓腿档位 MUST 按**周化**口径计算，收租腿档位 MUST 按**年化**口径计算（分母 = 准备金 K−P），两族 MUST NOT 用折年数直接互比。
- **FR-019**: 全腿 Tab 内每行 MUST 显式标注其所属腿族口径（周化 / 年化）与意图，排序 MUST 用统一的**档位**键而非跨族数值直比。
- **FR-020**: 空 Tab MUST 可进入并显示空态文案，MUST NOT 置灰、MUST NOT 隐藏面板。
- **FR-021**: 标的处于不动区时，MUST 将警示注置顶，**且** 腿数据 MUST 照常全量展示（全量可见原则）。
- **FR-022**: 一切档位边界与意图矩阵规则 MUST 可追溯到策略 SoT 条目，MUST NOT 在代码中自造参数；参数 MUST 可配置。

### Functional Requirements — 财报打标

- **FR-023**: 财报打标 MUST 按**意图分域**：建仓腿**无标**；收租长腿呈现「利空出清覆盖 ✓」或「缓冲不足 +Nd」；收租短腿呈现「跨财报提醒 ⚠」。<br>📌 **收租腿长 / 短的分界 = `RENT_SHORT_MAX_DTE_DAYS` = 28 天**（2026-08-04 user 拍板；`DTE > 28` 为长腿走「覆盖 / 缓冲」域，`DTE ≤ 28` 为短腿走「跨财报 ⚠」域）。起草时只写了「长腿 / 短腿」两个词而没给分界，属可多解的口子 —— 分界定错会让同一条腿进错打标域、且**永远不会红**。该值 MUST 落**一处具名常量**（`apps/server/src/optionsdesk/leg-tab.rules.ts` 顶部导出），MUST NOT 散落在判定函数内（同 FR-022 对档位边界的要求）。<br>⚠️ **它与 D-SOT-4 的收租腿 Tab 成员判据 `DTE ∈ [150, 365]` 是两件不同的事，MUST NOT 合并**：后者决定「这条腿出不出现在收租腿 Tab 里」，本条决定「一条收租腿按哪个财报域打标」。全腿 Tab 里的收租腿可以落在 28 天以内。
- **FR-024**: 缓冲判定 MUST 只约束「**最后利空 → 到期**」这一侧，MUST NOT 双侧约束。<br>📌 **缓冲达标线 = `EARNINGS_BUFFER_MIN_DAYS` = 7 天**（2026-08-04 user 拍板）：缓冲 = `到期日 − 该腿视野内最后一个财报日`，`≥ 7` 判「利空出清覆盖 ✓」，`< 7` 判「缓冲不足 +Nd」。<br>📌 **`+Nd` 的 N 是「还差几天」而非「已有几天」** —— `N = 7 − 缓冲天数`，与 US4-AS2「给出还差几天」的措辞一致。写成「已有几天」不会红，但屏幕上的数会与文案的意思相反。该值同 FR-023 落一处具名常量（`apps/server/src/optionsdesk/earnings-mark.rules.ts` 顶部导出）。
- **FR-025**: 全部财报打标 MUST 为提醒语义，MUST NOT 具备任何拦截 / 置灰 / 禁选效果。
- **FR-026**: 财报日 MUST 支持**三态**（确认 / 预估 / 无）；无日期时 MUST 显式区分于「已确认不跨财报」，MUST NOT 假设总有日期。<br>🚨 **打标输出的值域 = 5 值 + `null`，不是 4 值**（2026-08-07 实装期订正，plan D-UI-4 已同步）：`covered`「利空出清覆盖 ✓」· `buffer_short`「缓冲不足 +Nd」· `crosses_earnings`「跨财报 ⚠」· **`no_cross`「不跨」** · `no_date`「无日期」，外加**建仓腿恒 `null`**（按设计不打标）。<br>**为什么四值凑不出来**：本条自己要求「无日期 MUST 可与**已确认不跨财报**区分」，而验收面还有 US4-AS5 与 `state_branches` 第 12 条各要一遍 —— 「已确认不跨」是一个**独立的、必须能被说出口的判定**，不是「没有标」。四值里没有它，就只能靠「留空」表达，而留空同时还要承载「无日期」与「建仓腿无标」⇒ 三义挤一个占位符，正是 FR-006 好不容易拆开的那个糊法。（mockup handoff 本身写的也是「五形态同屏」。）<br>📌 **呈现面三者各不相同，MUST NOT 合并**：`null` → 「—」· `no_cross` → **无 chip 的纯文字**（已知答案，语气平静）· `no_date` → **虚线 chip**（走数据缺口体系，语气是「我们不知道」）。<br>🚫 **超 vendor 前向视野的到期日 MUST 落 `no_date` 而非 `no_cross`**（同 FR-034 📌）——渲成「不跨」是**编造一个未知事实**。
- **FR-027**: 系统 MUST 自建 PIT：每日快照 + 与前一日 diff，财报日发生变化时 MUST 记录变更前日期与变更时刻，并进复核名单（业界的 confirmed/estimated 双状态与修订历史只在机构级付费源存在，免费与 prosumer 级源均无该字段）。

### Functional Requirements — 数据采集

- **FR-028**: 系统 MUST 新增**链合约发现**能力，落合约静态属性（root / 标的 / 到期 / 行权价 / 类型 / 到期周期 / 结算方式）与 **`is_standard` 判定**。MUST NOT 存合约乘数、MUST NOT 做乘数感知计算。
- **FR-028a**（合约生命周期，08-04 随 FR-032 到期日范围定案补）: 已到期合约 MUST **永久保留**在合约表内，MUST NOT 删除或归档 —— 快照行指向它，且 M4 的归因与逐日 greeks 时序要回看已了结的腿。<br>🚫 MUST NOT 为「是否已到期」新增状态列 —— **到期日字段本身就是权威判据**，再存一份布尔即双写必 drift（同 p3b 对 L 层「锚是唯一真源」的判断）。<br>⇒ 快照采集工作集 MUST 按「到期日 ≥ 当前交易日」过滤；选约表 MUST 按「到期日 > 当前交易日」过滤（已到期腿不可交易）。
- **FR-028b**（兜底 seed，承 p3b §4.5 已定但本 spec 起草时漏写）: 采集侧 MUST 对**已建锚但 `Instrument` 表尚无对应行**的标的做幂等 upsert，保证「**有锚必有 `Instrument` 行**」这个不变量恒成立 —— 否则合约表指向标的的外键会因上游 universe 枚举缺失而断链。<br>📌 该 seed 是**兜底不是主路径**：`universe` 维度仍是标的入库的正规通道（已验证其 upsert 不会把未枚举到的行置 inactive，且保护 `syncTier` / `need_sync` 等列）；seed 只覆盖「新锚建了、universe 还没轮到」这个时间差与上游漏收。
- **FR-029**: 链发现 MUST 按 vendor 的到期日窗上限（≤30 天）做本地窗口分组，MUST NOT 依赖单次长窗请求。
- **FR-030**: 系统 MUST 新增**全链逐日快照**采集能力（bid/ask/size · 全 greeks · IV · OI/净OI · Vol/成交额 · 标的 spot · vendor 时间戳 · greeks 完整性标记），触发时点为 US 收盘后。
- **FR-031**: 快照采集 MUST **hard 依赖**链发现（无合约表即无从取快照）。
- **FR-032**: 采集 MUST **采全链** —— **两个维度都不设带**：① 不设**行权价**带 ② **不设到期日上限**，全部可得到期日（含 LEAPS）一并采。带定错会让腿静默消失；采集端默认全开、过滤放分析端。<br>📌 **到期日这一维是 08-04 clarify 补上的**（原文只钉死了行权价维）。判据同构：到期日窗定错是**同一类**无声 bug，且快照不可回补 —— 今天不采的远月，M4 归因 / CC 选腿要用时补不回来。<br>💡 **成本可控的机理**：贪心分组（相邻到期日 ≤30 天共享一次调用）使调用数**不随时间线性增长** —— 远端到期日稀疏（只剩月度 / 季度），实测「5–12 月 8 个到期日 = **5 次**调用」，外推到 2 年约 10–14 次/票。
- **FR-033**: 非标合约 MUST 在采集端**照常全采落库**（留证据与可审计性），排除只发生在选约层（FR-008）。
- **FR-034**: 系统 MUST 新增**财报日历**采集能力（财报日 + 盘前/盘后/盘中标记 + eps 实际/预期），并承载 FR-027 的 PIT 字段。<br>⏱️ **每日 MUST 重拉整个前向视野**（不是只拉增量窗）—— PIT diff 要发现的是「**已公布的日期被改了**」，只拉新窗永远看不到旧窗里的改动。按 vendor ≤7 天窗上限分窗，覆盖其可得的前向视野。<br>📌 **vendor 前向视野（约 6 个月）短于腿的最远到期（FR-032 已定采到 LEAPS）是预期状态，不是缺陷** —— 远月腿的财报关系天然落 FR-026 三态之「**无**」。MUST NOT 为此把「无日期」渲染成「不跨财报」。
- **FR-035**: **两个 per-code 维度**（链合约发现 / 全链逐日快照）的工作集 MUST 取自**锚白名单**（继承既有 `need_sync` 采集闸），MUST NOT 按 `market IN scope` 取全量 —— 后者会把工作集从十几只炸到约 19,465 只，实算需约 44 小时墙钟，日更任务永远跑不完。
- **FR-035a**（08-04 clarify 新增）: **财报日历维度 MUST NOT 挂锚闸**。它是**市场级**接口（单次 ≤7 天窗返回全市场，E8 实测峰值周 1559 条），调用次数只跟**前向视野**有关、**与锚有几只完全无关** ⇒ 锚闸对它没有收窄作用，只会带来 046 `FR-027` 那个坑：**零锚时静默不采**。<br>⇒ 其工作集 = **固定的前向时间窗序列**（按 vendor ≤7 天窗上限分窗覆盖可得视野）；零锚时该维度 MUST **照常跑**，MUST NOT 因锚表为空而跳过。<br>📌 **这是 046 已订正过一次的同形状问题**：FR-026 原文把「两个新维度」一律挂锚闸，plan 阶段 D1 扫出指数维度不该挂并订正出 FR-027。本条是同一判据在第三个维度上的应用 —— **判据 = 接口是不是 per-code，不是维度归属哪一片**。
- **FR-035b**（08-04 clarify 新增，落库范围）: 财报日历 MUST **全市场落库** —— 拉回什么存什么，MUST NOT 只保留锚白名单命中的条目。<br>**决定性理由 = PIT 语义**：FR-027 的 `first_seen_at` / `date_changed_at` 只有**连续观察**才成立。若只落白名单命中，某票在建锚**之前**的财报日变更史永久缺失，且建锚后其 `first_seen_at` 会是「建锚那天」而非「该日期首次公布那天」—— **语义是错的，不只是缺数据**。与期权快照「漏采即永久缺口」同类不可逆性，只是成本低三个数量级。<br>**红利**：新建锚的票，其财报数据**建锚当刻即已在库**，无需等下一轮采集（比 FR-038 对另两个维度的保证更强）。<br>**成本**：见 § Assumptions「财报日历体量」——绝对量对 PG 可忽略，且**真正的成本项是调用数不是行数**。
- **FR-036**: 三个新维度的业务日期 MUST 按 us 市场时区求值（继承 A′），MUST NOT 沿用全局上海日期（否则日期错位一天且每周固定丢掉周五）。
- **FR-037**: 采集 MUST 幂等（同日重跑不产生重复行）。
- **FR-038**: 新增锚 MUST 在下一轮采集自动纳入**两个 per-code 维度**的工作集，MUST NOT 需要代码改动或人工 SQL。财报日历维度因全市场落库（FR-035b），新锚的财报数据 MUST **建锚当刻即可用**，不需要等下一轮。
- **FR-039**: 系统 MUST 新增期权链取数端点于既有 vendor shim，端点 MUST 遵循 shim 既有纪律：限频只计首页、失败语义显式、`/healthz` 暴露已注册路由集合以支持部署版本闸。
- **FR-040**: 快照存储的幂等键 MUST 预留**来源**维度（`(合约, 交易日, 来源)`），单源期恒为主源。**这个决定必须现在做** —— 事后加列要改主键 + 回填，成本高得多；它是未来「同日双写冗余」（对抗永久缺口的唯一手段）的接入位。

### Functional Requirements — 数据质量防线

- **FR-041**: 一切派生值（周化 / 年化 / 折年 / σ距离 / 有效成本 / W / 四区间 / L 层 / 愿卖锚）MUST 在**请求时计算**，MUST NOT 预计算物化 —— 口径仍在演进（策略 SoT 会改），物化的收益远小于 drift 风险。<br>📌 **请求时的「今天」取谁的日期**（08-04 补，canonical = `docs/conventions/cross-timezone-date-semantics.md` §3 归属表 + §4 剩余期限口径）：一切请求时派生里的「今天」MUST 取**交易所的今天**（美股期权即 `America/New_York` 的日历日），MUST NOT 取宿主本地日期、MUST NOT 用绝对时刻差。剩余天数（DTE）MUST 是**整数日历日**（含周末与节假日），**到期日当天 = 0**，年化分母按日历日除 365（改用交易日则除 252，两套 MUST NOT 混）。判据：北京上午 = ET 前一日晚 ⇒ 取宿主日期会让 DTE **恒偏一天**，而 DTE 正是两个意图 Tab 的带判据与 FR-048 的豁免线 —— 偏一天让边界腿静默进出带，且**不会有任何东西报错**（故该基准 MUST 有测试钉住）。<br>🚨 **同屏存在一处有意的口径错配，MUST NOT「修」**：价格来自**上一场 session** 的收盘快照，而 DTE 从**当前** ET 日期起算，两者不同基准。这是有意为之 —— 决策是前瞻的（「我今天挂这张单还要扛多少天风险」），改成快照日基准会**系统性多算一天**。代价是同屏 MUST 有显式 `asOf` 让人看得见价格的时点（OI 列另有独立时点，见 FR-030）。
- **FR-042**: 本片 MUST NOT 引入任何盘中实时取数路径 —— 可验证判据 = 代码中不存在任何在美股交易时段主动拉起行情网关的调用。
- **FR-043**: 落库前 MUST 执行自洽硬门：`bid ≤ ask`；PUT `Δ ≤ 0` / CALL `Δ ≥ 0`；`|Δ| ≤ 1`；无套利下界。违规行 MUST 不入库 + ERROR，且 MUST NOT 破坏已落历史数据。
- **FR-044**: 🚨 无套利下界 MUST 用 **`ask ≥ 内在价值 − 容差`**，MUST NOT 用 `bid` —— 实测同一批 2138 行，`ask` 版 **0 违规**、`bid` 版 **706 违规**（做市商对实值腿的机械占位报价普遍让 bid 跌破内在价值）。写成 bid 版会误拦 706 行正常数据。
- **FR-045**: 系统 MUST 执行**完整性核对**，判据 = **逐合约覆盖率** —— 分母 = 上一交易日快照里、在当日**仍未到期**的合约集；分子 = 当日实得快照的合约数；覆盖率低于阈值 → ERROR。结果 MUST 逐票汇总呈现（指明掉的是哪一票），MUST NOT 只看全局总数（总数会被大票掩盖小票掉队 —— 实测 PEP 730 行足以盖住 VICI 48 行整票消失）。<br>📌 **08-04 clarify 由「逐票总行数 `[0.7,1.3]×`」改判为本条**。原判据有**结构性缺陷**：FR-032 定案采全到期日后，合约集**天天在变**（周期权每周到期 · 月度合约集体到期 · vendor 同时挂新到期日）⇒ 行数波动是**正常态而非故障信号**；而 p3b §6.3 的实测基线全是**单日截面**，`[0.7,1.3]` 这个带宽从未在「大到期日次日」验证过。逐合约覆盖率对「到期减少」与「新挂增加」**两个方向都天然免疫**。<br>🚫 MUST NOT 用交易日历打「今天是大到期日所以放宽阈值」这类补丁 —— 拿被监控对象的邻近物证明自己健康，是 p3b §5.3 反模式「**循环信任**」的近亲，044 事故正是那么绿的。<br>✅ **2026-08-07 T038 观察窗登记（阈值不在 impl 期拍，靠部署后的真实样本校准）**：**起手值 = 100% 已实装**为配置项 `MARKETDATA_OPTION_COVERAGE_THRESHOLD`（zod `default(1)`，值域 `[0,1]`），即「基线日在、当日未到期、当日却没数据」一条都不许有 —— 依据 = 快照按设计是「有合约就有一行」，无报价也照样落行（实证：227 行 greeks 整块缺失的腿仍在表内，FR-007 正为它写）。<br>📅 **观察窗 = 至少覆盖一个月度到期日的次日**。🚨 判据不是「跑够多少天」而是**必须跨过那一天**：月度到期日次日是行数天然骤降的日子，本条换判据（逐合约覆盖率）正是为它设计的，**若 100% 会假红，只有那天能暴露**；只在平常日子跑一个月全绿，对这条防线不构成任何证据（同 SC-002 第 ③ 向假阳性守卫的取样纪律）。<br>🔁 **放宽的纪律（不是「以后再看」）**：若观察窗内发现**正常态缺行**，由 env 放宽阈值，**且 MUST 同时把成因写回本条** —— 一个没写明成因的放宽，下次就没人能判断它是真实基线还是当初为了消音；这也正是该阈值做成配置项而非写死的理由。
- **FR-046**: 完整性核对判定缺失后，系统 MUST 先走**两级自动补救**，两级都失败才升 ERROR：① **当日重试**；② **次日美股盘前窗口（北京 16:00–21:30）兜底重采一次** —— 该窗口内 vendor 返回的**报价**仍是前一交易日的收盘值，故可用于补回昨日快照。ERROR 触达 MUST NOT 并入次日日报。<br>✅ **第 ② 级的前置验证（V-A）已由官方文档 + E32 结清，本条按已知漂移设计、不退级**（2026-08-04，plan D-DATA-4，推导见 § 本片必须先验证 的 ✅ 块）：逐字节相同的只有 **bid/ask 与 `update_time`**；**`OI` 在美股盘前时段翻新**（官方文档明示）、**greeks / IV 依赖盘前活跃的正股 spot** ⇒ 「原样补回」在这两组字段上本就不成立。<br>⇒ 处置**不是**退回一级补救，而是让每个时点自己说话：补采行落 `source = premarket_backfill` · `session_date` = 被补的那一天 · `quote_as_of` = 实际采集时刻 · **`oi_as_of = session_date`**（盘前 OI 已翻新，正是被补那天的真值）。两条路径产出的行因此可区分、可对账。<br>📌 **它同时改写了「漏采即永久缺口」的精确措辞**：不可补的不是「漏了一天」，而是「漏过了整个补采窗口」（约 17.5 小时：T 日 16:00 ET → T+1 09:30 ET）。这不削弱完整性告警的优先级 —— 窗口横跨深夜，靠人肉盯不住，自动兜底才是防线。
- **FR-047**: greeks 缺失 MUST 只在**虚值区**监控（虚值腿出现缺失 → WARN）；实值区缺失属数学固有现象，MUST NOT 告警、MUST NOT 计入指标 —— 否则是给固有现象设告警，必然长期噪音。
- **FR-048**: IV 离群判定 MUST 结合 DTE（极短 DTE 的宽价差属预期），MUST NOT 一刀切。
- **FR-049**: 出现**新的非标 root** MUST 进 WARN 复核名单（意味着某白名单票发生了并购类公司行为）。
- **FR-050**: 三个新维度 MUST 同步纳入通用表级数据健康探针（`ops/jobs/marketdata-table-health.{sh,sql}`），MUST NOT 等到下一片再补 —— M2a 那次漏做、隔日才补，本片不得重犯。
- **FR-051**: 探针判据 MUST 挂在**数据**上而非 run 上，且探针 MUST 独立于采集进程运行（既有反模式清单：循环信任 / 沉默=健康 / 降级=健康 / 探针与被监控对象同进程）。
- **FR-052**: 采集降级（回落到任何非主源或非实时路径）MUST 留痕 + 告警，MUST NOT 静默。
- **FR-052a**（08-04 clarify 新增，容量防线）: 系统 MUST 对 prod 数据库宿主的**磁盘水位**告警，阈值 MUST 留出足够的人工扩容窗口（按实测年增长速率反推，而非拍一个百分比）。<br>**存在理由**：本片是仓内第一个**无上限线性增长**的数据面（全量永久保留、不抽稀、不归档），而宿主磁盘余量有限且与其余 22 个维度同池。没有这道告警，「不设归档」这个决定就是把风险推给未来某天的一次磁盘写满事故。<br>MUST NOT 用抽稀 / 归档 / 分区压缩替代本条 —— 那是拿不可逆的手段解可逆的问题（见 § Assumptions 的不对称性论证）。<br>✅ **2026-08-07 T038 实测登记，三段**（原「整张估算表待实测替换」的 🚨 落在 § Clarifications 那条，已同步替换）：<br>① **阈值的计算方式已实装，且是自校准的** —— T025 落在 `ops/jobs/marketdata-table-health.sql` 判据 ⑩：`可用空间 < 实测日均增长 × 90 天`（等价「剩余可撑天数 < 90」）；日均增长 = 本片三表当前总字节 ÷ 快照已积累的交易日数，**每次跑现算不落状态表**（保住 FR-051「探针只读取证 / 独立于采集进程」那两条论证）；快照**不满 10 个交易日判「样本不足、不告警」**并显式写进 summary（上线首两周的正常空态，不静默）。⇒ 本条要的「按实测年增长速率反推」由**算法**承担，spec 与 frontmatter 里**不存在也不该存在一个拍出来的阈值数**。<br>② **当前容量现状（2026-08-07 SSH 只读 `df` 实测）**：prod 77 根分区 `/dev/vda3` 共 40 G / 已用 19 G / **可用 19 G** / 使用率 50%；PG 数据目录 = docker volume `nvy-tight_nvy-pgdata`（容器 `nvy-tight-postgres-1`，`postgres:16-alpine`），挂在 `/` 即同一 `vda3` ⇒ **根分区余量就是 PG 的余量**。⚠️ 登记的是**对照关系**而非孤立新数：p3b §10 记的 **6.7 G 是 08-01 数字，现已确认 stale**（成因 = #890 清掉 26 个 `mbw-app` 历史镜像 tag 中的 23 个，非扩容；`deploy.yml` 已加收尾自动 GC 防复发），免得下一个读者又拿 6.7 G 当现状。<br>③ **单行宽度（`pg_total_relation_size`）本次物理上做不了，登记为观察窗**：本片三张表在 prod 上**还没有任何数据**（feature 未部署），plan D-ARCH-4 早已写明这条得「落一批真数据后量」。🚫 **MUST NOT 拿本地 dev 库的数字冒充 prod 单行宽度** —— dev 的行是合成造数，没有 vendor 真实字段分布与 TOAST 行为，拿它填进容量账等于把估算包装成实测，正是本条禁的那件事。**观察窗 = 部署后满 10 个交易日**（复用 ① 的样本门，不另设第二个数）：届时探针的日均增长自然生效，同时跑一次 `pg_total_relation_size` 取单行宽度作**交叉核对**（核对 ①，不取代 ①）。

### Functional Requirements — 架构纪律

### Key Entities

- **OptionContract**（市场事实）：一份可交易期权合约的静态身份 —— root、标的、到期日、行权价、认购/认沽、到期周期、结算方式、**是否标准合约**。幂等键 = (市场, 合约代码)。
- **OptionDailySnapshot**（市场事实）：某合约在某交易日收盘后的完整读数 —— 双边报价与档位量、全套 greeks、隐含波动率、未平仓量与净未平仓量、成交量与成交额、标的当时价格、vendor 时间戳、**greeks 是否完整**。幂等键 = (合约, 交易日, 来源)。
- **EarningsEvent**（市场事实）：某标的的一次财报事件 —— 日期、盘前/盘后/盘中、报告期、eps 实际与预期，外加自建 PIT 三件套（首见时刻、日期变更时刻、变更前日期）。幂等键 = (标的, 财报日)。**全市场落库**（FR-035b），不限于锚白名单。<br>⚠️ 全市场落库会遇到少量标的不在 `Instrument` 表内（新上市 / OTC；us universe 19,465 行覆盖 STOCK ∪ ETF，绝大部分能匹配）。处置 = **跳过匹配不上的并计数**，保 FK 完整性；该计数本身 MUST 作为监控信号呈现（持续升高意味着 universe 枚举漏了一类标的）。MUST NOT 为规避 FK 而把幂等键改成不依赖 `Instrument` 的裸 (市场, 代码) 形式。
- **LegRow**（呈现派生，不落库）：选约表的一行 —— 由合约 + 快照 + 锚派生值 + 财报关系合成，含费率档位、有效成本相对 W 的位置、σ 距离、活跃度、动作建议标签、数据完整性标记。
- **EarningsMark**（呈现派生，不落库）：腿级财报打标，按意图分域取三种形态之一或无标；无拦截语义。

## Success Criteria

- **SC-001**: 每个美股交易日收盘后，全部锚定标的的当日快照在下一次盘前决策窗口开始前已就绪 —— 连续观察 5 个交易日，**零**次「打开详情页发现昨天的数据没进来且无人知情」。
- **SC-002**: 完整性防线可被证伪，**三个方向都要验**：① 注入「整票缺席」→ 必须 ERROR ② 注入「一批存续合约当日无数据」→ 必须 ERROR ③ **回放一个真实的大到期日次日 → 必须不告警**。第 ③ 项是 FR-045 换判据后新增的假阳性守卫 —— 只验前两项只能证明它会响，证不了它不乱响；而「每月假红一次」的告警等于没有告警。同时零锚场景下**不得**产生告警。
- **SC-003**: 选约表的每一处读数都带可见时点标注；抽查任意一屏，**零**处出现「无法判断这个数是哪天的」。
- **SC-004**: 决策带内的腿**零**静默丢失 —— 对同一批真实数据，落库行数与选约表可见行数（扣除非标与死档排序位移）逐条可对账。
- **SC-005**: 新增一条锚后，无需任何代码改动或人工 SQL，其期权链数据在下一轮采集后出现。
- **SC-006**: **两个 per-code 维度**（链发现 / 逐日快照）对非锚定标的的请求数为 **0**（锚闸生效的可验证判据）。<br>⚠️ **本条 MUST NOT 套到财报日历维度上** —— 它是市场级接口，一次调用本就返回全市场，「对非锚定标的的请求数」这个量对它无定义。它的对应判据是 **SC-006a**。

## 三条不要在下游阶段被"优化"掉的决定

1. **采全链、不设行权价带**（FR-032）。看起来「只采决策带能省 90% 成本」很诱人，但策略是锚轴 + 市场轴双轴，spot 偏离 V 时需要的 K 会掉出任何固定带外；而实际省下的只是 snapshot 批次数（约 2100 行 = 6 批），成本可忽略。带过滤换来的是「腿静默消失」这一整类无声 bug。
2. **无套利下界用 `ask` 不用 `bid`**（FR-044）。这条看起来像笔误 —— 直觉上「买价不应低于内在价值」。实测 2138 行：`ask` 版 0 违规、`bid` 版 706 违规。做市商对实值腿的机械占位报价普遍让 bid 跌破内在价值，这是市场常态不是脏数据。改成 bid 版会当场误拦三分之一的实值腿。
3. **完整性告警用逐合约覆盖率，不用行数区间**（FR-045）。「总行数落在 `[0.7,1.3]×` 就算健康」看着更简洁，但它错在两处：① 行数分布极不均（PEP 730 / VICI 48），一只小票整票消失完全落在总数波动的噪声里 ② **采全到期日之后，合约集天天在变** —— 周期权每周到期、月度合约集体到期、vendor 同时挂新到期日，行数波动本就是正常态，拿它当故障信号必然每月假红一次。逐合约覆盖率是这道防线成立的前提，不是加强项。<br>⚠️ 尤其**不要**退回去用交易日历给告警打「今天是到期日所以放宽」的补丁 —— 那是 044 事故的同款循环信任。
