# Feature Specification: 港股期权实时窄召回接线 — 港股锚盘中拿到与美股同构的实时选约表

**Feature Branch**: `071-optionsdesk-hk-realtime-recall`
**Created**: 2026-08-31
**Status**: Clarified（2026-08-31；specify 期 1 项由代码证据自解 + clarify 期 5 项裁决已回写）
**Input**: 港股期权实时窄召回接线（optionsdesk 读端）——数据面已就位、读侧仍是美股独占，港股锚盘中被守卫挡回收盘档并渲成降级红字

## User Scenarios & Testing _(mandatory)_

### User Story 1 — 港股锚在盘中看到的是此刻的盘口 (Priority: P1)

我在港股连续竞价时段打开一只港股锚的选约表，想按当下的真实盘口挑一条卖出认沽的腿。今天我拿到的是一张昨天收盘的表——而供应方此刻明明有报价。更麻烦的是它**两种坏法**：多数日子配一条红色横幅「盘中取不到实时源，勿据此下单」，而**周一完全没有横幅**（业务日基准写死美股，周一港股盘中折算出的美股日期是周日，日历把它判成休市 ⇒ 闸直接判非开市、连降级标都不打）—— 后者看起来完全正常，是更坏的那种。我要的是：和美股锚一样的东西，秒级的数据时点、此刻的逐腿报价、按同一套规则圈出来的候选集。

**Why this priority**: 这是本 feature 的全部价值。港股数据面在上一片就建成了，读侧这道闸是唯一挡在中间的东西；而它挡出来的不是「没数据」的诚实空态，是一条**劝阻用户下单的告警**——用户被告知不能用，实际是我们没接。

**Independent Test**: 在港股连续竞价时段对一只有挂牌期权的港股锚请求收租视角，断言：响应的数据时点是秒级时刻而非交易日、腿行报价与供应方此刻的值一致、无降级标。单独交付即可用。

**Acceptance Scenarios**:

1. **Given** 一只有挂牌期权的港股锚、港股处于连续竞价时段、定窗基准新鲜，**When** 请求收租视角的选约表，**Then** 响应标明为实时口径、数据时点精确到秒、腿行报价取自本次对外请求返回的值，且无任何降级标
2. **Given** 同上，**When** 请求建仓视角，**Then** 同样走实时窄召回，且其候选范围由建仓意图自己的预测落带决定，不与收租视角共用一个窗
3. **Given** 一只港股锚与一只美股锚，各自处在**自己市场**的连续竞价时段（⚠️ 这是**两次不同时刻**的请求——两市时段永不重叠，见 Edge Cases；「同一时刻各自开市」是不可能构造的前提），**When** 分别请求，**Then** 两者呈现范式逐项同构（差异只在数据本身），美股侧响应与本片之前逐值相同
4. **Given** 港股锚、港股连续竞价时段、但该锚的窗内没有任何腿满足既有规则，**Then** 呈现「规则内无腿」这一显式空态，**And** MUST NOT 呈现为降级或错误

---

### User Story 2 — 午休和收盘不该被说成故障 (Priority: P1)

港股每天中午休市一小时。我在午休时打开选约表，应该看到的是「这是收盘口径的数据」这种中性说明，而不是一条告诉我系统出问题了的红色告警。收盘后、非交易日同理。

**Why this priority**: 与 US1 同级。港股午休是**每个交易日都发生**的常态；如果接线后午休落进告警态，等于给用户每天一条假告警——那比现在的状态更糟，会让人从此不看这条横幅。

**Independent Test**: 在午休时段与收盘后分别请求同一只港股锚，断言两者都落中性收盘档呈现、零告警底色、零对外请求。

**Acceptance Scenarios**:

1. **Given** 港股锚、时间落在午休时段，**When** 请求选约表，**Then** 呈现为收盘档中性口径，**And** 无降级标，**And** 零对外请求
2. **Given** 港股锚、港股半日市当天下午（已提前收盘），**When** 请求，**Then** 判为非开市并按上一条处置，MUST NOT 判为场内
3. **Given** 港股锚、港股非交易日，**When** 请求，**Then** 与美股锚在美股非交易日的呈现同构

---

### User Story 3 — 降级标说的是真故障 (Priority: P2)

当我确实看到降级横幅时，我要能相信它说的是真的出了问题（源挂了、数据太旧），而不是「这个市场我们还没接」。

**Why this priority**: 告警的可信度是一次性资产。本片接入港股后，「市场未支持」这个触发源在港股上消失，是把该标的语义收回到「真故障」的唯一时机；错过这个窗口，语义就永久混着。

**Independent Test**: 分别构造「供应方取数失败」与「定窗基准陈旧且补不到」两种情形，断言各自落到语义正确、彼此可区分的状态。

**Acceptance Scenarios**:

1. **Given** 港股锚、盘中、供应方取数失败或超时，**When** 请求，**Then** 整体回落收盘档并标明源不可用
2. **Given** 港股锚、盘中、定窗基准既不新鲜也补不到，**When** 请求，**Then** 落「实时不可用」而非「源不可用」——两者 MUST 可区分
3. **Given** 一个既不受支持、也不允许建锚的市场的标的，**When** 构造请求，**Then** 未支持市场守卫仍然生效、零对外请求

---

### Edge Cases

- 港股锚**没有任何挂牌期权**（全库 3 只港股锚里就有一只如此）：走既有「无挂牌期权」终态，MUST NOT 抬告警、MUST NOT 与「有期权但今天没采到」混为一谈
- 港股锚的**收租窗结构必空**（现价高于估值的固定倍数时，成色上界把行权价区间挤成空集）：落「规则内无腿」，且该结论 MUST 可解释到「为什么空」，不是一张没有理由的空表
- 港股锚**新建当天**（无昨日预测面）：走矩形宽窗兜底；若兜底窗圈出的合约数超过单批上限，MUST 有显式处置而非静默截断
- 当天到期的腿在**盘中仍可交易**（港股期权到期日当天交易至收盘），但它**本就不在任何召回段内**（建仓段剩余期限下界为 1 天）：本片 MUST NOT 借换基准之机把它放进来，也 MUST NOT 在读端新增第二道排除
- **港股盘中恰逢周一**：业务日基准修正后，闸 MUST 判为开市（此前折算出周日被判休市）；该分支 MUST 有断言，否则修完也看不出修没修
- 港股与美股锚在**同一次会话内来回切换**：各自的数据时点互不污染，MUST NOT 出现一个市场的时点标在另一个市场的表上
- 供应方对某港股合约**不返回希腊值**：该行照常出现在表中并标明档位不可定，MUST NOT 丢行（沿用既有约定）
- 港股连续竞价时段与美股连续竞价时段**永不重叠**（港股 01:30–08:00 UTC / 美股 13:30–20:00 UTC），但两个市场的锚可能在同一次页面停留内被先后打开：每次请求 MUST 各自按**自己市场**判闸，MUST NOT 把一个市场的闸结论套到另一个市场。📌 供应方状态端口既有的短 TTL 缓存**不违反本条** —— 它缓存的是全市场单键的**原始状态**、不是某个市场的闸结论，且窗口远短于市场状态的变化粒度

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 系统 MUST 把港股纳入「可派生实时候选范围」的市场集合，使港股锚在港股连续竞价时段走与美股同构的两段式实时窄召回
- **FR-002**: bootstrap 矩形宽窗的行权价**上界** MUST 沿用现值，并在文档里写明它成立是**构造性的**——其职责是罩住收租成色上界与建仓有效成本的定义域，而成色上界恒不超过现价的既定倍数 ⇒ 上界恒罩得住，与市场和计价货币无关；MUST NOT 为它编造一个标定值。**下界** MUST 用港股数据检查其原义（「再深就没权利金 ⇒ 问了也是白问」）在港股是否成立，双基面取证（盘中全链探针 + 现有收盘交易日），结论取**更宽**的一侧——bootstrap 宽一点只是多问几条合约码，窄了是新锚首日静默缺腿
- **FR-003**: 沿用昨日预测面反推今日行权价区间时所加的容差，MUST 用港股双日回放验证召回率，**达标线 ≥ 95%**（与美股标定时同一条线，故两市场的差异是真差异而非口径差异）：达标则维持单一取值**并附回放证据**，未达标才分市场取值。两种结局都 MUST 留痕并写明样本期，MUST NOT 默认沿用
- **FR-004**: 实时读路径判定业务日期的基准 MUST 取自该锚所属市场，MUST NOT 写死为美股。🚨 该基准同时喂给**开市闸的日历判定**——写死美股会让港股周一盘中折算出周日、被判非交易日 ⇒ 闸判非开市、静默走收盘档且**不打任何降级标**。故本条修的是闸误判，不只是元数据日期
- **FR-005**: 「当天到期的腿不进候选」这条排除 MUST 由召回段的剩余期限下界**单点**承担；读端的到期日过滤 MUST NOT 被改成第二道会改变成员集的判定。换基准这件事本身对**两个市场的候选集都 MUST 逐值零变化**——今天港股盘中放进来的当天到期腿随后就被下界滤掉，改后是一开始就不放进来，殊途同归
- **FR-006**: 换基准 MUST NOT 改变离线档（收盘档）的任何行为——本片只动实时档那一处，两档的判据面与证据面都不同
- **FR-006a**: 系统 MUST 有一条断言钉住 FR-005 的等价性（换基准前后，两个市场的候选集与其排序逐值相同），使「顺手把比较符一起改了」这类改动当场红
- **FR-007**: 判定港股此刻是否处于可交易时段 MUST 取供应方的市场状态，MUST NOT 取本地时段表；该判定 MUST 有一次真实观测证据（覆盖午休进出与收盘前后），MUST NOT 凭推断写绿
- **FR-008**: 港股午休、收盘后、非交易日 MUST 落中性收盘档呈现，MUST NOT 落降级/告警态
- **FR-009**: 未支持市场守卫 MUST 保留（含其纵深防御的第二层），MUST NOT 因港股进入受支持集合而被拆除
- **FR-010**: 降级状态的值域 MUST NOT 因本片扩张——「市场未支持」不升格为独立状态，「源不可用」自本片起语义收回为「供应方取数真的失败」。理由：两者对用户是同一件事（此刻拿不到实时价），而扩值域要连带动契约值域、四条穷举文案与前端的穷举映射。该裁决 MUST 写回架构决策记录并消费其对应的复审触发条件
- **FR-011**: 港股锚在实时档下的响应契约 MUST 与美股逐字段同形，MUST NOT 新增港股专用字段或专用状态值
- **FR-012**: 系统 MUST NOT 为港股新开第二条读路径；市场差异 MUST 表达为参数与能力声明的取值差异，判据本身 MUST 保持单点
- **FR-013**: 本片 MUST 跑一轮「行军选档参数在港股上是否适用」的判定（参数系美股收盘分布标定），**三条判据同时成立才算通过**：① 形状类条件在港股净链上的触发率与美股同量级（不显著偏高——偏高意味着把常态噪音当异常，表现为推荐档莫名其妙地短且不报错）② 流动性下限不致港股收租候选**整梯清零**（清零梯占比不高于美股基线）③ 档界参数是策略定义的年化门槛、与计价货币无关，直接沿用。结论 MUST 落档并写明样本期；三条全过才放开港股收租的阶梯呈现，任一不过则维持不出阶梯
- **FR-014**: 港股收租视角在不出阶梯时，该状态 MUST 是显式判定的结果并与「算出来是空」可区分
- **FR-015**: 系统 MUST 有一条打真后端的契约冒烟覆盖港股标的下的选约表行为——该覆盖今天为零
- **FR-016**: 验收 MUST NOT 依赖真实港股锚的当下形态（全库仅一只锚能真正跑通收租路径），状态分支 MUST 由夹具播种覆盖
- **FR-017**: 行情底座的市场时段表 MUST 把港股恢复为**两段**（含午休），使「此刻能不能成交」这一问在本地也有正确答案。该改动 MUST 证明三个**跨段**谓词（该场进行中 / 收盘写闸 / 收盘分钟）**逐点不变**；既有那条钉住「港股两谓词不分道」的断言 MUST 同步翻面**并写明翻它的理由**（它是刻意设的绊线，不是遗留）
- **FR-018**: 该时段表里港股登记处的注释 MUST 更正三处失真：① 「趁港股期权尚未开通」这个时机前提已过期 ② 「港股期权采集未开通」这条**现已为假**的事实陈述 ③ 复审触发条件的措辞 —— 从「将来给港股接盘中告警时」扩为「**任何**需要判『此刻能不能成交』的港股消费方」
- **FR-019**: 「港股此刻能不能成交」MUST 只有一份判据。期权台 MUST 经供应方状态得到答案，MUST NOT 直接读时段表；供应方若不区分午休，归一化 MUST 落在供应方适配层而非各消费方

### Key Entities

- **锚**：一只被跟踪的标的，携带所属市场、估值与仓位相关的判据输入。市场归属在建锚时确定、此后不变
- **候选范围**：一次实时请求里「该问供应方哪些合约此刻的价」的集合，由意图（收租/建仓）的预测落带加容差推出
- **链级数据时点**：一次响应里全部腿共享的口径标记，取值粒度随档位而变——实时档为时刻、收盘档为交易日
- **降级状态**：一次响应为什么没能给出实时结果的显式原因，值域穷举、彼此互斥

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 港股连续竞价时段内，港股锚的选约表呈现的是当次请求取回的盘口，其数据时点与请求时刻的间隔不超过一次请求往返
- **SC-002**: 港股锚在港股连续竞价时段的降级横幅出现率为 **0**（连续 3 个港股交易日人工抽查，每日至少 1 次）
- **SC-003**: 港股午休时段的请求，告警态出现率为 **0**、对外请求次数为 **0**
- **SC-004**: 美股锚在本片前后的响应**逐值相同，零例外**
- **SC-005**: 港股锚实时档的候选集里，带实时报价的腿数 **恰等于**供应方本次返回的有报价腿数在窗内的那一部分——不多（不凭空造）不少（不因我们的取数方式额外丢腿）。该等式 MUST 由一条对拍断言承载，MUST NOT 只作口号
- **SC-006**: 全部状态分支（含午休、半日市、无挂牌期权、规则内无腿、新锚首日）各有至少一条自动化断言，且每条都能通过定向变异证明其会红
- **SC-007**: 港股与美股在契约层零形状差异——同一份契约冒烟套件换市场即可跑通，无需分支

> 📌 **SC-002 / SC-003 是部署后验收项，不阻塞合并**（clarify 裁决）——它们只能在真实港股交易时段验。tasks MUST 为其立独立验收 task 并**带到期日 + 配套 issue**：同类 task 在上一片因为没有到期日而至今未勾、把那份 spec 永久卡在 `implementing`，本片 MUST NOT 重蹈。
