# Feature Specification: 雷达按市场分页签

## Clarifications

### Session 2026-08-19

- Q: 不属于任一市场页签的锚，「可被发现的记录」做到哪一档 → A: 仅服务端 WARN 日志，不在雷达上露出。判据是它**并未真的失联** —— 锚管理页不分市场、仍完整列出它；雷达是「击球区」视图，不为不受支持市场的锚开后门。该记录守的是「将来新增市场时忘了加页签」这个场景。
- Q: 「另一市场有可动的锚」提示强度 → A: 页签上一个小圆点，**不带数量**。数量虽已算出且带上成本几乎为零，但市场页签上的数字极易被读成「那个市场有 N 只锚」而非「N 只可动」，两个意思差得很远。
- Q: 「该市场暂不提供盘中实时价」这句说明放哪里 → A: 页签下方**常驻一行**，与该市场有没有锚无关、不随滚动消失。明确排除「只在空态里显示」—— 那会让港股一旦有了锚说明就消失，而恰恰是有行之后用户才会去读行情时点、才真会误读。
- Q: 市场页签的标签用词 → A: 「美股」/「港股」。仓内既有的单字「美 / 港」是**行内标的徽标**，与**市场名**不是一回事，页签不受行宽约束，用两字更不歧义、也避免两者被当成同一个东西。

## User Scenarios & Testing

### User Story 1 — 只看一个市场的击球区 (Priority: P1)

**Why this priority**: 这是本片存在的理由。雷达把两个市场的锚混在一屏时，同一列里并置着两种时点粒度的价格（一边是当下时刻的成交价、一边是上一个交易日的收盘价），而排序键「距 W%」的分子正是这个价 —— 混排等于把不同时点的距离排在一起比大小。顶部那条新鲜度提示取全页最新的一条，于是**一只正在交易的美股就能让整屏看起来都是实时的**，而同屏港股行其实停在昨天。用户据此做的判断（「现在该不该动手」）建立在一个假象上。

**Acceptance Scenarios**:

1. **Given** 库中同时存在美股锚与港股锚，**When** 用户在雷达顶部选中「美股」，**Then** 列表只出现美股锚，且页内每一行的行情时点粒度一致
2. **Given** 用户正停在「美股」，**When** 切到「港股」，**Then** 列表换成港股锚，且从该市场的第一屏开始，不接续上一个市场的翻页位置
3. **Given** 用户在「美股」上选了若干筛选条件，**When** 切到「港股」，**Then** 这些筛选条件仍然生效（筛选是镜头，不随市场重置）
4. **Given** 用户滚到「美股」的第三屏，**When** 继续下拉，**Then** 后续加载进来的行仍全部是美股，不混入港股
5. **Given** 用户上次停在「港股」，**When** 在同一次使用中离开雷达再返回，**Then** 仍停在「港股」
6. **Given** 用户完全退出应用后重新打开，**When** 进入雷达，**Then** 落在默认市场「美股」

### User Story 2 — 看得出「这个市场就是没有实时价」 (Priority: P1)

**Why this priority**: 港股页签上线即是这个状态，且**上线当天港股页签是空的**（现有全部锚均为美股）。这两件事叠加，意味着「空态文案 + 市场能力说明」就是用户在这个页签上能看到的全部内容 —— 它们不是兜底分支，是这个页签的主体验。更要紧的是误读方向：行情时点显示为交易日而非时刻，用户会读成「今天还没开盘」这种当日临时状态，而实际是「这个市场根本不提供盘中价」这种长期能力状态。两者对「我要不要等一会儿再看」给出相反的答案。

**Acceptance Scenarios**:

1. **Given** 用户切到没有实时行情能力的市场，**When** 页面加载完成，**Then** 页面显式说明该市场暂不提供盘中实时价，且该说明不随一天中的时间变化
2. **Given** 该市场无实时能力，**When** 用户查看任一行的行情时点，**Then** 时点粒度为交易日（而非时刻），与说明一致
3. **Given** 该市场一只锚也没有，**When** 页面加载完成，**Then** 用户看到的是「这个市场还没有锚」而非「你还没有建过锚」，且不出现「清除筛选」这类当前无从执行的入口
4. **Given** 整个库一只锚都没有，**When** 用户查看任一市场页签，**Then** 用户看到的是「还没有锚，去建第一个」并带建锚入口

### User Story 3 — 建锚时看得出哪些市场能建 (Priority: P2)

**Why this priority**: 市场一旦成为雷达的作用域、且页签只覆盖受支持的市场，一只属于其他市场的锚就会**在雷达上不可达** —— 不在任何页签、不计入任何页签的统计、也没有任何空态会提到它。它并不会从系统里消失（锚管理页不分市场，仍完整列出它），但雷达正是「现在该不该动手」的判断入口，在这里静默缺席与「漏看一只即等于本功能失效」的既有判据直接冲突。堵在建锚入口是唯一能让「页签并集 = 全部锚」构造性成立的位置 —— 其余做法都只是在事后补救一个本可以不发生的状态。

**Acceptance Scenarios**:

1. **Given** 用户在建锚页搜索一只不受支持市场的标的，**When** 搜索结果返回，**Then** 该标的**出现在结果中但不可选**，并说明为何不可选
2. **Given** 用户搜索一只受支持市场的标的，**When** 搜索结果返回，**Then** 该标的可正常选中并完成建锚
3. **Given** 一次建锚请求携带不受支持市场的标的，**When** 服务端处理该请求，**Then** 请求被拒绝并说明当前支持的市场值域

### Edge Cases

- 用户在某市场页签上把筛选收紧到该市场无锚满足 → 显示「筛选无结果」而非「该市场还没有锚」，两者文案与行动入口均不复用 (covers FR-008, FR-010)
- 整库无锚**且**当前市场无锚 → 落「还没有锚」（整库空优先），因为此时「去建锚」才是有效动作，「切市场」不是 (covers FR-009)
- 翻页途中行情刷新导致排序键变化 → 仍不漏行、不重复行，且不因刷新而混入其他市场 (covers FR-004)
- 某市场有锚但无一只跌破 W → 行照常渲染，只在顶部加提示；该提示所依据的统计只看当前市场 (covers FR-003)
- 库中出现不属于任一页签的锚（历史遗留或将来新市场） → 留下可被发现的记录，不静默吞掉 (covers FR-015)
- 用户长期只看一个市场 → 另一市场锚的复核红标仍与其真实价格状态一致，不因无人查看而停滞 (covers FR-011)
- 某市场有可动的锚而用户停在另一市场 → 用户能察觉另一页签有情况，不必逐个点开才发现 (covers FR-016)

## Requirements

### Functional Requirements

- **FR-001**: 雷达 MUST 在页面顶部提供市场选择，值域恰为「美股」与「港股」两项，且 MUST NOT 提供「全部」这一项。标签用双字市场名，MUST NOT 复用行内标的徽标的单字写法（两者不是同一层概念）
- **FR-002**: 选定某市场后，雷达返回并呈现的锚 MUST 全部归属该市场
- **FR-003**: 市场是**作用域**而非叠加筛选项 —— 驱动顶部横幅与空态判定的统计口径 MUST 与列表口径同为当前市场；两者不一致会让横幅与列表互相矛盾且无人察觉
- **FR-004**: 增量翻页 MUST 在同一市场作用域内连续，MUST NOT 在后续页混入其他市场的锚，且刷新期间 MUST NOT 漏行或重复行
- **FR-005**: 切换市场 MUST 从该市场的第一屏重新开始，MUST NOT 沿用上一个市场的翻页位置
- **FR-006**: 既有筛选维度（生效 L 层多选 / 待复审 / 跌破 W）MUST 在切换市场后保留，MUST NOT 因切换而被清空
- **FR-007**: 首次进入 MUST 落默认市场「美股」；同一次使用期间用户选定的市场 MUST 被记住；系统 MUST NOT 依据「当前哪个市场正在交易」自动切换用户所在页签
- **FR-008**: 系统 MUST 提供独立的「该市场还没有锚」状态，其文案与行动入口 MUST NOT 与「整库还没有锚」复用 —— 前者的有效动作是切换市场，后者是去建锚
- **FR-009**: 当整库无锚时，MUST 落「整库还没有锚」，优先于「该市场还没有锚」
- **FR-010**: 三个既有空态（整库无锚 / 筛选无结果 / 全体不动区）与 FR-008 新增的第四态 MUST 两两文案互异、行动入口互异，且任一状态下 MUST NOT 出现当前无从执行的入口
- **FR-011**: 复核锚红标的判定 MUST 持续覆盖全部市场的锚，MUST NOT 因用户停留在某一市场页签而停止推进另一市场的判定；该判定一旦停滞将产生不可回补的偏差
- **FR-012**: 无实时行情能力的市场，其页签 MUST 显式说明该市场暂不提供盘中实时价；该说明是**市场级长期事实**，MUST NOT 表述成或呈现为「当前时段未开市」这类当日临时状态。该说明 MUST 常驻于该页签、**与该市场当前有没有锚无关**、不随列表滚动消失；MUST NOT 只在空态下呈现 —— 该市场一旦有了锚，说明反而更需要在场（用户此时才会去读每行的行情时点）
- **FR-013**: 每一只锚 MUST 归属于恰好一个受支持市场；该归属 MUST 在建锚时确定，且此后 MUST NOT 改变
- **FR-014**: 建锚 MUST 拒绝不受支持市场的标的，以及分隔符缺失或代码段为空这类形状非法的标的
- **FR-015**: 若库中存在不属于任一市场页签的锚，系统 MUST 在服务端留下一条可检索的告警级记录；该记录 MUST NOT 呈现在雷达界面上。此类锚**并未从系统中失联** —— 锚管理页不分市场、仍完整列出它；本条守的是「将来新增受支持市场时忘了同步加页签」这一场景
- **FR-016**: 当用户所在市场无可动的锚、而另一市场存在可动的锚时，**另一市场的那个页签**（即用户当前不在的那个）MUST 呈现一个可察觉的标记，使用户无需切换即可知道那边有情况。该标记 MUST NOT 携带数量 —— 市场页签上的数字会被读成「该市场的锚总数」而非「可动数」，两者语义相差甚远
- **FR-017**: 建锚的标的选择器 MUST 展示不受支持市场的搜索结果并标为不可选、附不可选的原因，MUST NOT 将其从结果中静默过滤掉

## Success Criteria

- **SC-001**: 任一市场页签上，页内所有行的行情时点粒度**同质** —— 全部为时刻，或全部为交易日，不出现两种粒度并置
- **SC-002**: 顶部新鲜度提示所述的时点 MUST 只由当前市场页签内的行决定，其他市场的行情新旧对它零影响
- **SC-003**: 两个市场页签所含锚的**并集等于全部锚，交集为空** —— 任一只锚恰好在一个页签中出现一次，无遗漏亦无重复
- **SC-004**: 在任一空态下，屏幕上呈现的行动入口 100% 可执行 —— 无筛选时不出现「清除筛选」，另有他市场锚时不出现「去建第一个锚」
- **SC-005**: 连续 30 天只查看单一市场页签后，另一市场每一只锚的复核红标状态与其价格事实一致，偏差数为 0
- **SC-006**: 建锚入口对不受支持市场的标的**零成功率** —— 且用户在提交前即可知道它不可选，不出现「选得到、提交才被拒」
- **SC-007**: 切换市场后首屏内容可见时间与切换前同量级，用户不感知额外等待

## Assumptions

- **港股的实时报价源与期权链接入不在本片范围。** 港股页签上线即为「恒收盘档、详情无可选合约」的形态，这是已知且被接受的能力缺口，不是缺陷。
- **上线时港股页签为空。** 取证于 2026-08-21（**prod 库**）：16 只锚全部为美股，全部形状合法、无其他市场（dev 库同形，12 只全美股）。故本片的第四空态与市场能力说明是港股页签的首屏主体验。⚠️ **本条有到期风险**：同日 prod 待审收件箱 129 条 PENDING，其中**港股 21 条**。它们一旦被采纳，港股页签就不再是空的 —— 功能本身不受影响，但 US2「空态即主体验」的优先级论证随之失效、验收重点要跟着换。impl 期间若采纳了待审，回头复核 US2 与 T14。
- **待审估值提交的采纳流程不在本片范围**，本片不改动其收件与处置方式。
- **锚管理列表页不在本片范围**。它与雷达对「已排除」的锚态度相反、刻意不共用查询，本片不触碰。
- **温度计仍是跨市场视角**（含与市场无关的指数计量），不随雷达页签变化。这是一处已知的作用域不连续：用户可能从港股页签一跳进入以美股为主的温度计。本片**明确不改**，在此记录以免将来被当作漏洞重新发现。
- **锚表规模上限约 1000 行的既有假设不变** —— 分市场后单页签规模更小，不改变既有的分页与加载策略前提。
- **与「雷达跨标的聚合三视图」的顶部控件层级已裁决**：市场是**外层作用域**，聚合视图选择器是其**下层镜头**。该 feature 尚未落 spec、其设计稿为本机私有不入库，故此裁决只能落在本文件 —— 接手者以此为准，不要在雷达顶部再并列一条同级控件。
- **本片 supersedes 045 关于雷达空态三分与雷达查询作用域语义的部分**（空态由三态扩为四态、查询新增市场作用域维度）。045 spec 作为冻结决策记录**不回改**。
