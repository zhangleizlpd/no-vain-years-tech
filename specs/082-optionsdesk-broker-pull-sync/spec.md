# Feature Specification: 期权台券商账户同步底座（拉取式）

**Input**: User description: "把富途账户里属于锚标的的持仓、成交、订单同步进服务端：新建锚自动补齐该标的历史、每个交易日开盘前按市场对账，并为每个持仓算出开仓时间；同步范围默认只含锚标的，带开关可切全量。上线时的一次性历史回填不做成系统能力，上线前用脚本执行一次。" 方案依据：`docs/private/plans/2026-09/09-13-broker-account-master.md` §1、§5、§6、§9、§12 与 `09-13-broker-account-p0-poc.md`（维护者本机私有，不入库）。

## Clarifications

### Session 2026-09-14

- Q: 对账失败后，同一交易日内要不要重试？ → A: 最多重试 3 次，每次间隔 15 分钟；仍失败则放弃到下一交易日，失败留痕，缺口由下一交易日的对账窗口补回。
- Q: 每日对账往回看多远？ → A: 从该市场上次成功对账那天到今天，且不少于近 7 个自然日；缺口多长就补多长。
- Q: 新建锚补齐完成后，要不要当场刷新持仓？ → A: 要。补齐成功后立即刷新目标标的所属市场的持仓并计算开仓时间，新锚标的的持仓不必等到下一交易日对账。
- Q: 同步出问题时，要不要主动通知维护者？ → A: 不主动通知。失败与补回条数记入同步记录并写告警级日志，数据是否陈旧由读取方（后续持仓页）以「上次同步于何时」提示；主动通知需要时单独补。
- Q: 补齐遇基础设施故障时，重试有没有上限？ → A: 有。每 15 分钟重试一次，自首次尝试起满 24 小时仍失败则记为失败、停止重试，由维护者手动重新触发（参照业内「有上限的延迟重试 + 耗尽后单独收口」的做法）。

## User Scenarios & Testing

### User Story 1 — 新建锚后自动补齐该标的的交易历史 (Priority: P1)

**Why this priority**: 后续的持仓列表要按「开仓时间」排序并展示持仓，而券商的持仓数据**不带开仓时间**，只能由历史成交还原；历史不全，开仓时间就错，且错得无声无息。锚集合会持续增长，新锚标的在建锚之前的成交与订单若不补，它的持仓看起来就像刚开的 —— 靠人记得去手动补必然会漏。同一套补齐逻辑也承接上线前的一次性回填（见 Assumptions），是整组工作的数据底座。

**Independent Test**: 为一只账户里有历史交易、此前没有锚的标的新建锚，确认该标的全部历史成交与订单在时限内进库、与券商 App 记录条数一致，补齐状态可查，持仓的开仓时间及其来源标记正确。

**Acceptance Scenarios**:

1. **Given** 某标的此前无锚且账户里有其历史交易，**When** 为其新建锚，**Then** 该标的全部可回溯的历史成交与订单被自动补齐，条数与券商记录一致，其当前持仓随即进库，无需人工触发
2. **Given** 某标的的补齐已成功执行过一次，**When** 再执行一次，**Then** 库内成交、订单、持仓与第一次的结果逐条一致，不产生重复
3. **Given** 该标的的某持仓在中途清仓后又重新开仓，**When** 补齐完成，**Then** 该持仓的开仓时间落在重新开仓那笔成交，而不是最早的一笔
4. **Given** 某持仓由成交推算的净数量与券商报告的持仓数量不一致，**When** 补齐完成，**Then** 开仓时间取首次发现该持仓的时间，并标明来源为回落值
5. **Given** 补齐时券商连接不可用，**When** 补齐失败，**Then** 建锚照常成功，库内既有数据不被改动，补齐保持待执行；连接在 24 小时内恢复则自动完成，超过 24 小时记为失败、由维护者重新触发
6. **Given** 一次补齐，**When** 查看同步记录，**Then** 能看到它的状态（待执行 / 执行中 / 成功 / 失败）与写入条数

### User Story 2 — 每个交易日开盘前按市场自动对账 (Priority: P1)

**Why this priority**: 实时推送（后续片交付）断线时会丢事件且券商不补发；新成交、到期、指派、拆股都需要一个按天的完整校准点兜底。放在开盘前，是因为到期与指派在券商侧的记账发生在隔夜（港股到期当晚、美股次日凌晨），开盘前那一拍能看到这些变化，开盘后用户看到的是已校准的数据。

**Independent Test**: 删除一条近期成交，推进到该市场的对账时点，确认被补回且补回条数被记录；再执行一次，确认补回条数为 0。

**Acceptance Scenarios**:

1. **Given** 某市场今天是交易日，**When** 到达该市场开盘前的对账时点，**Then** 执行一次该市场对账：从上次成功对账日起（不少于近 7 个自然日）的成交与订单缺则补，当前持仓与开仓时间刷新
2. **Given** 对账补回了库内缺失的成交或订单，**When** 对账结束，**Then** 补回条数被记录，并以告警级别留痕（说明此前的同步链路有遗漏）
3. **Given** 该市场本交易日已对账成功，**When** 同一交易日内再次到达判定，**Then** 不重复执行
4. **Given** 服务在对账时点处于停机状态，**When** 服务在同一交易日内重启，**Then** 补跑本交易日对账
5. **Given** 某期权持仓在券商侧已被指派，**When** 对账成功，**Then** 该期权持仓被移除，指派得到的正股持仓出现
6. **Given** 对账时券商连接不可用，**When** 对账结束，**Then** 既有持仓不被清空，失败被记录，持仓仍可识别出「上次成功同步于何时」

### User Story 3 — 同步范围在「只锚标的」与「全量」之间切换 (Priority: P3)

**Why this priority**: 默认只同步锚标的是维护者的显式决定（锚 = 我关心的标的）。开关是回头路：将来需要全账户视角时，不必改代码。

**Independent Test**: 在两种范围下各执行一次「当前同步范围内全部标的」的补齐，比对写入集合：只锚标的时不含非锚标的，全量时与账户全部记录一致。

**Acceptance Scenarios**:

1. **Given** 范围为只锚标的（默认），**When** 同步，**Then** 只写入属于锚标的的持仓、成交、订单 —— 正股按自身判定，期权按其正股判定；被标为「不参与交易」的锚同样算锚标的
2. **Given** 范围为全量，**When** 同步，**Then** 账户内全部持仓、成交、订单写入
3. **Given** 某期权代码判定不出正股，**When** 同步，**Then** 该行照常写入并标记为未解析，未解析条数可统计

### Edge Cases

- 券商侧同一登录下有多个账户（模拟户、已停用户、基金户）→ 只同步符合选户条件的那一个；符合条件的为 0 个或多于 1 个时同步失败并记录原因 (covers FR-003)
- 组合单（如跨期价差）的订单代码是合成串 → 按各腿合约分别归属正股 (covers FR-007)
- 公司行动后产生的调整合约，代码与正股代码字面不同，且不能靠截掉尾部数字还原 → 按已知合约映射判定 (covers FR-006)
- 带点号的美股代码 → 与锚的同形代码对应；对应不上时按未解析处理，不丢弃 (covers FR-006)
- 券商返回的时间不带时区 → 美股按美东、港股按香港解析，由 FR-008 保证；美股夜盘成交、周六凌晨记账的到期作废是最容易解析错的两类，一旦当作北京时间，开仓时间与日期归属会整体偏移 (covers FR-008)
- 美国夏令时切换日 → 美股对账时点仍为美东 09:10，不随北京时间漂移 1 小时 (covers FR-010)
- 交易日历对当天无法判定 → 照常对账，宁可多跑一次也不漏 (covers FR-010)
- 同一订单的较旧状态晚到 → 不覆盖较新状态；已撤单、失败的订单作为终态保存，不被当作在途 (covers FR-013)
- 券商单次历史查询有跨度上限 → 补齐仍覆盖该标的全部可回溯历史，不漏段 (covers FR-009)
- 连续多日对账失败或服务长时间停机 → 恢复后第一次成功的对账覆盖从上次成功对账日起的全部缺口 (covers FR-011)
- 锚被删除 → 已同步的成交与订单保留；该标的不再进入「只锚标的」的同步范围，其持仓在下一次持仓刷新时随范围移除 (covers FR-005, FR-014)
- 开发环境没有真实券商连接 → 同步静默跳过，不写入、不报错 (covers FR-018)
- 券商接口限频 → 同步节流；因限频导致的失败按失败处理，不清空既有数据 (covers FR-015)

## Requirements

### Functional Requirements

- **FR-001**: 每条持仓、成交、订单与同步记录 MUST 直接记录其归属账号，不经由其他记录间接推导 —— 间接推导时任一查询漏掉关联就会把一个账号的数据暴露给另一个账号
- **FR-002**: 券商连接在服务端只保存券商名、人读标签与券商账户号末 4 位；完整券商账户号 MUST NOT 出现在服务端存储、日志、测试样本或入库文件中
- **FR-003**: 券商侧有多个账户时，同步对象 MUST 为唯一一个同时满足「实盘 ∧ 状态可用 ∧ 具备港股或美股交易权限 ∧ 非基金账户」的证券账户；符合条件的账户数不为 1 时同步失败并记录原因
- **FR-004**: 本片 MUST NOT 引入任何下单、改单、撤单或解锁交易的能力；代码中出现此类调用时自动化检查失败
- **FR-005**: 同步范围由部署配置决定，取值「只锚标的」（默认）或「全量」。「锚标的」= 锚表中的全部锚，含被标为不参与交易的锚。持仓、成交、订单三类数据 MUST 使用同一判定口径
- **FR-006**: 标的判定：正股为其自身；期权为其正股，按已知的「市场 + 合约词根 → 正股」映射判定，覆盖已过期合约与调整合约，MUST NOT 从代码字面截断推断；映射查不到时以行情侧提供的正股信息兜底；仍判定不出的行写入并标记未解析
- **FR-007**: 组合单订单按其各腿合约分别判定归属，不以组合单的合成代码判定
- **FR-008**: 券商返回的时间 MUST 按所属市场的交易所时区解析（美股 = 美东，港股 = 香港）
- **FR-009**: 历史补齐覆盖目标标的全部可回溯的成交与订单，不因券商单次查询的跨度上限漏段；执行范围可为「一只标的」或「当前同步范围内的全部标的」。补齐成功后立即刷新目标标的所属市场的持仓并计算开仓时间（范围为全部标的时刷新全部市场）。新建锚后 MUST 自动对该标的执行补齐；补齐不阻塞、不影响建锚；遇基础设施故障每 15 分钟重试、自首次尝试起满 24 小时仍失败则记为失败并停止重试（由维护者重新触发），遇数据无法处理立即记录失败且不阻塞其他补齐
- **FR-010**: 每个市场每个交易日执行一次开盘前对账，时点按交易所当地时间确定（美股 09:10 美东，港股 09:05 香港）；非交易日跳过；交易日历无法判定时照常执行；本交易日已成功则不重复；错过时点且仍在同一交易日时补跑；执行失败后同一交易日内最多重试 3 次、每次间隔 15 分钟，仍失败则放弃到下一交易日并留痕；同一市场同一交易日同一时刻至多存在一条进行中的对账，前一次执行未结束时不发起下一次
- **FR-011**: 对账覆盖的成交与订单区间 = 从该市场上次成功对账日起至今，且不少于近 7 个自然日（缺则补），并刷新当前持仓 —— 固定窗口会让超过窗口长度的故障缺口永远补不回；每次对账记录补回条数，补回条数大于 0 时以告警级别留痕
- **FR-012**: 成交以券商成交号唯一，订单以券商订单号唯一；补齐、每日对账（及后续实时推送）写同一份数据，任意次重复写入结果一致
- **FR-013**: 同一订单以券商更新时间判新旧，较旧版本 MUST NOT 覆盖较新版本；已撤单、失败等终态订单照常保存
- **FR-014**: 一次成功拉取后，库内该账户该市场的持仓集合 = 券商本次报告并经 FR-005 范围过滤后的持仓集合（新增、更新、移除作为一个整体完成）；已存在持仓的首次发现时间保持不变
- **FR-015**: 拉取失败 MUST NOT 改动既有数据；失败被记录；持仓记录最近一次成功同步的时刻，供读取方判断数据是否陈旧。只有券商明确返回成功且结果为空时，才视为确实空仓
- **FR-016**: 开仓时间：按时间顺序累计该持仓合约的带符号成交数量，数量由零变非零、或正负翻转处为持仓起点；推算净数量与持仓数量不一致时，开仓时间取首次发现时间。每个持仓 MUST 记录开仓时间来源（推算 / 回落），不存在无来源的开仓时间
- **FR-017**: 每次补齐与每日对账都产生一条同步记录：类型、市场、状态（待执行 / 执行中 / 成功 / 失败）、开始与结束时间、写入或补回条数、失败原因。本片不主动通知维护者：同步异常的可见性由同步记录、告警级日志与持仓上的最近成功同步时刻（FR-015）承担
- **FR-018**: 无真实券商连接的开发环境中，同步静默跳过，不写入任何数据、不报错
- **FR-019**: 同步 MUST NOT 降低既有行情数据获取（期权台雷达、详情与每日行情采集）的速度与可用性

### Key Entities

- **券商连接**：一个账号与一家券商的一个证券账户之间的绑定；记录券商名、人读标签、账户号末 4 位、归属账号。
- **券商持仓**：某连接在某市场的一个合约的当前持仓；记录代码、判定出的正股（或未解析标记）、数量、市值、成本、币种、首次发现时间、开仓时间及其来源、最近成功同步时刻、券商原始记录；归属账号。
- **券商成交**：一笔成交；以券商成交号唯一；记录代码、正股、方向、数量、价格、按交易所时区解析的成交时间；归属账号。
- **券商订单**：一张订单的最新已知状态；以券商订单号唯一；记录代码或组合单各腿、方向、数量、价格、状态、券商更新时间；归属账号。
- **合约归属参考**：合约代码到正股的判定结果缓存；属于公共参考数据，不归属任何账号。
- **同步记录**：一次补齐或对账的执行留痕，字段见 FR-017；归属账号。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 上线时（发版后、首个交易日对账前）一次性回填执行完成后，逐只锚标的比对，库内成交与订单条数与券商 App 记录的一致率为 100%
- **SC-002**: 单只新建锚从建锚到补齐成功、其持仓可见 ≤ 5 分钟
- **SC-003**: 同一补齐或对账重复执行任意次，库内数据与首次执行结果的差异条数为 0
- **SC-004**: 上线后连续 5 个交易日，每个市场每个交易日恰有 1 条成功的对账记录，缺失与重复次数均为 0
- **SC-005**: 人为删除 1 条近期成交后，下一次对账补回条数为 1；紧接着再执行一次，补回条数为 0
- **SC-006**: 开仓时间来源为「推算」的持仓，其开仓时间与券商 App 成交记录的一致率为 100%；开仓时间缺少来源标记的持仓数为 0
- **SC-007**: 券商连接不可用期间执行的补齐或对账，导致既有持仓或成交被清空或改动的次数为 0
- **SC-008**: 人工抽核锚标的相关的期权代码，正股判定错误（归到错误标的）的次数为 0；未解析的代码逐条可解释
- **SC-009**: 同步上线前后，既有行情数据获取的延迟中位数变化 < 10%（个别请求的短暂卡顿不计入判定），行情采集链路新增错误为 0 条
- **SC-010**: 服务端存储、日志、测试样本与入库文件中出现完整券商账户号的次数为 0

## Assumptions

- **本片是「券商持仓」整组工作的第二片。** 第一片（081）交付了交易账户页骨架；实时推送、持仓读接口与列表展示、冷启动页的「券商历史」状态行由后续片交付；订单展示、报表统计与其他券商接入不在该组范围。
- **上线时的一次性历史回填不是系统能力**（维护者 2026-09-14 定）：上线时（发版后、首个交易日对账前）由维护者用一次性脚本执行一次「当前同步范围内全部标的」的补齐，复用 FR-009 的补齐逻辑，起点取 2024-09-01；执行后按 SC-001 核对。本片不为它提供常驻的命令入口、专用同步记录类型或专项测试。持续发生的行为 —— 新建锚补齐（FR-009）与每日对账（FR-010）—— 才是系统能力。
- **不保留每日持仓快照**（维护者 2026-09-14 定）：本组暂无读取方，需要时再补。历史某日的持仓可由已同步的成交倒推，拆股、转入转出这类成交记录看不见的变化除外。
- **券商暂只有富途，且只有期权台管理员账号绑定券商连接**，上线时一次性建立；外部账号的绑定、导入、注销清理与数据留存不在本片。锚暂维持全局（所有账号看到的锚相同），同步范围按全局锚集判定。
- **「只同步锚标的」是维护者的显式决定**，与仓内「采集端不过滤」的惯例相反；FR-005 的开关是回头路。范围由「只锚标的」切到「全量」后，非锚标的的历史不会自动出现，由维护者执行一次「当前同步范围内全部标的」的补齐（一次性动作，同上线前回填）；切回「只锚标的」时已同步的历史保留。
- **以下为 2026-09-13 在真实账户上只读实测的结论**：
  - 只读查询无需解锁交易
  - 可回溯的最早成交与订单均在 2024-10 前后，覆盖全部当前持仓的起点
  - 全量历史拉取在限频下实测约 1–2 分钟；单只标的补齐同样要先拉全账户历史再过滤，耗时同一数量级
  - 行权、指派、到期作废在券商侧都以成交记录出现 ⇒ 开仓时间推算自动覆盖这几类变化
  - 存在成交记录看不见的持仓变化（拆股、转出），占当前持仓的少数 ⇒ FR-016 的回落必要
  - 持仓与订单的币种按市场单一（美股美元、港股港币），成交记录不带币种；期权数量单位为张，市值已含合约乘数
  - 调整合约的词根不能由截断还原
- **对账时点待复核**：历史记录显示港股指派记账在到期当晚、美股在次日凌晨（美东），均早于 FR-010 的开盘前时点。实时时点由 2026-09 月度到期实测复核，结果出来后修正时点参数，不卡任何 SDD 步骤；若开盘前尚未反映，调整的是时点参数，不改本 spec 的需求形态。
- **同步按「不影响既有行情服务」设计，短暂卡顿可接受**（维护者 2026-09-14 定）：常驻交易连接对行情接口的影响在实测中，但不作为任何 SDD 步骤的前置条件；若实测出现持续影响，交易连接改为独立进程运行，业务逻辑不变。由 SC-009 验收。
- **未验证、按兜底处理的三点**：带点号美股代码在券商侧的具体格式无样本（判定不出时按 FR-006 标未解析）；订单在途中间态实测只见到部分，其余取值按券商文档；历史查询是否包含当日未验证（补齐与当日查询按唯一号去重，结果不受影响）。
- **锚被删除后，已同步的成交与订单保留**，持仓在下一次持仓刷新时随范围移除（见 Edge Cases）；保留下来的历史在展示时是否随锚过滤，由读取方（后续片）决定。
- **选户条件命中多于 1 个账户时判失败而非任取其一**：当前实测仅 1 个账户满足；判失败是为了防止静默同步错账户。
- **服务端归属期权台（optionsdesk）**。拆出为独立上下文的条件（范围开关打开且出现期权台以外的读取方，或接入第二家券商）记入 ADR-0062 复审记录，随本片 PR 提交。
