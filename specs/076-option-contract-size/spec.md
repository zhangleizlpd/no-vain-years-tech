# Feature Specification: 期权合约股数落库 —— 单笔权利金与成交额按每张合约的真实股数算

**Feature Branch**: `076-option-contract-size`
**Created**: 2026-09-06
**Status**: Draft
**Input**: User description: "期权合约股数落库 —— 港股每张合约的正股股数逐标的不同（150 到 2000），读端按美股常量 100 算单笔权利金与成交额，21/22 只港股锚静默错数；改为链发现逐合约取 vendor lot_size 存 option_contract.contract_size，非标合约存 null，读端改吃合约行，删美股常量"

**病根一句话**：读端把「一张合约 = 100 股」当成市场常量，而港股每张合约的正股股数逐标的不同。2026-09-06 直查 prod 的 28 只港股锚：有期权链的 22 只里只有 1 只（00700）是 100 股，其余 21 只在 150 到 2000 股之间 ⇒ 屏上「单笔权利金」偏小 1.5 到 20 倍，且没有任何一处会红。

## Clarifications

### Session 2026-09-06 — specify 期裁决（四问，owner 采纳建议）

- Q1: 已到期合约的股数留空还是一次性回填？ → A: **留空**。读端只取未到期合约，历史行不进选约表；回填要打供应方，且供应方对已到期码未必认。（→ FR-006、state_branch 12）
- Q2: 部署后首轮回填前，单笔权利金显示空还是临时兜底 100？ → A: **显式空值**。窗口只有一轮采集，兜底 100 就是把错数再显示一天。（→ FR-009、state_branch 11）
- Q3: 快照轮对账进本片还是另片？ → A: **进本片**。它是资本调整发生时唯一的运行期信号，而 specify 期取证证明「调整后系列」这形态今天在 prod 造不出来。（→ FR-008）
- Q4: 「合约表 MUST NOT 存合约乘数」这条既有裁决改写落在哪？ → A: **本 spec FR + 047 FR-028 注记 + schema 注释**，不另起 ADR：expand-only、可回滚、单 context 写。（→ FR-013）

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 港股锚的单笔权利金是这张合约真收多少钱 (Priority: P1)

我在港股锚的选约表挑一条卖出认沽的腿，看到「单笔权利金」那一列，想知道卖出一张实际收多少港币。今天这个数是按 100 股算的，而阿里（09988）一张是 500 股、中国电信（00728）一张是 2000 股 —— 屏上的数比真实收款少 5 倍到 20 倍，且每一行都同样错，看不出异样。

**Why this priority**: 这是本片的全部价值。它是用户看得见的数字，错的方向是**低估收款**，会让人对港股腿的租金判断整体偏悲观；而它错得很整齐，没有任何一处会告警。

**Independent Test**: 对 22 只有期权链的港股锚各请求一次选约表，逐只断言「单笔权利金 ÷ 买价」等于交易所 class list 里该类的合约股数。单独交付即可用。

**Acceptance Scenarios**:

1. **Given** 港股锚 09988（交易所 class list：500 股 / 5 手），**When** 请求任一视角的选约表，**Then** 每条腿的单笔权利金 = 买价 × 500，成交额 = 成交量 × 买价 × 500
2. **Given** 港股锚 00700（100 股），**When** 请求选约表，**Then** 两个数与改动前逐值相同
3. **Given** 任一美股锚，**When** 请求选约表，**Then** 两个数与改动前逐值相同
4. **Given** 某合约的股数尚未落库（部署后首轮链发现之前），**When** 请求选约表，**Then** 该腿的两个数显示为空、其余列照常，页面不报错不降级

---

### User Story 2 - 合约股数随交易所变动跟着变，且变动看得见 (Priority: P2)

交易所会因资本调整（供股、红股、拆合股、特别股息 ≥ 2%）改所有未到期系列的合约股数，港股板手数改革（2026-11 起分阶段）也会让新挂系列的股数不同于旧系列。我要的是：库里的数跟着供应方每轮刷新，变了有记录，而不是建表时写一次就永远不动。

**Why this priority**: 没有它，本片修的是「今天的 22 只」，明年板手改革后又静默错回去。P2 而非 P1，是因为今天 prod 上没有一只港股锚处在调整后状态（specify 期实查 22 只全部标准、单一 class code）。

**Independent Test**: 用夹具让同一合约两轮链发现给出不同股数，断言第二轮库值被更新、并出一条可查的变更记录；再让链发现本轮不干净，断言股数一行不动。

**Acceptance Scenarios**:

1. **Given** 库里某未到期合约股数为 500，**When** 下一轮成功的链发现给出 1000，**Then** 库值变为 1000 且本轮产生一条变更记录（标的、变更条数）
2. **Given** 部署前入库的合约股数全部为空，**When** 部署后第一轮成功的链发现跑完，**Then** 该标的全部未到期标准合约的股数被填上，已到期的仍为空
3. **Given** 链发现本轮差集不干净或失败，**When** 轮次结束，**Then** 股数一行未变
4. **Given** 快照轮读到某合约的股数与库值不一致，**When** 轮次结束，**Then** 产生一条留痕记录，库值不变

---

### User Story 3 - 算不出的时候说算不出，不用 100 顶上 (Priority: P3)

非标合约（并购 / 分拆后调整的合约）交割的不是整数股正股，供应方对它照样报 100。我要系统对这类合约明确记「算不出」，读端显示为空，而不是拿一个看起来合理的数糊上。

**Why this priority**: 它不改变任何一个今天在屏上的数（非标合约本就不进选约表），但它决定了「空」这个状态的可信度：空 = 真不知道，不是漏算。

**Independent Test**: 夹具里放一张非标合约（供应方股数字段为 100）与一张股数缺失的标准合约，断言两者落库都为空且本轮其余合约照常入库。

**Acceptance Scenarios**:

1. **Given** 供应方对一张非标合约报股数 100，**When** 链发现落库，**Then** 该合约股数为空
2. **Given** 供应方对一张标准合约的股数字段缺失、为哨兵串或为非正整数，**When** 链发现落库，**Then** 该合约股数为空并写日志，同批其余合约照常入库

### Edge Cases

- **同一标的两套系列并存**（港股资本调整后，调整后系列换新交易所代码，原代码留给新挂的标准系列）：两组各自的股数各自落库、各自参与读端计算，股数按合约行逐张取（FR-001），不按标的取。判「非标」沿用既有判据（供应方标准类型字段 ∧ 词根尾数字）；港股调整后代码的形态与供应方对它的标准类型取值**未验证**，今天 prod 无真实样本，由夹具覆盖
- **跨市场混入行**：港股 09988 的链里混进 72 行美股 Albemarle（词根同为 ALB，股数 100）；取值发生在混入行被剔除之后，否则 09988 会落成 100
- **正股行不是合约行**：供应方在正股行上也给同名的股数字段，含义是板手数（美股正股为 1、港股正股为 100 / 200 / 2000）；取值只看期权合约行
- **供应方字段形态**：港股专属字段在美股行上是字符串哨兵而不是空；港股的「对应手数」字段是浮点（实测 1 / 3 / 5）；股数落库前按正整数校验
- **已到期合约永久为空**：链发现每轮只重下未到期阶梯，已到期合约供应方不再返回；读端过滤未到期，历史行触不到。链报表 / 归因若将来要看历史成交额，另片处理
- **股数变更后的历史快照**：成交额与单笔权利金都是读端现算，用当前股数；历史快照行不回算。资本调整前后同一合约的成交额口径因此可能不连续，本片接受并写明
- **首轮回填窗口**：部署到下一轮成功链发现之间（港股主轮 16:20 HKT、美股夜轮）未到期合约股数为空，屏上两个数为空；一轮采集的窗口，已接受（Q2 裁决）
- **港股无期权链的锚**（00291 / 00371 / 00777 / 00960 / 06117 / 06186）：零影响

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 系统 MUST 为每张**标准**期权合约记录「一张合约对应的正股股数」，取值来自链发现时供应方给出的逐合约数据
- **FR-002**: 非标合约的股数 MUST 记为空，MUST NOT 采用供应方对非标给出的数（实测美股非标供应方恒报 100，与 OCC 调整后交割物不符；采了就是把错数当真值）
- **FR-003**: 股数 MUST 只从期权合约行取，MUST NOT 从正股行取 —— 正股行的同名字段是板手数（美股为 1），拿错了每张美股合约会算成 1 股
- **FR-004**: 取值 MUST 发生在跨市场混入行被剔除之后（否则港股 09988 会混入股数 100 的美股 Albemarle 行）
- **FR-005**: 股数缺失、为哨兵串或非正整数时 MUST 记空并写日志（采集 adapter 层无采集轮上下文，不进轮次记录）；MUST NOT 阻断本轮采集，MUST NOT 以 100 或任何常量顶上
- **FR-006**: 既有未到期合约（含部署前入库的）MUST 在下一轮成功的链发现中被回填或更新；发生变更（含空 → 值）MUST 留 notice 记录；已到期合约 MUST NOT 回填（Q1 裁决）
- **FR-007**: 股数的更新 MUST 只在链发现整轮干净（差集为零）时执行，与软下架对账同一道闸 —— 链抖动时更新会把一次空返写成整票清空
- **FR-008**: 快照轮 MUST 比对快照行的股数与库值，不一致 MUST 留痕（采集轮记录，`notice` 类：非失败、不改判、不计数）；MUST NOT 改库值（写手只有链发现一处，Q3 裁决）
- **FR-009**: 读端「单笔权利金」与「成交额」MUST 用该合约自己的股数计算；股数为空时两个数 MUST 为空（显式态），MUST NOT 回落任何常量（Q2 裁决）
- **FR-010**: 美股锚的两个数 MUST 逐值零变化 —— 100 自此来自供应方逐合约实测，不再来自常量
- **FR-011**: 「按市场写死的合约股数」常量 MUST 退役，代码中 MUST NOT 保留任何以市场为键的合约股数取值
- **FR-012**: 契约字段形状 MUST 零变化（两个字段本就可空）；字段说明 MUST 去掉「× 100」并写明「× 该合约的股数，港股逐标的不同」；mobile MUST 零代码改动
- **FR-013**: 「合约表 MUST NOT 存合约乘数」这条既有裁决 MUST 改写为「标准合约 MUST 存、非标 MUST 空」：047 spec FR-028 加 superseded 注记指向本片，schema 列注释与派生函数处的旧注释同步更正（Q4 裁决：不另起 ADR）
- **FR-014**: 本片 MUST 附供应方字段语义的实测证据（22 只港股锚三式互证 + 美股标准 / 非标对拍），MUST NOT 凭文档字面定语义
- **FR-015**: 部署后 MUST 做一次 prod 核对：首轮成功链发现之后，未到期标准合约股数为空的行数为 0

### Key Entities

- **期权合约**：供应方下发的市场事实，一行一张合约。本片新增一个属性「一张合约对应的正股股数」：标准合约取供应方值，非标为空；可随链发现每轮变化
- **链发现轮次**：一次对某标的全部未到期阶梯的重下。本片让它成为股数的唯一写手，并在整轮干净时对既有行做回填与更新
- **快照轮次**：一次对工作集合约的报价采集。本片让它顺带比对股数并留痕，不写
- **选约表腿行**：读端呈现的一条腿。本片改变其中两个派生数的算法输入，不改形状

### 3 · 交易所规则（一手）

- 合约股数逐类不同，上市时 = 当时板手数 × N；资本调整改**所有未到期系列**的股数与行权价（新股数 = 旧合约价值 ÷ 新行权价）—— HKEX Operational Trading Procedures Chapter 8 §8.3、Appendix B2
- 调整后系列换新交易所代码，原代码留给之后新挂的标准系列 ⇒ 同一标的两套代码并存 —— Appendix B2、Stock Options FAQ 6
- 触发面：供股 / 红股 / 拆合股 / 并购 / 私有化必调；特别股息 ≥ 收盘价 2% 才调；普通股息不调 —— Chapter 8 §8.2
- 板手数改革：统一为 8 档，2026-11-16 起分阶段，发行人在无纸化转换后 6 个月内改板手；咨询文件 §104 明说期权合约股数「may need to be adjusted」

## Assumptions

- 供应方字段语义按本片实测定：期权合约行 `lot_size` = 一张合约的正股股数（官方文档原文「stock options represent the number of shares per contract」），`option_owner_lot_multiplier` = 对应正股手数（仅港股），`option_contract_nominal_value` = 现价 × 股数（仅港股，派生值，不存）
