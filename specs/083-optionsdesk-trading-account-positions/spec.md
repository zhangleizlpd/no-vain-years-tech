# Feature Specification: 期权台交易账户页 · 持仓展示与下钻

**Input**: User description: "083 optionsdesk 交易账户页持仓展示与下钻（p3，设计 SoT = docs/private/plans/2026-09/09-13-broker-account-master.md §8「p3」+ p3 子 plan「本片裁决」）" —— 把 082 已同步进服务端的券商持仓，在交易账户页（081）的「持仓」分段按正股分组展示；期权持仓可下钻看持仓批次，正股持仓可下钻看订单，二者最终都能打开单张订单详情；冷启动页为新锚补一行「券商历史」补齐状态。方案依据：`docs/private/plans/2026-09/09-13-broker-account-master.md` §1、§8「p3」、§9 与 `09-13-broker-account-p3-positions-view.md`（维护者本机私有，不入库）。

## Clarifications

### Session 2026-09-15（specify 前，维护者逐项定）

- Q: 价格与盈亏的时效？ → A: 读本系统最近一次成功同步的券商数据并显示同步时刻，接受日级延迟（实时推送片合入后自然接近实时）；不叠加实时行情、不做触发券商同步的手动刷新。
- Q: 盈亏列显示哪个口径？ → A: 只显示持仓盈亏（开仓以来的浮动盈亏，金额 + 比例），不显示今日盈亏。
- Q: 成本取哪个口径？ → A: 平均成本（只累计买入，卖出部分转为已实现盈亏、不影响成本）；持仓盈亏随之取同一口径。
- Q: 分组怎么展现？ → A: 照维护者提供的富途 App 持仓截图：某正股只有 1 行时平铺；≥ 2 行时先出一行正股组头，下挂该正股的正股行与各期权行；组头 = 名称(行数) · 组市值 · 正股现价 · 组持仓盈亏；可折叠。将来多券商时每条分行展示，正股（各券商）在前、期权在后。排序沿用 master U2 / U3，不重议。
- Q: 期权主列表是逐笔一行还是按合约汇总？ → A: 按合约汇总一行（参照 thinkorswim：持仓详情里「View Lot Details」看组成持仓的交易批次）；逐笔信息通过「持仓批次」下钻查看。
- Q: 批次怎么划分与扣减？ → A: 一张开仓订单 = 一个批次（同一订单多次成交合一，成本 = 订单成交均价）；部分平仓、被指派、到期作废按先开先平（FIFO）扣减；批次剩余之和与券商持仓数量对不上时详情页标「批次无法还原」、只显示合约汇总，主列表不受影响。正股不做批次。
- Q: 点持仓行去哪？ → A: 期权合约行 → 持仓详情（合约汇总 + 持仓批次）→ 订单详情；正股行 → 持仓详情（汇总 + 当前持仓周期订单列表）→ 订单详情。订单详情字段照富途 App「交易详情」页。
- Q: 顶部要不要账户汇总？ → A: 本片不做；将来做时按券商分开、不跨券商合并。用户自选排序本片不做。
- Q: 组内没有正股行时，组头「正股现价」取什么？ → A: 取本系统行情里该正股的最新价，取不到留空（维护者未反对默认）。

### Session 2026-09-15（clarify）

- Q: 期权持仓详情里，除了批次列表，要不要也能看到该合约的平仓 / 减仓订单？ → A: 要。批次列表下方加「本合约订单」列表：当前持仓周期内该合约的全部订单（含平仓、被指派、到期作废产生的系统订单），按下单时间倒序，与正股持仓详情的订单列表同一形态；平仓订单不挂到具体批次下。
- Q: 持仓分段与下钻页什么时候重新读取本系统数据？ → A: 进入页面、App 回到前台时自动重读；另支持下拉重读。重读只读本系统已同步的数据，不触发券商同步（Session「specify 前」所说「不做手动刷新」指不做触发券商同步的刷新）。
- Q: 到期日已过、尚未被同步移除的期权持仓行怎么显示？ → A: 照常显示，行上（及其持仓详情）标「已到期 · 待同步」；市值、持仓盈亏照常计入组市值、组持仓盈亏与跨组排序。「已过期」= 到期日早于所属市场交易所当地的今天。
- Q: SC-001 与富途 App 比对在什么时段、比哪些字段？ → A: 数量与成本任意时段比对；现价、市值、持仓盈亏只在「该市场当日对账成功后至开盘前」窗口内比对（本页价格是开盘前对账时的快照，其他时段必然与 App 的实时价格不同）。

### Session 2026-09-15（mockup）

- Q: 主列表数字列放不下长数值（如 5 位以上整数的市值 / 盈亏）时怎么办？ → A: 用「万」缩写，不改列宽、不降字号。缩写阈值、小数位与是否作用于数量由 plan 定（定值见 FR-022）。

### Session 2026-09-15（analyze）

- Q: 交易日历判定不了上一交易日时，陈旧提示怎么表现？ → A: 不标陈旧，记告警日志（避免误报；日历端口约定 null = 不可判定、调用方不得猜日期）。
- Q: 同一券商有两个连接时，每行的券商标显示什么？ → A: 连接的名称（建连接时的人读标签），用于区分同一券商的不同连接。
- Q: 已经显示列表时重读失败怎么提示？ → A: 保留列表，在同步时刻那一行显示「刷新失败，显示的是上次加载的数据」；详情页同样保留数据并在顶部提示。

## User Scenarios & Testing

### User Story 1 — 按正股分组查看锚标的持仓 (Priority: P1)

维护者打开交易账户页、选中市场，在「持仓」分段看到该市场属于锚标的的券商持仓：同一正股的正股与期权归在一组，按组市值大小排列；每行给出名称代码、市值 / 数量、现价 / 成本、持仓盈亏，并能看出数据同步于何时、是否陈旧。

**Why this priority**: 082 已把券商持仓同步进服务端，但目前没有任何地方能看到它；持仓分段仍是「建设中」占位。这是整组工作第一次把「我在券商的账户事实」按期权台的视角（锚标的、按正股）呈现出来，下钻都建立在它之上。

**Independent Test**: 在一个有正股 + 期权混合持仓、单行持仓、非锚标的持仓与未归类持仓的数据集上打开持仓分段，核对行的归组、组头出现与否、组头数值、行顺序、行字段口径、未归类提示与同步时刻；再把同步时刻调到陈旧、把服务端置为不可达，核对陈旧提示与加载失败态。

**Acceptance Scenarios**:

1. **Given** 某正股在该市场有正股持仓与 2 个期权合约持仓，**When** 打开持仓分段，**Then** 出现该正股组头「名称(3)」，组市值 = 三行市值带符号求和，组持仓盈亏 = 三行持仓盈亏带符号求和，组头正股现价 = 正股行现价；组下正股行在前，两个期权行按开仓时间先后排列
2. **Given** 某正股只有 1 个期权持仓，**When** 打开持仓分段，**Then** 该期权单行平铺、无组头，并按其市值绝对值参与跨组排序
3. **Given** 一个港股空头认沽期权持仓，**When** 查看该行，**Then** 名称为「正股名 沽」，第二行为到期日与行权价，数量显示为负数，市值为负数
4. **Given** 券商报告的某正股平均成本与摊薄成本不同，**When** 查看该行，**Then** 成本显示平均成本，持仓盈亏的金额与比例按平均成本口径
5. **Given** 账户里有非锚标的的持仓与判定不出正股的持仓，**When** 打开持仓分段，**Then** 二者都不出现在列表中，列表顶部提示「未归类 N 条」（N = 判定不出正股的条数）
6. **Given** 该市场最近一次同步失败，**When** 打开持仓分段，**Then** 照常显示上次成功同步的持仓与其同步时刻；满足 FR-009 陈旧条件时提示数据陈旧
7. **Given** 点某组组头，**When** 再点一次，**Then** 该组先折叠后展开；离开页面再进入后所有组恢复展开
8. **Given** 停留在持仓分段期间本系统完成了一次同步，**When** 下拉列表（或把 App 切到后台再回到前台），**Then** 列表与同步时刻更新为新数据，且此操作本身不触发券商同步
9. **Given** 某美股期权周五到期、下一次对账在下周一开盘前，**When** 周六打开持仓分段，**Then** 该期权行照常显示并标「已到期 · 待同步」，其市值仍计入所在组的组市值
10. **Given** 持仓列表已显示，**When** 下拉重读时服务端不可达，**Then** 列表保持不变，同步时刻那一行显示「刷新失败，显示的是上次加载的数据」；服务端恢复后再次下拉，提示消失、数据更新

### User Story 2 — 期权持仓下钻看持仓批次与订单详情 (Priority: P2)

维护者按每笔期权开仓来跟踪与管理：点一个期权合约行，看到该合约的汇总、组成它的持仓批次（每个批次对应一张开仓订单，含开仓时间、剩余张数、成本、市值、持仓盈亏），以及这一轮持仓期间该合约的全部订单（含平仓与指派 / 到期产生的系统订单）；点某批次或某张订单，看到那张订单的详情。

**Why this priority**: 维护者的管理单元是「每一笔期权开仓」，而券商持仓把同一合约的多次开仓合成了一行。批次让主列表保持与券商一致的汇总形态，同时不丢逐笔视角。依赖 US1 的列表作为入口。

**Independent Test**: 构造一个合约先后两张开仓订单、其中一张分两次成交、随后部分平仓 1 张的成交序列，打开该合约持仓详情，核对批次数量、各批次剩余张数与成本符合先开先平；再构造批次之和与持仓数量不符的数据，核对「批次无法还原」提示与主列表不受影响；点批次核对订单详情字段。

**Acceptance Scenarios**:

1. **Given** 某合约在当前持仓周期内由两张开仓订单建立（A 早、B 晚），其中 A 分两次成交，**When** 打开该合约持仓详情，**Then** 显示 2 个批次：A 的数量为两次成交之和、成本为 A 的成交均价
2. **Given** 上述持仓随后买回平仓 1 张，**When** 打开持仓详情，**Then** 从批次 A 扣减 1 张，批次 B 不变；A 扣减为 0 时不再显示
3. **Given** 某空头期权部分被指派或到期作废，**When** 同步后打开持仓详情，**Then** 被指派 / 作废的张数同样按先开先平从最早批次扣减
4. **Given** 某合约批次剩余数量之和与券商报告的持仓数量不一致，**When** 打开持仓详情，**Then** 显示「批次无法还原」与合约汇总，不显示批次列表；主列表中该合约行照常显示
5. **Given** 某批次，**When** 点击它，**Then** 打开该批次开仓订单的详情，字段包括交易方向、订单状态、名称代码、订单数量 / 价格、订单金额、成交数量 / 均价、成交金额、下单时间（交易所当地时间并标注时区）、订单类型
6. **Given** 某批次来自组合单的一条腿，**When** 点击它，**Then** 打开该组合单的订单详情，并能看到各腿
7. **Given** 某合约按 FR-016 口径列入的订单中有开仓订单、1 张买回平仓订单与 1 张到期作废产生的系统订单，**When** 打开持仓详情，**Then** 批次列表下方的「本合约订单」列表按下单时间倒序列出这 3 类订单；点其中任一张打开其订单详情

### User Story 3 — 正股持仓下钻看订单列表与订单详情 (Priority: P2)

维护者点一个正股行，看到该正股的汇总与当前这一轮持仓期间的全部订单（按下单时间倒序，含已撤单与失败单）；点某张订单看详情。

**Why this priority**: 正股持仓由多次买卖累积而成，维护者需要回看「这轮仓位是怎么建起来的」。与 US2 共用订单详情。

**Independent Test**: 为一只开仓时间来源为推算的正股构造「清仓 → 重新开仓 → 加仓 → 一张撤单」的订单序列，打开其持仓详情，核对列表只含重新开仓以来的订单、倒序、撤单带状态；再把开仓时间来源改为回落，核对列出该正股全部订单。

**Acceptance Scenarios**:

1. **Given** 某正股的开仓时间来源为推算，**When** 打开其持仓详情，**Then** 订单列表只含最后更新时间不早于开仓时间的订单（开仓那张订单即使在开仓时间之前下单也包含在内），按下单时间倒序
2. **Given** 某正股的开仓时间来源为回落，**When** 打开其持仓详情，**Then** 订单列表含该正股在该券商的全部订单
3. **Given** 列表中有已撤单与失败的订单，**When** 查看列表，**Then** 它们照常列出并显示状态
4. **Given** 一张未成交即撤销的订单，**When** 打开其详情，**Then** 成交数量、成交均价、成交金额显示为「—」

### User Story 4 — 冷启动页查看新锚的券商历史补齐状态 (Priority: P3)

维护者在冷启动结局页，除原有行情冷启动结局外，还能看到每只新锚的「券商历史成交 / 订单」补齐状态。

**Why this priority**: 082 在新建锚时自动补齐该标的的券商历史，但补齐是否完成只能查库；放到冷启动页是因为维护者建锚后本来就会去那里看结局。不影响 US1–US3。

**Independent Test**: 为冷启动页上的几只新锚分别准备「待执行 / 执行中 / 成功 / 失败 / 无记录」五种补齐记录，核对每行显示的状态与时刻。

**Acceptance Scenarios**:

1. **Given** 某新锚的券商历史补齐已成功，**When** 打开冷启动结局页，**Then** 该锚行显示「券商历史 · 成功」与完成时刻
2. **Given** 某新锚没有券商历史补齐记录，**When** 打开冷启动结局页，**Then** 该锚行显示「券商历史 · 未触发」

### Edge Cases

- 期权到期日与行权价由合约代码解析；行权价不补尾零（如 12.5、300、7.25），到期日按 6 位年月日 (covers FR-007)
- 下单时间、开仓时间一旦按北京时间而非交易所当地时间展示，美股夜盘与周六凌晨记账的单子会整体差一天 (covers FR-017)
- 同一合约的批次盈亏之和，与券商报告的合约级持仓盈亏在发生过部分平仓时可能不同（规则不同：先开先平 vs 平均成本）；这是预期，不作为错误提示 (covers FR-014)
- 被指派得到的正股持仓：其订单列表包含指派产生的系统订单 (covers FR-016)
- 期权到期后到下一次对账移除之前仍在库中（美股周五到期可跨整个周末）：照常显示并标「已到期 · 待同步」；「今天」若取北京时间而非交易所当地日期，美股会在到期当天北京时间次日凌晨被提前标为已到期 (covers FR-021)
- 合约清仓后重新开仓：批次只计最近一次持仓数量归零之后的开仓 (covers FR-014)
- 删除锚：该标的持仓在下一次同步刷新前仍在库中，但读时按当前锚集过滤、立即从列表消失 (covers FR-001)
- 同一正股组内既有美股持仓又有港股持仓：不会发生，两个市场分属不同页签 (covers FR-001)
- 组市值为 0（正股与期权市值恰好抵消）：按绝对值 0 参与排序，不视为无效 (covers FR-006)
- 陈旧判定跨非交易日：以该市场最近一个交易日的对账时点为准；交易日历无法判定当天时按交易日处理 (covers FR-009)
- 其他账号登录：看不到任何券商持仓，持仓分段显示「暂无交易账户」 (covers FR-002, FR-010)
- 昨天对账没有成功、今天刚过对账时点仍在 1 小时宽限内：按上一交易日的对账时点判定，照样提示陈旧（只看今天的时点会让旧了两天的数据不被提示） (covers FR-009)
- 同一券商有两个连接：同一合约各为一行，靠连接名称区分；只显示券商名会让两行标签完全相同 (covers FR-012)
- 已显示列表时网络中断、下拉重读失败：列表保持不变并提示刷新失败，不被错误卡替换 (covers FR-023)

## Requirements

### Functional Requirements

- **FR-001**: 持仓分段展示当前账号在所选市场、属于锚标的的券商持仓。「锚标的」= 锚表中的全部锚（含被标为不参与交易的锚），在读取时按当前锚集判定，与同步范围开关无关（同步范围为全量时，非锚标的持仓同样不展示）；经直达链接访问正股未归类或不在锚集的持仓 / 订单详情，与访问不存在的记录同样处理
- **FR-002**: 持仓、持仓批次、订单列表与订单详情 MUST 只返回请求账号自己的数据；经直达链接访问不属于本账号的持仓或订单，与访问不存在的记录同样处理
- **FR-003**: 主列表行形态：正股每个券商连接一行；期权每个券商连接每个合约一行（数量为券商报告的合并数量）；不同券商连接的同一合约 MUST NOT 合并为一行
- **FR-004**: 按正股分组：某正股在所选市场只有 1 行时单行平铺；≥ 2 行时出组头，组头显示 名称(行数)、组市值（组内各行市值带符号求和）、正股现价（见 FR-005）、组持仓盈亏（组内各行持仓盈亏带符号求和）。进入页面时所有组展开；点组头切换折叠 / 展开；进入详情再返回时保留折叠状态，离开交易账户页后不保留
- **FR-005**: 组头正股现价：组内有正股行时取该行现价（多个券商的正股行取排序在前的那行）；组内无正股行时取本系统行情中该正股的最新价；仍取不到则留空
- **FR-006**: 排序为全序：组内正股行在前、期权行在后，两段内各按开仓时间正序，开仓时间缺失排段尾，再按合约代码与券商连接兜底；跨组（单行平铺视为一组）按组市值绝对值降序，并列按正股代码，市值无效（缺失）的组排末
- **FR-007**: 行字段：名称与代码（期权名称 = 正股名 + 美股 `Call` / `Put`、港股 `购` / `沽`；期权第二行 = 到期日 + 行权价）· 市值 / 数量（空头为负）· 现价 / 成本 · 持仓盈亏金额与比例。成本 MUST 为平均成本口径，持仓盈亏 MUST 为同一平均成本口径（取错口径不报错，只是数字与券商 App 的平均成本视图对不上）；不展示今日盈亏；主列表金额的缩写规则见 FR-022
- **FR-008**: 列表与下钻页展示本系统最近一次成功同步的券商数据，不叠加实时行情，不提供触发券商同步的刷新；列表顶部显示所选市场的最近成功同步时刻。进入页面、App 回到前台时自动重读本系统数据，列表与下钻页支持下拉重读；重读不触发券商同步
- **FR-009**: 数据陈旧判定：判定时点 = 所选市场最近一个**已过宽限**的开盘前对账时点（交易所当地时间，沿用 082 的对账时点，宽限 1 小时）—— 今天为交易日且当前已过今天时点 1 小时则取今天的时点，否则取上一交易日的时点；最近成功同步时刻早于判定时点 ⇒ 标记陈旧并提示。交易日历无法判定上一交易日时 MUST NOT 猜测日期，不标陈旧并记告警日志 —— 猜错日期不报错，只会让陈旧提示静默判错
- **FR-010**: 持仓分段区分四种非列表状态，互不混用：无券商连接「暂无交易账户」、从未成功同步「尚未同步」、已成功同步但没有可展示的锚标的持仓「暂无持仓」（未归类条数 > 0 时仍显示 FR-011 的提示）、无已显示数据时加载失败「加载失败 + 重试」。同步失败时列表保留上次成功同步的数据（FR-008、FR-009）；已显示数据时的重读失败见 FR-023
- **FR-011**: 判定不出正股的持仓不进入列表；其条数 > 0 时在列表顶部显示一行「未归类 N 条」，不列明细
- **FR-012**: 每条持仓与订单数据都带所属券商连接；当前账号只有 1 个券商连接时行上不显示连接标签，多于 1 个时每行显示该连接的名称（建连接时的人读标签，同一券商的多个连接靠它区分）
- **FR-013**: 点期权合约行进入持仓详情：合约汇总（主列表行字段 + 开仓时间）+ 持仓批次列表（按开仓时间正序）+ 本合约订单列表（口径同 FR-016 的订单列表，含平仓、被指派、到期作废产生的系统订单；平仓订单不挂到具体批次下）。每个批次显示开仓时间、剩余数量 / 原始数量、成本（该批次成交的数量加权均价，即开仓订单在本合约上的成交均价）、市值（现价 × 剩余数量 × 合约乘数）、持仓盈亏（按批次成本）；批次无法还原时（FR-015）订单列表照常显示
- **FR-014**: 持仓批次还原规则：只看该合约当前持仓周期（最近一次持仓数量归零之后）的成交；每张开仓方向订单的成交合为一个批次（组合单按各腿合约分别成批次）；减仓方向的成交（含行权、被指派、到期作废）MUST 按先开先平从最早批次起扣减 —— 扣错批次不报错，只是批次成本与剩余数量静默错位；剩余数量为 0 的批次不展示；缺订单号的开仓成交单独成为批次且不可进入订单详情
- **FR-015**: 批次剩余数量之和与券商报告的该合约持仓数量不一致时，持仓详情 MUST 显示「批次无法还原」并只显示合约汇总，不显示与持仓数量对不上的批次；主列表不受影响
- **FR-016**: 点正股行进入持仓详情：正股汇总（主列表行字段 + 开仓时间）+ 订单列表。订单列表口径（正股与期权合约共用）：该持仓代码在该券商连接的订单，按下单时间倒序；开仓时间来源为推算时只含**最后更新时间**不早于开仓时间的订单（开仓订单通常在开仓时间之前下单、之后成交，按下单时间过滤会漏掉它），来源为回落时含全部订单；已撤单、失败的订单照常列出并显示状态；点任一订单进入订单详情。正股不做批次
- **FR-017**: 订单详情显示：交易方向、订单状态、名称代码、订单数量 / 价格、订单金额、成交数量 / 均价、成交金额（成交数量 × 成交均价 × 合约乘数）、下单时间、订单类型；组合单另显示各腿。下单时间 MUST 按所属市场的交易所当地时间显示并标注时区；无成交时成交数量、均价、金额显示「—」
- **FR-018**: 冷启动结局页的每只新锚行显示该标的最近一条券商历史补齐记录的状态（待执行 / 执行中 / 成功 / 失败）与对应时刻；无记录显示「未触发」；该状态请求失败时只隐藏券商历史行，冷启动结局照常展示
- **FR-019**: 本片 MUST NOT 提供任何下单、改单、撤单、平仓入口
- **FR-020**: 持仓详情或订单详情请求的记录不存在（含已被同步移除、不属于本账号、正股未归类或不在锚集）时，分别显示「持仓已不存在」「订单不存在」而非错误态，且优先于已显示的旧数据；详情页无已显示数据时加载失败显示「加载失败 + 重试」
- **FR-021**: 期权到期日早于所属市场交易所当地的今天、但仍在同步数据中的持仓，主列表行与持仓详情标「已到期 · 待同步」；其市值与持仓盈亏照常计入组市值、组持仓盈亏与跨组排序。「今天」MUST 取所属市场的交易所当地日期 —— 取北京时间日期会让美股期权提前一天被标为已到期且不报错
- **FR-022**: 主列表的市值、组市值、持仓盈亏金额、组持仓盈亏按「万」缩写：绝对值 < 1 万显示千分位两位小数；1 万 ≤ 绝对值 < 1 亿显示「x.xx万」；≥ 1 亿显示「x.xx亿」；保留正负号。数量、价格、比例不缩写；持仓详情与订单详情显示完整数值
- **FR-023**: 列表或详情页已显示数据时重读失败，MUST NOT 用错误态替换已显示的数据：保留数据，列表在同步时刻那一行、详情页在顶部显示「刷新失败，显示的是上次加载的数据」，下一次重读成功后提示消失 —— 替换会让网络一抖就丢掉用户正在看的内容

### Key Entities

- **持仓行（展示）**：主列表的一行；对应一个券商连接下的一个正股或一个期权合约的当前持仓；携带名称代码、数量、市值、现价、平均成本、持仓盈亏金额与比例、开仓时间及来源、所属券商连接（含名称）、所属市场、所属正股；来源为 082 同步的券商持仓。
- **正股组**：同一正股在同一市场下的全部持仓行；携带行数、组市值、正股现价、组持仓盈亏；只在行数 ≥ 2 时以组头呈现。
- **持仓批次**：某期权合约当前持仓中由一张开仓订单贡献、尚未被平掉的部分；携带开仓时间、剩余数量与原始数量、成本、市值、持仓盈亏、所属开仓订单；由已同步的成交与订单在读取时还原，不单独存储。
- **订单详情**：一张券商订单的最新已知状态；来源为 082 同步的券商订单；组合单携带各腿。
- **同步状态**：某市场的最近成功同步时刻与是否陈旧；某新锚的券商历史补齐记录状态；来源为 082 的同步记录。

## Success Criteria

- **SC-001**: 与富途 App 逐行比对（App 成本口径切为平均成本），本页锚标的持仓：数量与成本在任意时段一致率为 100%；现价、市值、持仓盈亏在「该市场当日对账成功后至开盘前」窗口内一致率为 100%
- **SC-002**: 在覆盖 FR-004 ~ FR-006 全部分支的固定数据集上，组头出现与否、组头数值与行顺序与规则期望逐项一致率为 100%
- **SC-003**: 真实账户中批次可还原的期权持仓，其批次剩余数量之和与持仓数量一致率 100%；构造的「多订单开仓 + 部分成交 + 部分平仓 + 被指派 + 到期作废」样本，批次扣减结果与按先开先平手算结果一致率 100%

- **SC-005**: 在常规网络下打开持仓分段到列表可见 ≤ 2 秒
- **SC-006**: 以另一账号登录时，看到的券商持仓条数为 0，经直达链接能打开的他人持仓或订单数为 0
- **SC-007**: 同步失败期间持仓分段被清空的次数为 0；满足 FR-009 陈旧条件时陈旧提示出现率 100%；已显示数据时重读失败导致数据被错误态替换的次数为 0
- **SC-008**: 抽核订单详情（含至少 1 张已撤单、1 张被指派产生的系统订单、1 张组合单），逐字段与券商 App「交易详情」一致率 100%
- **SC-009**: 冷启动结局页每只新锚的券商历史状态与同步记录一致率 100%
- **SC-010**: 本片入库文件、测试样本与 PR 文本中出现真实账户持仓、成交、订单数据的次数为 0

## Assumptions

- **本片是「券商持仓」整组工作的第三片。** 081 交付了交易账户页骨架，082 交付了持仓 / 成交 / 订单的拉取式同步与开仓时间推算；本片只读展示。交易账户页「订单」分段的列表、「报表」分段、账户汇总、用户自选排序、实时价格与触发券商同步的手动刷新都不在本片；实时推送由另一片交付，合入后本页数据自然接近实时，无需本片改动。
- **分组与排序规则来自 master U2 / U3（维护者 2026-09-13 定）**，组头形态与组市值算法照维护者提供的富途 App 截图（2026-09-15），本片不重议。
- **成本与持仓盈亏取平均成本口径（维护者 2026-09-15 定）**。券商直接报告按平均成本口径的浮动盈亏金额与比例：维护者 2026-09-15 用 082 POC 私有持仓样本逐行验算吻合（证据在 `docs/private/evidence/broker-account-poc/`）。富途 App 的成本口径可切换，SC-001 比对前须把 App 切到平均成本；富途持仓列表最右栏的数字与本页持仓盈亏不同属预期（该栏按截图验算不等于持仓盈亏，推断为今日盈亏，未验证）。
- **「持仓批次」参照 thinkorswim 移动端的「View Lot Details」**（持仓详情里查看组成持仓的交易批次）；先开先平取嘉信新开户默认的批次方法。富途不记录平仓对应哪个批次（推断，未验证），因此批次只能按规则还原，与维护者心中「平的是哪一笔」可能不同。
