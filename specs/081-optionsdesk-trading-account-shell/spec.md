# Feature Specification: 期权台交易账户页骨架（分市场布局）

**Input**: User description: "在期权台里新增一个按市场组织的「交易账户」区域：一级按 美股 / 港股 区分市场（照雷达的市场页签），二级分 持仓 / 订单 / 报表；先完成分市场的布局骨架，持仓数据的同步与展示由后续 feature 交付。" 方案依据：`docs/private/plans/2026-09/09-13-broker-account-master.md` §1-U4、§8「p1」（维护者本机私有，不入库）。

## Clarifications

### Session 2026-09-13

- Q: 本页与入口的名称 → A: 「交易账户」（初稿暂称「券商账户」，已弃用）。「券商账户」在 App 内已是「设置 → 券商账户」绑定列表（012）的名称，「持仓」已是投资 Tab 同花顺持仓屏（025）的入口名；「交易账户」覆盖持仓 / 订单 / 报表三类内容且全仓未被占用。本页与后续同组 feature 统一用此称呼。

## User Scenarios & Testing

### User Story 1 — 从期权台一步进入交易账户页，并按市场分开看 (Priority: P1)

**Why this priority**: 用户以期权卖方身份同时在美股、港股持有正股与期权。后续的持仓、订单、报表都要按市场组织 —— 两个市场的币种、交易时段、到期与指派节奏都不同，混在一屏里既无法比较也无法汇总。本片先把「在哪看、怎么切」的骨架立起来，后续数据片直接往里填，避免每一片各自发明入口与切换方式。

**Independent Test**: 只交付本片，即可从雷达点入口进入页面、切换市场、再返回雷达，完整走通导航骨架。

**Acceptance Scenarios**:

1. **Given** markets 开关打开且用户停在雷达，**When** 查看雷达题头，**Then** 能看到交易账户入口；**When** 点击该入口，**Then** 进入交易账户页
2. **Given** 本次使用中第一次进入交易账户页，**When** 页面呈现，**Then** 市场选中「美股」
3. **Given** 用户在交易账户页选中「港股」，**When** 在同一次使用中离开后再次进入，**Then** 仍停在「港股」
4. **Given** 用户完全退出应用后重新打开，**When** 再次进入交易账户页，**Then** 回到「美股」
5. **Given** 雷达当前选中「美股」，**When** 用户在交易账户页切到「港股」后返回雷达，**Then** 雷达仍是「美股」
6. **Given** 用户经直达链接打开交易账户页（没有上一页），**When** 执行返回，**Then** 落到雷达

### User Story 2 — 在一个市场内切换 持仓 / 订单 / 报表 (Priority: P1)

**Why this priority**: 二级分段是后续三类能力的承载位。市场与分段是两个正交维度 —— 用户在比较两个市场的同一类信息（例如两边的订单）时，切市场却被弹回「持仓」，会把一次比较变成两次重新导航。

**Independent Test**: 在任一市场下切换三个分段，再切换市场，确认两个维度互不干扰且记忆行为符合预期。

**Acceptance Scenarios**:

1. **Given** 本次使用中第一次进入，**When** 页面呈现，**Then** 分段选中「持仓」
2. **Given** 用户选中「订单」，**When** 切换市场，**Then** 分段仍为「订单」
3. **Given** 用户选中「报表」，**When** 在同一次使用中离开后再次进入，**Then** 仍为「报表」
4. **Given** 页面处于任一状态，**When** 用户查看页面，**Then** 当前选中的市场与分段都能一眼辨认

### User Story 3 — 占位不被误读成「没有数据」 (Priority: P2)

**Why this priority**: 本片三个分段都还没有数据来源，而用户确实持有仓位。若「持仓」分段显示「暂无持仓」一类表述，会被读成「同步出错」或「仓位丢了」—— 真实原因却是功能尚未上线。两种读法导向相反的动作（去券商 App 核对 vs 等待上线），所以占位必须说清「建设中」。

**Independent Test**: 逐一查看 2 个市场 × 3 个分段共 6 种组合的占位说明，并在断开服务端的情况下重复一遍。

**Acceptance Scenarios**:

1. **Given** 任一市场、任一分段，**When** 页面呈现，**Then** 用户看到该分段专属的说明，表明该功能正在建设中，且不含「暂无」「空仓」「无数据」一类字样
2. **Given** 服务端不可达，**When** 用户进入页面并在市场与分段间切换，**Then** 骨架与占位照常呈现，不出现加载失败或重试提示
3. **Given** 三个分段，**When** 用户逐一切换，**Then** 三处说明文案互不相同，用户能据文案知道自己停在哪一个分段

### Edge Cases

- markets 开关关闭时经直达链接进入 → 与期权台其余页面同样被拦下，不出现半截可用的页面 (covers FR-009)
- 网页版刷新或应用冷启动导致记忆丢失 → 回到默认「美股 · 持仓」，不报错 (covers FR-004)
- 快速连续切换市场与分段 → 最终呈现与最后一次选择一致，界面上不出现两个同时选中的市场或分段 (covers FR-003, FR-005)
- 雷达题头入口变多后在窄屏上 → 每个入口仍能被单独点中，不遮挡页面标题、不互相重叠 (covers FR-001)
- 用户停在「港股 · 订单」时用系统返回手势离开 → 同一次使用中再进入仍是「港股 · 订单」 (covers FR-004)

## Requirements

### Functional Requirements

- **FR-001**: 雷达题头 MUST 提供进入交易账户页的入口；在最窄支持屏宽下，该入口与题头既有入口 MUST 各自可被单独点中，且不遮挡页面标题
- **FR-002**: 交易账户页的一级选择为市场，值域恰为「美股」「港股」两项，与雷达市场页签的值域与用词一致；MUST NOT 提供「全部」—— 两个市场币种不同，混排会让后续的市值排序与汇总失去意义
- **FR-003**: 市场选择之下提供二级分段，值域恰为「持仓」「订单」「报表」三项；任一时刻恰有一个市场与一个分段处于选中态
- **FR-004**: 本次使用中第一次进入 MUST 落在「美股 · 持仓」；同一次使用期间 MUST 记住用户最后选中的市场与分段；应用完全退出重开后回到默认
- **FR-005**: 切换市场 MUST NOT 改变当前分段；切换分段 MUST NOT 改变当前市场
- **FR-006**: 交易账户页的市场选择与雷达的市场选择互相独立 —— 任一侧的切换 MUST NOT 改变另一侧（否则用户在账户页随手一切，回到雷达时击球区视角已被悄悄换掉）
- **FR-007**: 每个分段 MUST 呈现专属的「建设中」占位说明；说明 MUST NOT 使用「暂无」「空仓」「无数据」一类会被读成真实数据状态的表述；三个分段的说明文案互不相同
- **FR-008**: 本片页面 MUST NOT 依赖任何服务端数据才能呈现；服务端不可达时，骨架与占位完整呈现，不出现错误态或重试入口
- **FR-009**: 交易账户页及其入口 MUST 与期权台其余页面同受 markets 功能开关门控 —— 开关关闭时入口不出现，直达链接被拦下
- **FR-010**: 经直达链接（没有上一页）进入交易账户页时，返回 MUST 落到雷达

## Success Criteria

### Measurable Outcomes

- **SC-001**: 从雷达到达交易账户页任一「市场 × 分段」组合，所需点击次数 ≤ 3（入口 1 次 + 市场 1 次 + 分段 1 次）
- **SC-002**: 全部 6 种「市场 × 分段」组合下，占位说明 100% 表达「建设中」，出现「暂无 / 空仓 / 无数据」类字样的次数为 0
- **SC-003**: 服务端完全不可达时，进入页面并遍历全部 6 种组合的成功率为 100%，出现错误提示的次数为 0
- **SC-004**: 在交易账户页进行任意次数的市场切换后返回雷达，雷达市场选择被改变的次数为 0
- **SC-005**: 同一次使用中离开并重新进入交易账户页，恢复到离开前「市场 × 分段」组合的比例为 100%
- **SC-006**: 在最窄支持屏宽下，雷达题头每个入口均能被单独点中，误触相邻入口的次数为 0

## Assumptions

- **本片是「券商持仓」整组工作的第一片（布局骨架）。** 持仓数据的同步与展示由后续 feature 交付；订单、报表两个分段的真实内容不在该组范围，由维护者另起计划推进。
- **页面与入口名称定为「交易账户」**（见 Clarifications）。**mockup 评审定稿（2026-09-13）**：雷达题头入口为图标形式（钱包形）；二级分段为胶囊式分段控件（与一级市场页签形态明显区分）。题头入口增多后的排布方式在 plan 阶段确定。
- **「最窄支持屏宽」= 360**（RN 逻辑像素宽度，FR-001 / SC-006 的判定口径；与 plan 的窄视口验收同一数值）。
- **「同一次使用」= 应用进程存活期间**，与雷达市场页签（065）的记忆口径一致；网页版刷新视同重新打开。
- **不涉及账号维度。** 后续持仓等数据按账号隔离、别的账号看到空列表；本片不展示任何数据，故无账号相关行为。
- **雷达自身的市场页签行为（065）不变**；本片不改动锚管理页、温度计与雷达列表。
- **无服务端改动、无接口契约改动。**
