# Feature Specification: 实时窄召回两段式重建 — 窗即召回第一段

**Feature Branch**: `068-optionsdesk-two-stage-recall`
**Created**: 2026-08-30
**Status**: Tasks-ready（2026-08-30；clarify 3 问已裁决回写；analyze 5 发现已闭合——G1 US3-AS4 补臂 / G2 窗规模观测 / G3 over_cap 回归网 + 2 LOW 顺手）
**里程碑**: [ADR-0068](../../docs/adr/0068-realtime-narrow-recall-two-stage.md) 实施序列的 **P2 片**（server + mobile；P1 = 067 W 轴统一已 ship，P3 清链 + 行军 + 审计弹层在后）

## 背景

064 落地的实时读路径是「离线档 + 报价覆盖」：库内收盘快照当基线，vendor 实时值按矩形窗（`0.7–1.05 × spot`）尾部覆盖。ADR-0068 的设计对焦确认该范式与实时档的定位冲突：实时档的价值是**窄视野执行**（只看已定规则内的少量腿），而「离线 + 覆盖」承袭了离线档的宽视野形态，并携带四个结构缺口（窗绊线单向 / `window_over_cap` 余量仅 4.5% / 混合口径 / 未支持市场处置）。

ADR-0068 决策已定：实时档废弃覆盖范式，改为**两段式召回**——第一段（选码）按昨日 Δ 面查表（sticky moneyness）得 moneyness 包络 + pad，生成 K-梯形窗，规则先定合约码；第二段（判腿）用与离线档**同一个**召回判据入口吃实时值。窗从「呈现辅助」升格为「召回第一段」；064 立的「窗 MUST NOT 当 filter」教义在实时档撤销，存续范围收窄为 bootstrap 宽窗。离线档零改动——窗永不进离线档。

## Clarifications

### Session 2026-08-30

- Q: 实时开态下，全腿（all）视角的窗与外呼怎么定？ → A: 全腿回落收盘档——实时窄召回只服务建仓/收租两个意图视角；全腿视角不定带、不外呼，实时开态下仍返收盘全量并标明口径。
- Q: spot 降级第三级（实时补发失败，无法定窗）时，响应给用户什么？ → A: 与 `source_unavailable` 同构——零窗零外呼，整体回落收盘档全量并打显式降级标「实时不可用」；复用既有降级标机制，不新造空态形态。
- Q: mobile 呈现面（带内/带外标、降级标、窄候选集）走不走 mockup-first 的 Mockup 步？ → A: 跳过——既有选约表屏的语义扩展，无新屏/新布局/库选型，UI 规格直接进 plan 的 UI 段。
- Q: 退役 overlay 后，链报表（chain report）的实时开态怎么处置？（impl 期发现 spec 未钉，2026-08-30 裁决） → A: 与全腿视角同形态——零外呼回落收盘档全量、`priceKind` 标口径，直到 P3 按净链重建实时报表；overlay 机器彻底退役，四缺口不随链报表残留。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 盘中窄召回：规则先定码，再问实时价 (Priority: P1)

用户盘中打开一只锚的选约表（实时开态）。系统不再全链取回后用收盘基线拼实时值，而是先按已定规则（昨日 Δ 面预测 + 意图 DTE 段 + 收租 W 帽）圈出 K-梯形窗内的合约码，再对这批码取同批实时报价、用与收盘档同一把尺判腿。用户看到的是规则内的少量腿，带内腿有明确的带内标，同 K 其他到期日以带外横档保留供比价。

**Why this priority**: 这是范式重建的主体——实时档从「宽视野打折版」变成「窄视野执行版」，窗成本降一个量级，且四个结构缺口随范式一并消灭。P3 的清链与行军都跑在这个召回结果之上。

**Independent Test**: 取一只有昨日 Δ 面的锚，盘中实时请求：断言外呼的合约码集合 = K-梯形窗产物（意图段内任一到期日预测落带的 K × 段内全部到期日，收租视角再与 W 帽取交）；返回候选由实时值经既有腿级判据产出；带内/带外标按同批实时 Δ 判定。

**Acceptance Scenarios**:

1. **Given** 锚有昨日 Δ 面且实时开态，**When** 检索某意图视角，**Then** 第一段产出的 K 集合 = 「该 K 在意图 DTE 段内任一到期日预测落带」的 K；进窗 K 附带段内**全部**到期日的腿（含预测带外者），阶梯不断链
2. **Given** 收租视角，**When** 定窗，**Then** 窗上沿与成色上界同轴（K ≤ min(spot, W) × 1.03），复用既有单点，无第二处轴定义
3. **Given** 窗内腿的同批实时 Δ，**When** 呈现，**Then** 落带者打带内标，未落带者保留为带外横档供比价（不删除）
4. **Given** 新锚（无昨日 Δ 面），**When** 盘中首次实时检索，**Then** 走 bootstrap 宽窗一次矩形宽取；次日有 Δ 面后自动转两段式
5. **Given** 同一锚同一批码，**When** 第二段判腿，**Then** 走与收盘档同一召回判据入口，仅输入为实时值——两口径候选差异完全可由输入值差异解释

---

### User Story 2 - 降级与空态诚实：拿不到就说拿不到 (Priority: P2)

盘中窗基准价拿不到新鲜值、或 vendor 实时不可用、或市场不支持实时，用户看到的是显式的降级/空态说明，而不是错误、也不是拿陈旧值硬算出来的窗。

**Why this priority**: 窄召回把「窗定错」的后果从「呈现瑕疵」升级成「召回缺腿」——降级路径必须 fail-closed 且可解释，否则用户无法区分「规则内确实无腿」与「系统没取到」。

**Independent Test**: 分别构造三级降级与未支持市场入参，断言各态的响应形态、降级标与零外呼行为。

**Acceptance Scenarios**:

1. **Given** 盘中窗基准新鲜（≤90s），**When** 定窗，**Then** 直接以该基准定窗，不发起额外的基准补取
2. **Given** 基准陈旧，**When** 定窗，**Then** 实时补取一发；成功则以实时值定窗
3. **Given** 实时补取失败，**When** 定窗，**Then** 零外呼整体回落收盘档并打显式降级标「实时不可用」（与 `source_unavailable` 同构）；MUST NOT 拿昨收定窗，MUST NOT 呈现为错误
4. **Given** 未支持实时的市场，**When** 实时开态请求，**Then** 闸后定窗前 guard 生效：零外呼、整体回落收盘档并标 `source_unavailable`（沿用既有语义）
5. **Given** 窄召回执行成功但规则内无腿，**When** 呈现，**Then** 沿用既有「有链无候选」空态形态，附可解释原因，非错误态

---

### User Story 3 - 离线档与既有能力零回归 (Priority: P3)

收盘档（离线档）的全部行为——全量宽视野、三视角、检索条件覆盖、候选与呈现——与本次重建前逐字节一致；每视角独立时刻是设计而非缺陷。

**Why this priority**: 离线档的价值主张是宽视野防盲点，窗进离线等于拆掉「全腿视角」；重建的爆炸半径必须钉死在实时档读路径内。

**Independent Test**: 重建前后各跑一遍收盘档全量请求（含三视角与覆盖入参），逐值对比；实时关态/休市路径同样对比。

**Acceptance Scenarios**:

1. **Given** 实时关态或休市，**When** 检索，**Then** 收盘档响应与重建前逐值相同（窗未进离线）
2. **Given** 实时开态下的建仓与收租两个意图视角，**When** 各自检索，**Then** 两视角各有独立窗、独立外呼、独立 `quoteAsOf`；跨视角一致性只判业务日，MUST NOT 引入跨视角同刻约束
3. **Given** 实时开态下的全腿视角，**When** 检索，**Then** 回落收盘档全量（不定带、不外呼），呈现标明数据口径，与既有收盘档响应逐值相同
4. **Given** 用户对检索条件的覆盖（052 六维），**When** 实时开态检索，**Then** 覆盖能力与三态判定零改动（窗是召回第一段，不触碰条件层）

---

### Edge Cases

- 昨日 Δ 面**部分缺失**（某 K 或某到期日无 Δ 读数）→ 按 moneyness 包络就近处理，MUST NOT 因局部缺失整体失败、也 MUST NOT 静默缩窗漏 K（处置细则归 plan）
- 窗内某腿实时报价缺失（vendor 单腿缺数）→ 沿用既有缺失语义（ADR-0067 同族），缺失腿不进候选但可见于横档
- 意图 DTE 段跨视角重叠区（如 [30,49]）→ 同一 K 可同时进两个视角的窗，各视角独立判定互不影响
- bootstrap 宽窗当日多次请求 → 每次仍走宽窗（Δ 面要等收盘轮才有），MUST NOT 用盘中已取的实时批自造 Δ 面
- 窗产物超出外呼单批上限 → 按既有截断保险丝语义处置且可观测，MUST NOT 静默丢 K
- v_manual 盘中被修改 → 下一次检索起收租 W 帽随新 W 变化（复用 067「无缓存滞留」语义）

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 实时档召回 MUST 为两段式：第一段按规则产出合约码集合（K-梯形窗），第二段以同批实时值判腿；MUST NOT 再以收盘快照当基线做实时覆盖。
- **FR-002**: K-梯形窗判据 MUST 为「该 K 在意图 DTE 段内**任一**到期日、按昨日 Δ 面（sticky moneyness）+ pad 预测落带」；进窗 K MUST 取段内**全部**到期日，阶梯不断链。
- **FR-003**: 收租视角窗上沿 MUST 与成色上界同轴（K ≤ min(spot, W) × 1.03），复用既有单点派生；🚫 MUST NOT 出现第二处轴或第二份 W 计算。
- **FR-004**: 064 窗教义（窗 MUST NOT 当 filter / 0.7 × spot 下界 / 矩形包络）在实时档 MUST 撤销；bootstrap 宽窗（新锚无昨日 Δ 面）为矩形宽取的唯一存续场景。
- **FR-005**: 第二段判腿 MUST 与离线档共用同一召回判据入口——腿级成员判定恰好一处，实时路径仅换输入值；🚫 MUST NOT 为实时档另设成员判据分支。
- **FR-006**: 窗基准 spot MUST 按三级降级取：盘中基准新鲜（≤90s）→ 实时补一发 → 第三级零外呼整体回落收盘档 + 显式降级标「实时不可用」（与 `source_unavailable` 同构，复用既有降级标机制）；🚫 MUST NOT 新造 TTL 缓存，🚫 MUST NOT 拿昨收定窗。
- **FR-007**: 未支持市场 guard MUST 沿用既有语义：闸判开之后、定窗之前判市场支持，不支持 ⇒ 零外呼整体回落收盘档并标 `source_unavailable`。
- **FR-008**: 每**意图**视角（建仓 / 收租）MUST 独立定窗、独立外呼、独立报价时刻；跨视角一致性 MUST 只判业务日；🚫 MUST NOT 引入跨视角同刻硬约束。
- **FR-009**: 带内标 MUST 按同批实时 Δ 判定；进窗 K 段内预测带外的腿 MUST 保留为带外横档供比价（打标不删）。
- **FR-010**: 窄召回空态（规则内无腿）MUST 呈现为非错误形态并附可解释原因；降级（实时不可用 / 未支持市场）走降级标形态而非空态；🚫 MUST NOT 新增错误态。
- **FR-011**: 离线档（收盘档）读路径 MUST 零改动——实时关态、休市、未开实时的响应与重建前逐值相同；窗判据 MUST NOT 被离线档消费。
- **FR-012**: 客户端 MUST 消费重建后的实时档契约（窄候选集 + 带内/带外标 + 降级态），实时档与离线档两种呈现范式并存；离线档呈现零改动。
- **FR-013**: 每意图视角每请求批量报价外呼 MUST 恒为 1 次，另 spot 基准陈旧时至多 1 次补发外呼；全腿视角恒为 0；窗产物规模 MUST 可观测。
- **FR-014**: 实时开态下全腿视角与链报表 MUST 回落收盘档全量（不定带、不外呼）——宽视野职责归离线档（链报表的实时形态归 P3 净链重建）；呈现 MUST 标明数据为收盘口径；🚫 MUST NOT 为全腿视角新造 Δ 带参数。

### Key Entities

- **Δ 面（昨日）**: 每 K × 每到期日的收盘 Δ 读数集合，sticky moneyness 查表的数据源；随每日收盘轮更新。
- **K-梯形窗**: 第一段选码产物——按意图 DTE 段逐到期日预测落带的 K 集合（∩ 收租 W 帽），附段内全部到期日；随意图视角独立（全腿视角无窗）。
- **带内标 / 带外横档**: 腿级呈现语义——同批实时 Δ 落带者为带内（执行目标），带外者保留供比价。
- **窗基准 spot**: 定窗所用的标的现价，三级降级取值；与 067 的 axis 输入同源。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 窗成本降一个量级：全量锚回放实测 K-梯形窗外呼码数 max ≤ 180（矩形范式实测 max 381），分布留档。
- **SC-002**: 回放对照零漏腿：双日回放中，K-梯形窗（含 pad）漏掉的「本应进候选」的腿 = 0；pad 取值以此为标定判据。
- **SC-003**: 离线档零回归：收盘档全量请求（三视角 × 覆盖入参）重建前后逐值不变的机器判据通过。
- **SC-004**: 判据单点可数：腿级成员判定恰好一处（离线/实时共用）；K 级窗判据恰好一处；收租 W 帽与 067 axis 同单点（`rg` 可数）。
- **SC-005**: 降级链路可判别：三级降级 + 未支持市场 + 规则内无腿各态在响应中可区分、错误率零新增。
- **SC-006**: 外呼预算保持：每意图视角每请求批量报价外呼恒 1 次（+ 基准陈旧时至多 1 次 spot 补发）、全腿视角 0 次；实时开态请求 p95 不劣于 064 现状。

## Assumptions

- **P2/P3 边界**：本片交付两段式召回 + 降级/空态 + 带内外标呈现；凸包清链、φ+形状行军、审计弹层、「整梯无可成交」态归 P3。「无法确认」财报三态亦归 P3（依赖清链后的 fwd 段落点）。
- **空态显式化范围**：067 defer 的「规则内无腿」显式化在本片只落**实时档**；离线档空态文案零改动（宽视野下该态罕见，P4 再议）。
- **Δ 带界与 pad 是可标定的意图级参数**：带的 Δ 下限即「再深就没权利金」的判据；标定值随 plan/tasks 定，spec 不载数。
- **昨日 Δ 面数据已在库**：每日收盘轮已落每腿 Δ，无需新增采集面；新锚首日无 Δ 面是结构性事实（bootstrap 兜底）。
- **契约为非破坏演进**：mobile 消费与 server 变更同 PR 原子合入（仓纪律），不存在跨版本兼容窗口。
- **未支持市场清单沿用现状**（当前实时仅 us）；港股实时接线是 ADR-0068 sunset trigger，不在本片。
- **无 Mockup 步**（2026-08-30 clarify 裁决）：mobile 面为既有选约表屏语义扩展，UI 规格由 plan 的 UI 段承载。
