# Feature Specification: 采集轮次内存足迹治本 —— 异常监控改增量累加器 + 链发现与快照错开峰值

**Feature Branch**: `075-marketdata-sync-memory-footprint`
**Created**: 2026-09-05
**Status**: Draft
**来源**：2026-09-05 生产内存耗尽夯机 5h08m 的复盘，层 2「治本」两项（复盘全文 local-only：`docs/private/plans/2026-09/09-05-prod-memory-hang-postmortem.md`）。层 1 四道防护已随 `server-v0.46.0` 上线，本片建立在其之上。

**病根一句话**：期权快照采集把**整轮 9.7 万行**的异常监控输入攒在一个数组里等到最后才判，这个中间数组实测常驻 **74.8 MB**；而事故当晚整机的缺口只有 **51 MB** —— 也就是说，光这一个数组就够把机器推过临界；紧邻它的链发现维度在同一拍先跑完、内存尚未回落，则把基线又抬高了一截。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 采集一轮的内存占用不再随行数增长 (Priority: P1)

运维者每天凌晨跑一轮美股期权快照采集。今天这一轮的写入量以约 +10%/周 的速度爬升（事故前一周的实测区间 88658 → 97648 行，中间连续两天进入部分成功态），而异常监控为了「看到全域」把整轮的判定输入攒成一个数组，占用随行数**线性**增长。结果是：同一段代码在数据量爬到某一天时会把机器吃夯，而在此之前它一直是绿的。

**Why this priority**: 单这一条的收益（74.8 MB）就大于事故当晚的缺口（51 MB）。其余各条都是纵深，它是治本。

**Independent Test**: 只做这一条（不动调度错开）即可独立验收 —— 对同一份真实规模的输入，改动前后的异常监控结论逐字段相同；再把行数放大一个数量级，判定侧的常驻规模不随之增长。

**Acceptance Scenarios**:

1. **Given** 一轮采集落库约 9.7 万行，**When** 异常监控跑完，**Then** 产出的全部 finding（编码 / 影响条数 / 样本 / 理由文本）、新非标 root 列表、全部指标与改动前对同一输入的结论**逐字段相同**
2. **Given** 同一形态的输入把行数放大 10 倍，**When** 判定跑完，**Then** 判定侧的常驻状态规模不随之增长（样本集有固定上界、root 集基数与行数无关）
3. **Given** 一批行已喂入判定并被调用方释放，**When** 该轮尚未结束，**Then** 这批行不再被判定侧引用（可被回收），不因判定而被钉住到轮末
4. **Given** 全轮零可用 greeks，**When** 判定跑完，**Then** 仍只出**一条**批级降级结论，而不是逐腿 N 条

>
> 降级理由两条，都不是「实现太麻烦」：
>
> 1. **BullMQ 里「错开」与「失败传播」拆不开**（源码 + 官方文档 + 真机实测三重证据，逐条落在 [`plan.md`](./plan.md) §B）。已按本 US 落地过一版实现（`178ce17d`），它会让美股 hard 边的失败**晚 30 分钟**才报 —— 直接违反本片自己的 FR-016 / SC-005 / `state_branches` 12。⇒ 已整块回退（`18fc750e`）。
> 2. **本 US 的前提观测已经过期**：下文那个「上游一完成、下游立刻起跑，此时上游那一轮的内存尚未回落」，唯一支撑是事故当晚的 345 MB 基线 —— 而那次观测既在**层 1 四道防护上线之前**，也在 **US1 之前**。完整论证见 Assumptions「US2 的前提观测为何已过期」。

链发现与快照两个重活由依赖链保证「先后」，今天它们**紧邻执行**：上游一完成，下游立刻起跑，此时上游那一轮的内存尚未回落。事故当晚下游起跑时的可用内存基线只有 345 MB（稳态是 688 MB），随后 294 MB 的增长把它推过零点。

**Why this priority**: 它不改变任何采集结果，只改起跑时刻；且 US1 落地后缺口已被覆盖，本条是纵深。P2 而非 P1，也因为它的取值目前用的是有先例的兜底值，实测校准要等 09-08 的曲线（见 Assumptions）。

**Independent Test**: 让上游正常完成，观测下游起跑时刻减去上游完成时刻是否 ≥ 配置的错开间隔；再让上游失败，观测失败传播的时延**没有**因错开而增加。

**Acceptance Scenarios**:

1. **Given** 上游链发现正常完成，**When** 下游快照被唤醒，**Then** 其起跑时刻 ≥ 上游完成时刻 + 错开间隔
2. **Given** 上游链发现失败且两者间是 hard 依赖，**When** 失败传播，**Then** 下游立即按失败处理，其时延与未加错开时同量级
3. **Given** 上游本轮未参与调度（被禁用 / 暂停 / 未 due），**When** 下游作为链根执行，**Then** 它不因错开而空等
4. **Given** 错开已生效，**When** 该轮跑完，**Then** 落库行的采集业务日、口径日与全部告警口径与错开前**逐项相同**

### Edge Cases

- **全轮零落库行**：不做任何判定、不产生任何结论 —— 空批算得出的只有空洞结论（现行早退语义，本片保持）。
- **某标的整票失败 / 限频顺延**：已喂入判定的行仍计入本轮结论，未采到的标的不计。判定面恒等于「本轮落库行」，与改动前同构。
- **同一个新非标 root 出现在多批 / 多个标的**：跨批去重，整轮只报一次；输出次序为字典序。
- **命中条数远超样本上限**：样本截到上限且次序与输入序一致，影响条数仍为全量 —— 「样本有上界」正是常驻 O(1) 的前提之一。
- **错开间隔取得过大**：可能把下游推出当日归属窗、或与同市场的后续采集轮次次序颠倒。⇒ 由 FR-018 的上界判据在装配期拒掉，而不是等到采成另一天才发现。
- **错开间隔取得过小**：上游内存尚未回落到位，纵深失效但不产生错误数据。这是可接受的残余风险，取值来源见 Assumptions 第 1 条。
- **有人试图用「改触发时刻」来实现错开**：🚨 两者的依赖边在两端落到不同拍时**不报错但静默失效**（失败传播绕过，下游拿旧合约集采快照且不报）—— 这条路径由 FR-015 显式排除。
- **上游完成但下游所在队列此刻正忙**：错开定义的是「不早于」，不是「精确等于」；下游实际起跑时刻只要求 ≥ 下界。
- **判定的「全域」判据在增量形态下退化**：本片最大的行为风险 —— 逐批求值会让休市时段的一次采集从 1 条 WARN 变成 N 条假 WARN。由 FR-005 与 FR-004a 的差分验收正面钉住整轮域。

## Requirements _(mandatory)_

### Functional Requirements

#### 异常监控：从「攒齐再判」改为「边喂边判」

- **FR-001**: 异常监控 MUST 支持**增量喂入**：调用方每处理完一批行即可交出该批，不要求先攒齐整轮再判。
- **FR-002**: 判定侧在整轮内的常驻状态规模 MUST NOT 随已喂入行数增长。
- **FR-003**: 一批行喂完之后，判定侧 MUST NOT 继续引用该批行或其任何字段对象 —— 调用方释放后即可回收。
- **FR-004**: 对同一输入序列，增量形态产出的结论 MUST 与既有一次性形态**逐字段相同**（finding 的编码 / 影响条数 / 样本序列 / 理由文本、新非标 root 列表、全部指标）。
- **FR-004a**: 等价性的验收基准 MUST 不随本次改动一起被重写；且切批本身要有一条**差分**验收：同一输入「一次喂完」与「切成 N 批喂」结论逐字段相同（N ≥ 2，至少覆盖一次跨批才成立的判据，见 FR-005）。
- **FR-005**: 🚨 「整轮零可用 greeks ⇒ 全域降级单条」这一判据 MUST 仍以**整轮**为求值域 —— 退化为逐批求值即为回归。
- **FR-006**: 实值区的 greeks 缺失不计入任何指标、不产生任何告警（数学固有现象）。
- **FR-007**: 判不出实值 / 虚值的行（缺标的现价、或非标合约）仍计入显式的「不可算」态，不并入另两个数。
- **FR-008**: IV 超阈但因短期限豁免的行数仍单独留数。
- **FR-009**: 新出现的非标 root 跨批去重，输出为字典序。
- **FR-010**: 全轮零落库行时不产生任何结论。
- **FR-011**: 每条结论的样本条数有固定上界，样本次序与输入序一致；影响条数仍为全量计数。
- **FR-012**: 判定所需的到期期限基准交易所仍在整轮层面确定并对全轮一致，无法确定时抛错而非静默取宿主时区。
- **FR-013**: 本片 MUST NOT 改动异常监控的任何判据语义、阈值或告警文案 —— 只改它拿到行的形态。上面 FR-006…FR-012 是这条总约束在增量形态下的逐条落点（全部保持现状、不引入新语义），规范性由本条承载，故各自写成陈述句。

#### 调度：链发现与快照错开峰值 🚫 DEFERRED（2026-09-05）

> 🚫 **本组（FR-014…FR-020）随 US2 / US3 降级，本片不验收**。FR-015 是唯一一条**反向**要求（「MUST NOT 用改触发时刻来实现」），它今天仍然成立、也不需要改 —— 将来重开时若照 Assumptions「重开时的形状约束」把「等待」做成**一个节点**，边仍是普通 hard 边，与 FR-015 的立场一致。

- **FR-014**〔本片不验收〕: 下游快照维度 MUST 在其上游链发现**完成之后**再等待一个错开间隔才起跑。
- **FR-015**〔本片不验收；立场仍成立，见上〕: 错开 MUST NOT 通过改动两者的触发时刻实现 —— 两端落到不同拍会让它们之间的失败传播静默失效。
- **FR-016**〔本片不验收〕: 🚨 上游失败时，失败传播 MUST 立即发生，不被错开间隔延后。⚠️ **`178ce17d` 那版实现违反了本条**（实测延后 1511 ms / 一个完整错开间隔，等比放大到生产取值即 30 分钟），这正是 US2 被摘掉的直接原因之一。
- **FR-017**〔本片不验收〕: 上游本轮未参与调度时，下游 MUST NOT 因错开而空等。
- **FR-018**〔本片不验收〕: 🚨 错开间隔 MUST 有显式上界判据，违反时在**装配期**拒绝而非运行期静默偏移。上界至少保证：① 下游起跑仍落在当日采集归属窗内；② 与同市场后续采集轮次的先后次序不变。

#### 可验收 / 可观测

- **FR-021**: 「判定侧常驻不随行数增长」MUST 有两层验收：① 一条每次回归都跑的确定性判据（不读内存数字，只判结构 —— 喂完的行不再被引用、样本集有固定上界、root 集基数与行数无关）；② 一次针对**新实现**的实测内存读数，用以钉住 SC-003。只有 ① 则 SC-003 没有属于本实现的数，只有 ② 则日常回归零覆盖。

### Key Entities

- **异常监控累加器**：一轮采集期间存活的判定状态。持有计数器、有上界的样本序列、非标 root 集合；**不持有**任何已喂入的行。
- **采集轮次**：一个采集维度的一次执行。它是异常监控「全域」判据的求值域，也是内存足迹的度量单位。
- **依赖边**：链发现 → 快照的 hard 依赖。它承载的是**失败传播与执行序**两件事；错开只加「不早于」的下界，不改动这两件事。
