# Feature Specification: 交易日历前瞻视野与三态语义收口

**Feature Branch**: `062-trading-calendar-horizon`
**Created**: 2026-08-18
**Status**: Implementing
**Input**: 交易日历表只向后填充（每日 21:00 北京填 `[今天-30, 今天]`，前瞻 0 天），而读侧把「无记录」读成「不是交易日」。于是「今天那一行」落库之前，所有问「今天是不是交易日」的消费方都拿到静默的错误答案 —— 已导致盘中预警全天不求值、期权快照二级兜底从不执行、建锚补数在美东凌晨标错来源与 OI 归属日。要一劳永逸地解决：让日历有前瞻视野、让「还没到」与「不是交易日」在语义上分开、并让下一个消费方不可能再踩。

## Clarifications

### Session 2026-08-18（起片时，已在对话内拍板）

- Q: 日历主源顺序是否反转成「离线年历为主、活源校验」？ → A: 否，采用**混合** —— 历史段维持现有活源链不动，**前瞻段只走权威年历**；两条路径互为交叉校验，改动最小且错误可被发现
- Q: 「已覆盖到哪天」用现有数据的最大日期派生，还是独立声明？ → A: **独立声明**。从最大日期派生本身就是又一次「库里没有的即为假」推断（中间空洞看不出来），而这正是本 feature 要根治的病
- Q: 判定为「未知」时是否一律放行？ → A: 否，**按调用点语义分派**（见 `state_branches` 第 5–8 条）。一刀切放行会让真节假日白烧配额，一刀切拦截就是今天的静默停摆
- Q: 美股是否补一份离线年历作第三层兜底？ → A: **不补**，沿用 2026-07-31 的拍板（新增假日采集 = 新的漂移面；离线表反映不了临时休市与半日市；美股两个活源本就走不同物理通路）。代价由本 feature 的视野探针接住

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 交易日的盘中预警真的在求值 (Priority: P1)

用户设了盘中价格预警。在 A 股交易日的连续竞价时段内，系统每隔几分钟就该真的算一次、该触发就触发。今天它每一拍都判「今天是节假日」直接返回，用户设的盘中预警从未被求值过，而界面上没有任何异常。

**Why this priority**: 这是一个**已在生产发生**的静默功能失效 —— 用户以为预警在跑。它也是本 feature 最容易被证伪的验收面。

**Independent Test**: 造一个「日历只填到昨天」的库，把时钟停在交易时段内，跑一次盘中拍 —— 断言求值真的发生（当前代码此处必红）。

**Acceptance Scenarios**:

1. **Given** 今天是交易日且日历已覆盖到今天，**When** 交易时段内的一拍到来，**Then** 系统执行求值
2. **Given** 今天是交易日但日历只填到昨天（视野未覆盖今天），**When** 交易时段内的一拍到来，**Then** 系统**仍执行求值**并留下「判定未知、按开市处理」的痕迹
3. **Given** 今天是法定休市日且已在覆盖区间内被确认为非交易日，**When** 交易时段的时钟到来，**Then** 系统跳过求值且零外呼
4. **Given** 时钟落在午休或盘前盘后，**When** 一拍到来，**Then** 系统按时段跳过（与日历判定无关）

---

### User Story 2 - 期权快照的二级盘前兜底不再静默失踪 (Priority: P1)

夜间采集漏掉的期权快照有两级补救：当日重试 + 次日盘前兜底。二级兜底判「今天是不是美股交易日」的那一刻（北京 18:00 = 美东清晨），今天的记录还没进表，于是它每天都静默判定「无事可做」并返回。「两级补救」实际只有一级，而期权收盘数据**无跨日补救**，二级放弃掉的就是永久缺口。

**Why this priority**: 与 US1 同为生产静默失效，且它守的是不可再生的数据。

**Independent Test**: 造「日历只填到昨天」的库 + 停在盘前时刻，制造一个有缺口的交易日 —— 断言二级兜底真的执行了复判与补采。

**Acceptance Scenarios**:

1. **Given** 上一交易日的快照有缺口且日历视野已覆盖今天，**When** 盘前兜底时刻到来，**Then** 系统补采该缺口并把落库记录标为盘前兜底来源
2. **Given** 视野未覆盖今天（判定未知），**When** 盘前兜底时刻到来，**Then** 系统**仍执行**起手复判；复判显示不缺则零外呼返回
3. **Given** 一级重试已补回缺口，**When** 二级时刻到来，**Then** 零外呼且不留降级痕
4. **Given** 今天已确认是美股休市日，**When** 盘前兜底时刻到来，**Then** 跳过（无盘前窗口，下一个交易日仍能补回同一场）

---

### User Story 3 - 任意时刻建锚，来源与 OI 归属日都标得对 (Priority: P2)

用户在一天中的任意时刻新建一个锚，系统会补上最近一场收盘的数据。在美东凌晨到开盘前那段（北京白天，正是用户最可能建锚的时段），系统会把这批数据标成常规收盘来源、并把持仓量归到早一天 —— 归属交易日本身是对的，但来源标记与持仓量归属日错了，而这两个字段下游有真消费方。

**Why this priority**: 数据被标错但不报错，且错的是难以事后订正的溯源信息；发生频率高（用户活跃时段）但单次影响面小于 US1/US2。

**Independent Test**: 停在美东凌晨的时钟 + 视野充足的日历，跑一次建锚补数 —— 断言来源为盘前补采、持仓量归属日等于被补的那一场。

**Acceptance Scenarios**:

1. **Given** 视野已覆盖今天且今天是交易日、时刻在美东开盘前，**When** 新建锚触发补数，**Then** 来源标为盘前补采、持仓量归属日 = 被补的那一场
2. **Given** 同上但时刻在美东收盘之后，**When** 触发补数，**Then** 来源标为常规收盘、持仓量归属日 = 被补那场的上一交易日
3. **Given** 今天是周末或休市日（已确认），**When** 触发补数，**Then** 按常规收盘口径处理（持仓量不会翻新）
4. **Given** 日历视野未覆盖今天（判定未知），**When** 触发补数，**Then** 系统**放弃本次**并落既有的「日历缺行」结局，不猜口径、不写库

### User Story 4 - 日历视野停下来的时候，有人在几小时内知道 (Priority: P2)

日历前瞻填充某天开始失败（源被下线 / 隧道断 / 年历漏更），视野停止前进。今天这种情况没有任何信号 —— 现有探针只看「填充有没有心跳」，看不到「视野有没有往前走」。

**Why this priority**: 这是「一劳永逸」的支点：本 feature 的其余部分都可能再次失效，**唯有失效可见**能保证不会重演今天这种「几个月后靠翻数据才发现」。

**Independent Test**: 埋一份终点距今过近的覆盖声明，跑探针 —— 断言告警；再埋一份年末场景（终点已抵当年末），断言不告警。

**Acceptance Scenarios**:

1. **Given** 某市场覆盖声明终点距今不足阈值且未到当年末，**When** 探针运行，**Then** 告警并指明是哪个市场、停在哪天
2. **Given** 所有市场覆盖声明终点均满足阈值，**When** 探针运行，**Then** 静默通过
3. **Given** 时值年末、覆盖终点已抵当年 12-31（次年年历尚未发布），**When** 探针运行，**Then** **不**告警
4. **Given** 覆盖声明整体缺失，**When** 探针运行，**Then** 告警（比「视野过近」更严重的一档）

---

### User Story 5 - 下一个消费方不可能再把「还没到」读成「不是交易日」 (Priority: P3)

未来任何人（含 AI agent）新写一处「今天是不是交易日」的判断时，不应该有机会重新发明今天这个错误。

**Why this priority**: 防复发。不做也不影响本次三个缺陷的修复，但少了它，同样的坑三个月后会以第五处消费方的形式回来。

**Independent Test**: 写一个绕过共享判定、直接裸查日历表的样例文件，跑门禁 —— 断言被拒；再让一个合规文件通过 —— 断言放行。

**Acceptance Scenarios**:

1. **Given** 一个新文件绕过共享判定直接裸查日历表，**When** 本地钩子或 CI 运行，**Then** 拒绝并指明该走的判定入口
2. **Given** 一个新文件走共享判定，**When** 门禁运行，**Then** 放行
3. **Given** 日历表的属主模块自身读表，**When** 门禁运行，**Then** 放行（属主不受此约束）

### Edge Cases

- **年末跨年**：次年年历尚未发布时，视野只能停在当年 12-31，跨年后头几天全部落入「未知」—— 系统 MUST 按各调用点的未知分派继续工作，探针 MUST NOT 在年末收缩期假红
- **前瞻源返回残缺区间**：源少返了一段却不报错 —— MUST 由「区间未被完全覆盖即失败」的判据拦住，且 MUST NOT 推进覆盖声明（宁可视野不动，不可声明失真）
- **声明存在但区间内有空洞**：人为清表或部分导入造成 —— 声明是承诺，MUST 只在整段成功后推进；空洞属于需要人工介入的破坏态
- **首次上线**：覆盖声明为空 → 全部判定为「未知」→ 各调用点按未知分派工作（不停摆），探针立即告警提示灌视野
- **市场未登记前瞻源路由**：MUST 显式失败留痕，MUST NOT 静默落到某条现成链上
- **交易所临时休市（国丧等）**：年历发布后才出现的变更 —— 本 feature 不解决，但 MUST NOT 因前瞻记录已存在而阻止历史段活源在事后修正该日
- **半日市**：不影响「是不是交易日」的判定（半日市即交易日），其时段语义不在本 feature 范围
- **时区**：「今天」MUST 按各市场交易所所在时区求，MUST NOT 用宿主时区（美股会整体错一天）

## Requirements _(mandatory)_

### Functional Requirements

**覆盖声明（视野是承诺，不是推断）**

- **FR-001**: 系统 MUST 为每个市场维护一条**显式的交易日历覆盖声明**（起点、终点、本次由哪个来源服务、更新时刻）
- **FR-002**: 覆盖声明 MUST 只在某段填充**整段成功**后才推进终点；部分成功、源返回区间未被完全覆盖、或写入中途失败 MUST NOT 推进
- **FR-003**: 系统 MUST NOT 用日历记录的最大日期充当覆盖终点 —— 该推断无法区分「区间内确无交易日」与「这段根本没填」
- **FR-004**: 覆盖声明的更新 MUST 与填充在同一次运行内完成，MUST NOT 由独立的补写路径维护（两处维护必漂移）

**前瞻填充**

- **FR-005**: 系统 MUST 每日把交易日历向前填充到**当年年末**（自然收缩：年内终点恒为当年 12-31，次年年历发布并入库后自然延展）
- **FR-006**: 前瞻段 MUST 只采用**权威日历来源**（交易所/券商发布的年历）；MUST NOT 采用「某指数当日有行情 ⟺ 当日开市」这类由行情反推的来源 —— 该类来源在结构上无法回答未来与当天
- **FR-007**: 前瞻填充失败 MUST NOT 影响历史段填充的结果，反之亦然；两段 MUST 各自留下可告警的痕迹
- **FR-008**: 前瞻填充 MUST 逐市场隔离 —— 一个市场失败 MUST NOT 阻断其余市场
- **FR-009**: 系统 MUST 在前瞻记录与历史段活源对同一日给出**相反答案**时留下可查痕迹（两条路径互为交叉校验）

**三态判定与分派**

- **FR-010**: 交易日判定 MUST 返回三种互斥结果：**是交易日 / 不是交易日 / 未知**。MUST NOT 用布尔表达 —— 布尔必然把「未知」折进「不是」
- **FR-011**: 「未知」的判据 MUST 是「该日落在已声明覆盖区间之外（含无声明）」，MUST NOT 用「附近若干天有没有记录」之类的启发式
- **FR-012**: 每一处消费方 MUST 显式声明它对「未知」的处置，且该处置 MUST 与该处的失败代价相称：盘中采集闸 → 继续执行并留痕；缺口补救的盘前兜底 → 继续执行；建锚补数的写入决策 → 放弃并落既有「日历缺行」结局；陈旧度折龄 → 按开市折算；陈旧度基准（最近一场已收盘交易日）→ 视为不可判定并回退当期档
- **FR-013**: 任何一处判定为「未知」而继续执行时 MUST 留痕，使「今天跑是因为确认是交易日」与「今天跑是因为不知道」在事后可分辨
- **FR-014**: 交易日闸 MUST NOT 被其他闸（行情源的市场状态等）顶替；多闸并存时 MUST 取交集
- **FR-015**: 判定所用的「今天」MUST 按该市场交易所时区求

**可观测与防复发**

- **FR-016**: 系统 MUST 对覆盖终点距今的余量告警：余量不足阈值且尚未抵达当年末 → 告警；已抵当年末（年末收缩期）→ 不告警；声明整体缺失 → 更高一档告警
- **FR-017**: 上述判据 MUST 与既有的填充心跳告警**并存且分工明确** —— 心跳答「填充还活着吗」，视野答「视野还在往前走吗」，二者 MUST NOT 互相替代
- **FR-018**: 系统 MUST 以机器门禁禁止日历表属主模块之外的任何代码绕过共享三态判定直接查日历表；门禁 MUST 同时验证正反两例（合规放行 / 绕过被拒）
- **FR-019**: 本 feature MUST 保留既有的跨模块只读访问纪律（跨上下文读日历表仍是只读直查 + 显式注释 + 护城河探针可见），MUST NOT 通过注入属主模块的服务来绕开边界

### Key Entities

- **交易日历覆盖声明（calendar coverage）**：某市场的日历「已完备覆盖到哪一段」的显式承诺 —— 市场、覆盖起点、覆盖终点、本次由哪个来源服务、更新时刻。它是判定「未知」的唯一依据
- **交易日记录（trading day）**：既有概念，某市场某日开市的事实记录。本 feature 不改其语义，只改「无记录」的解读方式

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 部署后任一 A 股交易日的连续竞价时段内，盘中预警的求值执行率为 **100%**（当前为 **0%**：2026-08-18 生产实测在时段内的 43 拍全部判为休市）
- **SC-002**: 部署后任一时刻查询三个市场「今天是不是交易日」，得到确定答案（非「未知」）的比例为 **100%**，年末次年年历未发布的窗口除外
- **SC-003**: 交易日历的前瞻视野在年内任一天 MUST ≥ **今日 + 5 个交易日**，年末收缩期以「已抵当年 12-31」为达标
- **SC-004**: 期权快照的二级盘前兜底，在存在缺口的交易日的执行率为 **100%**（当前为 0%）
- **SC-005**: 在 24 小时内的任意时刻新建锚，其补数的来源标记与持仓量归属日 **100%** 与常规轮/盘前兜底在同一时刻的口径一致
- **SC-006**: 视野停止推进后，告警在 **4 小时**内送达
- **SC-007**: 试图绕过共享判定直接查日历表的改动，在本地提交或 CI 阶段被拒的比例为 **100%**，且合规改动的误拒为 **0**
- **SC-008**: 年末场景（视野已抵当年末）下视野探针的假告警数为 **0**
- **SC-009**: 本 feature 不新增任何行情/日历供应商，前瞻填充带来的额外外部调用 ≤ **每市场每日 1 次**

## Assumptions

- 前瞻段的权威年历数据**已在仓内或已可取**：A 股/港股的离线年历已覆盖本年度全年，美股的券商官方日历视野可达当年年末 —— 本 feature 不新增采集面
- 离线年历的**年度更新按既有机制执行**（已有月度催更提醒器）；本 feature 只保证「没更新时失败响亮」，不承担年更本身
- 次年安排的发布节奏（内地节假日安排约每年 11 月发布、交易所对应休市公告约 12 月下旬发布）决定了年末视野必然收缩，这是外部约束而非缺陷
- 美股不引入离线年历第三层兜底（沿用 2026-07-31 拍板），其双源同时失效的场景由视野告警 + 人工介入承接
- 半日市语义、临时休市的事后修正不在本 feature 范围
- 生产部署后需要**一次性灌入前瞻视野**（首次运行前视野为空，此时全部判定为「未知」，各调用点按未知分派工作，不停摆）
