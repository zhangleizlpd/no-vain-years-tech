# Feature Specification: 港股财报日期多源采集与确认层（片 1/2：数据层）

**Feature Branch**: `079-hk-earnings-date-sources`
**Created**: 2026-09-13
**Status**: Draft
**Input**: User description: "港股财报日期多源采集与确认层（数据层片，片1/2）。目标：为期权台收租腿「跨财报提醒」准备港股财报日期数据；本片只做 marketdata 数据层，港股打标仍保持「无日期」（两态打标=片2）。约束与已拍板决策：①「财报日期来源」按市场通用抽象，每个来源一个可插拔 adapter，可灵活增删、替换为新数据源；②首批两个来源：富途财报日历 + 理杏仁港股公告（董事会会议通知=确认信号与刊发日，正文解析会议/公布日期；业绩公告=历史业绩公布日）；③每日采集一次；④多源合并：任一来源先确认即生效，确认时刻取各来源中最早的公告刊发日，首次观测仍 PIT 留痕；⑤交叉验证：来源间日期不一致时两个日期都保留为可能事件、标记来源冲突并告警；⑥美股：抽象市场无关，但美股现役采集与打标行为逐字节不变；⑦附带落历史业绩公布日（供片2推算预计区间）。"

**病根一句话**：港股收租腿今天看不到任何跨财报提醒——库里没有港股财报日期。而唯一在用的结构化来源（富途财报日历）对港股只给**已公告**的日期、不给确认状态、历史有缺洞，且在「周五开会、周日刊发」这类公司上记的是会议日而非公布日；单靠它既覆盖不全，也答不了「这个日期是谁、在什么时候、以什么口径确认的」。

## Clarifications

### Session 2026-09-13（一）— 立项前裁决（owner 拍板）

- Q: 终局形态？ → A: **两态日期**（已确认 + 按历史推算的预计区间，区间与持仓期相交即提醒）。本片只交付「已确认」这一态所需的数据层与历史底座；预计区间与打标归片 2。
- Q: 切片？ → A: **两片**。片 1（本片）= marketdata 多源日期层；片 2 = 期权台两态打标 + 契约 + 移动端。
- Q: 采集频率？ → A: **每日一次**。入库延迟对业务影响小，不等延迟实测再开工。
- Q: 多源怎么合？ → A: **任一来源先确认即生效**，确认时刻取最早；来源之间**交叉验证**。
- Q: 来源怎么接？ → A: 沿用仓内 adapter / port 模式，**每个来源一个可插拔实现**，可增删、可替换成新数据源。

### Session 2026-09-13（二）— specify 期裁决（owner 拍板）

- Q: 会议日与公布日以谁为准？ → A: **以业绩公布日为准**。上市规则 13.43 预告的是审批业绩的董事会会议，13.49 要求批准后于下一交易日开市前 30 分钟之前刊发，且只能在刊发窗口刊发（交易日 06:00–08:30 / 12:00–12:30 / 16:30–23:00；紧接交易日之前的非交易日 18:00–20:00）⇒ 市场能交易到信息的时点由公布决定，会议日只是近似。（→ FR-008）
- Q: 两个来源差 1 天算不算冲突？ → A: **不算**。进一步定：**不保留「较早 / 较晚」两个日期**，同一次财报只存**一个公布日**，并标注取值口径；口径优先级 = 刊发事实 > 正文明写 > 结构化日历 > 会议日推定。冲突只在精确口径之间、或近似口径相差 ≥ 2 天时成立。（→ FR-009 / FR-010 / FR-014）
- Q: 正文明写的公布日按哪个时区？ → A: **交易所当地时区**（港股 `Asia/Hong_Kong`、美股 `America/New_York`）；正文标注了时区按标注换算，未标注按交易所当地，刊发后以刊发日校验。（→ FR-008；首批来源不产出正文明写口径，本条留给后续来源）
- Q: 美股是否进入合并层？ → A: **进，只落数、不被读**；富途美股来源声明为「确认状态未知」，美股事件 MUST NOT 记为已确认。（→ FR-002 / FR-021）
- Q: 通知识别与正文解析覆盖范围？ → A: ~~**全部港股**~~ —— **已被 Session（四）改裁决取代，Session（五）进一步取消正文解析**。
- Q: 腾讯自选股数据要不要作为第三个来源？ → A: **不接入**（PoC 结论见取证段）。

**其他数据商（2026-09-13 调研，不接入的依据）**

- 境外：没有一家能以公开资料证实「港股覆盖 + 前瞻日期 + 确认状态字段」三项齐全。Wall Street Horizon（含 IBKR 集成）有已确认 / 未确认概念与董事会会议事件，但港股覆盖无公开证据、机构报价；EODHD / Finnhub / FMP / Alpha Vantage 无确认状态字段；Benzinga / Zacks 仅美股；长桥 OpenAPI 财报日历支持 `HK`，是否含未公告日期未核实。
- 境内：Tushare `disclosure_date`、AKShare `stock_yysj_em` 仅 A 股；Wind / Choice / iFinD 无公开港股字段文档；經濟通业绩日历与港交所清单抽样同源（推断）；阿斯达克日历有清单未列的行，但口径不明、只能抓网页；港交所 IIS 推送只给「董事會召開日期」公告分类码、无日期字段且付费。

**公告正文兼容性（方案 A 取证，已不采用；保留为否决依据）**

- 格式层足够规范（港交所要求可检索文本 PDF；全市场 247 份样本 42 种生成工具、解析异常 0）；难点在写法差异与同形异码字符。锚表港股两年：候选 425 份，识别会前通知 177 次全部正确，公布日逐日一致 174 次。代价是 PDF 解析依赖、受限线程、文档队列与内存闸门。

**腾讯自选股数据（不接入的依据）**

- 取数经第三方技能通道代理（内置应用 token），非面向第三方的正式接口。
- 「财报披露日」每只票只返回一条「最近一次」，无确认状态、无历史、不支持全市场：未公告的票回显上一次（`hk:00005` 08-04、`hk:03690` 08-28、`us:DIS` 08-05、`us:GOOGL` 07-22）；已公告的与官方一致（`hk:09961` 09-16、`us:GIS` 09-23、`us:PEP` 10-08）。
- 缺口与富途同形，且对官方未公告的 `us:ACN` 给出与富途相同的 10-01 ⇒ 与富途很可能同源（推断），交叉验证不具独立性。「投资日历」只含宏观指标，已知财报日（09-16 / 09-23 / 10-08）的事件类均为空。

**为什么港股打标会被本片意外打开**：期权台读财报日期只按标的过滤、不分市场（`apps/server/src/optionsdesk/get-legs.usecase.ts:733-739`）⇒ 任何港股行一旦进入它读的那张表，港股收租腿就会按美股的 182 天视野开始打标，而港股前向视野只有几周 —— 正是需要避免的静默错。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 港股锚的已公告财报日期可查，并知道是谁、何时、以什么口径确认的 (Priority: P1)

维护者（以及下游的片 2 打标）要知道每只港股标的**已经公告**的下一次业绩公布日：日期是多少、按什么口径取得、由哪些来源给出、最早是哪天公告的。今天库里一行港股财报日期都没有；即便接上结构化日历，也分不清一个日期是「公司公告的会议日推出来的」「数据商给的」还是「数据商自己排的」。

**Why this priority**: 这是片 2 两态打标里「已确认」那一态的唯一数据来源；没有它，片 2 无从开始。

**Independent Test**: 用一只刚刊发会前通知、且已进入清单的港股锚跑一轮合并，查询该标的：出现已确认事件、公布日与取值口径、来源列表、确认时刻等于通知刊发日。

**Acceptance Scenarios**:

1. **Given** 港股标的 X 刊发会前通知，清单列出其会议日 M，结构化日历给出 D，**When** 当日合并运行，**Then** X 出现一条已确认事件：公布日 = D，取值口径 = 结构化，确认时刻 = 通知刊发日，M 作为会议日留痕。
2. **Given** 清单只给出 X 的会议日 M，X 往年同类报告均在会议当天刊发，且结构化日历无该事件，**When** 合并运行，**Then** 公布日 = M，取值口径 = 会议日推定。
3. **Given** `hk:00857` 在清单上的中期业绩会议日为 2026-08-28（周五），其上一次同类报告的「会议 → 刊发」间隔已学到 2 天，**When** 合并运行，**Then** 公布日 = 2026-08-30，取值口径 = 会议日推定；结构化日历给出的 2026-08-28 作为差异留痕，不告警。
4. **Given** 结构化日历对 X 给出 D、X 无会前通知、清单也未列出，**When** 合并运行，**Then** 公布日 = D，取值口径 = 结构化，确认时刻 = 该来源首次观测到 D 的时刻，口径标为「首次观测」。

---

### User Story 2 - 来源之间真正对不上时看得见，口径差异不制造噪音 (Priority: P1)

两个来源给同一次财报的日期不一样。维护者需要区分两类：一类是「口径不同」（结构化日历记了会议日、刊发事实给出公布日），按口径取值即可，不必打扰人；另一类是「信息互相矛盾」（两处精确信息不同，或两个近似日期差得离谱且解释不了），必须当天知道，且日期都要留下。

**Why this priority**: 对卖方而言，错过一次真实的财报日是资金风险；而把口径差异也当冲突告警，会让真正的冲突被噪音淹没。两种错都不会报错。

**Independent Test**: 分别构造「刊发事实 vs 结构化日历差 2 天」与「两个精确口径日期不同」，跑一轮合并：前者取刊发事实、差异留痕、零告警；后者全部日期保留、冲突标记存在、产生告警。

**Acceptance Scenarios**:

1. **Given** X 已刊发业绩（刊发事实 08-20），刊发前结构化日历为 08-19，**When** 合并运行，**Then** 公布日 = 08-20（口径 = 刊发事实），08-19 作为差异留痕并计入偏差统计，本轮无冲突告警。
2. **Given** 两个精确口径对 X 同一报告期分别给出 11-12 与 11-13，**When** 合并运行，**Then** 两个日期都保留，事件标记「来源冲突」，本轮运行记录出现冲突告警。
3. **Given** X 在清单上的会议日为 11-14、历史间隔 0 天（会议日推定 11-14），结构化日历给出 11-11，**When** 合并运行，**Then** 相差 3 天且结构化日期不等于会议日，判为冲突并告警；若结构化日历给出 11-15（差 1 天），则按口径优先级取结构化值并留痕、不告警。
4. **Given** X 处于冲突状态，**When** 次日来源重新一致，**Then** 冲突解除，解除时刻与原日期留痕可查。

### User Story 3 - 业绩刊发后自动校准，推定越用越准 (Priority: P2)

公布日在刊发前多数是结构化或推定出来的；刊发后交易所的刊发日才是事实。维护者希望刊发后自动以事实覆盖，并看得到每个来源、每种口径过去准不准——会议日推定所依赖的「会议 → 刊发」间隔也应当来自这些已刊发的事实。

**Why this priority**: 它把「会议日推定」从一个固定假设变成可度量、可自我修正的规则，并为片 2 的预计区间提供准确度基线。

**Independent Test**: 回放一段有清单会议日与刊发事实的序列：对每次财报先按刊发前可得信息取公布日，再用刊发日覆盖，检查偏差统计与 `hk:00857` 的间隔被正确学到 +2 天。

**Acceptance Scenarios**:

1. **Given** X 的事件公布日为 11-13（口径 = 会议日推定），**When** 交易所于 11-13 刊发业绩公告并被采集，**Then** 公布日口径变为「刊发事实」，该口径的偏差统计记一次「0 天」。
2. **Given** 上线后清单列出 `hk:00857` 年度业绩会议日（周五），**When** 其业绩公告于周日刊发并被采集，**Then** 该公司年度报告的「会议 → 刊发」间隔学到 2 天；下一次年度报告的会议日推定按 +2 天取值。

---

### User Story 4 - 数据源可以加、可以拔、可以换 (Priority: P2)

维护者将来可能换一家更好的数据商，或某个来源停服。希望加一个新来源、停用一个旧来源时，不需要改合并、口径与交叉验证规则；停掉任一来源后，其余来源照常工作。

**Why this priority**: 用户明确要求的结构约束；它不产生当下可见的业务价值，但决定后续换源的成本。

**Independent Test**: 停用清单来源跑一轮：合并照常完成，只剩其余来源的确认；既有确认不丢失。再恢复：清单的数据重新参与合并。

**Acceptance Scenarios**:

1. **Given** 全部来源均启用，**When** 停用清单来源并运行合并，**Then** 本轮正常完成、无中断；此前由清单参与确认的事件不被删除。
2. **Given** 新增一个只提供「历史业绩公布日」的来源，**When** 运行合并，**Then** 其数据进入历史公布日，不影响已确认事件的判定逻辑。

---

### User Story 5 - 港股历史业绩公布日沉淀，供片 2 推算下一次 (Priority: P2)

片 2 要按「同一报告期往年在哪天公布」推算下一次的预计区间。维护者需要每只港股标的一份干净的历史业绩公布日：报告期、公布日（刊发事实）、来源。

**Why this priority**: 片 2 预计区间的输入；本片顺带落库成本低（两个来源都已提供历史）。

**Independent Test**: 查询锚表内全部港股锚，每只都能列出近两年的业绩公布日与报告期，`hk:00005` 的 2026-02-25 / 2026-05-05、`hk:00857` 的三个周日刊发日在列。

**Acceptance Scenarios**:

1. **Given** 两个来源对 `hk:00005` 的历史覆盖不同（A 缺两条），**When** 历史合并完成，**Then** `hk:00005` 的历史公布日包含 2026-02-25 与 2026-05-05，并标明来源。

### Edge Cases

- **会议日 ≠ 公布日**：`hk:00857` 年度 / 中期业绩周五开会、周日刊发；以美股为主上市的票（`09988` / `09961` / `09999`）在会议后 1–4 天公布，而清单只列会议日。由 FR-008 / FR-009 / FR-010 规定取值，结构化日期优先于会议日推定。
- **周末 / 假日刊发**：港交所在紧接交易日之前的非交易日开放 18:00–20:00 刊发窗口，公布日可以落在非交易日；公布日按日历日记录，不得挪到最近交易日。
- **清单只收主板**：创业板公司不会出现在清单上，其事件只来自结构化日历与刊发事实；标题识别到的创业板会前通知只计数、不告警（FR-017）。
- **清单漏收 / 页面滞后**：清单自述未必尽列，页面也可能晚约 1 个营业日。通知已刊发而清单未列时，结构化日历有日期照常确认；满 2 个交易日仍无任何日期且该标的曾出现在清单 → 「已通知、日期未知」并告警（FR-017）。
- **多日会议**：清单只列开始日，按开始日作为会议日（FR-006）。
- **同一公司同日多行**：停牌公司补批多个报告期 → 每期独立成事件；人民币柜台等不在标的主表内的代码 → 跳过计数。
- **纯股息行**：目的只含股息的行不作财报事件，计数（FR-006）。
- **长得像通知、其实不是**：「董事會會議決議公告」「董事名單與其角色和職能」「委任代理主席」都带「董事」字样。由 FR-005 按标题排除；误把会后决议当会前通知会产生一个错误的确认时刻。
- **通知、清单与业绩公告对不上报告期**：来源 A 写 `2026Q2`，清单写「截至30/06/26止6個月」，业绩公告写「截至二零二六年六月三十日止六個月」；阿里财年与自然季度错位（`2027Q1` = 2026 年 4–6 月）；清单期间是两位年份。由 FR-015 处理。
- **改期**：港交所规则下改期无需再提前 7 天通知，只须尽快公告；清单下一次更新时同一期出现新的会议日，或富途日期变化。旧日期保留为变更史（FR-016）。
- **清单行提前消失**：会议日前清单不再列出该期、也没有新日期（可能是取消或延期而未定新日期）。保留最后日期、不撤销确认，告警（FR-016）。
- **日期已过仍未刊发**：公司延期而清单与富途未更新，或公告漏采。事件不转历史，满 2 个交易日转「逾期未刊发」并告警（FR-019a）。
- **来源停服 / 单轮失败 / 页面改版 / 换地址**：按 FR-018 隔离；不能把「今天没取到」读成「日期被撤销」；清单页面结构变了、地址跳转或失效、页面停更，由 FR-025 判为来源失败并经飞书日报标红，不能读成「今天没有会议」。
- **无历史间隔的公司**：清单无历史存档，上线后每家公司每类报告的第一个周期无间隔，会议日推定按 0 天（`hk:00857` 首个年度 / 中期周期会偏 2 天，除非结构化日期先到）；刊发后由 FR-019 学到真实间隔。
- **公司不为某类报告发会前通知**：`hk:00941` 只为年度业绩发通知，一季度 / 三季度没有。该期事件只能来自结构化日历，没有就保持无事件直至刊发（FR-019）；不当作漏采告警。
- **非标的主表内的代码**（DRS / 临时柜台 `-T` / 人民币柜台等）：跳过计数，与现役财报采集同口径。
- **美股**：只有结构化日历一个来源，且其日期确认状态未知 ⇒ 美股事件在合并层永远不是「已确认」（FR-021）。

## Requirements _(mandatory)_

### Functional Requirements

**来源抽象**

- **FR-001**: 系统 MUST 以统一的「财报日期来源」接口接入各数据源。每个来源独立实现、独立启停；新增、移除或替换一个来源 MUST NOT 需要修改合并、取值口径与交叉验证规则。
- **FR-002**: 每个来源按市场声明能力：① 前向日期 ② 确认信号及其刊发日 ③ 历史业绩公布日；并声明其前向日期的确认语义（「仅含已公告日期」或「确认状态未知」）。合并层只按声明取用；声明为「确认状态未知」的来源 MUST NOT 使任何事件进入「已确认」——否则推算日期会以确认身份写入，下游无从分辨。
- **FR-003**: 首批来源 A = 结构化财报日历（富途）。港股提供 ①（仅含已公告日期，取值口径 = 结构化）与 ③；美股提供 ①（确认状态未知）。
- **FR-004**: 首批来源 B = 交易所公告（理杏仁港股公告，全部港股），提供 ②（会前通知的刊发日，只按标题识别，不取正文）与 ③（业绩公告的刊发日，取值口径 = 刊发事实）。来源 B MUST 复用系统已在采集的港股公告数据，不新增对该数据商的调用。业绩刊发事实中「補充」「更正」类的排除 MUST 只排除不含业绩公告本体的公告——按「含補充即排除」会漏掉真实刊发（`hk:09992` 2026-08-20），事后误报逾期且不报错。
- **FR-005**: 来源 B 识别会前通知只看公告标题：标题属于取证中的通知写法、且不是业绩公告本身，才作为会前通知信号；会后决议、董事名单、委员会职权范围等带「董事」字样的公告 MUST 排除。识别规则只有一个维护点。会前通知信号只提供刊发日，不提供会议日或公布日。
- **FR-006**: 首批来源 C = 港交所「董事會會議通知」清单（覆盖主板），提供 ②（会议日；公布日按 FR-010 推定）。每日取一次，解析每行的会议日（多日会议取清单所列开始日）、代码、目的与期间；只取目的含业绩的行，纯股息行不作财报事件并计数；报告类型与期末日由目的与期间换算，换算不出期末日的行按来源内报告期独立保留并计数。清单中的日期是交易所当地日期；日期写法为「日/月/年」、期间里的年份为两位，解析 MUST 按此顺序与世纪取值——按「月/日」解析会把 10/09 读成 10 月 9 日且不报错。
- **FR-007**: 各来源每日采集一次；合并在各来源当日数据可用之后执行。

**公布日与确认**

- **FR-008**: 财报日 = 业绩公布日，按交易所当地日期记录（港股 `Asia/Hong_Kong`、美股 `America/New_York`）；公布时刻或时段可得时一并记录。会议日本身 MUST NOT 直接当作公布日（反例：`hk:00857` 周五开会、周日刊发；`hk:09961` 会议后 2 天公布）。
- **FR-009**: 同一事件存在多个取值时，公布日按口径优先级取：刊发事实 > 正文明写 > 结构化日历 > 会议日推定。每个取值 MUST 标注口径；未被采用的取值留痕、不丢弃。唯一例外：FR-014 判定的可解释差异取会议日推定值。首批来源不产出「正文明写」口径，该口径保留给后续来源。
- **FR-010**: 会议日推定：公布日 = 会议日 + 该公司同类报告（年度 / 中期 / 季度）最近一次的「会议 → 刊发」间隔；无历史时按 0 天。间隔由 FR-019 的已刊发事件逐次学习（清单无历史存档，上线时不回填）。
- **FR-011**: 任一「仅含已公告日期」语义的来源给出某标的某报告期的公布日（任一口径），该事件即为「已确认」。清单来源的语义为「仅含已公告日期」（能上清单即公司已公告会议）。
- **FR-012**: 事件的确认时刻 = 最早的公告刊发日：清单或结构化日历给出日期时，以同一标的对应的会前通知信号（FR-005）的刊发日为准；无对应通知时，以给出日期的来源首次观测到该日期的时刻代替。确认时刻 MUST 标明口径（「刊发日」或「首次观测」）——两种口径混用而不标，下游「晚确认」统计会系统性偏晚且不报错。
- **FR-013**: 每个事件 MUST 保留每个来源各自的首次观测时刻、最近观测时刻、取值口径与日期变更史（旧日期、变更时刻）。任何更新 MUST NOT 覆盖掉历史观测。
- **FR-014**: 交叉验证与冲突判定（精确口径 = 刊发事实 / 正文明写；近似口径 = 结构化日历 / 会议日推定）：
  - 精确口径之间日期不一致 → MUST 保留全部日期，标记「来源冲突」并告警；
  - 精确口径与近似口径不一致 → 取精确口径，差异留痕，不告警；
  - 仅有近似口径且相差 1 天 → 按 FR-009 优先级取值，差异留痕，不告警；
  - 仅有近似口径且相差 ≥ 2 天：若结构化日期等于清单会议日、且会议日推定 = 会议日 + 该公司历史间隔，判为可解释差异 → 取会议日推定值，差异留痕，不告警；否则 MUST 保留全部日期，标记「来源冲突」并告警；
  - 来源重新一致后冲突解除并留痕。
- **FR-015**: 跨来源对齐「同一次财报」按标的 + 报告期进行，报告期 MUST 先统一口径（含非自然财年的公司与清单的两位年份期间）。无法对齐时各自作为独立事件保留并计数，MUST NOT 猜测性合并。
- **FR-016**: 某来源给出的日期发生变化（含清单前后两次出现的同一期会议日不同），记为改期：保留旧日期与变更时刻，并按 FR-009 / FR-014 重新判定。清单行在会议日之前消失且无新日期时，MUST 保留最后日期、不撤销确认，并告警。
- **FR-017**: 识别到会前通知信号后满 2 个交易日，仍无任何来源给出该标的的日期：若该标的曾出现在清单中，MUST 记为「已通知、日期未知」并告警；从未出现在清单中的标的（清单不覆盖的板块）只计数。MUST NOT 丢弃通知或当作未通知。之后任一来源给出日期即以其确认，确认时刻仍取通知刊发日。
- **FR-018**: 单一来源本轮失败 MUST NOT 阻断其他来源的合并，MUST NOT 撤销已有确认；失败留痕。
- **FR-019**: 业绩公告刊发并被采集后，系统以刊发日覆盖公布日（口径 = 刊发事实），按来源、按口径统计刊发前取值与刊发日的偏差（天数），并以会议日到刊发日的天数更新 FR-010 的间隔。
- **FR-019a**: 事件在见到业绩公告刊发之前 MUST NOT 转为历史——否则一个日期已过、实则延期的财报会被下游当成「已经发生」，不再提醒。公布日之后满 2 个交易日（按该市场交易日历）仍未见刊发 → 状态转「逾期未刊发」并告警；见到刊发或改期后自动解除并留痕。

**历史与范围**

- **FR-020**: 系统沉淀港股标的的历史业绩公布日（报告期、公布日、来源，口径 = 刊发事实），合并各来源，覆盖来源可得范围内至少最近 2 年。
- **FR-020a**: 清单观测按日留存：每个「标的 + 报告期」记录首次与最近出现时刻、会议日变更史。清单无历史存档，本片不回填历史清单。
- **FR-021**: 美股：来源 A 的美股观测进入合并层，事件状态为「确认状态未知」。现役美股财报采集与期权台财报打标 MUST 逐字节不变——同一输入下打标结果、对数据商的调用次数与现役落库内容与本片之前一致；美股进入合并层 MUST NOT 新增对数据商的调用。
- **FR-022**: 本片产出 MUST NOT 被期权台财报打标读到：港股收租腿的财报标签在本片上线后仍为「无日期」，直至片 2 显式开启。（依据：打标读端不按市场过滤，见取证段最后一条）
- **FR-023**: 冲突、已通知日期未知、逾期未刊发、来源失败、清单页面陈旧、清单行提前消失、清单行数与会前通知识别数异常 MUST 写入现有采集运行记录的发现项与日志，与现役采集同一出口。
- **FR-024**: 覆盖范围：清单来源覆盖**全部主板**（清单本身只含主板，每日一次请求）；结构化日历、业绩刊发事实与会前通知信号覆盖**全部港股**；合并覆盖全部港股。
- **FR-025**: 清单获取与解析 MUST fail loudly：取数失败（网络错误、非 200 响应、页面地址跳转）、页面日期无法解析、表头缺失或任一数据行无法按列解析时，本轮清单来源 MUST 判为失败，且 MUST NOT 写入任何清单观测——否则一次改版会被读成「今天没有董事会会议」且不报错。获取 MUST NOT 跟随重定向——跟随后若新地址结构未变，换地址会被静默吞掉。页面日期超过 2 个交易日未更新同样判为失败，已有清单观测照常参与合并。以上各情形 MUST 计入本轮运行的失败数，使运行状态为部分失败并经每日运行日报在飞书标红、带失败原因——只写发现项而运行状态仍为成功时，日报显示为绿色，告警会被淹没。每日只请求一次，临时失败的重试次数有上限。

### Key Entities _(include if feature involves data)_

- **财报日期来源（Earnings Date Source）**: 一个可插拔的数据供给方。属性：名称、按市场的能力声明（前向日期 / 确认信号 / 历史公布日）、前向日期的确认语义、启停状态。
- **来源观测（Source Observation）**: 某来源在某次运行中对「标的 + 报告期」给出的日期信息。属性：来源、标的、报告期（原文与统一口径）、公布日及其口径、会议日、公布时刻、刊发日（若有）、首次观测时刻、最近观测时刻、原始凭据指针（如公告链接或清单页面日期）。
- **会前通知信号（Pre-results Notice Signal）**: 标题识别出的会前通知。属性：标的、公告刊发日、公告标题与链接；不含会议日或公布日。
- **财报事件（Earnings Event, 合并后）**: 某标的某报告期的一次业绩公布。属性：标的、报告期、状态（已确认 / 确认状态未知 / 来源冲突 / 已通知日期未知 / 逾期未刊发 / 已公布成为历史）、公布日及其取值口径、冲突时的全部候选日期、公布时刻、确认时刻及其口径、参与来源、变更史。
- **会议 → 刊发间隔（Meeting-to-Publication Lag）**: 某公司某类报告（年度 / 中期 / 季度）最近一次会议日到刊发日的天数，供会议日推定使用。
- **口径偏差统计（Provenance Accuracy）**: 按来源、按取值口径统计的「刊发前取值 − 刊发日」天数分布。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 锚表内全部港股锚（2026-09-13 为 29 只）近两年的历史业绩公布日（刊发事实口径）与交易所刊发日逐条一致率 100%，且包含来源 A 缺失的 `hk:00005` 两条、`hk:00857` 三个周日刊发日，以及标题带「補充」字样的真实刊发（`hk:09992` 2026-08-20）。
- **SC-002**: 清单解析：以留存的港交所清单页面为输入（2026-09-13 基线：8 份可解析快照 + 当日页面，共 1776 行），业绩类行 100% 解析出代码、会议日、报告类型与期末日，或被显式计入「无法换算期末日」；纯股息行 100% 被排除并计数；0 行被静默丢弃。
- **SC-003**: 通知与清单衔接：上线后 30 天内，锚表港股经标题识别的会前通知，100% 在 2 个交易日内被清单收录、或由结构化日历给出日期、或产生「已通知、日期未知」告警（基线：会议日落在快照时段内的锚表通知 16 / 16 被清单收录）。
- **SC-004**: 回放锚表港股两年（176 次有会前通知的刊发）：按口径优先级取出的公布日与事后刊发日逐日一致率 ≥ 97%（基线 172 / 176）；其余 100% 落在「会议日 → 其下一交易日」之内或以来源冲突告警（基线余 3 次 `hk:00857` 周日刊发、1 次 `hk:00960` 冲突）。
- **SC-005**: 通知刊发后，清单或结构化日历首次给出日期的那一轮合并中，该事件即为已确认，确认时刻等于通知刊发日（不等于系统首次观测时刻）。
- **SC-006**: 人为构造的精确口径冲突、以及近似口径相差 ≥ 2 天且不可解释的冲突，100% 产生冲突标记与告警且全部日期可查；精确 vs 近似口径的差异、以及可解释差异（`hk:00857` 形态回放）0 条告警、100% 留痕。
- **SC-007**: 停用任一来源后，合并照常完成，已有确认 0 条丢失；恢复后该来源的数据重新参与合并。
- **SC-008**: 美股财报打标结果与美股采集行为在本片前后逐字节一致（同输入回放对比）；合并层中美股事件被记为「已确认」的数量为 0。
- **SC-009**: 本片上线后，港股收租腿财报标签为「无日期」的比例保持 100%。
- **SC-010**: 新增一个只提供历史公布日的来源、或移除一个来源，不需要修改合并、取值口径与交叉验证规则即可完成（以一次增删演练验证）。
- **SC-011**: 人为构造「公布日之后满 2 个交易日仍未刊发」的事件，100% 转为「逾期未刊发」并告警、且未转为历史；随后注入刊发，100% 自动解除并转为历史。
- **SC-012**: 注入五类异常——页面 404、页面地址 301 跳转、缺页首日期、缺表头、含一行无法按列解析的数据行——100% 判为来源失败：本轮运行状态为部分失败、失败原因可在运行记录中查到、清单观测写入 0 条、其余来源照常合并；页首日期超过 2 个交易日未更新的页面同样 100% 使运行状态为部分失败；每日运行日报对这些运行 100% 标红并显示失败原因。

## Assumptions

- 业务口径 = **业绩公布日**，按交易所当地日期记录。
- 港交所清单是公开的非正式报表页（「僅供參考」「未必盡列」），无接口承诺，可能改版或停更；由 FR-025 的失败告警、结构化日历与刊发事实兜底。页面使用条款未核实（推断公开页面可程序读取），每日仅一次请求。
- 清单更新时点推断为营业日白天（观测：2026-09-10 12:30 香港时间生成、2026-09-11 未见更新）；每日采集时页面可能滞后约 1 个营业日，确认时刻由通知刊发日承担，不受影响。
- 告警时效：采集在 23:30 运行，失败经次日 09:00 的运行日报推送飞书（日报与推送为既有链路），即页面问题最晚约 10 小时后被看到；对每日一次的日期数据可接受。
- 告警沿用现役采集的发现项与日志出口；该出口今天没有专门的接收端（issue #209 已登记），本片不另建告警通道。
- 「每日一次」按港股收盘后、公告数据当日入库之后安排；具体时点在 plan 阶段对齐现役 `announcement` 维度（每日 22:00）与港股期权采集时段。
- 腾讯自选股数据经 PoC 不作为来源接入：非正式接口、单条「最近一次」、缺口与富途同形且疑似同源。
- 美股锚前向财报日覆盖低（112 只中 26 只有未来财报日）且没有独立的第二来源——不在本片范围，由片 2 的预计区间与后续补源决策承接。
- 预计区间、两态打标、契约与移动端呈现均不在本片范围（片 2）。
- 港股指数期权、A 股、下单相关不在范围内。
