## Context

- **为什么现在做**：021 V1 与 user 对焦时把技术指标/基本面条件明确收进下期 backlog；现在 021 已 ship（含评估引擎纯函数 seam）、数据底座全就绪（估值快照/财报/历史日线在库，020 前复权读取已上线），扩指标是零数据采集成本的纯仓内增量。业内最小公约数（到价 + 涨跌幅 + 均线 + MACD/KDJ/RSI + 换手率）目前只覆盖一半。
- **用户价值**：左侧价值投资者的核心监控诉求从「价格碰线」升级为「估值到位」（PE/PB/分位/股息率——买点本质是估值买点）与「趋势确认」（均线/金叉/新低——盘后信号免每日人工翻图）。
- **预警模型不变**：沿用 021 统一模型——一个预警 = 1..N 条 AND 条件、提醒频率三档、≤22 字备注、per-account；本 feature 只扩条件类型词表与求值能力，CRUD/消息中心/触达面零改动。
- **求值口径分层**：估值条件比当日估值快照；窗口/指标条件算自前复权日线序列；换手率/量比用原始量价。全部 EOD 盘后判定（盘中实时是独立 backlog——p2 实时预警，依赖 022 推送）。

## Clarifications

### Session 2026-06-07

- Q: 状态型条件（超买超卖/估值触及/换手率/量比）在「每日 1 次」频率下的触发节奏？ → A: 每日触发（FR-S10 维持）——与 021 涨跌幅条件语义完全一致，不做边沿去抖、不改默认频率档；用户控噪手段 = 「仅 1 次」频率档（触发即删/停，匹配左侧买点「到位提醒一次」模式）
- Q: BOLL「突破上轨/跌破下轨」是穿越事件还是状态？ → A: 穿越事件——昨收在轨内 ∧ 今收出轨才命中（与 MA 穿越/金叉死叉同构）；持续在轨道外的后续交易日不命中。状态语义仅保留给 RSI/KDJ 超买超卖与估值/量类条件
- Q: 估值快照陈旧度（staleness）容忍界限？ → A: 容忍 ≤3 个交易日——快照落后评估交易日 ≤3 个交易日仍可求值；超限 → 估值条件不命中（数据缺失防御语义），触发快照记录所用估值日期（短期 staleness 不实质影响阈值判定，同时罩住长假后首日与偶发同步失败）

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 配置四类新条件（条件库分类浏览 + 参数输入）(Priority: P1)

用户在添加条件页看到分类树扩展为多个分类（价格跟踪 / 估值 / 成交量 / 技术指标），从「估值」分类选「PE 低于」输入阈值 10，从「价格跟踪」选「股价跌破均线」选择周期 MA20，组合为一条 AND 预警并保存。带参条件（均线周期、新高新低窗口、RSI 阈值）在选择时提供参数输入，参数出域被拒。

**Why this priority**: 条件配置是新指标价值的入口；UI 分类承载条件数从 4 → ~20 的膨胀，没有它新求值能力不可达。

**Independent Test**: 不依赖评估引擎——每个分类各创建至少 1 条含新类型条件的预警，列表卡片正确显示条件摘要（含参数，如「跌破 MA20」「PE 低于 10」），编辑/启停/删除全程数据正确持久化。

**Acceptance Scenarios**:

1. **Given** 添加条件页, **When** 浏览分类树, **Then** 可见「价格跟踪 / 估值 / 成交量 / 技术指标」分类，各分类下条件可选（021 仅「价格跟踪」单分类成为历史）
2. **Given** 选「股价上穿均线」, **When** 选择周期, **Then** 仅可选 MA5/10/20/60/120/250 白名单；选 MA20 保存后卡片摘要显示「上穿 MA20」
3. **Given** 预警内已有「上穿 MA5」, **When** 再添加「上穿 MA20」, **Then** 允许（同类型不同参数共存）；再添加第二条「上穿 MA5」 → 拒（同类型同参数限 1）
4. **Given** 选「RSI 超卖」, **When** 不改默认值, **Then** 阈值默认 30；可调出域（如 −5 或 105）→ 拒
5. **Given** 一条预警含「PE 低于 10」+「创 60 日新低」两条件, **When** 保存, **Then** 跨类 AND 组合成功，卡片两行摘要

---

### User Story 2 - EOD 评估正确求值四类新条件 (Priority: P1)

每个交易日 EOD 评估轮对含新类型条件的预警求值：估值条件比当日估值快照、均线/新高低/累计涨跌幅/技术指标算自前复权日线序列、量类条件用原始量价。命中写触发流水（含实际值快照），消息中心展示「招商银行(600036) PE 9.8 低于 10」式描述。除权日不产生假信号；数据不足（warm-up/停牌/字段缺失）防御性不命中。

**Why this priority**: 求值正确性是本 feature 的兑现端，与 US1 合计构成最小价值闭环；复权口径与 warm-up 防御是财务级正确性要求。

**Independent Test**: 服务端独立可测——构造日线/估值序列（触发样本、边界样本、除权样本、warm-up 不足样本），跑评估，断言触发流水与实际值快照，不需要 UI。

**Acceptance Scenarios**:

1. **Given** 预警「PE 低于 10」、当日估值快照 PE_TTM=9.8, **When** EOD 评估, **Then** 触发，流水快照含实际值 9.8
2. **Given** 亏损股（估值快照 PE 为空）的「PE 低于 10」预警, **When** 评估, **Then** 不触发（字段缺失不命中），不报错
3. **Given** 「上穿 MA20」预警、昨收 < 昨 MA20 且今收 ≥ 今 MA20（前复权口径）, **When** 评估, **Then** 触发；次日继续站上均线（非穿越日）→ 不再因「在上方」触发
4. **Given** 标的当日分红除权（前复权后价格序列连续）, **When** 评估「创 60 日新低」「上穿 MA20」, **Then** 不因除权价格跳变产生假命中
5. **Given** 上市仅 30 个交易日的标的挂「MACD 金叉」（需 ~60+ 根）与「创 250 日新高」, **When** 评估, **Then** 两条件均不命中（warm-up 防御），预警不报错
6. **Given** 「MACD 金叉」预警、昨日 DIF≤DEA 今日 DIF>DEA, **When** 评估, **Then** 触发；「量比 ≥ 2」且今量为前 5 日均量 2.3 倍 → 触发
7. **Given** 含「股价跌到 13.00」（021 既有）+「PE 低于 10」（新增）的混合预警, **When** 两条件同日命中, **Then** 触发（AND 语义跨新旧类型一致）

### User Story 3 - 既有预警与触达面零回归 (Priority: P2)

021 既有 4 类价格条件预警在本 feature 上线后行为不变：求值口径、频率后置动作、消息中心展示、未读角标全部如旧。新类型条件触发的消息复用同一消息中心与展示投影。

**Why this priority**: 023 是 021 的增量扩展，存量用户预警的零回归是底线约束；独立列出以强制回归验证。

**Independent Test**: 021 既有 IT 套件全绿（不改断言）；新旧条件类型各一条预警同轮评估，各自正确触发/不触发。

**Acceptance Scenarios**:

1. **Given** 021 存量预警（如「股价跌到 13.00」）, **When** 023 上线后 EOD 评估, **Then** 求值口径与触发行为与 021 验收时一致
2. **Given** 新类型条件触发, **When** 查看消息中心, **Then** 消息格式与 021 一致（股票名(代码) + 命中条件及实际值 + 触发时间），未读角标正常累计

### Edge Cases

- 估值快照日期落后于 bar 日期（同步时序差）：落后 ≤3 个交易日仍求值（触发快照记录估值日期）；落后超限或快照缺失整行 → 估值条件不命中（per Clarifications）
- 分位字段（3y/5y cvpos）对上市不足窗口期的标的为空 → 分位条件不命中
- ST/北交所标的：四类新条件求值口径一致适用（涨跌幅限制差异不影响 EOD 指标语义）
- 换手率字段由同步管线下游计算（理杏仁不直返）：字段 null → 换手率条件不命中
- 量比在送转日股数变化下短窗失真：已知局限（窗口仅 5 日），不做特殊处理
- 技术指标状态型条件（RSI 超买等）持续满足多日：每个交易日均判命中,「每日1次」频率下每日提醒,「仅1次」档触发即删/停——与 021 涨跌幅条件的频率语义完全一致,不为状态型单设边沿去抖（用户控噪手段=选「仅1次」档；下期实时预警如需「进入状态才提醒」再议）
- 同轮多条件混合 warm-up：一条预警内部分条件可算、部分 warm-up 不足 → 不足者不命中 → AND 整体不触发（不跳过整条预警，与停牌跳过区分）

## Requirements _(mandatory)_

### Functional Requirements

**Server**:

- **FR-S01**: 系统 MUST 支持估值类条件：PE_TTM / PB / 股息率 高于或低于阈值，PE / PB 历史分位（3 年或 5 年窗口，窗口为条件参数）高于或低于阈值（百分位 0-100）；求值比对最新估值快照，快照落后评估交易日 MUST ≤3 个交易日（超限按数据缺失不命中），触发快照 MUST 记录所用估值日期（per Clarifications）
- **FR-S02**: 系统 MUST 支持价格扩展类条件：收盘上穿/下穿 MA(N)（N ∈ {5,10,20,60,120,250}，穿越事件语义：昨收在均线一侧 ∧ 今收到达另一侧）；创 N 日新高/新低（N ∈ {60,120,250}，今高/低突破前 N 日极值）；3/5/10 日累计涨跌幅超阈值
- **FR-S03**: 系统 MUST 支持成交量类条件：换手率 ≥ 阈值；量比 ≥ 阈值（今量 / 前 5 日均量）
- **FR-S04**: 系统 MUST 支持技术指标类条件：MACD(12,26,9) 金叉/死叉（DIF 与 DEA 穿越事件）；KDJ(9,3,3) 金叉/死叉（K 与 D 穿越）、超买（J>100）/超卖（J<10）；RSI(14) 超买/超卖（阈值用户可调，默认 70/30，值域 (0,100)）；BOLL(20,2σ) 收盘突破上轨/跌破下轨（穿越事件：昨收在轨内 ∧ 今收出轨，与 MA 穿越同构，per Clarifications）。指标参数除 RSI 阈值外 MUST 固定为上述标准参数
- **FR-S05**: 所有窗口/指标计算（MA / 新高低 / 累计涨跌幅 / MACD / KDJ / RSI / BOLL）MUST 使用前复权价格序列；估值/换手率/量比 MUST 使用原始口径数据
- **FR-S06**: 历史数据不足条件所需窗口（warm-up）、当日数据字段缺失（估值空值/换手率 null）时，该条件 MUST 判定不命中且不报错；停牌（无当日 bar）时整条预警本轮跳过（021 语义沿用）
- **FR-S07**: 创建/编辑校验 MUST 扩展：词表外类型拒；参数出域拒（N 不在白名单、RSI 阈值出 (0,100)、分位阈值出 [0,100]、量比/换手率阈值 ≤0 拒）；同类型同参数重复拒，同类型不同参数 MUST 允许共存
- **FR-S08**: 触发流水的条件快照 MUST 含新类型条件的实际值（如 PE 实际值、今收与 MA 值、RSI 值），消息中心展示投影 MUST 渲染人类可读的条件描述（含参数）
- **FR-S09**: 021 既有 4 类条件的求值口径、频率后置动作、消息中心行为 MUST 零回归

### Key Entities

- **预警条件（AlertCondition，扩展）**: 021 既有实体扩展——类型词表从 4 扩至约 26 个（四类新条件，最终词表 plan 定稿）；新增「条件参数」概念（均线/窗口周期 N、分位窗口 3y/5y、RSI 阈值），无参条件参数为空；同类型同参数唯一约束替代 021 的同类型唯一。参数的持久化形态（独立参数字段 vs 编码进类型）为 plan 阶段决策
- **指标值（推导数据，非持久实体）**: MA/MACD/KDJ/RSI/BOLL 由前复权日线序列按标准参数推导，仅在求值时使用并以实际值进入触发快照；是否预计算缓存为 plan 阶段决策（spec 不约束）

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 四类新条件每类至少 1 条真实预警走通「创建 → EOD 评估 → 触发 → 消息中心可见」全链路（实测验收，含实际值快照正确）
- **SC-002**: 指标计算正确性对照：≥2 只样本股（含 1 只年内有除权事件的）的 MA/MACD/KDJ/RSI/BOLL 当日值与主流行情软件展示值一致（容差 ≤1%，由复权基准日差异解释的偏差除外）
- **SC-003**: 除权样本回归：分红/送转除权日当日及次日，穿越/新高新低类条件 0 假触发（构造样本断言）
- **SC-004**: 全量启用预警的单轮 EOD 评估耗时 ≤ 5 分钟（现量级几十~几百条预警，含窗口取数与指标计算）
- **SC-005**: 021 既有验收场景（US1-US5 acceptance 全集）在 023 合入后 100% 通过，存量预警零行为变化
- **SC-006**: 条件库 UI：全部新条件可经分类浏览与搜索两路径到达并配置成功（逐条 e2e 走查）

## Assumptions

- **warm-up 历史深度待 prod 实测**：MA250/新高 250 需 250+ 根前复权 bar，MACD 稳定需 ~60+ 根。prod backfill 深度尚未实测（specify 前置 gate 被环境拦，user 自跑）；不足则数据补档先行，不阻塞 spec/plan
- **N 白名单固定**：均线周期 {5,10,20,60,120,250}、新高低窗口 {60,120,250}、累计涨跌幅 {3,5,10}——不开放自由输入（自定义参数在 out-of-scope）
- **分位窗口（3y/5y）作为条件参数**而非独立条件类型（与均线周期同构）
- **跨类 AND 自由组合允许**：一条预警内四类新条件与 021 既有条件任意混搭，021「1..N 条 AND、≤22 字备注、频率三档」模型不变
- **估值快照与 bar 的日期对齐**：求值取最新估值快照，陈旧度上限 3 个交易日、超限不命中、触发快照记录估值日期（per Clarifications，不再留 plan 决策）
- **技术指标参数固定**（除 RSI 阈值）：MACD(12,26,9) / KDJ(9,3,3) / RSI(14) / BOLL(20,2σ)——业内默认参数，不开放自定义
- **指标计算落点 / on-the-fly vs 预计算 / 参数持久化形态**为 plan 阶段技术决策（p1 子 plan Open Decisions 1-3），spec 不锁定
- **Out of scope**：技术形态识别、事件预警、盘口条件、自编公式、盘中分钟线指标、除 RSI 阈值外的自定义指标参数、盘中实时求值（p2 实时预警 backlog）
