# Feature Specification: 港股期权接入与锚冷启动开通港股

**Feature Branch**: `066-hk-option-cold-start`
**Created**: 2026-08-22
**Status**: Draft

## Clarifications

### Session 2026-08-22 — 供应方侧 PoC 实测（直连港机行情网关，未改一行代码）

这一节记录的是**实测事实**，不是推断。它们把本片原本三个未知里的两个消掉了。

- **港股期权在供应方侧全线可用**：到期日阶梯、期权链、期权快照、标的概览、历史波动率五条能力对港股正股全部返回，**字段集与美股逐字相同**。网关本身市场无关（市场参数对着 SDK 自己的枚举白名单校验、代码原样透传），**无需任何网关侧改动**。
- **数据完整度优于美股**：单个 30 天到期窗取到 132 个合约，隐含波动率 + 五个希腊值 + 未平仓合约数**全部非空**（132/132）。美股同类采集曾实测 2150 行里 227 行因深实值腿报价跌破内在价值导致波动率无解。
- **三个港股独有字段全部有真值**：净未平仓合约数、合约名义金额、相等正股手数。快照表已有对应列可直接承接。
- **批量上限与美股同档**：一次传 133 个代码返回成功，官方对「港股期货期权基础行情标的」的 20 个/次上限**未生效**（账号持有高级档行情权限）。
- **标的波动率历史起点 2023-06-27**（美股 2023-06-26），深度约 3.15 年。⚠️ **单个 364 天窗港股只返 244 个交易日、美股 250 个，两者都不足最小分位窗 252** ⇒ 首次回填**必须跨 ≥2 个窗**，只拉一年会让分位恒为「不可算」且不报错。
- 🚨 **合约标识的词根是交易所助记符，不是标的数字代码**（腾讯期权是 `TCH…` 而非 `00700…`）⇒ **从合约标识反推不出标的**，关联只能走供应方给的「标的代码」字段。美股是可反推形态，**不要把美股假设带过来**。
- ⚠️ **港股期权的结算方式字段返回「不适用」**（美股给 AM/PM）。要确认它被规范成空值而不是字面量字符串。

### 待定 — 港股未平仓合约数的归属交易日

现行归属规则来自美股：收盘当晚抓到的未平仓合约数属于**上一场**（清算所隔日才翻新）。港股的日终数据每晚 22:00 定稿，**该时刻是否已把当日的未平仓合约数写定，尚无证据**。

正在跨交易日采样（周六基线已采：以周五终值为原点；周一起在 16:30 / 21:30 / 23:00 / 次日 06:00 四个时点取同一组合约），**2026-08-25 出结论**。

- 若 22:00 已定稿 ⇒ 归属规则需按市场分叉
- 若未定稿 ⇒ 现行规则逐字适用

**在结论落地前，本片 MUST NOT 让港股期权快照进入生产采集轮**（错误的归属不报错，只让持仓量整体偏一天，而活跃度排序与界面上的「数据时点」都读它）。

## User Scenarios & Testing _(mandatory)_

### User Story 1 — 建一只港股锚，期权数据自动就位 (Priority: P1)

我把一只港股标的的估值结论录成锚。今天这只锚建完之后什么都不会发生——雷达的港股页签依旧是空的，因为系统压根没有这只标的的期权合约与报价。我期望它和美股锚一样：建完就有数据。

**Why this priority**: 这是港股页签存在的全部意义。没有它，065 交付的分页签是个永远空着的壳。其余两个故事都是在这条链路成立之后才有价值。

**Independent Test**: 建一只港股锚，不做任何其他操作，随后查该标的在目标交易日是否有期权合约集与期权日快照，以及本次冷启动的结局记录是否为「已补齐」。

**Acceptance Scenarios**:

1. **Given** 库中没有某港股标的的任何期权数据，**When** 为它建一只锚且此刻港股休市，**Then** 系统补齐该标的的期权合约集与目标交易日的期权日快照，并把本次结局记为「已补齐」
2. **Given** 同上，**When** 建锚时港股正处于连续竞价时段，**Then** 系统补齐期权合约集但**不**写任何按交易日归属的快照，结局记为「盘中跳过」
3. **Given** 某港股标的的目标交易日数据已由常规采集轮落齐，**When** 为它再建一只锚，**Then** 系统对外零请求，结局记为「数据已具备」
4. **Given** 一只 universe 尚未收录的港股标的，**When** 为它建锚，**Then** 系统为它登记行情记录，且该记录**享有与 universe 登记的同市场标的完全相同的采集资格**（后续常规日线轮不得跳过它）

---

### User Story 2 — 港股标的的波动率分位可读 (Priority: P2)

我看港股锚的详情时，想知道当前隐含波动率在它自己一年的历史里处在什么位置——这是判断「贵不贵」的入口。美股锚已经有这个数，港股锚现在整列是空的。

**Why this priority**: 它让港股锚从「有数据」升到「可判断」。但它不是链路成立的前提——没有分位，锚与合约表照样可用，所以排在 P1 之后。

**Independent Test**: 为一只港股标的完成首次历史回填后，查它的波动率分位是否可算；再用一只历史窗不足的标的，确认它呈现为「不可算」而不是 0。

**Acceptance Scenarios**:

1. **Given** 某港股标的已完成首次波动率历史回填且样本达到最小分位窗，**When** 查看它的标的详情，**Then** 显示可算的波动率分位
2. **Given** 某港股标的的历史样本不足最小分位窗，**When** 查看它的标的详情，**Then** 显示「分位不可算」，**且不显示 0 或空白**
3. **Given** 首次回填只覆盖了一年，**When** 检查分位可算性，**Then** 系统能明确指出样本不足（本条是防回归：一年 = 244 个交易日 < 252）

### User Story 3 — 港股锚在盘中跟随实时报价 (Priority: P3)

港股开市时，我希望雷达上的港股锚显示当下的价，而不是昨天的收盘。美股锚已经这样了，港股锚现在挂着一条「港股无盘中报价」的常驻说明。

**Why this priority**: 体验提升，不是数据完整性问题。收盘档本身是正确的，只是不够新。放最后还有一个原因：它牵动交易时段表的改动，风险面与前两个故事不同。

**Independent Test**: 在港股连续竞价时段观察锚的价格是否随行情推进；在午休时段确认价格**不**推进且不被标成盘中价。

**Acceptance Scenarios**:

1. **Given** 港股处于连续竞价时段，**When** 行情变动，**Then** 港股锚的价格随之更新并标注为盘中
2. **Given** 港股处于午休时段（12:00–13:00），**When** 观察锚，**Then** 价格**不**更新，且**不得**把午休期间的盘口标注成盘中价
3. **Given** 港股半日市当天下午，**When** 观察锚，**Then** 按已收盘处理
4. **Given** 实时报价已对港股可用，**When** 打开雷达港股页签，**Then** 065 挂的「港股无盘中报价」常驻说明不再出现

### Edge Cases

- 某港股标的的期权链在目标窗内**零合约**（冷门标的 / 期权已全部到期）→ 结局必须是「已执行但未补齐」，**不能**记成「已补齐」。期权日终数据无跨日补救，记错就是把永久缺口标成正常。
- 供应方对某个港股合约**不返回希腊值**（数学上无解）→ 该行照常落库并标注「档位不可定」，**不得丢行**——丢了就无法与「这条腿今天整行没采到」区分。
- 港股与美股的期权采集**同时被触发**（建锚随时可能发生，不受采集时刻约束）→ 必须串行，不得并发争抢供应方的调用配额。
- 港股标的**停牌** → 链与快照照常尝试，停牌状态由供应方字段体现，不作为跳过依据。
- 某港股锚的标的**同时在美股上市**（如 `hk:09888` 与 `us:BIDU`）→ 两者是两只独立证券，各自独立采集，**不得**互相顶替。
- 交易日历**前瞻视野未覆盖**港股的今天 → 放弃本次并留需人工介入的记录，**不得**猜测口径。
- 建锚事务回滚 → 不得发起冷启动。
- 同一次建锚的冷启动请求被**重复投递** → 第二次起零对外请求、零新增行。

## Requirements _(mandatory)_

### Functional Requirements

**采集能力**

- **FR-001**: 系统 MUST 能为港股标的获取期权到期日阶梯、期权合约静态属性、期权日快照（含隐含波动率、希腊值、未平仓合约数）三类数据。
- **FR-002**: 系统 MUST 能为港股标的获取标的层面的隐含波动率快照与历史序列。
- **FR-003**: 系统 MUST 能为港股标的获取连续竞价时段的实时成交价。
- **FR-004**: 系统对港股期权合约与其标的的关联 MUST 依据供应方给出的标的字段，**MUST NOT** 从合约标识反推。
- **FR-005**: 供应方返回「不适用」的字段（如港股期权的结算方式）MUST 被规范成空值，**MUST NOT** 以字面量字符串落库。

**工作集与采集闸**

- **FR-006**: 港股期权采集的工作集 MUST 恰为**有锚的**港股标的；整库零港股锚时 MUST 零对外请求且判定为成功。
- **FR-007**: 开通港股期权采集 **MUST NOT** 改变既有 cn / hk 非期权同步维度的工作集范围。
- **FR-008**: 开通港股期权采集 **MUST NOT** 改变美股任何维度的工作集或行为；新旧判据在美股上 MUST 产出同一集合。
- **FR-009**: 由建锚路径首次登记的行情标的记录，其采集资格 MUST 与 universe 登记的同市场标的一致。**违反此条的后果是该标的永久缺日线且无任何告警。**

**冷启动**

- **FR-010**: 港股锚首次创建 MUST 触发冷启动补数，覆盖期权合约集与期权日快照两档。
- **FR-011**: 港股锚的冷启动 **MUST NOT** 新增日线采集维度——港股日线已由既有的每晚 22:00 采集轮覆盖。
- **FR-012**: 冷启动在港股连续竞价时段（**含午休**）MUST NOT 写入任何按交易日归属的期权快照。
- **FR-013**: 冷启动跑完但目标交易日快照仍不在库 MUST 记为「已执行但未补齐」，**MUST NOT** 记为「已补齐」。
- **FR-014**: 港股冷启动的八种结局值域 MUST 与美股共用同一套，**MUST NOT** 为港股新增或折叠结局。

**时间语义**

- **FR-015**: 港股期权采集的触发时刻 MUST 晚于港股日终数据定稿时刻（每晚 22:00），且 MUST 排在既有 22:00 采集族之后。
- **FR-016**: 港股期权快照的未平仓合约数归属交易日 MUST 依据实测确定的港股口径；在实测结论落地前，港股期权快照 **MUST NOT** 进入生产采集轮。
- **FR-017**: 港股的午休时段 MUST 在交易时段表中被显式表达；判定「此刻能不能采盘中价」MUST 使用排除午休的谓词。

**波动率分位**

- **FR-018**: 港股标的的首次波动率历史回填 MUST 覆盖足以算出分位的样本量（**单个供应方窗口不足，必须跨多窗**）。
- **FR-019**: 样本不足最小分位窗时，分位 MUST 呈现为「不可算」，**MUST NOT** 落 0、**MUST NOT** 省略该标的。

**呈现**

- **FR-020**: 港股实时报价可用后，雷达港股页签上「该市场无盘中报价」的常驻说明 MUST 下线。

## Success Criteria _(mandatory)_

- **SC-001**: 为一只真实港股标的建锚后，在**不做任何其他操作**的前提下，该标的在目标交易日的期权合约集与期权日快照均可查到，且本次冷启动结局记为「已补齐」。
- **SC-002**: 整库零港股锚时，港股期权采集轮对供应方的请求数为 **0** 且判定为成功。
- **SC-003**: 库中有 N 只港股锚时，港股期权采集覆盖的标的数**恰为 N**（不是全港股 universe）。
- **SC-004**: 开通港股前后，既有 cn / hk 非期权同步维度覆盖的标的数**零变化**。
- **SC-005**: 开通港股前后，美股各维度覆盖的标的集合**逐元素相同**。
- **SC-006**: 一只 universe 未收录的港股标的经建锚登记后，能被随后的常规日线采集轮**采到**。
- **SC-007**: 港股标的完成首次波动率回填后，其分位**可算**；样本不足的标的呈现为「不可算」而非 0。
- **SC-008**: 港股连续竞价时段锚价随行情推进；**午休时段锚价不推进**。
- **SC-009**: 港股与美股期权采集在同一时段被触发时，两者**串行完成**，无一方因配额耗尽而失败。
- **SC-010**: 港股期权快照中希腊值缺失的行**照常在库**并带可判读的标注，缺失率与供应方返回一致。

## Key Entities

- **锚（Anchor）**：一只标的的估值结论。已有 `market` 一等列，值域 `us | hk`。本片不改其形状。
- **行情标的（Instrument）**：市场 + 代码唯一。本片修正其「采集资格」在建锚登记路径下的默认值。
- **期权合约（OptionContract）**：标的的一份可交易合约，静态属性。本片新增港股来源，**不新增列**。
- **期权日快照（OptionDailySnapshot）**：一份合约在某交易日的报价、希腊值与持仓量。港股独有的净未平仓合约数已有对应列。
- **标的波动率历史（UnderlyingIvHistory）**：标的层面的逐日隐含 / 历史波动率序列，分位的样本源。
- **采集维度（SyncDimension）**：一类数据的采集节奏与范围声明。本片新增港股期权相关维度行。
- **冷启动运行记录（AnchorColdStartRun）**：每只锚最近一次冷启动的结局。本片不改其值域。

## Assumptions

- 港股账号持有的行情权限档位在本片生命周期内不变（已实测为高级档；若降级为基础档，期权快照的单次批量上限会从 400 掉到 20，需要调整批次大小而非改设计）。
- 港股日终数据每晚 22:00 定稿这一事实稳定；采集时刻据此排在其后。
- 供应方的标的波动率历史起点（2023-06-27）为固定数据纪元而非滑动窗——**此假设仅影响「首次回填的紧迫性」论证，不影响做法**（回填拉满在两种情形下都正确）。
- 港股期权的合约标识词根规则（交易所助记符）由供应方维护，本片不自行解析或构造合约标识。
