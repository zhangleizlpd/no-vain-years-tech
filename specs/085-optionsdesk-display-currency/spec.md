## Clarifications

### Session 2026-09-16

- Q: 展示币种的作用范围到哪里？ → A: **只持仓列表页**。需求原意是「统一折算看总量」，而总量只存在于列表页的组市值与跨组排序。持仓详情页与订单页不折算：订单成交价折算后是一个**从未真实存在过的数字** —— 那笔单就是以原币种成交的，把它显示成另一币种，等于让用户对着一个虚构的成交价做判断。
- Q: 选择器形态、档位与默认值？ → A: **下拉选择器，三档 USD / HKD / CNY，默认跟随当前市场页签**（us ⇒ USD、hk ⇒ HKD）。不做平铺分段：它要独占一条控件行，实测占 **57px** 高，而页头已有题头 53 + 市场页签 40 + 胶囊分段 57 三层；改下拉后列表可用高度从 **542px 回到 599px**（多放约一行半持仓）。不设「原币种」档：同屏各行必然同币种 ⇒ 在 hk 页签选「HKD」与选「原币种」显示结果逐字相同，两个档位长得一模一样，留着只会让人猜它俩差在哪。
- Q: 选择器放在哪？ → A: **与「同步于 …」同一行、置于右侧**。实测该行文本实占 156px、**余量 234px**，放得下；而「参考汇率」行文本实占 307px、余量仅 83px，塞进去必溢出；列头行高 31px 且市值列仅 88px，放不下。
- Q: 用户选的币种要不要记住？ → A: **不持久化**。本次进入页面期间手动切换即时生效，**离开交易账户页后再进入即复原为当前市场原币种**。状态放进程内（与既有市场 / 分段选择同层），不写入本地存储 —— 这样点进持仓详情再返回时币种不会跳变，而 App 重启后自然复原。
- Q: 未切过币种时切换市场页签，币种怎么变？ → A: **跟随新市场**（us→hk 即 USD→HKD）；**本次已手动切过**则保持所选不变。没切过时用户要的是「这个市场的原始口径」，切过之后那是明确表达的偏好。（⚠️ 本问的后半段已由 **Session 2026-09-17** 修订，以那条为准）
- Q: 折算在 server 还是 mobile 做？ → A: **server**。三条理由：① **组聚合值口径唯一性** —— `groupMarketValue` 由 server 用 `Prisma.Decimal` 算，若改由 mobile 折算，要么两处各折一次（两份折算逻辑必漂），要么组值与行值各自舍入而对不上；② **Decimal 精度** —— `format/compact-amount.ts` 文件头明写「Decimal string → Number 只用于展示，不回写」，把折算挪到 mobile 等于让这步乘法走 Number；③ **vendor I/O 归属**在 server。
- Q: CNY 用什么货币符号？ → A: **不用符号，用三字母代码 `CNY`**。本仓从不使用货币符号：`optionsdesk-copy.ts` 的 `marketValueLabel` 体例是 `市值（USD）` / `市值（HKD）`，币种以三字母代码进 label 括号、金额数字本身不带任何标识。
- Q: 含降级行的组，在跨组排序里放哪？降级行怎么标？ → A: 组**沉底**、组内保持原有相对顺序，与 083 既有的「市值无效排末」同构，两种「排不了」的情形共用一套规则。降级行**明确标注其原币种**；不逐行在金额旁挂三字母代码 —— 金额列仅 88px 且已放着千分位数字，再加必然要改列宽或换行，与 083「不改列宽、不降字号」冲突。

### Session 2026-09-17

- Q: 已手动切过币种后再切换市场页签，币种怎么处理？ → A: **两个市场页签各记各的，互不联动**（修订 Session 2026-09-16 第 5 问的后半段）。在港股页签选 CNY 只影响港股页签；切到美股页签显示 USD（该页签本次未切过），切回港股页签仍是 CNY。原答案让一个页签的选择传导到另一个页签，用户在美股页签看到的是他在**另一个页签**做的选择 —— 而他在这个页签从未表达过。各记各的同时去掉了「是否切过」这个标志本身：每个页签的当前值就是全部状态，少一个需要维护、也少一个会判错的量。不持久化不变：离开交易账户页后两个页签一并复原。

## User Scenarios & Testing

### User Story 1 — 把跨市场持仓折算到同一币种看总量 (Priority: P1)

**Why this priority**: 这是本 feature 存在的唯一理由。当前美股持仓显示 USD、港股持仓显示 HKD，用户在两个市场页签之间切换时，两边的金额无法相加也无法比大小，看不出自己一共持有多少、哪个市场占比更重。没有这条，其余都无意义。

**Acceptance Scenarios**:

1. **Given** 账号在美股与港股页签下各有持仓，**When** 用户把展示币种切到 CNY，**Then** 两个页签下的市值与持仓盈亏均以 CNY 显示，用户在页签间切换即可直接比较跨市场的金额大小
2. **Given** 展示币种为 CNY，**When** 某个市场页签的列表渲染，**Then** 各组的排列顺序与它们在原币种下的顺序相同（同屏各行同币种，折算为等比例缩放），且排序依据与屏幕显示的数字是同一个币种口径
3. **Given** 当前在美股页签且展示币种为 USD，**When** 列表渲染，**Then** 市值与原始回报值一致，未因「折算」而发生任何数值变化
4. **Given** 展示币种为 CNY，**When** 用户查看一只美股持仓的现价与成本价，**Then** 这两个价格仍以 USD 显示并带币种标识（股价本身即以该市场币种计价，折算无业务含义）
5. **Given** 展示币种为 CNY，**When** 用户点进任一持仓的详情页或订单页，**Then** 那些页面的金额与价格仍按原币种显示，不受展示币种影响

### User Story 2 — 不改变默认视图，切换是临时的 (Priority: P1)

**Why this priority**: 与 US1 同为 P1，方向相反但同等重要。083 刚上线，若本 feature 改变了进入页面时看到的数字，等于在没有告知的情况下改掉了既有视图。「折算」是用户临时想看总量时的动作，不该变成常驻状态。

**Acceptance Scenarios**:

1. **Given** 用户进入交易账户持仓页的港股页签，**When** 列表渲染，**Then** 展示币种为 HKD，各行金额即券商回报的原值，与本 feature 上线前的数值与排序完全一致
2. **Given** 展示币种等于当前市场的原币种，**When** 页面渲染，**Then** 不出现参考汇率信息，屏幕上不出现任何折算数字
3. **Given** 用户已把展示币种切到 CNY，**When** 离开交易账户页后再次进入，**Then** 展示币种复原为当前市场原币种
4. **Given** 用户已把展示币种切到 CNY，**When** 点进持仓详情页后返回列表，**Then** 展示币种仍是 CNY（未离开交易账户页）
5. **Given** 用户当前在美股页签（展示 USD）且港股页签本次未切过币种，**When** 切到港股页签，**Then** 展示币种为 HKD
6. **Given** 用户在港股页签把展示币种切到 CNY，**When** 切到美股页签，**Then** 美股页签展示 USD（该页签本次未切过，不受港股页签选择的影响）；**When** 再切回港股页签，**Then** 仍为 CNY

### User Story 3 — 汇率拿不到时不骗我 (Priority: P2)

**Why this priority**: 折算依赖外部行情，必然有取不到的时候。此时显示一个错误的数字，比不显示折算更危险 —— 用户会据此判断仓位。它是降级路径，但正确性要求最高。

**Acceptance Scenarios**:

1. **Given** 展示币种为 CNY 而港元对人民币汇率此刻不可用，**When** 港股页签的列表渲染，**Then** 各行金额以 HKD 原币种显示并带币种标注，屏幕上不出现任何以 CNY 为单位的港股金额
2. **Given** 某持仓行的币种券商未回报，**When** 列表渲染，**Then** 该行按汇率不可用同样降级处理，不被默认成任何币种
3. **Given** 某组内既有可折算行也有降级行，**When** 该组聚合值渲染，**Then** 组市值与组持仓盈亏**两个**聚合值均标注为不完整，且降级行的金额未被混入求和
4. **Given** 列表中同时存在可完整折算的组与含降级行的组，**When** 跨组排序，**Then** 降级组排在所有可完整折算的组之后，组内各行保持原有相对顺序
5. **Given** 展示币种为 CNY 且汇率可用，**When** 用户查看页头，**Then** 显示所用汇率数值与该汇率的取数时刻，措辞表明这是参考汇率而非实时或结算汇率

### Edge Cases

- 选定币种与该行原币种相同时（进入页面时即如此），走不折算的直出路径，避免「乘以 1」引入的舍入差 (covers FR-002, FR-008)
- 同屏各行必然同币种（列表恒按单一市场页签呈现），故折算是等比例缩放；FR-004 的口径一致要求仍须遵守，但它在本 feature 范围内是**防御性**约束而非实发风险 (covers FR-004)
- 跨组排序遇到降级组时沉底处理，不得让未折算的裸数值与已折算数值比大小 (covers FR-004, FR-012)
- 汇率尚在加载时不得先渲染未折算数字再跳变成折算值，用户会看到金额突然变化 (covers FR-009)
- 汇率数据有一定陈旧时仍照常显示并标注取数时刻，不因陈旧而清空或隐藏金额 (covers FR-007)
- 账号无任何持仓时币种选择器仍然可用，不因列表为空而隐藏 (covers FR-001)
- 展示币种等于当前市场原币种时不出参考汇率信息，避免暗示此时也发生了折算 (covers FR-007, FR-011)
- 点进持仓详情再返回列表不算「离开交易账户页」，币种不复原；否则用户每次下钻回来都要重选 (covers FR-005)

## Requirements

### Functional Requirements

- **FR-001**: 交易账户持仓列表页 MUST 提供展示币种选择器，档位为 USD / HKD / CNY 共三档；选择器 MUST 以收起态显示当前币种、展开后列出三档，MUST NOT 做成常驻平铺的分段/页签形态
- **FR-002**: 当选定币种与该屏持仓的原币种不同时，系统 MUST 将金额类数据折算为该币种显示，金额类包含：单行市值、单行持仓盈亏、分组市值、分组持仓盈亏
- **FR-003**: 系统 MUST NOT 折算价格类数据，价格类包含：现价、成本价、行权价；这些数值始终以其所属市场的原币种显示并带币种标识
- **FR-004**: 分组聚合与跨组排序 MUST 与屏幕显示使用同一币种口径；系统 MUST NOT 出现「按原币种排序、按折算币种显示」的错位
- **FR-005**: 展示币种的选择 MUST NOT 持久化 —— 离开交易账户页后再进入时 MUST 复原为当前市场的原币种。该选择在本次停留期间 MUST 保持（含从持仓详情页返回列表）；两个市场页签的展示币种 MUST 各自独立 —— 在某页签所做的选择 MUST NOT 影响另一页签，切走再切回该页签时 MUST 仍为其本次停留内最后所选
- **FR-006**: 当某行所需汇率不可用、或该行币种未知时，系统 MUST 以该行原币种显示其金额并标注币种，MUST NOT 显示任何折算后的数字；含此类行的分组，其**组市值与组持仓盈亏两个聚合值**均 MUST 标注为不完整，且 MUST NOT 把未折算金额混入求和
- **FR-007**: 当展示币种不等于当前市场原币种时，系统 MUST 显示所用汇率数值与该汇率的取数时刻，且措辞 MUST 表明其为参考汇率；系统 MUST NOT 宣称该汇率为实时汇率或可用于结算。当展示币种等于当前市场原币种时，MUST NOT 显示汇率信息
- **FR-008**: 当某行原币种与选定币种相同时，系统 MUST 直出原值而不经折算路径，以免引入舍入差
- **FR-009**: 切换展示币种后，列表 MUST 即时按新币种重算金额、重新聚合分组并重新排序，无需用户手动刷新
- **FR-010**: 展示币种的作用范围 MUST 限于持仓列表页；持仓详情页与订单列表/详情页的金额与价格 MUST 始终按原币种显示，不受展示币种影响
- **FR-011**: 本次停留内首次进入某个市场页签时，该页签的展示币种 MUST 为该市场的原币种；此时列表的金额数值与排序 MUST 与未引入本功能前一致，且 MUST NOT 出现参考汇率信息
- **FR-012**: 含降级行的分组在跨组排序中 MUST 沉底，排在所有可完整折算的分组之后；这些分组之间及组内各行 MUST 保持其原有相对顺序
- **FR-013**: 币种选择器 MUST 在收起态即显示当前展示币种；降级行 MUST 明确标注该行原币种；系统 MUST NOT 为此改变列表既有的列宽或字号

### Key Entities

- **展示币种**：用户在持仓列表页选定的金额呈现口径；三档（USD / HKD / CNY）；只影响呈现，不改变任何已落库的持仓金额。它是**本次停留期间的临时状态，且按市场页签各自独立**：每个页签首次呈现时为该市场原币种，手动切换只对当前页签即时生效，离开该页后两个页签一并复原，不写入本地存储。
- **原币种**：某持仓行所属市场的计价币种，由券商回报提供（美股为 USD、港股为 HKD）；券商未回报时为未知，此时该行按降级处理。它不是可选档位，但仍是「进入页面时的落点」与「是否需要折算」的判定依据。
- **参考汇率**：把某一币种的金额换算为展示币种所用的比率；来自外部公开行情源，携带取数时刻；与券商实际结汇或交收汇率无关，不用于结算，也不承诺与之一致。仅在展示币种 ≠ 当前市场原币种时才存在并呈现。
- **降级行**：因所需汇率不可用、或原币种未知而无法折算的持仓行；以原币种呈现并明确标注币种；其金额不参与所属分组的聚合。
- **降级组**：含至少一个降级行的正股组；其组市值与组持仓盈亏两个聚合值均标注为不完整，且在跨组排序中沉底于所有可完整折算的组之后。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 选定某个具体币种后，列表中 100% 的金额类字段以该币种显示（降级行除外，降级行 100% 带原币种标注）
- **SC-002**: 在汇率可用的前提下，跨组排序结果与屏幕显示金额的大小关系 100% 一致；且因同屏各行必然同币种，折算前后的组顺序 100% 相同
- **SC-003**: 汇率不可用时，屏幕上以选定币种为单位显示的错误金额数量为 0
- **SC-004**: 用户切换展示币种后，列表在 1 秒内完成重算与重排，期间不出现金额数值的二次跳变
- **SC-005**: 离开交易账户页后再次进入时，两个市场页签的展示币种等于各自市场原币种的比例为 100%；本次停留期间（含从详情页返回、含切走再切回该页签）保持该页签所选币种的比例为 100%；某页签的选择影响到另一页签的次数为 0
- **SC-006**: 进入持仓列表页时的**金额数值与排序**与本 feature 上线前 100% 一致（逐字段比对）
- **SC-007**: 本 feature 上线前后，持仓列表的列宽与字号 100% 不变

## Assumptions

- **持仓列表恒为单一市场**：列表按市场页签分开呈现（`us` / `hk` 两档，无「全部」档），且服务端查询本身按单一市场过滤 ⇒ **同屏各行必然同币种**。这使 FR-004 所禁的排序错位在本 feature 范围内**结构上不可能发生**；FR-004 仍保留为防御性约束 —— 将来若出现跨市场汇总视图，它就是那时的正确判据。这同时也是「不设『原币种』档」成立的前提：单市场下该档与该市场币种档显示结果逐字相同。
- 持仓行的币种由券商回报提供。082 采集的券商持仓样本中该字段只出现 USD 与 HKD 两种取值、未见空值（定性结论；原始样本见 `docs/private/evidence/`，per information-boundary）。尽管如此，FR-006 仍要求处理币种未知的分支 —— 券商回报的字段可空，样本无空值不等于契约保证非空。
- 汇率来自外部公开行情源，属参考汇率，与任何券商的实际结汇/交收汇率无关。本 feature 不承诺两者一致。
- 本 feature 只改变金额的**展示**口径，不改变任何已落库的持仓金额、不改变同步逻辑、不改变分组规则本身（分组仍按正股聚合）。
- 展示币种状态与既有的市场 / 分段选择同层（进程内、不落本地存储），因此不引入任何新的持久化机制。
- 币种以三字母代码呈现（`USD` / `HKD` / `CNY`），沿用既有 `市值（USD）` 体例；本 feature 不引入货币符号。
- Web 兼容性按 `full` 声明：本 feature 不引入任何仅原生可用的能力（与同页 083 的声明一致）。
- **明确不在范围内**：① 持仓详情页、订单列表页、订单详情页的金额与价格折算（FR-010 显式排除）；② 账户级汇总即跨券商或跨市场的总资产合计（083 已记「本片不做」，本 feature 同样不做）；③ 用户自定义汇率或手工录入汇率；④ 历史某时点的汇率回溯；⑤ 展示币种的跨会话持久化（本次明确不做）。
