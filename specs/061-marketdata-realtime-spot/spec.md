# Feature Specification: 行情实时面 + 美股正股盘中价接入期权台雷达

**Feature Branch**: `061-marketdata-realtime-spot`
**Created**: 2026-08-17
**Status**: Draft
**Input**: 让美股正股的盘中价在交易时段内做到 30 秒级刷新，喂给期权台雷达的排序键「距 W%」；同时在行情模块长出一个通用的实时行情面，供后续市场与后续消费方复用，而预警模块的现有行为一行不动。

## Clarifications

### Session 2026-08-17（起片时）

- **Q**: 刷新间隔取多少？ → **A**: **30 秒**。上游探针实测标的报价每 9–26 秒推进一次，60 秒会系统性欠采样（每两拍漏 2–6 次价格变动）；而行情源配额余量 60 倍、单次响应 10 KB 级、端到端 0.12 秒 ⇒ 提速不产生任何成本。新鲜度闸随之派生为 **90 秒**（见下一条）。
- **Q**: 新鲜度闸取刷新间隔的几倍？ → **A**: **3 倍 = 90 秒**（原先写「3–4 倍」是个区间，等于留了第二个没人定的自由变量）。取 3 而不是 4 的理由：熔断阈值是连续 **3** 轮失败，3 × 30 秒 = 90 秒 ⇒ 「熔断打开」与「数据被判陈旧」**同刻发生**。取 4 会留出 30 秒窗口——熔断已开、界面还在按实时档呈现，正是本 feature 最想消灭的那种「静默骗人」形态。
- **Q**: 价格档位要不要呈现给用户？ → **A**: **不上屏**。档位进 API 响应（供调用方与排查用），但界面**只以 `asOf` 的粒度**表达它：实时档呈**时刻**、收盘档呈**交易日**。理由：档位标记会是一个新的视觉元素（用文字？圆点？颜色？放哪？），而 `asOf` 的粒度变化已经无歧义地表达了同一件事，不必为它多定一套视觉语言。
- **Q**: 交易时段怎么判 —— 自己维护时段表，还是读行情源的市场状态？ → **A**: **读行情源的市场状态**。收盘竞价的结束时刻本就不该由我们猜：港股侧实测收盘竞价状态持续到官方收盘后 8 分钟、期间价格一路在动，写死时段表会拿到竞价前的价当收盘价**且不报错**。代价是不支持实时的市场没有对应状态，其时段判定留待后续 feature。
- **Q**: 距 W% 实时化后排序键在翻页过程中就在动，怎么办？ → **A**: **维持现有分页语义不变，显式接受漏/重，并下一条 tripwire**（锚数达默认页大小 80% 时重新评估）。为一个当前用不上的场景引入排序快照缓存属过度设计，且会衍生「第 2 页的价该标实时还是陈旧」这个新的未决问题。⚠️ 一处措辞订正：最初写的是「当前锚数远低于单页容量，该路径不可达」—— **两半都要收窄**。「远低于」不准（现锚数已达默认页大小的约三分之二，tripwire 只差几只锚就会响）；「不可达」也只在默认页大小下成立，调用方主动请求更小的页时今天就可达。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 盘中看雷达，距 W% 是「现在」的 (Priority: P1)

美股开盘期间我打开期权台雷达，每只锚的「距 W%」反映的是此刻的正股价，而不是昨天的收盘价；排序也随之实时重排 —— 今天跌到我的建仓带里的票会自己浮上来，不必等到明天。

**Why this priority**: 这是本 feature 的诉求本体。当前雷达价的时效上限是「延迟一整天」，意味着盘中出现的建仓机会在当天完全不可见 —— 而期权建仓的判断窗口本来就是以小时计的。没有这条，后面两条都无处附着。

**Independent Test**: 美股交易时段内打开雷达，静置观察两分钟：距 W% 的数值发生变化，且变化节奏与正股实际报价一致；同一时刻的排序与按实时价手工计算的排序一致。

**Acceptance Scenarios**:

1. **Given** 美股处于常规交易时段且某锚的正股价正在变动，**When** 用户停留在雷达页并触发刷新，**Then** 该锚的距 W% 反映的是不超过一个刷新周期之前的价，且接口回报的价格档位为「实时」（界面侧的对应表现是 `asOf` 呈时刻，见 FR-009）
2. **Given** 多只美股锚的实时价使它们的距 W% 相对次序发生了变化，**When** 用户查看雷达，**Then** 列表按实时价重新排序，次序与按实时价手工计算的一致
3. **Given** 某锚的实时价与收盘价差异显著，**When** 用户查看该锚，**Then** 呈现的时间戳是一个**时刻**（而非日期），使「这是盘中价」不需要推断即可读出

---

### User Story 2 - 数据不新鲜时它明说，不冒充 (Priority: P2)

非交易时段、行情源断了、或者某个市场根本不支持实时 —— 这些时候雷达上的价格必须明确告诉我「这是收盘价」，而不是给我一个看起来像实时价的旧数，更不能给 0。

**Why this priority**: 一个会静默骗人的价格比没有实时价危险得多 —— 它会让我在断源期间按一个陈旧的距 W% 下建仓判断。这条是 P1 的安全前提，但它本身不产生新能力，故列 P2。

**Independent Test**: 人为断开行情源，观察雷达：三轮失败后所有美股锚的档位切回「收盘」、距 W% 仍是可用的数（来自收盘价）而非 0 或空白；恢复源后无需任何人工操作即自动回到「实时」档。

**Acceptance Scenarios**:

1. **Given** 行情源连续三轮不可用，**When** 用户查看雷达，**Then** 所有受影响的锚回落到「收盘」档 —— 界面上表现为 `asOf` 从时刻变回交易日 —— 距 W% 由收盘价算出，**且既有的实时价不被清空**
2. **Given** 处于非交易时段，**When** 用户查看雷达，**Then** 呈现为「收盘」档，且系统在该时段内不对行情源发起任何调用
3. **Given** 某锚所属市场当前不在实时支持范围内，**When** 用户查看该锚，**Then** 它恒为「收盘」档且与其他锚并列可比，不表现为错误状态
4. **Given** 行情源恢复可用，**When** 下一轮采集成功，**Then** 档位自动回到「实时」，无需人工介入
5. **Given** 任一降级场景，**When** 距 W% 无法计算，**Then** 它显式为空，**MUST NOT 呈现为 0**（0 是一个有意义的距离值，用它表达「没有数据」会被读成「正好在带上」）

---

### User Story 3 - 收盘那一刻雷达就是当日收盘价 (Priority: P3)

美股收盘后我打开雷达，看到的已经是当天的收盘价，而不是要等某个后台批处理追上来之后才更新。

**Why this priority**: 这是 P1 的免费副产品 —— 只要盘中采集的窗口覆盖到收盘那一拍，收盘价就自然到手了。它独立可测、独立交付价值（缩短「收盘 → 可决策」的空窗），但不实现它 P1 依然成立，故列 P3。

**Independent Test**: 在美股收盘后两分钟内打开雷达，把显示的价与该交易日的官方收盘价比对，两者一致；且此时用于收盘价的常规每小时投影尚未运行过。

**Acceptance Scenarios**:

1. **Given** 美股常规交易时段刚刚结束，**When** 用户在收盘后两分钟内查看雷达，**Then** 呈现的价即为当日收盘价
2. **Given** 后续的收盘价投影随后运行并写入权威收盘价，**When** 两者比对，**Then** 用户看到的数值不发生可感知的跳变

### Edge Cases

- 行情源新增了一个我们没见过的市场状态值，系统会不会把它当成「开市」而在盘前或夜盘误采？(covers FR-002, FR-003)
- 行情源本身不可达、连市场状态都取不到时，系统是停下还是默认开市继续采？(covers FR-003)
- 市场状态说「开市」但当天其实是节假日（源侧状态机滞后），以哪个为准？(covers FR-011)
- 一轮采集里有的标的取回了、有的没取回，没取回的那些会不会被写空？(covers FR-008, FR-013)
- 刚建好、还没经历过任何交易时段的锚，在雷达上排在哪里？(covers FR-014)
- 收盘后的一段时间里，收盘价与盘中最后一笔「都是今天的」，排序会不会在两个来源之间来回抖？(covers FR-006, FR-007)
- 锚的数量增长到超过单页容量之后，翻页过程中排序键仍在变，会不会漏掉或重复某些锚？(covers FR-016)
- 港股锚已经可以建（模型导入通道已上线），它们混在同一张雷达上时会不会因为「没有实时价」被判成故障？(covers FR-010)

## Requirements _(mandatory)_

### Functional Requirements

**采集与时段**

- **FR-001**: 美股常规交易时段内，系统 MUST 以不超过 **30 秒**的间隔刷新美股锚对应正股的实时价
- **FR-002**: 交易时段判定 MUST 依据行情源给出的市场状态，且 MUST 采用**白名单**语义 —— 仅明确列举的「常规交易」状态视为开市；白名单之外的一切状态（含未来新增的未知值）MUST 按闭市处理并留痕
- **FR-003**: 市场状态不可得时系统 MUST fail-closed —— 不采集、显式留痕、计入失败计数，MUST NOT 默认当作开市
- **FR-004**: 采集 MUST 按锚所属市场分组求值，市场状态闸与交易日闸 MUST **逐市场**判定；本 feature 的分组中只有美股一个成员，但该结构 MUST 能容纳第二个市场而不需改形
- **FR-005**: 盘中采集窗口 MUST 延伸到常规交易状态结束之后至少一拍，使当日收盘价在收盘当刻即被收入
- **FR-011**: 市场状态闸与交易日闸 MUST 取**交集** —— 二者任一为否即不采集；交易日闸 MUST NOT 被市场状态顶替

**新鲜度与档位**

- **FR-006**: 实时价的新鲜度 MUST 以**系统自身的采集时刻**判定；行情源自带的时间戳 MUST NOT 参与新鲜度判定（它是「最后成交时刻」而非「报价时刻」，实测其盘中滞后中位 40 秒、p95 292 秒、最大 672 秒，按它判会在正常交易时段内把活跃标的稳定误判成陈旧）
- **FR-007**: 新鲜度阈值 MUST 由刷新间隔**派生**，倍数固定为 **3**（= 90 秒），MUST NOT 在第二处独立配置成一个手写数字。刷新间隔 MUST 是系统中唯一的自由变量 —— 倍数本身**不得**再留成一个区间
- **FR-009**: 每条锚的价格 MUST 携带明确的档位标记（实时 / 收盘）并出现在接口响应中。呈现层 **MUST NOT** 为档位新增独立的视觉标记，而是**只以 `asOf` 的粒度**表达它：实时档呈**时刻**，收盘档呈**交易日**

**排序与呈现**

- **FR-008**: 距 W% 的排序 MUST 在实时价新鲜时采用实时价，否则回落收盘价；该回落 MUST 是单点裁决，MUST NOT 在两个来源之间产生抖动
- **FR-014**: 既无实时价也无收盘价的锚，其距 W% MUST 显式为空，MUST NOT 呈现为 0，且 MUST NOT 因空值被排到榜首或榜尾造成误读
- **FR-016**: 雷达的分页语义 MUST 在本 feature 内保持不变。实时化带来的「翻页期排序键变动 ⇒ 行跨过游标会被漏掉或重复」是**显式接受**的取舍。⚠️ 该取舍的适用条件要说准：**在客户端使用的默认页大小下**，当前锚数尚未触发分页；但调用方若主动请求更小的页，分页路径**今天就可达**——本 feature 不为此额外设防。🚨 系统 MUST 在锚数达到**默认页大小**的 **80%** 时使这一条重新可见（tripwire），MUST NOT 让它在锚数增长后静默失效

**降级与韧性**

- **FR-010**: 不在实时支持范围内的市场（当前为港股与 A 股）MUST 显式表达为「该市场不支持实时」，MUST NOT 静默返回空、MUST NOT 表现为系统故障
- **FR-012**: 连续 **3** 轮采集全部失败 MUST 触发熔断并显式降级为收盘档；熔断恢复 MUST 自动，MUST NOT 需要人工介入
- **FR-013**: 任何降级路径（熔断 / 非交易时段 / 市场不支持 / 单个标的缺失）MUST NOT 清空既有的实时价与其采集时刻 —— 清空会把「陈旧但可用」误降成「不可用」
- **FR-017**: 一轮内部分标的失败 MUST NOT 导致整批回滚；成功的落库、失败的保留旧值

**边界不变式**

- **FR-015**: 收盘价的语义 MUST 不变 —— 它仍是当日收盘的权威值与一切降级的落脚点；盘中价是与它**并列的第二个来源**，不是替代
- **FR-018**: 预警模块的现有盘中行为 MUST 逐字节不变；本 feature MUST NOT 修改其现役实时行情契约
- **FR-019**: 实时行情 MUST NOT 落库存历史 —— 历史归既有的日线数据，本 feature 只保留「最近一次」
- **FR-020**: 盘前 / 盘后 / 夜盘三族价格 MUST NOT 被消费；本 feature 只取常规交易时段的最新成交价

### Key Entities

- **估值锚**：期权台雷达的行主体。新增两个自有属性 —— **盘中实时价** 与 **该价的采集时刻**；既有的收盘价与收盘交易日两个属性语义不变
- **价格档位**：标记某个价来自实时源还是收盘源，值域为「实时」/「收盘」二档（枚举已存在，无需新增值）
- **市场状态**：行情源给出的某市场当前开闭状态，是交易时段判定的唯一依据；其值域由观察枚举，白名单之外一律按闭市处理

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 美股常规交易时段内，正股成交到雷达上距 W% 反映出该变化的端到端延迟 **P95 ≤ 60 秒**（= 刷新间隔 30 秒 + 30 秒处理余量）
- **SC-002**: 美股收盘后 **2 分钟内**打开雷达，显示的价与该交易日官方收盘价一致，且此时收盘价投影尚未运行
- **SC-003**: 断源与非交易时段两类降级场景下，**100%** 的美股锚呈现为收盘档且距 W% 由收盘价算出；呈现为 **0 的锚数为 0**
- **SC-004**: 预警模块既有盘中预警的回归验证全绿，行为差异为 **0** 项
- **SC-005**: 单个交易时段内本 feature 对行情源的调用量占其配额的 **≤ 5%**（设计值 1 次/30 秒 vs 配额 60 次/30 秒 ≈ 1.7%）
- **SC-006**: 连续 **3 个**美股交易日的采集在无人工干预下全程运行，失败轮次可从留痕中逐条查出
- **SC-007**: 熔断触发到恢复的全过程中，用户可见的价格**没有任何一刻**是 0 或空白

## Assumptions

- **行情源的市场覆盖受账号权限限制** —— 美股与港股有实时权限、A 股没有。这是本 feature 只覆盖美股（港股留待后续 feature）、且实时源必须按市场路由而非全局替换的根因；预警模块的 A 股盘中预警因此 MUST 继续走它现有的源
- **锚的数量**：当前 13 只，规格上限按约 1000 只设计；行情源单次批量查询上限 400 个标的 ⇒ 最坏情况一轮 3 次调用，当前一轮 1 次。⚠️ **切批是采集侧调用方的职责，不是行情源适配层的** —— 适配层对超限**显式拒绝**（沿既有同源适配层的成例：同一段边界逻辑写两遍必漂移）
- **行情源限频**：60 次 / 30 秒
- **交易日历数据已存在**且可被本 feature 跨模块只读取用
- **收盘价的既有每小时投影继续运行**，本 feature 不改它；本 feature 只是卸掉它的时效压力，不是取代它
- **实时行情面是新建的通用面**，不是把预警模块现有的那个实时契约搬过来 —— 后者的键是行情源专有符号形态，属单市场专用，契约归一留待后续 feature
- **本 feature 同时触发了三条已写好的架构决策 sunset 条件**（实时行情从单消费者升格为共享能力 / 跨模块读形态升格 / 服务端强一致同步读场景出现），因此交付物 MUST 包含对应的架构决策修订，而非纯功能实现
