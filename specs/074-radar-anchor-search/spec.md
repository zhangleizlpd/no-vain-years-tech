# Feature Specification: 雷达页锚搜索 —— 温度计旁搜索入口 + 底部浮层按名称直达锚详情

**Feature Branch**: `074-radar-anchor-search`
**Created**: 2026-09-03
**Status**: Draft
**Input**: User description: "击球区雷达页头部在温度计入口旁新增搜索按钮；点击弹出底部浮层（搜索框 + 防抖 + 提示列表）；输入中文名/拼音简拼/代码实时给出提示，点击提示行直达该票的标的详情页；搜索域仅限已建锚的标的；提示行 = 标的名 + market:code + L 级徽标；server 侧提供锚域模糊搜索能力，锚表零 schema 变更"

**病根一句话**：雷达上的锚已到 140 只（美股 112 + 港股 28）且还在涨，L 级筛选只能把列表收窄成「一档几十只」，想看**某一只具体的锚**仍要靠滚动肉眼扫 —— 港股行首还是数字代号，扫起来更慢。缺一个「输入名字 / 代码 → 直达那只锚」的定位通道。

## Clarifications

### Session 2026-09-03

- Q: 交易意愿已关闭（excluded）的锚，要不要进搜索域？（这类锚不显示在雷达列表上）→ A: 搜得到，不加标记 —— 搜索是定位通道不是可动区镜头，被排除的锚恰恰只能靠搜索找到；提示行保持三字段不加新徽标

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 按名称 / 代码 / 拼音直达某只锚 (Priority: P1)

用户在雷达页想查看某只具体的锚（例如「腾讯」）。点击题头温度计旁的搜索按钮，底部弹出搜索浮层；输入「腾讯」（或「txkg」「700」任一形态），提示列表立即给出「腾讯控股 hk:00700 L2」这样的行；点击该行，浮层关闭、直接进入该标的的详情页 —— 与在雷达列表里点到这一行是同一个目的地。

**Why this priority**: 这是本片唯一的核心旅程，其余 story 都是它的边界反馈。没有它，定位一只锚的成本随锚数线性上涨。

**Independent Test**: 只实现「入口 + 浮层 + 搜索 + 点击直达」，对任一已建锚标的用中文名、代码、拼音简拼三种输入各搜一次，均能在提示列表命中并一步到达详情页，即构成完整 MVP。

**Acceptance Scenarios**:

1. **Given** 雷达页已加载，**When** 用户点击题头搜索按钮，**Then** 底部浮层弹出且搜索框就绪可输入
2. **Given** 浮层已打开，**When** 输入某只已建锚标的的中文名（或其一部分），**Then** 提示列表出现该标的行，含标的名、市场:代码、生效 L 级徽标
3. **Given** 同一只锚，**When** 分别用交易所代码（含 `BRK.B` 这类带点形态）与拼音简拼输入，**Then** 均能命中同一行
4. **Given** 提示列表已出现命中行，**When** 点击该行，**Then** 浮层关闭并进入该标的的详情页，内容与从雷达行点入完全一致
5. **Given** 当前停在港股页签且勾选了 L1 筛选，**When** 搜索一只美股 L3 的锚，**Then** 该锚照常命中（搜索不受页签与筛选约束）；关闭浮层后页签与筛选保持原状

---

### User Story 2 - 无命中与失败的显式反馈 (Priority: P2)

用户输入了一个不存在的名字、或一只没建过锚的票、或此刻网络不通。浮层必须把「搜不到」和「搜不了」区分开、说清楚，而不是留一片空白让用户怀疑自己没搜。

**Why this priority**: 搜索域刻意限定在「已建锚」，这个边界只有靠显式空态才能被用户理解；失败静默则会被误读为「没这只锚」。

**Independent Test**: 分别构造「零命中」「标的存在但无锚」「请求失败」三个输入场景，验证三种反馈形态各自正确且互不混淆。

**Acceptance Scenarios**:

1. **Given** 浮层已打开，**When** 输入任何无命中的串，**Then** 显示「无匹配的锚」类显式空态，且不提供建锚等旁路入口
2. **Given** 某只票在标的库存在但从未建锚，**When** 按其名称搜索，**Then** 该票不出现在结果中（呈现同零命中）
3. **Given** 搜索请求失败，**When** 用户停止输入等待结果，**Then** 浮层内出现错误提示且可重试，浮层不关闭、雷达页不受影响
4. **Given** 搜索框为空或仅空白，**When** 用户尚未输入有效内容，**Then** 结果区不显示任何内容 —— 尤其不显示「无匹配」空态

---

### Edge Cases

- 输入含 SQL / 模糊匹配元字符（`%`、`_`、`:`、引号）：按字面处理，不报错、不改变匹配语义
- 单个汉字（如「腾」）：应能命中含该字的锚
- 超长输入串：正常处理或按上限截断，不崩溃
- 命中数超过一页上限：截断到上限呈现（继续细化输入即可收窄，不做翻页）
- 标的名尚为注册表占位（名=代号）：照实显示代号，不拼假名（同雷达行降级纪律）
- 交易意愿已关闭的锚：可被搜到并直达详情 —— 它不在雷达列表上，搜索正是其主要入口（Clarifications 2026-09-03）
- 防抖窗口内快速连续输入与删除：只有最后一次输入产生结果，不出现旧输入的结果闪回
- 搜索期间锚被并发增删：结果按查询时刻快照呈现即可，不要求实时一致

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 雷达页题头 MUST 在温度计入口旁提供搜索入口，视觉体例与既有题头图标一致（放大镜形态、同尺寸热区）
- **FR-002**: 点击搜索入口 MUST 弹出底部浮层，内含搜索框与结果区；浮层可经遮罩 / 取消手势关闭，关闭后雷达页状态（页签、筛选、滚动位置）不受影响
- **FR-003**: 搜索 MUST 同时支持中文名、拼音简拼、拼音全拼、交易所代码四路输入形态的模糊匹配，并容错近似输入
- **FR-004**: 搜索域 MUST 仅限已建锚的标的；未建锚标的 MUST NOT 出现在结果中，且浮层 MUST NOT 提供建锚旁路。域的判据严格是「有没有锚」：交易意愿已关闭（不显示在雷达列表上）的锚 MUST 照常命中，提示行不加额外标记（Clarifications 2026-09-03）
- **FR-005**: 搜索 MUST 跨市场覆盖全部已建锚标的，MUST NOT 受当前市场页签与 L 级筛选约束
- **FR-006**: 提示行 MUST 呈现三样：标的名、市场:代码、生效 L 级徽标（徽标视觉与雷达行一致）；MUST NOT 呈现行情类数值（现价 / 距 W% 等）
- **FR-007**: 点击提示行 MUST 关闭浮层并进入该标的的详情页，目的地与点击雷达行完全一致
- **FR-008**: 输入 MUST 经停顿防抖后才发起搜索；防抖窗口内的连续输入只有最后一次生效
- **FR-009**: 零命中 MUST 显示显式空态文案；空输入 MUST NOT 显示空态（结果区留空）
- **FR-010**: 搜索请求失败 MUST 在浮层内给出错误提示并允许重试，MUST NOT 关闭浮层或影响雷达页
- **FR-011**: 结果 MUST 按「代码精确命中优先 → 相似度 → 代码序」排序，单次呈现有上限（一页，无翻页控件）
- **FR-012**: 搜索能力的鉴权与合规门 MUST 与既有雷达 / 锚管理呈现面一致（登录 + markets 合规位），不开放新的匿名面

### Key Entities

- **锚（Anchor）**: 已由用户建立估值锚的标的，搜索域的成员判据；持有生效 L 级（提示行徽标来源）。本片对锚 **零结构变更**
- **标的注册表（Instrument）**: 标的名 / 拼音 / 代码的唯一真相源，搜索匹配的字段来源；已验证当前 140/140 锚全部能关联到注册表且拼音覆盖完整
- **搜索命中行**: 一次搜索的呈现单元 = 标的标识（名 + 市场:代码）+ 生效 L 级；点击语义 = 直达该标的详情页

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 用户从雷达页定位到任一具体的锚 ≤ 3 次交互（点搜索 → 输入 → 点结果行），全程 10 秒内可完成
- **SC-002**: 全部已建锚标的（当前 140 只）用中文名、交易所代码、拼音简拼三种输入形态搜索，每种形态命中率 100%
- **SC-003**: 输入停顿后 1 秒内提示列表完成呈现（含零命中空态）
- **SC-004**: 未建锚标的在结果中出现 0 次；搜索前后雷达页的页签 / 筛选状态变化 0 次

## Assumptions

- 搜索域跨市场、不受当前页签与筛选影响 —— 「精准定位某只锚」语义下，用户输入名字时不关心自己停在哪个页签
- 结果单页上限沿用既有标的搜索体例（约 20 行），零命中细化输入即可，不做翻页
- 浮层交互体例参考既有「加入自选」搜索浮层（底部 sheet + 防抖 + 提示列表），但去掉分组选择与加入动作 —— 本浮层是纯定位通道
- 提示行不承载行情数值：定位场景只需「是哪只」，数据由详情页承载
- 锚表零 schema 变更；名称 / 拼音的唯一真相源是标的注册表（探查实证：140/140 锚 join 命中，us+hk 拼音覆盖 22556/22556）
- 服务端已具备经过验证的多路模糊匹配能力（既有标的搜索在用），本片在锚域上复用同一套匹配语义，不发明新的匹配规则
- 搜索为查询时刻快照，不要求与锚增删实时一致（浮层生命周期内锚集变化属可接受窗口）
