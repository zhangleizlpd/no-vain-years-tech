# Feature Specification: 选约表横滑范式换代 + 行权价区间筛选 + 意图 Tab 重设计

**Feature Branch**: `049-optionsdesk-leg-table-scroll-filter`
**Created**: 2026-08-10
**Status**: Draft
**里程碑**: sell-put 可视化决策系统 —— 047（M2b）已 ship 后的**修复 + 收窄**片，排在 048（M2c 跨标的聚合视图）之前

## 背景：为什么切在这里，为什么排在 048 之前

047 已 ship 的选约表有一个**正确性缺陷**和两笔**产品欠账**，三者都落在同一张表上，且都是 048 的前置。

### 一、横滑失步是缺陷，不是规模问题（已由 ADR-0063 定案）

047 的实现让**表头与每一个数据行各挂一个横向滚动容器**、共享一个位移值、靠「谁滚了就把其余容器推到同一位移」来同步。真机上反复出现**列左右震荡 / 表头自己在滚 / 行间失步**，2026-07 起至少三次，行数从 10240 到 200 都复现。

[ADR-0063](../../docs/adr/0063-mobile-frozen-column-table-scroll-sync.md)（Accepted, 2026-08-10）定案：根因是**跟随者容器把系统钳制后的位移写回共享值**，形成不收敛的自激环 —— **与行数无关**，只要任一容器的钳制边界与其余不同，环就不收敛。采纳方案 E（零滚动容器：单一横向拖拽手势 → 单一共享位移 → 各行各自位移），并逐条否决了其余六个候选。

⇒ 本片是该 ADR 的**实施载体**。ADR 只落了决策，被判为缺陷载体的那段实现一行未动。

**这条决定了本片必须排在 048 之前**：048 的跨标的聚合表要复用同一套横滑范式，在缺陷载体上再叠一层聚合，等于把同一个环复制到第二个屏。

### 二、730 行没有任何收窄手段

单票选约表按全量呈现原则渲染，实测上界 730 行。屏上除三个意图 Tab（成员判据切片）外**零筛选控件** —— 用户要从 730 行里找一个行权价段位，只能靠手滑。

### 三、意图 Tab 视觉过弱

三个 Tab 夹在意图条与 12 列表头之间，字号与行高都是全屏最小的一档，**看不出它是这张表的主控件**。

## Clarifications

### Session 2026-08-10

- Q: 横向滑动指示条什么时候出现？ → A: 有可滑动余量就常显，不做「滑动时才现、停手后淡出」
- Q: 筛选框获焦、软键盘弹起时怎么处理？ → A: 不做整屏键盘避让；筛选行右端在获焦期间提供「完成」以收起键盘
- Q: 行权价输入的小数位上限取多少？ → A: 2 位
- Q: 「清除筛选」放哪里？ → A: 筛选行右端，与「完成」共用同一个槽位

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 横向看隐藏列，表不散架 (Priority: P1)

用户在标的详情页的选约表上左右滑动查看被隐藏的列（费率、成本、Δ、σ 距、OI、成交额、标注、动作）。行权价那一列始终钉在左侧不动，表头与所有数据行**作为一个整体**横向移动。用户随手来回滑动多次、松手，表停在该停的位置。

**Why this priority**: 这是**缺陷修复**，不是新功能。当前实现会让表在真机上散架 —— 列震荡、表头自漂、行与行之间错位到读错数（行权价对上了别人的报价）。一张读错数的期权表比没有表更危险。且它是 048 的硬前置。

**Independent Test**: 只做这一块就能独立交付：真机上对同一张 730 行的表反复手滑，配数值探针观察位移写入与方向反转计数，与修复前的对照数据比较。

**Acceptance Scenarios**:

1. **Given** 选约表已渲染且列宽合计超出可视宽，**When** 用户横向滑动，**Then** 表头与全部可见行的同一列左缘逐像素对齐，行权价列一像素不动
2. **Given** 用户随手来回快速滑动十余次，**When** 松手并静置三秒，**Then** 位移停止增长并收敛；🚨 **判定必须靠数值探针** —— 「净位移为零但写入仍在涨」是自激环的签名，此时静态截图看起来是对齐的
3. **Given** 用户在表格区域纵向滑动，**When** 纵向位移超过方向仲裁阈值，**Then** 列表纵向滚动且横向位移不变（横向手势让位）
4. **Given** 用户横滑到最右端，**When** 继续向左拖，**Then** 最后一列完整露出且不越界，松手不回弹到越界位置
5. **Given** 用户旋转屏幕或进入分屏，**When** 可视宽度改变，**Then** 横向位移被拉回新的合法区间，且仍能滑到最右列

### User Story 2 - 按行权价区间收窄 (Priority: P2)

用户在表头上方的筛选行里填入行权价的下界与上界（任一端可留空表示不限），表格立即只显示落在该区间内的腿。计数条同时告诉用户「筛后多少行 / 全量多少行」，并给出一个常驻的清除入口。换一只标的时筛选自动清空。

**Why this priority**: 730 行是当前最大的可用性瓶颈，但它是**可用性问题不是正确性问题** —— 用户今天靠手滑仍能完成任务，只是慢。

**Independent Test**: 独立可测：在有腿数据的标的详情页输入区间、观察行数与计数条变化、清除、切 Tab、切标的。

**Acceptance Scenarios**:

1. **Given** 表当前显示 N 行，**When** 用户填入下界与上界，**Then** 表只显示行权价落在闭区间内的腿，计数条转为「筛后 X / 全量 N」，清除入口出现
2. **Given** 筛选生效中，**When** 用户点清除，**Then** 表恢复全量、计数条恢复原文案、清除入口消失
3. **Given** 用户只填一端，**When** 另一端留空，**Then** 按单边开区间筛选（留空端不设限）
4. **Given** 用户把下界填得比上界大，**When** 两端都能解析出数值，**Then** **筛选不生效、表保持全量**，同屏给出显式提示 —— MUST NOT 筛成空表（空表会被读成「这只票没有腿」）
5. **Given** 筛选后无任何腿命中，**When** 表为空，**Then** 显示「筛选后无匹配」而不是「该 Tab 零适格腿」，且清除入口常驻
6. **Given** 筛选生效中，**When** 用户切换意图 Tab，**Then** 筛选条件保留，计数条分母按新 Tab 的筛前行数重算
7. **Given** 筛选生效中，**When** 用户离开并进入另一只标的的详情页，**Then** 筛选条件已清空
8. **Given** 用户正在输入（只打了一个小数点或前导零），**When** 该端尚不能解析成数值，**Then** 不报错也不生效，表保持当前状态
9. **Given** 用户点中筛选输入框，**When** 软键盘弹出，**Then** 筛选行与表头栈原位不动、输入框与至少三行结果同屏可见，且筛选行右端出现「完成」可收起键盘

### User Story 3 - 一眼看出自己在哪个意图下 (Priority: P3)

用户扫一眼就能分辨当前停在「全腿 / 建仓腿 / 收租腿」的哪一个，且点击热区足够大不误触。

**Why this priority**: 纯视觉可用性。功能今天是通的（三个 Tab 都能进、切换都生效），只是不显眼。放在最后，因为它是**唯一一块不影响正确性、也不阻塞 048 的**。

**Independent Test**: 独立可测：选中态与未选态在样式上可区分、三个 Tab 均可进入、切换后表内容确实更换。

**Acceptance Scenarios**:

1. **Given** 用户停在某个 Tab，**When** 扫视 Tab 行，**Then** 选中项与未选项在视觉上明确可分（不依赖读屏语义）
2. **Given** 某个 Tab 下零适格腿，**When** 用户点它，**Then** 仍可进入并显示空态 —— MUST NOT 置灰或隐藏（继承 047 FR-020）
3. **Given** 表头栈已加入筛选行与更高的 Tab 行，**When** 用户进入详情页并滚到腿区，**Then** 表格数据区仍有可用高度（栈不把表压成一条缝）

### Edge Cases

- 表格列宽合计**不超过**可视宽（宽屏 / 未来减列）→ 无可滑动余量，横向指示条整条不渲染，拖拽不产生位移
- 用户在锚卡 / 温度计 / 区间时序区域横滑 → 位移照常发生（那时表在屏外，视觉无感），MUST NOT 为此加坐标判定这类脆逻辑
- 腿的行权价字段取不到值 → 该行**保留**在表内（与 047 FR-007「greeks 缺失也不筛除」同族：「不知道」不等于「不匹配」）
- 输入法吐出非数字字符（部分 Android 输入法在数字键盘下仍可输入分隔符与负号）→ 在输入时刻吞掉，不进入筛选条件
- 软键盘弹出时的版式 → **不做整屏避让**，筛选行与表头栈原位不动，输入框与至少三行结果同屏可见；输入非法值触发提示时不掉焦、键盘不收
- 筛选生效期间数据刷新（改仓位水位导致整表失效重取）→ 筛选条件保留，按新数据重新求值
- 三个 Tab 的空态与筛选空态同时可能发生 → 两者文案必须可区分（是「没有腿」还是「被筛掉了」）

## Requirements _(mandatory)_

### Functional Requirements

#### 横向滑动（US1）

- **FR-001**: 选约表的横向位移 MUST 由**单一来源**驱动，表头与全部数据行读同一个位移值；MUST NOT 存在任何「跟随者把自己的实际位移写回共享值」的路径（该路径是 ADR-0063 判定的自激环成因）
- **FR-002**: 首列（行权价 / 到期）MUST 保持钉住不动，其钉住方式沿用 047 的布局判据（首列渲在横向位移区之外），本片不改
- **FR-003**: 横向与纵向手势 MUST 各自归属明确：横向位移超过仲裁阈值才接管横滑；纵向位移超过阈值则让位给列表纵向滚动。MUST NOT 出现纵滑被横向手势吃掉、或横滑期间列表纵向抖动
- **FR-004**: 横向位移 MUST 被约束在合法区间内（左端为零、右端为「内容宽减可视宽」），松手后的惯性衰减同样受该约束；**可视宽变化时（旋转 / 分屏）位移 MUST 被拉回新区间**
- **FR-005**: 由于新范式不再有系统原生的横向滚动条，系统 MUST 自绘一条横向位置指示条，其长度比例反映「可视宽 / 内容宽」、位置反映当前位移。**有可滑动余量时 MUST 常显** —— MUST NOT 做成「滑动时才出现、停手后淡出」：隐藏列占了表总宽的一半以上，静态首屏是用户唯一能得知「这张表还能横滑」的时机。无可滑动余量时整条不渲染。指示条为只读，本片不做可拖拽
- **FR-006**: 指示条的位置 MUST 由驱动表格的**同一个**位移值派生，MUST NOT 另立第二个来源（否则引入表与指示条不同步这一新的失步面）
- **FR-007**: 047 已定的列集、列宽、首列宽度与「横向滑动查看隐藏列」这一能力 MUST 保持不变 —— 本片只换实现机制，不改 047 `FR-003` 的任何判据

#### 行权价筛选（US2）

- **FR-008**: 系统 MUST 在意图 Tab 行与 12 列表头之间提供一行筛选器，含行权价的下界与上界两个数值输入
- **FR-009**: 筛选 MUST 实时生效（输入即筛，无需确认动作），并 MUST 与意图 Tab 的成员判据**复合**生效（先按 Tab 取成员，再按区间收窄）
- **FR-010**: 任一端留空 MUST 被视为该端无界；两端都留空 MUST 等价于未筛选
- **FR-011**: 下界大于上界时，筛选 MUST 退化为不生效（表保持全量）并给出显式提示；**MUST NOT 返回空表**
- **FR-012**: 输入 MUST 在输入时刻拒绝非法字符（非数字、负号、第二个小数点、**小数位超过 2 位**），使筛选条件中永远只存在合法形状的值
- **FR-013**: 行权价取不到值的腿 MUST 保留在表内，MUST NOT 被区间筛选剔除
- **FR-014**: 计数条 MUST 在未筛选时保持原有「共 M 行」文案；筛选生效时 MUST 转为「筛后 N / 全量 M」，其中 M 是**当前 Tab 的筛前行数**，MUST NOT 是全 Tab 全量、更不能是渲染窗口大小
- **FR-015**: 筛选生效时 MUST 常驻一个清除入口，位于**筛选行右端**，点击后恢复全量。该位置与 `FR-023` 的「完成」**共用同一槽位**：输入获焦期间显「完成」，失焦且筛选生效时显「清除」—— 两者互斥出现，MUST NOT 同时占两份宽度（表头栈高与宽度都是本片最紧的资源）
- **FR-016**: 筛选命中 0 行时 MUST 显示区别于「该 Tab 零适格腿」的专用空态，明确告知是筛选所致
- **FR-017**: 切换意图 Tab MUST 保留筛选条件；切换标的 MUST 清空筛选条件（行权价是标的相关的量纲）；筛选条件 MUST NOT 跨会话持久化
- **FR-018**: **对 047 `FR-005` 的显式改判** —— 「MUST NOT 筛除 / MUST NOT 截断」这条禁令**继续完整适用于系统侧行为**（top-N、静默丢弃、「划到底再加载」式分页）；**用户显式发起、当前可见、随时可清除的筛选不属于该禁令**。该豁免的成立以 `FR-014` / `FR-015` / `FR-016` / `FR-017` 四条配套同时落地为条件 —— 缺任一条，筛选就退化成「静默丢弃」

- **FR-023**: 筛选输入获焦、软键盘弹出时，系统 MUST NOT 做整屏键盘避让 —— 筛选行与其上方的表头栈保持原位，键盘只遮住下半屏的数据行，输入框与至少三行结果同屏可见。获焦期间筛选行右端 MUST 提供「完成」以收起键盘（数字键盘无系统级「完成」键，否则用户无从收起）。非法值提示出现时 MUST NOT 导致输入框掉焦或键盘收起

#### 意图 Tab（US3）

- **FR-019**: 三个意图 Tab 的视觉 MUST 重新设计，使选中态一眼可辨、点击热区足够；具体形态由 mockup 阶段出 2–3 稿后选定
- **FR-020**: Tab 改版 MUST NOT 改变其行为契约：三个 Tab 恒可进入、恒不置灰、恒不按条件隐藏（继承 047 `FR-017` / `FR-020`）；就地注明仍渲在 Tab 行下方；切 Tab 仍只更换表格数据而不重建列表
- **FR-021**: Tab 的无障碍语义（角色、选中状态、标签）MUST 保留；且选中与未选 MUST 在**视觉样式**上可区分，不得仅靠无障碍语义编码
- **FR-022**: 表头区（警示条 + 计数条 + 意图与水位条 + Tab 行 + 就地注明 + 筛选行 + 列头 + 指示条）的总高 MUST 留给表格数据区可用高度；mockup 阶段 MUST 给出该总高与视口的占比证据

### Key Entities

- **行权价区间**: 用户输入的收窄条件，含下界与上界两端，每端可为「未设」；与意图 Tab 正交，与标的绑定（换标的即失效）
- **筛选后计数**: 一对数（筛后行数 / 筛前行数），筛前行数以**当前 Tab** 为口径

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 真机上对 730 行的选约表连续手动横滑十余次并松手静置，位移写入停止增长、方向反转计数不再增加；与修复前同条件对照，反转计数下降**两个数量级以上**（修复前实测 558 次 / 修复后个位数）
- **SC-002**: 横滑过程中任意时刻截停，表头与全部可见行的同列左缘偏差 **≤ 1 像素**（修复前实测首行与全表错开约 35 像素）
- **SC-003**: 纯纵向滑动时横向位移变化为 **0**；纯横向滑动时列表纵向位置不变
- **SC-004**: 横滑到最右端时最后一列**完整可见且无越界空白**；旋转屏幕后仍满足该条
- **SC-005**: 用户从进入详情页到把 730 行收窄到 20 行以内，**操作次数 ≤ 3**（两次输入 + 收起键盘），且无需滚动查找筛选入口
- **SC-006**: 任一时刻用户都能从屏上读出「当前看到的是全部还是筛后的一部分」—— 未筛选时显总行数，筛选时显筛后与全量两个数
- **SC-007**: 非法输入（下界 > 上界）不会让用户看到空表；空表只可能来自「真的没有腿」或「筛选确实无命中」，且两者文案可区分
- **SC-008**: 筛选后的行集合恒为筛前集合的**子集**且**保持原有排序**（不重排、不去重、不补行）
- **SC-009**: 在 730 行下逐字符输入筛选条件，界面无可感知卡顿（每次按键的结果在下一帧可见）
- **SC-010**: 选中的意图 Tab 与未选的在视觉样式上可区分（可由自动化断言以样式自比较验证，不依赖无障碍语义）
- **SC-011**: 加入筛选行与新 Tab 形态后，表格数据区在标准手机视口下仍可见 **≥ 3 行**腿数据；**软键盘弹出时同样满足该条**（表头栈不把表压成一条缝，键盘也不把结果全遮住）

## Assumptions

- **行权价是本片唯一的筛选维度**（已拍板）。权利金 / 到期天数 / 费率等维度不在本片范围，将来若加，`FR-018` 的豁免逻辑可直接复用
- **筛选在客户端完成**：腿数据本就是单次全量取回（047 已定形态），筛选是呈现层的收窄，不改变数据获取方式，因此本片零服务端改动
- **输入精度取两位小数**（已 clarify）：美股行权价的实际步长以 0.5 / 1 / 2.5 为主，两位足够；且与仓内价格显示统一两位的口径一致。⚠️ 这只约束**筛选输入**，行权价列本身的显示口径仍是去尾零（047 为 88px 窄列做的刻意选择），本片不动
- **表格列数维持 12 列不变**，因此本片不需要横向虚拟化（ADR-0063 假设横向不虚拟化，前提是列数受控）
- **纵向虚拟化沿用 047 的现状**（全页单一纵向滚动容器），本片只改横向，两个方向正交
- **真机是唯一的验收环境**（针对 US1）：合成手势是单指、单向、无交错的干净手势，ADR-0063 已实证缺陷实现在它下面**完全测不出问题**；网页端视口宽松同样必然假绿
- **Tab 形态延后到 mockup 阶段决定**，spec 只钉行为契约与不可动的约束（`FR-020` / `FR-021`）
- **048 的 V-C 验证判据需随本片改写**（ADR-0063 已记：规模不再是那道 gate 的风险源），但改写动作**属于 048**，本片只备措辞不改其文件
