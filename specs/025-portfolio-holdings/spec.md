## User Scenarios & Testing _(mandatory)_

### User Story 1 - 持仓数据导入（Priority: P1）

用户在本机将同花顺投资账本导出的汇总持仓 Excel（含持仓数据、已清仓、交易记录三部分）上传到服务端；服务端解析校验后，将该账户名下的持仓快照、已清仓记录、全量交易流水**整体替换**为本次文件内容，并返回导入摘要（各部分入库/跳过行数）。重复上传同一文件结果不变（幂等）。

**Why this priority**: 数据源是整个 feature 的地基——没有导入，持仓展示、013 持仓组、预警买卖点参考全部无米下锅。

**Independent Test**: 用真实样本文件（2 持仓 + 1 已清仓 + 23 条流水）调用导入接口，断言返回摘要行数与库内数据一致；重复导入断言结果状态不变。

**Acceptance Scenarios**:

1. **Given** 已登录账号且库内无持仓数据, **When** 上传合法的汇总持仓 xlsx, **Then** 三类数据全部入库，返回摘要列出各 sheet 入库行数与跳过行（含跳过原因，如"汇总"聚合行）
2. **Given** 库内已有上次导入的数据, **When** 上传新导出的文件, **Then** 该账户旧数据被整体替换为新文件内容，无残留、无重复
3. **Given** 同一文件已导入过, **When** 再次上传同一文件, **Then** 导入成功且库内数据与上次一致（幂等）
4. **Given** 上传文件缺少必要 sheet 或非 Excel 格式或超过大小上限, **When** 导入, **Then** 整体拒绝并返回明确错误，库内数据保持导入前状态
5. **Given** 文件中个别数据行含 `--`/空值等不可解析字段, **When** 导入, **Then** 该字段按空处理或该行跳过并在摘要留痕，其余行正常入库

### User Story 2 - 持仓与已清仓查看（Priority: P2）

用户在 App 内查看自己的当前持仓列表（持有数量、摊薄成本、仓位占比、持仓天数、累计盈亏，叠加实时行情计算的现价/浮动盈亏）与已清仓历史（建仓/清仓日期、买入/卖出均价、总盈亏、跑赢大盘），对自己的投资全貌一目了然。

**Why this priority**: 用户明确诉求"显示曾经的建仓和清仓数据"；这是导入数据的第一消费面。

**Independent Test**: 导入样本数据后打开持仓屏，断言当前持仓 2 行与已清仓 1 行的关键字段正确显示；行情字段随报价接口返回值变化。

**Acceptance Scenarios**:

1. **Given** 用户在投资 tab 自选主屏, **When** 点击顶部工具栏「持仓」入口, **Then** 进入持仓屏（默认当前持仓视图，可切已清仓 tab）
2. **Given** 已导入样本数据, **When** 打开持仓列表, **Then** 显示 2 条当前持仓，每行含名称、持有数量、摊薄成本、仓位占比、持仓天数、累计盈亏，以及由实时行情合成的现价与浮动盈亏
3. **Given** 已导入样本数据, **When** 切换到已清仓视图, **Then** 显示已清仓记录，含建仓日期、清仓日期、买入/卖出均价、总盈亏、盈亏比、跑赢大盘
4. **Given** 持仓中含行情系统不可识别的标的（如国债逆回购）, **When** 查看列表, **Then** 该行降级展示（无行情字段），不影响其他行
5. **Given** 账号从未导入数据, **When** 打开持仓屏, **Then** 显示空态与"持仓数据待导入功能"类引导文案

### User Story 3 - 标的历史买卖点查看（Priority: P2）

用户按标的查看自己的全部历史交易记录（精确到秒的买入/卖出时间、价格、数量、费用，以及除权除息、税费等事件），作为收到预警后判断买卖点的参考。

**Why this priority**: 用户明确诉求"基于历史的交易数据作为报警后我买卖点的参考"——这是本 feature 与预警体系的衔接点。

**Independent Test**: 导入样本后按 (market, code) 查询国茂股份，断言返回其全部 9 条相关流水（买入×4/卖出×2/除权除息×1/股息个税×2）按时间序排列。

**Acceptance Scenarios**:

1. **Given** 已导入样本数据, **When** 查询国茂股份的交易历史, **Then** 返回该标的全部流水（含买卖、除权除息、股息个税征收），按成交时间排序，每条含类别、数量、价格、金额、费用
2. **Given** 已导入样本数据, **When** 在标的交易历史屏查看, **Then** 买入/卖出记录可视区分（买卖点参考），非交易事件（除权除息等）一并可见
3. **Given** 查询从未交易过的标的, **When** 查询其交易历史, **Then** 返回空列表（非错误）

### User Story 4 - 持仓组自动派生（Priority: P3）

导入完成后，013 自选体系中的系统"持仓"分组成员自动与持仓事实对齐：份额>0 且行情系统可识别的标的进入持仓组；清仓/清空后自动移出。用户无需手动维护。

**Why this priority**: 013 已预留派生只读持仓组（V1 空态），本 feature 补上数据源闭环；依赖 US1 故 P3。

**Independent Test**: 导入样本后查看 013 持仓组，断言成员 = 当前持仓中行情可识别的标的集合；再导入一份清空持仓的文件，断言持仓组清空。

**Acceptance Scenarios**:

1. **Given** 导入了含 2 条股票持仓的文件, **When** 查看自选体系的持仓组, **Then** 持仓组成员恰为这 2 只股票
2. **Given** 持仓中含行情不可识别标的, **When** 派生持仓组, **Then** 该标的不进入持仓组（持仓列表仍可见）
3. **Given** 再次导入后某标的份额归零或消失, **When** 派生完成, **Then** 该标的自动移出持仓组
4. **Given** 持仓组为派生只读, **When** 用户尝试手动增删持仓组成员, **Then** 仍按 013 既有规则拒绝（本 feature 不改变只读语义）

### Edge Cases

- 持仓 sheet 末行"汇总"聚合行（代码列='汇总'）：跳过不入库，摘要留痕
- 交易类别覆盖 7 种实测值（买入/卖出/除权除息/股息个税征收/质押回购拆出/拆出质押购回/其他）；出现未知新类别时按"其他类"入库并在摘要警示，不丢行
- 资金转入转出行（类别='其他'）代码/名称/时间为空：照存（未来现金口径唯一来源），不参与标的维度查询
- 除权除息行名称带 `XD` 前缀：保留原始名称不清洗
- 列名带日期后缀（如"当日盈亏05-06"）：解析按列语义映射，不依赖列名全等
- 同一标的"已清仓记录"与"当前持仓"并存（清仓后重建仓）：两处独立展示，不互斥
- 部分盈亏字段为 `--`（多次买卖无法单算）：按空值入库，展示端显示占位
- 导入文件的导出日期（asOf）语义：快照字段（仓位占比/持仓天数/累计盈亏）均为"截至导出日"口径，展示需带 asOf 标注
- 并发导入（同账户两次上传交叠）：后完成者整体覆盖，不产生混合状态

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 系统 MUST 提供认证后的文件导入能力，接受同花顺投资账本导出的汇总持仓 Excel（三 sheet：持仓数据/已清仓/交易记录），并校验文件类型、大小上限与必要 sheet 存在性
- **FR-002**: 系统 MUST 按"账户整体替换"语义落库：单次导入在一个事务内替换该账户全部持仓快照、已清仓记录与交易流水；任何整体性失败不留半态
- **FR-003**: 系统 MUST 按已锁定的字段保留清单持久化（持仓 27→8、已清仓 13→9、交易记录 11 列全存），并对每行附原始行数据备查；时变行情类字段不持久化
- **FR-004**: 系统 MUST 对脏数据行级容错：`--`/空值规范化、"汇总"聚合行跳过、未知交易类别归入兜底类，均在导入摘要中可见
- **FR-005**: 系统 MUST 返回导入摘要：各 sheet 入库行数、跳过行数及原因、本次快照的导出日期（asOf）
- **FR-006**: 重复导入同一文件 MUST 幂等（库内结果状态一致）
- **FR-007**: 用户 MUST 能查看当前持仓列表（持有数量/摊薄成本/仓位占比/持仓天数/累计盈亏 + 实时行情合成字段）与已清仓列表（建仓/清仓日期、买卖均价、总盈亏、盈亏比、跑赢大盘）
- **FR-008**: 用户 MUST 能按标的（market, code）查询本人全部历史交易流水，按成交时间排序，买卖方向可区分
- **FR-009**: 导入完成后系统 MUST 派生 013 系统持仓组成员：份额>0 且行情可识别的标的集合；不可识别标的不入组但持仓列表可见；持仓清空时组员清空；持仓组只读语义不变
- **FR-010**: 持仓数据 MUST 归属用户默认账户（不关联具体券商账户，不预留空列）；所有读写均以登录账号隔离
- **FR-011**: 导入与查询能力 MUST 可被脚本类客户端使用既有 token 体系调用（无新增认证机制）
- **FR-012**: 本 feature MUST 交付配套本机同步工具（拉取 + 上传两段，仓内维护）：复用本机浏览器既有登录态拉取同花顺导出文件，并自动续期登录凭证后调用导入能力；首次使用需人工登录一次。验收方式为本机人工跑通完整同步一轮（不进 CI 自动化）

### Key Entities

- **持仓快照（Holding）**: 某账户截至导出日（asOf）的单标的持仓事实——标的标识 (market, code)、名称（参考）、持有数量、摊薄单位成本、仓位占比、持仓天数、累计盈亏（额/率）+ 原始行备查；仅保留最新一次导入
- **已清仓记录（ClosedPosition）**: 一轮完整建仓→清仓的封闭结果——标的标识、建仓/清仓日期、买入/卖出均价、总盈亏、盈亏比、交易费用、同期大盘/跑赢大盘 + 原始行备查
- **交易流水（TradeRecord）**: 账户全量历史交易事实源——成交日期/时间、标的标识（资金行可空）、原始名称、交易类别（7 类 + 兜底）、数量、价格、发生金额、成交金额、费用、备注 + 原始行备查
- **导入摘要（非持久化响应）**: 单次导入的结果回执——asOf、各类入库/跳过统计与原因

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 用真实样本文件完成一次导入往返（上传→落库→摘要返回）耗时 < 10 秒；摘要行数与库内逐表一致（样本口径：2 持仓 + 1 已清仓 + 23 流水，跳过 1 汇总行）
- **SC-002**: 同一文件连续导入 2 次，第二次后库内数据与第一次后逐行一致（幂等验证 0 差异）
- **SC-003**: 导入后 013 持仓组成员与"份额>0 且行情可识别"的持仓事实 100% 一致，无需任何手动操作
- **SC-004**: 持仓屏可见全部已导入持仓与已清仓记录；标的交易历史查询返回该标的 100% 流水且时序正确（样本国茂股份 9 条）
- **SC-005**: 含脏数据（`--`/汇总行/未知类别）的文件导入成功率 100%（行级容错不中断），且每条跳过/规范化在摘要可追溯

## Assumptions

- 同花顺导出文件为全量历史口径（交易记录自开户起全覆盖）——整体替换幂等语义依赖此前提；若未来导出窗口化，需改增量策略（已在方案文档风险备注）
- 汇总持仓文件本身是多资金账户聚合口径，V1 不区分券商账户，全部挂默认账户（012 读侧虚拟派生），不预留券商关联空列
- 本机同步工具（拉取 + 上传）是本期交付物（FR-012），但属客户端配套工具、不在服务端能力面内；其产出文件与手动导出文件等价，导入端点对两者一视同仁
- 行情/最新价/区间涨幅等时变指标一律由既有行情能力（015 /quote、EOD 数据）在读取侧合成，持仓数据不冗余存储
- 单用户单账户、低频导入（手动或脚本日频），无多租户并发导入压力
- 预警体系（021/022/预警指标）与本 feature 的运行时联动（如报警弹窗内嵌买卖点）不在本期 scope，本期只交付按标的查询历史买卖点的能力与展示屏
