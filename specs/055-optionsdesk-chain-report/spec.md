# Feature Specification: 标的链分析报表 —— 打开选约表之前，先看清这条链的机会长什么样

**Feature Branch**: `055-optionsdesk-chain-report`
**Created**: 2026-08-14
**Status**: Draft
**Input**: 看数逻辑与标定实测 `docs/private/plans/2026-08/08-14-optionsdesk-chain-report-reading-logic.md`（本机私有）；上游 master plan `docs/private/plans/2026-08/08-11-optionsdesk-leg-engine-master.md` 的 P5 行与退出标准（同上，本机私有）

## 背景：这一片补的是哪一个洞

选约表回答的是「**这个视角、这套条件下，前 N 条腿是什么**」——它是**已经决定好带什么条件之后**的执行工具。

但用户在打开它之前先要回答四个问题，而这四个问题今天**只能靠在选约表里逐条翻**：这条链该挂哪一段期限？同一段期限里价外让到多深？哪些位置真有人接？这条链现在整体值不值得挂？

⇒ 本片做的是选约表的**上游**：一屏之内把整条链的机会分布铺开，让用户带着结论去选约，而不是在 573 行里翻出结论。

📌 **它不是选约表的补充列，也不是它的另一种排版。** 两条判据由此而来：① 报表的总体 **MUST NOT** 被当前视角的期限段裁过 —— 裁过就回答不了「我该去哪个视角」；② 报表 **MUST NOT** 复用选约表的显示条数截断 —— 那是给逐条阅读设的认知负荷手段，而报表要的是全景。

## Clarifications

### Session 2026-08-14（设计阶段，写 spec 前已定）

- Q: master plan P5 行写的「regime 读数」怎么处置？→ A: **改为链级 IV 分位**，复用 046 已有的读数与四态。原措辞与 046 `FR-015` 📌（2026-08-03 拍板）正面冲突 —— 那次否掉的是**市场级** regime N/X（vault 未给 N/X 的机械判据，且三处一手依据一致把它定性为「温度计的极致读数 + 人判 + 无 gate」），并留下两条机器断言。**市场级 regime 与链级 IV 分位是同名不同物**，后者不冲突且零新增采集。
- Q: 格子里放什么？→ A: **随视角切换的双读数 + IV 期限结构曲线解毒**。单以年化为格值必然呈现「越短越亮」的单调梯度，而那是时间折算的算术产物（年化 ∝ 1/√T，`FR-004` 已成文）。实测印证：被行下界排除的深实值腿年化中位数 154.6%、最高 237.7%，全是内在价值造成的假象。
- Q: 报表是独立屏还是详情屏的折叠块？→ A: **独立屏**。折叠块被详情屏的手势结构堵死：049 的横滑手势挂在包住整个列表的那一层且覆盖列表头部，报表自身也要横滑 ⇒ 同一手势树两个横滑消费者。
- Q: 活跃度是单开一张图还是并进同一张网格？→ A: **并进同一张网格作为第四种格值**。切换保持行列对齐 ⇒「这格机会好但没人接」的对照靠位置完成，无需在两张图之间找对应。

- Q: 从「全腿」或「活跃度」格值下点格子，下钻落到选约表的哪个视角？ → A: **落全腿视角**。⇒ `FR-039`
- Q: 报表与选约表是两个屏、两次取数，中间可能跨换日或换批报价 ⇒ 下钻后条数与报表所示不符。怎么处置？ → A: **复用选约表侧已有的业务日比对机制**，两侧不一致时显式告知两个时点，零新增契约字段。⇒ `FR-039a`、`SC-010` 收窄为「同一业务日下一致」
- Q: 色阶的档界按全局固定还是每链自适应？ → A: **全局固定**（每种格值各一套，跨标的跨业务日恒定），取值走一次实测标定。⇒ `FR-019a`
- Q: 未建锚的标的，报表可达吗？（起草时的 edge case 说「建仓格值不可用、其余三种照常」，但那与入口位置矛盾 —— 详情屏未建锚时是整页建锚引导，三块不存在） → A: **不可达**，入口随建锚引导一起不出现。⇒ `FR-037a`，并删去原 edge case

### Session 2026-08-14（档界标定实测后的三处定夺）

实测面 = dev 库 `2026-08-11` 那一期 / **12 条链 / 3531 条认沽腿**，三视角召回判据**逐字按 `leg-recall.rules.ts` 复刻**（权利金门槛 + 活性门槛三视角一律；建仓另加 DTE 段 / 流动性门槛 / 有效成本硬门槛；收租另加 DTE 段 / 流动性门槛 / 成色上界）。

🚨 **这一轮首先订正了一个口径错误**：四种格值**各自跑在不同的召回集**上，而起草期的标定脚本对全部过权利金门槛的腿统一算年化、未按视角切分 ⇒ 当时读成「收租年化在价内区爆炸」。按真判据复算后，**收租年化没有爆炸**（值域仅 `[2.2, 71.4]`，成色上界本就不召回深价内腿），爆炸的只有全腿年化。下面三条定夺都建立在订正后的数上。

- Q: 一个格「空」现在有第四种成因 —— 有腿、过了三视角一律的门槛、但不在当前格值对应视角的召回集内（实测占全网格：建仓格值 **35.3%** / 收租格值 **28.0%**）。怎么编码？ → A: **两级编码**。期限段造成的那部分走**列级**淡出（复用 `FR-009` 的召回段标记），段内其余成因归已有的「被门槛挡下」格态。🚫 不为它单开第四种格级色码。⇒ `FR-009a`、`FR-016a`<br>📌 实测支持这个分工：建仓格值下第四成因的 **87%（280/322 格）落在召回段之外** ⇒ 列级手段一刀管掉绝大部分，剩给格级的只有 42 格。收租格值下这个比例是 49%（125/255），两级都用得上。
- Q: 全腿年化格值下价内 0-10 行 max **948.3%** / p75 **95.0%**，而其余各行 max ≤ **141.8%** —— 全是内在价值造成的假象。怎么处置？ → A: **该行不参与色阶**，走「口径不适用」标记，读数与下钻照常。⇒ `FR-019c`
- Q: master plan P5 行的「DTE 活跃度分布」是一维（每到期日汇总一个数）还是二维？ → A: **二维**，即已有的第四种格值。🚫 不另加按到期日的一维分布条 —— 一屏高度预算（`FR-041` 零纵向滚动）要从曲线或页头挤，而列求和这件事用户在网格上做得到。
- Q: 实装里「三视角一律」的门槛其实有**两道**（权利金 + 活性），而页脚只有两个计数、`FR-005` 也只提了权利金。活性挡下的那批腿归哪儿？ → A: 骨架**维持只过权利金**（活性挡下的腿有合约、只是没人碰过，踢出骨架会误报成「无合约」），页脚**加第三个互斥计数**。⇒ `FR-005` 补注、`FR-034` 改三计数、`SC-006` 同步<br>🚨 这一条在本轮内**改过一次口径**：初判用「骨架全域上被活性挡下 985 条 = 27.9%」当分量，实为**与②重复计** 865 条；按互斥拆分真值是 **120 条 = 11.0% of 行下界内**。⇒ 加它的理由随之从「量级大」换成「在全腿格值下它是『被门槛挡下』格的**唯一**成因」。

## 标定实测（T020，2026-08-15 跑完）

> `FR-019a` / `FR-019b` / `SC-012` 的取值来源。**四组数与形态都由本节的实测定案**，产出物 = `apps/mobile/src/optionsdesk/chain-report-scale.rules.ts` 的 `CHAIN_REPORT_BAND_SCALES`。改那四组数 MUST 重跑本节的方法，🚫 不许就地拍一个「看着更整」的数。

### 样本窗口与污染自检

- **窗口 = 4 个业务日**：`2026-08-10 / 11 / 12 / 13`（dev 库 `mbw_poc`，每日 12 条链）。⚠️ 起草期的 `FR-019b` 只有**单日**实测，答不了「单日分位标出来的数换一天漂不漂」—— 那正是本 task 存在的理由。
- 🚨 **数据面污染自检（052 T016 撞过「12 只票共用同一个 spot」）**：逐日核对**每票 spot 互异** —— 四天全部 **12/12 去重**，非 mock。

### 方法（口径同源，🚫 零重推）

一次性脚本（本机 local-only，不入库），**调服务端那份真代码**而不是在 SQL 里重推判据：链的读取与 dedupe 逐字照抄 `leg-retrieval.adapter.ts#loadChain`（`PUT ∧ is_standard ∧ 到期日 > 业务日`，同合约同日按 `quote_as_of` 取新的那条）；成员集走 `recallCandidates(ctx, LEG_TABS, legs, legs.length, null)`；四种格值走 `computeEffectiveCostVsWPct` / `computeLegRates` / `activityVolume`；分格与聚合走 `classifyOtmBand` + `aggregateCell`。**取到的样本 = 屏上真正着色的那些格值**（每格的最优值），不是腿级值。

📌 `all_annualized` 的样本**排除价内那一行**（`FR-019c` 已把它移出色阶）—— 含着它标出来的档界会被内在价值的算术假象拉偏。

### 四组定案

| 格值     | 形态          | 切点                           | 4 日汇总样本 | 逐日最大档（上限 50%）        |
| -------- | ------------- | ------------------------------ | ------------ | ----------------------------- |
| 建仓成色 | `linear`      | `-20 / -3 / 14 / 31`           | 240 格       | 39.4 / 36.8 / **43.5** / 36.4 |
| 收租年化 | `quantile`    | `0.065 / 0.12 / 0.20 / 0.30`   | 530 格       | 21.3 / **27.4** / 22.4 / 25.0 |
| 全腿年化 | `quantile`    | `0.035 / 0.065 / 0.115 / 0.21` | 1119 格      | 21.8 / **22.0** / 21.4 / 21.7 |
| 活跃度   | `quantile` ⚠️ | `45 / 215 / 535 / 1150`        | 1548 格      | 21.0 / 21.6 / 20.7 / **22.2** |

`SC-012` 在**每一个**标定日上都成立（不是只在汇总上成立）。

### 🚨 本轮唯一的口径改动：活跃度从 `log` 改成 `quantile`

起草期按「幂律长尾 ⇒ 走对数」把活跃度定成 `log`。实测证伪：值域 `[1, 131693]` 上的等比切点 `11 / 112 / 1180 / 12464` 让**中间那一档吃到 50.4%**，`2026-08-11` 与 `2026-08-12` 两天破 `SC-012`（另两天 48.8% / 46.9%，擦着线过）。

⇒ 「幂律 ⇒ 对数」只保证**切点跨越量级**，不保证**每档人数均衡**；而 `FR-019b` 的可验判据要的正是后者。分位切法按构造均衡。📌 形态只描述这四个常量**当初怎么切出来的** —— 运行期它们是固定值，色阶不随当日样本浮动，故这次改动不触碰 `FR-019a`「全局固定」。

### 设备权威几何（🚫 别拿名义参数换算）

`adb shell dumpsys window displays` ⇒ `init=1224x2700 520dpi base=1088x2400 462dpi app=1088x2292`。

- 有效 **462dpi ⇒ 2.8875 px/dp** ⇒ 屏 **376.8 × 831.2 dp**、应用区 **793.8 dp**。

### 🚨 ⑤ 首轮 FAIL：列头整行在真机上高度塌成 0（已修）

`chain-report-grid.tsx` 的**列头行**与**范围框行**父容器方向不同，而 `LegColumnPane` 自带 `flex-1`：

| 行     | 结构                                                    | `flex-1` 落在 | 结果                                                       |
| ------ | ------------------------------------------------------- | ------------- | ---------------------------------------------------------- |
| 范围框 | `LegColumnPane` 直挂 `flex-row`                         | **宽**        | ✅ 高度由内容撑（14px）                                    |
| 列头   | 多包一层 `<View className="flex-1" onLayout>`（column） | **高**        | ❌ `flexBasis:0` ⇒ 高塌成 0，被自身 `overflow-hidden` 裁净 |

那层包装只为拿 `onTrackLayout`，却把轴翻了。修法 = 给它加 `flex-row`，与范围框行同构。

🚨 **web e2e 结构上照不到这件事**：`chain-report-out-of-band-chip` 的可见性 + `toHaveCount(2)` 断言在 web 上**一直是绿的** —— CSS 下 auto 高的 flex 容器仍按 max-content 参与父高计算，Yoga 直接得 0。**同一份断言在两个平台上问的不是同一个问题**，绿了也不能替真机背书。这条属 `mobile-impl-playbook` §「无确定高度父容器内禁裸 `flex-1`」的一个新形态：坑不在视口宽窄，在**跨端 flex 主轴语义差**。

### 手势归属（`state_branch` 16-17）

`Gesture.Exclusive(crosshairPan, columnPan, cellTap)`，`crosshairPan = Pan().activateAfterLongPress(300ms)`。三种情形各自实测：

1. **直接快拖**（600px / 1600ms）→ 列移动（thumb `208 → 247 → 287 → 333` 单调），4/4 帧**无读数面板** ⇒ 十字线未激活。
2. **按住不动**（4000ms，位移 8px）→ 读数面板出现，**网格区 `y 1055..1791` 零像素变化** ⇒ 列不动。
3. **按住后再拖**（254px / 4000ms，前 300ms 仅位移 19px < 触摸 slop）→ 读数由 `09-04 21天` 换到 `09-11 28天`，而 thumb **恒在 `x=208`** ⇒ 十字线跟手指走、列仍不动。
4. **松手** → 读数面板消失（`FR-025`）。

⚠️ **取证纪律两条**（都当场踩过）：`adb shell "input swipe … &"` 的子进程随 shell 退出被杀，长按探针必须用宿主侧后台作业；`input motionevent` 分次注入 `DOWN`/`MOVE` **不形成同一条触摸流**（前后帧零像素差 = 事件根本没送到），拿它下结论会得到一个假的「十字线不跟手」。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 一屏看出这条链的机会分布 (Priority: P1)

用户从标的详情进入报表，**不滚动**即可看到整条链按「价外深度 × 到期日」铺开的机会网格，并可在四种读数之间切换：建仓成色、收租年化、全腿年化、活跃度。每个格子给出该位置**最好的那条腿**的读数与该位置的腿数。

**Why this priority**: 这是本片的全部价值所在。没有网格，其余三个故事都无所依附；有了网格，即使曲线、三态、下钻都没做，用户也已经能回答「该挂哪段期限、价外让到多深」——那正是他今天做不到的事。

**Independent Test**: 在一条已知形状的链上打开报表，网格的行数、列数、每格的读数与腿数可逐一核对；切换四种格值，行列位置不变而读数按各自口径变化。全程无需滚动。

**Acceptance Scenarios**:

1. **Given** 某标的链有多个到期日与多档价外、且已建锚，**When** 用户打开报表，**Then** 网格、页头读数、格值切换、页脚计数全部落在首屏之内，用户无需纵向滚动即可看到全部行
2. **Given** 网格已渲染且当前格值为「收租年化」，**When** 用户切到「建仓成色」，**Then** 行与列的位置逐格不变，仅格内读数与着色按建仓口径重算
3. **Given** 某格内有多条腿，**When** 用户查看该格，**Then** 该格同时给出最优读数与格内腿数
4. **Given** 链的到期日数超过一屏可容纳的列数，**When** 用户横向滑动，**Then** 列随手指移动、首列（价外档标签）保持冻结、滑到最右端时末列完整露出且不越界

### User Story 2 - 分辨「这里没得挂」与「这里有但都太便宜」 (Priority: P2)

网格里的空位有两种完全不同的成因：该位置**根本没有合约**，与该位置**有合约但权利金全部低于门槛**。用户能一眼分辨这两者。

**Why this priority**: 实测这条链上四成的空位属于后者（权利金门槛前空位率 9.6%，门槛后 42.4%）。把「有合约、只是太便宜」显示成「没有合约」，给出的是**错误信息而不是缺失信息** —— 用户会据此排除掉一整段本来可挂的期限。而「哪些位置有腿但都太便宜」本身就是「挂哪儿有人接」的一部分答案。

**Independent Test**: 构造一条链，使某些位置无合约、另一些位置有合约但权利金全部低于门槛，报表上这两类位置呈现不同且不依赖图例即可分辨；页脚给出被门槛移出的条数。

**Acceptance Scenarios**:

1. **Given** 某位置在链上没有任何合约，**When** 用户查看该格，**Then** 该格呈「无合约」态
2. **Given** 某位置有合约但全部低于权利金门槛，**When** 用户查看该格，**Then** 该格呈与「无合约」**视觉可分**的第三态
3. **Given** 报表已渲染，**When** 用户看页脚，**Then** 被权利金门槛移出、被行下界排除、被活性门槛挡下这三个条数**各自可见且各带分母**，不合并成一个总数，且三者与「有值」条数相加等于该链全量

### User Story 3 - 判断短期限的高年化是真机会还是算术假象 (Priority: P2)

网格上方有一条与网格列**严格对齐**的隐含波动率期限结构曲线。用户长按网格进入十字线，横向拖动时竖线同时贯穿网格的某一列与曲线上的对应点，固定读数面板同步给出该位置的明细。页头另给这条链的 IV 分位，回答「这条链现在整体贵不贵」。

**Why this priority**: 年化收益率随期限缩短而系统性升高，这是时间折算的算术性质，不是机会。短期限的高年化**可能**是这个算术产物，**也可能**是市场在为一个临近事件定价 —— 两者在年化数字上完全一样，只有在隐含波动率的期限结构上才分得开。没有这条曲线，网格会诱导用户永远选最短的那一列。

**Independent Test**: 在一条期限结构已知的链上，曲线的点数与网格列数相等且逐列对齐；长按拖动十字线，读数面板同时反映当前列的格明细与该列的 IV 读数。

**Acceptance Scenarios**:

1. **Given** 报表已渲染，**When** 用户查看曲线，**Then** 曲线上的点数与网格的列数相等，且第 n 个点与第 n 列在横向位置上对齐
2. **Given** 用户长按网格，**When** 用户横向拖动，**Then** 十字线随之移动、竖线同时落在网格的某一列与曲线的某一点上，读数面板给出该格的到期日、期限天数、价外档与对应行权价区间、格内腿数、最优值与**次优值**
3. **Given** 用户未长按而直接横向拖动，**When** 手势开始，**Then** 走列位移而不是十字线
4. **Given** 某到期日无法定出 ATM 隐含波动率，**When** 曲线渲染，**Then** 该点断开，且不以邻近值或最近行权价的值填充
5. **Given** 该标的的 IV 分位处于四种状态中的任一种，**When** 用户查看页头，**Then** 该块都渲染，不可用的三种状态各自给出自己的说明句而不合并、不回落成 0

---

### User Story 4 - 从看清楚的那一格直接进选约 (Priority: P3)

用户在网格上认定某个位置值得看，点它即落到该标的的选约区块，并已按该格对应的视角与检索条件预填好。

**Why this priority**: 它把报表的结论接到执行上。但报表本身在没有下钻的情况下已经成立（用户可以自己回到选约表手动设条件），且下钻的条件形状依赖选约表侧正在进行的改造 ⇒ 排在最后。

**Independent Test**: 点某个有值的格，落到选约区块且该格对应的期限与行权价范围已生效，条数与该格腿数一致。

**Acceptance Scenarios**:

1. **Given** 用户在标的详情屏，**When** 用户查看详情的三块之后、选约区块之前的位置，**Then** 报表入口可见，且该入口的措辞与已有的温度计入口不重复
2. **Given** 用户在报表上点某个有值的格，**When** 跳转完成，**Then** 落在该标的选约区块、检索条件已按该格的到期日与行权价区间预填
3. **Given** 用户点一个空格，**When** 手势结束，**Then** 不发生跳转（空格无可选之物）

---

### Edge Cases

- 该标的**未建锚** ⇒ 报表整体不可达（详情屏此时是整页建锚引导，入口无处可挂；且四种格值里的建仓成色本就无从谈起）
- 链**从无任何快照** ⇒ 整屏「链数据未就绪」，与「有链但全被门槛挡下」必须可分辨
- 链上**只有一个到期日** ⇒ 单列网格，横滑不可用且滑动指示条整条不渲染
- 行下界内**只有一个价外档非空** ⇒ 单行网格，行标签与列头照常
- **spot 缺失** ⇒ 价外幅度无从计算 ⇒ 行轴不成立，整屏显式不可用
- 某格内**只有一条腿** ⇒ 读数面板的「次优」显式为无，不复述最优充数
- 十字线**拖到空格** ⇒ 读数面板给出该格为空的原因，不停留在上一格
- 标的的锚 **excluded** ⇒ 报表照常渲染并在页头带标记（用户是主动进来的）
- 合规开关关闭 ⇒ 报表随期权台整栈被拦截，深链不可达
- 某格值下该链**零非空格**（实测 12 链里有 1 条在建仓格值下段内 0 格）⇒ 网格骨架与行列标签照常渲染，不呈空白页或错误页——「这条链现在没有建仓机会」本身就是答案
- 当前格值对应视角的**召回段之外的列** ⇒ 整列淡出，列仍在且仍可横滑到（`FR-009a`）

## Requirements _(mandatory)_

### Functional Requirements — 网格本体

- **FR-001**: 报表 MUST 以「价外幅度档 × 到期日」的二维网格呈现整条链。行为价外幅度档，列为链上**实际存在的到期日**。
- **FR-002**: 价外幅度档 MUST 等距切分，档宽 10%，下界为价内 10%。🚫 MUST NOT 按分位切分 —— 价外幅度已是相对量（已除以标的现价），等距切分才能跨标的比较；分位切分会让每条链的行不同。
- **FR-003**: 列 MUST NOT 分箱。到期日是真实可挂单的对象，分箱会造出链上不存在的到期日，并会把「哪个到期日有人接」这条信息糊掉。
- **FR-004**: 列数超出一屏时 MUST 支持横向滑动，且首列（价外档标签）保持冻结。滑动语义（位移域、边界夹取、惯性收敛、指示条）MUST 复用选约表已有的那一套，🚫 MUST NOT 另立第二套。
- **FR-005**: 报表的总体（网格骨架）MUST 是**过权利金门槛之后的整条链**。🚫 MUST NOT 按当前所选视角的期限段裁剪，🚫 MUST NOT 套用选约表的显示条数截断。<br>📌 **活性门槛（`OI ≥ 下限` 或当日成交 `≥ 下限`）虽与权利金门槛同为「三视角一律」，却 MUST NOT 一并踢出骨架**：被它挡下的腿**有合约、只是没人碰过**，踢出骨架会让那些位置显示成「该位置无合约」——那正是 US2 反对的「给出错误信息而不是缺失信息」。它们 MUST 留在骨架内呈「被门槛挡下」态（`FR-016a`），量级由 `FR-034` 的第三个计数给出。
- **FR-006**: 一格 = 该到期日 × 该价外档内的全部腿。格值 MUST 取该格内**最优的那条**，🚫 MUST NOT 取均值（均值会被格内边缘腿拉低，而边缘腿已被权利金门槛滤过一轮）。
- **FR-007**: 每个有值的格 MUST 同时呈现格内腿数。
- **FR-008**: 界面 MUST 表明格值是「该格最优」而非「该格典型」。实测收租读数下格内最优与中位的落差中位数达 25%，把最优读成典型会系统性高估整条链。
- **FR-009**: 各视角的期限召回段 MUST 在列上以范围标记呈现，且两段的重叠区 MUST 呈现为两段同时覆盖，而不是归给其中一段。
- **FR-009a**: 当前格值对应视角的**召回段之外的列 MUST 整列淡出**，且淡出 MUST 与格级的「被门槛挡下」编码可分。淡出的**主信号 MUST 是列头上的显式标记，措辞为「段外」**；底色差异只作辅助信号。<br>🚨 **主信号不得只靠底色**：实测那层灰底与「无合约」的纯白只差约 4% 亮度，在 40×32 的格子上两者读起来一样，而 `SC-003` 要的是**不查图例即可分辨**。<br>📌 **淡出不是裁剪，与 `FR-005` 不冲突**：列仍在、仍可横滑到、仍参与列数与曲线点数（`FR-020` 的恒等关系不受影响）。裁掉列会让用户回答不了「召回段之外还有什么」，而那正是报表相对选约表的独有信息。<br>📌 判据是**成片的空要用列级手段说**：实测建仓格值下「该视角不召回」的格有 **87%（280/322 格）落在召回段之外**——最大的那条链 16 列里有 9 列整列如此。用格级色码逐格表达一个列级事实，既浪费 40×32 的格内空间，又要用户从几十个格里反推出「这是一整段期限的事」。

### Functional Requirements — 四种格值

- **FR-010**: 报表 MUST 提供四种格值，同一时刻生效一种：建仓成色、收租年化、全腿年化、活跃度。切换 MUST 保持行列位置逐格不变。<br>⚠️ **「位置不变」MUST NOT 被读成「格态不变」**：四种格值各自跑在**不同的召回集**上（三视角判据不同），同一个格在一种格值下有值、在另一种下为空是**正确行为**而非缺陷。实测填充率（口径 = 8 行 × 该链全部到期日）：建仓 **6.3%**、收租 **13.6%**、全腿 **41.6%**；只看各自召回段内则为 **14.5%** / **21.5%** / **41.6%**（全腿不设期限段，两个口径同值）。
- **FR-011**: 「建仓成色」格值 = 该格内**有效成本相对愿买价的位置**取最优（越低于愿买价越好）。口径 MUST 与选约表同源，🚫 MUST NOT 另算一份。
- **FR-012**: 「收租年化」与「全腿年化」格值 = 该格内年化费率取最高。口径 MUST 与选约表同源。
- **FR-013**: 「活跃度」格值 = 该格内活跃量取最高，活跃量口径 MUST 与选约表的活跃标同源。
- **FR-014**: 「活跃度」格值的时点标注 MUST 跟持仓量自己的业务日，🚫 MUST NOT 使用区块级的报价业务日 —— 二者常态下不是同一天。
- **FR-015**: 🚫 报表 MUST NOT 提供以年化费率作为唯一格值的呈现方式。年化随期限缩短而系统性升高是时间折算的算术性质，单一年化格值会把它呈现成机会梯度。

### Functional Requirements — 格的三态

- **FR-016**: 格 MUST 有三种可分辨的状态：**有值**、**有腿但全部低于权利金门槛**、**该位置无合约**。
- **FR-016a**: 因四种格值各自的召回集不同，一个格为空还有**第四种成因**：有腿、过了三视角一律的门槛、但**不在当前格值对应视角的召回集内**。该成因 MUST 按**两级**编码，🚫 MUST NOT 为它单开第四种格级色码：<br>① **列级** —— 期限段造成的那部分走列级淡出（`FR-009a`）。<br>② **格级** —— 段内其余成因（流动性门槛 / 成色上界 / 有效成本硬门槛 / 活性门槛）归已有的「被门槛挡下」态。<br>📌 **代价是显式接受的**：段内不再分辨是哪一道门槛挡的。判据是分层——报表这一层回答「这儿挂不挂得出去」，「被哪道门槛挡的」属于选约表那一层（那里有六维检索条件与逐维的边际计数）。把六道门槛的区分搬进 40×32 的格子，既编码不下，也与选约表重复。<br>📌 **格态因此是「当前格值」的函数**，切换格值时 MUST 重算，🚫 MUST NOT 缓存成格的静态属性。
- **FR-017**: 「有腿但全部低于门槛」与「无合约」MUST 视觉可分，且分辨 MUST NOT 依赖阅读图例。
- **FR-018**: 缺失类状态 MUST NOT 用第二种色相编码 —— 色阶已被格值占满，第二色相会与值的色阶抢读。
- **FR-019**: 色阶 MUST 为单向（值越好越强），🚫 MUST NOT 使用双向色阶 —— 四种格值都是单向好坏，双向色阶会暗示存在中性点。
- **FR-019a**: 色阶的档界 MUST **全局固定**（每种格值各一套），跨标的、跨业务日恒定。🚫 MUST NOT 按当前链的分布自适应 —— 那会让同一个颜色在两条链上含义不同（连着扫几条链时形成错误印象），且同一条链隔天颜色也会变，而颜色变了并不代表机会变了。<br>📌 判据与本 spec 两处既有决定同源：`FR-002` 的行分箱取「等距、跨链可比」而非分位；以及仓内已否决过「把成交门槛改成链内分位数」的先例 —— 「这一格值不值得挂」是**绝对**问题，不能用相对答案回答。<br>⚠️ 档界取值 MUST 走一次实测标定（档界属「把连续量分箱」，分位切分是该类参数的标准做法），🚫 **不得先拍一个数**。

- **FR-019b**: 档界的**形态**（等距 / 分位 / 对数）MUST 按每种格值**各自的实测分布**定，🚫 MUST NOT 四种格值套同一种切法。可验判据：**任一档 MUST NOT 吞掉过半的非空格**。<br>📌 实测（dev `2026-08-11` 一期 / 12 链）线性等距下最淡档的占比：建仓成色 **7.0%** ✅ / 收租年化 **52.4%** ⚠️ / 全腿年化 **96.8%** 🚫 / 活跃度 **99.2%** 🚫 —— 后三者的色阶实际只剩一档在用。**两种病因不同**：全腿年化是价内内在价值（结构性，见 `FR-019c`），活跃度是幂律长尾（值域 `[1, 127 000]`，标的池再大也是这个形状）。同一份数据上分位切分让四种格值都做到五档近均分。<br>📌 **「全池分位标定出的固定档界」与 `FR-019a` 否掉的「按当前链分布自适应」是两回事**，MUST NOT 因为都叫分位就当成同一件事：前者标一次、此后跨链跨日恒定；后者每条链每天各算一套。判据是**档界这个数会不会随数据变**，不是它当初怎么算出来的。
- **FR-019c**: 「全腿年化」格值下，**价内 0-10 档那一行 MUST NOT 参与色阶**，改走「该口径在此行不适用」的标记；该行的读数、腿数与下钻 MUST 照常可用。<br>📌 判据与 `FR-015` 同源：那条否掉的是「把时间折算的算术产物呈现成机会梯度」，而价内腿的高年化是**内在价值**造成的同类算术假象——权利金里那一段本来就是你自己的钱。实测该行 max **948.3%** / p75 **95.0%**，其余各行 max ≤ **141.8%** ⇒ 让它参与色阶，报表最显眼的位置会系统性地推荐一批假机会，而这正是本片存在的理由的反面。<br>📌 **只作用「全腿年化」一种格值**：收租年化不受影响（收租视角的成色上界本就不召回深价内腿，实测值域仅 `[2.2, 71.4]`）；建仓成色更不受影响（价内行恰是建仓要看的，且其实测分布健康——线性档界下最淡档仅 7.0%）。

### Functional Requirements — 隐含波动率期限结构曲线

- **FR-020**: 网格上方 MUST 有一条隐含波动率期限结构曲线，其点数与网格列数相等，且第 n 个点与第 n 列横向对齐。
- **FR-021**: 曲线的横轴 MUST 按列序等距，🚫 MUST NOT 按到期天数等距。链上的到期日阶梯极度非等距（实测同一条链上相邻到期日的间隔从 7 天到 329 天不等），按天数等距会把短期那一段的多列挤成一团；而本曲线要回答的是**逐列对照**，序信息即足够。
- **FR-022**: 每列的取值 MUST 为该到期日的平值隐含波动率，由跨现价两侧的相邻行权价**线性插值**得出。🚫 MUST NOT 直接取离现价最近的那一档 —— 实测两种取法的中位差可忽略（0.26 个波动率点）但最大差达 17.21 点，而典型波动率水平仅 20–40 点。
- **FR-023**: 某到期日无跨现价两侧的行权价 ⇒ 插值不可得 ⇒ 曲线该点 MUST 断开，🚫 MUST NOT 回落成最近行权价的值。
- **FR-024**: 单条腿的希腊字母缺失只影响曲线，四种格值 MUST 照常可算。

### Functional Requirements — 十字线

- **FR-025**: 用户 MUST 能通过长按进入十字线、拖动移动、松手退出。
- **FR-026**: 十字线的竖线 MUST 同时落在网格的某一列与曲线的某一点上。
- **FR-027**: 十字线读数面板 MUST 给出：到期日、期限天数、价外档与对应行权价区间、格内腿数、最优值、**次优值**。
- **FR-028**: 格内只有一条腿时，「次优」MUST 显式为无，🚫 MUST NOT 复述最优值。
- **FR-029**: 十字线落在空格时，读数面板 MUST 给出该格为空的**原因**，🚫 MUST NOT 停留在上一格的读数。
- **FR-030**: 长按与横滑 MUST 靠「是否先长按」区分，🚫 MUST NOT 依据触点坐标分流（脆逻辑，与选约表横滑那条同一纪律）。

### Functional Requirements — 页头与页脚

- **FR-031**: 页头 MUST 呈现该标的的 IV 分位，四种状态（齐备 / 分位不可算 / 暂无数据 / 读数暂不可用）都渲染该块，三句降级说明各自成句不合并，🚫 禁回落 0。呈现 MUST 复用已有的 IV 读数与分段条，🚫 MUST NOT 新造读数。
- **FR-032**: 🚫 报表 MUST NOT 呈现市场级的离散状态档（regime N/X）—— 2026-08-03 已拍板不做，理由是判据不存在而非未实现。
- **FR-033**: 页头 MUST 分别标注三个时点：本次检索的交易所业务日、报价业务日、持仓量业务日。三者 MUST NOT 合并成一个「数据截至」。
- **FR-034**: 页脚 MUST 分别呈现**三个互斥的被排除计数**，🚫 MUST NOT 合并成一个总数，且每个计数 MUST 标明自己的分母：<br>① **被权利金门槛移出**（分母 = 该链全量）—— 语义「太便宜」，**整条不在图上**。实测 27.0%。<br>② **被行下界排除**（分母 = 骨架，即过权利金后）—— 语义「太深的价内」，在行轴之外。实测 57.6%。<br>③ **被活性门槛挡下**（分母 = 行下界内）—— 语义「没人碰过」，**在图上**、呈「被门槛挡下」态。实测 11.0%。<br>📌 **三者 MUST 互斥，与「有值」条数相加 MUST 等于该链全量**（实测 `952 + 1485 + 120 + 974 = 3531` ✅）。这是一条可机器断言的不变量，而它**恰恰是最容易被写错的地方**：若把③写成「在骨架全域上数被活性挡下的腿」，得到的是 985 而非 120，其中 865 条与②重复 —— 那时三个数照样都出得来、界面照样正常，只是加起来对不上账。<br>📌 三条各有各的必须显式的理由：②是**量级**（一半以上的腿在行轴之外）；③不是量级而是**唯一性** —— 在全腿格值下活性门槛是「被门槛挡下」格的唯一成因，不给量级用户就只知道有灰格、不知道那是多少条腿。

### Functional Requirements — 入口与下钻

- **FR-035**: 报表入口 MUST 位于标的详情屏既有三块**之后**、选约区块**之前**。报表是选约的上游，入口出现在用户看到选约表之后就失去了意义。
- **FR-036**: 入口 MUST NOT 常驻于任何吸顶区域 —— 它随页面滚动，零常驻区成本。
- **FR-037**: 入口措辞 MUST NOT 与已有的温度计入口重复。
- **FR-037a**: 该标的**未建锚**时，入口 MUST NOT 出现，且报表 MUST 不可达（含深链）。🚫 MUST NOT 做成「建仓格值不可用、其余三种可用」的缺角报表 —— 四种格值里建仓成色是核心之一，缺一角容易被读成「这条链没有建仓机会」而不是「你还没给它估值」。此判据与 046 详情屏「未建锚 → 整页建锚引导而非降级页」的既有取舍同源。
- **FR-038**: 点有值的格 MUST 落到该标的选约区块，并预填该格对应的视角与检索条件（期限区间取该到期日、行权价区间取该价外档对应的区间）。点空格 MUST NOT 跳转。
- **FR-039**: 在「全腿」或「活跃度」格值下点格子 MUST 落到**全腿视角**。两条理由：① 格值口径与全腿视角同源（全腿年化用年化档界；活跃度本就不分视角）⇒ 落全腿看到的就是用户刚点的那条腿，而另两种落法都可能让用户「点了 A 看到 B」；② 全腿视角不受期限段与流动性门槛约束 ⇒ 🚫 不会出现「跳过去发现那条腿不在里面」的**静默落空**（那种落空不报错，只给一个空列表）。
- **FR-039a**: 下钻落地后，若报表侧与选约侧的**业务日不一致**（跨换日或换批报价），MUST 显式告知两个时点。🚫 MUST NOT 让用户面对「报表说 5 条、进去只有 3 条」而界面上一个字都没有 —— 那时条数不符是**数据真的变了**，不是缺陷，但不说出来就变成了缺陷。判据 MUST 复用选约表侧已有的业务日比对，🚫 不新增契约字段、🚫 不另立第二套时点语义。

### Functional Requirements — 结构约束

- **FR-040**: 报表 MUST 是独立屏，落在期权台的二级页栈内并继承该栈的合规门控。🚫 MUST NOT 做成标的详情屏的内嵌折叠块 —— 详情屏的横滑手势覆盖其列表头部，报表自身也需要横滑，同一手势树内两个横滑消费者会相争。
- **FR-041**: 报表的全部内容 MUST 在一屏之内可见，**零纵向滚动**。若高度预算越线，MUST 先压缩曲线高度、再压缩页头，🚫 网格 MUST NOT 纵向滚动 —— 网格一滚，报表就退化成了另一张逐条阅读的表。
- **FR-042**: 🚫 本片 MUST NOT 引入任何新的第三方运行时依赖。
- **FR-043**: 设计令牌 MUST 取自既有设计体系，🚫 MUST NOT 为本片重设一套。
- **FR-044**: 🚫 锚的派生规则（估值锚 / 愿买价 / 四区间 / 信心层级）与意图判定矩阵 MUST 零改动 —— 本片只消费。
- **FR-045**: 🚫 选约表的召回判据 MUST 零改动 —— 报表与选约表共用同一套门槛与费率口径，报表不得为自己另设一套。

### Key Entities

- **格（Cell）**：一个「价外档 × 到期日」的交点。属性：格内腿数、当前格值下的最优值与次优值、该格对应的行权价区间、格态（有值 / 被门槛挡下 / 无合约）。⚠️ 腿数与格态都是**当前格值的函数**（各格值的召回集不同，`FR-016a`），🚫 不是格的静态属性。
- **列（到期日）**：属性：到期日、期限天数、是否月度到期链、是否跨财报、该到期日的平值隐含波动率、各视角召回段是否覆盖本列。
- **行（价外档）**：属性：价外幅度区间、对应的行权价区间（随现价变）。
- **链级读数**：属性：IV 分位与其状态、现价、三个业务日时点、**三个互斥的被排除计数**（各带自己的分母）。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 在本机可达的**最大真实链**上打开报表，全部内容在首屏可见，用户读出「该挂哪一段期限」**无需任何纵向滚动**。
- **SC-002**: 切换四种格值时，网格的行数、列数与每一格的屏上位置**逐格不变**。变的是读数、着色**与格态**——同一格在一种格值下有值、在另一种下呈空是正确行为（实测全网格填充率：建仓 6.3% / 收租 13.6% / 全腿 41.6%），可逐格按各视角召回集复核。
- **SC-003**: 三种格态在**不查阅图例**的前提下可分辨；「有腿但太便宜」与「无合约」被误读为同一件事的次数为零。
- **SC-004**: 一次十字线操作**同时**给出网格格明细与该列的隐含波动率读数 —— 用户回答「这一列年化高是不是因为波动率高」所需的操作次数为 **1**。
- **SC-005**: 曲线的点数与网格列数**恒等**，且逐列横向对齐；插值不可得的到期日呈断点而非任何形式的填充值。
- **SC-006**: 三个被排除计数在界面上**各自可见**、措辞不同、**各自标明分母**；三者与「有值」条数相加**恒等于该链全量**（实测 `952 + 1485 + 120 + 974 = 3531`）。实测量级：权利金门槛 **27.0%**（占全量）、行下界 **57.6%**（占骨架）、活性门槛 **11.0%**（占行下界内）。
- **SC-007**: 本片新增的第三方运行时依赖数为 **0**。
- **SC-008**: 本片前后，同一标的的**锚判定结果、意图判定结果、选约表返回的腿集合与顺序**逐条一致 —— 报表是纯增量的读侧，对既有判定零影响。
- **SC-009**: 报表屏在合规开关关闭时**不可达**，含深链。
- **SC-010**: **在两侧业务日相同的前提下**，从报表某格下钻到选约区块后，选约结果的条数与该格呈现的腿数**一致**；业务日不同时，两个时点在界面上**各自可见**。
- **SC-011**: 页头 IV 分位在四种状态下**都渲染该块**，且三种不可用状态各自给出可读的说明句、无一处呈现 0。
- **SC-012**: 四种格值各自的档界下，**任一档吞掉的非空格数不过半**。实测线性等距在收租年化 / 全腿年化 / 活跃度上分别为 52.4% / 96.8% / 99.2% ⇒ 三者均不合格，标定必须换形态而不是只换取值。
- **SC-013**: 「全腿年化」格值下，价内 0-10 行**不着色**，而该行的读数、腿数与下钻**照常可用** —— 不参与色阶不等于不可用。

## Assumptions

- **报表覆盖认沽腿**，与选约表当前的呈现面一致。认购腿虽已落库但不在本片呈现面内。
- **锚被排除（excluded）的标的照常渲染报表**，仅在页头带标记 —— 与锚管理列表「显示且带排除原因」一致。用户是主动进入某个标的的报表，与跨标的聚合视图「排除即不进」的语义不同。
- **十字线读数面板固定在网格下方**（而非顶部）：拖动时手指在网格上，读数放下方会被手掌遮挡的风险低于放顶部时视线来回跳的成本。此项本为版式细节、留待 mockup 推翻，**2026-08-14 mockup 已定案采用下方**（两种选择的高度预算相同）。
- **色阶采用离散档而非连续渐变**：离散档在小尺寸格子上可读性更好。档界的口径（全局固定）由 `FR-019a` 定、形态判据由 `FR-019b` 定，**取值的标定仍归实现阶段的一个独立任务**。<br>⚠️ 该 task 的样本窗口 MUST 跨**多个业务日**：`FR-019a` 要的是跨业务日恒定，而 `FR-019b` 的形态判据只跑在**单个业务日**的全池分布上 —— 单日分位标出来的四个数换一天会不会漂，本次实测答不了这个问题。
- **价外幅度以现价为分母**（而非以估值锚或愿买价为分母）—— 价外是相对市场价格的概念，行轴用现价、格值用愿买价，两者各司其职。
- **报表为只读**，不提供任何改锚 / 改水位 / 下单入口。
- **加载与失败态**：主数据（网格 + 曲线）加载期呈整屏加载态、取数失败呈整屏错误与重试。🚫 **不做骨架网格** —— 列数等于链上实际到期日数、加载前未知，骨架必然跳变，比一个诚实的加载态更差。而页头的 IV 分位块按**自己的四态独立呈现**（承详情屏「两端点并行、各自独立降级、禁整页失败」的既有范式）⇒ 🚫 IV 读数失败 MUST NOT 波及网格。
- **不在详情屏预取报表数据**：详情屏已是两端点并行合成、各自独立降级，加第三个请求会让降级矩阵复杂化；而报表是主动进入的二级页，一次等待在用户预期之内。
- **不设到期日上界**：实测链上到期日数为 5–16，横滑无压力 ⇒ 设上界属过早优化，且会砍掉「召回段之外还有什么」这条报表独有的信息。标的池显著扩大后若列数失控，再单独处置。
- **数据来源与选约表同一次检索口径**，本片不新增采集，不新增落库。

## Dependencies

- **可并行、但实现阶段有先后**：本片的下钻（FR-038 / FR-039）依赖选约表侧正在进行的请求形状改造（每视角独立请求 + 响应收窄 + 检索条件下沉）。⇒ **spec / mockup / plan / tasks 阶段与之并行不受阻；实现 MUST 在那一片合入之后开始**，否则下钻要按两套契约写两遍。
- **消费但不改动**：锚派生与意图矩阵、选约表的召回判据与费率口径、已有的 IV 读数与分段条、已有的横滑手势范式。
