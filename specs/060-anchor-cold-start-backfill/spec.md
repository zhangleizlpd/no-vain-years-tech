# Feature Specification: 锚首建冷启动补数

**Feature Branch**: `060-anchor-cold-start-backfill`
**Created**: 2026-08-17
**Status**: Tasks Ready
**Input**: 锚首次创建后以异步事件触发一次冷启动补数：把「最近一个已收盘交易日」的期权链、期权快照、正股日线补齐；该市场盘中则跳过 session 敏感的期权快照，交给当晚常规轮。整条路径按 market 参数化，为后续接港股期权留结构位（本片不开 hk 采集行为）。

## Clarifications

### Session 2026-08-17

- Q: 冷启动的执行结果留什么痕？（跳过类结局没有数据行可当痕） → A: 新建一张轻量的冷启动运行记录表，每只锚一行；不复用逐维度的采集运行记录
- Q: 短时间内连续建多只锚（如模型批量导入），冷启动怎么收敛？ → A: ~~合流~~ **不做合流**（同日追加约束，见下条）
- Q: （追加约束）合流机制是否必要？ → A: **不必要，移除**。当前建锚入口是 by-ticker 的单只接口，一次调用 = 一只锚 = 一条消息，批量路径根本不存在；将来真有批量，做法是**一条消息带多只锚**，收敛在消息形态里而不在消费侧。且「起手复判 + 非敏感档跑全量工作集」已顺带给出等价效果，无需额外机制
- Q: 冷启动失败后要不要自动重试？ → A: 有限次自动重试 + 退避，耗尽后升级为需人工介入
- Q: 正股日线补到什么程度算「补齐」？ → A: 复用常规增量路径的回看窗，不为冷启动另设目标日参数

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 休市时建的新锚，当场就能看 (Priority: P1)

我在周末或美股收盘后决定盯一只新标的，建了锚。我希望它立刻就带着最近一场收盘的期权链、期权盘口与正股收盘价 —— 而不是一个空壳，要等到下一个交易日凌晨的采集轮才第一次有数。

**Why this priority**: 这是整片的存在理由。当前建锚后必须等下一轮采集，周五盘后建的锚要到下周二凌晨才有第一份数据 —— 中间整个周末，雷达的距 W%、选约表、链报表在这只锚上全是空的，而周末恰恰是坐下来做研究的时候。

**Independent Test**: 在该市场休市时段建一只全新的锚，不做任何其他操作，隔一段时间后核对：该标的的期权合约集非空、期权盘口数据的归属交易日等于最近一个已收盘交易日、正股日线已落。

**Acceptance Scenarios**:

1. **Given** 一只从未建过锚的标的、且其所属市场当前休市，**When** 我建锚成功，**Then** 系统自动补齐该标的最近一个已收盘交易日的期权链、期权快照与正股日线，我无需触发任何东西
2. **Given** 上述补数已完成，**When** 我打开雷达与选约表，**Then** 这只锚与其他既有锚一样有真值，不是空态
3. **Given** 建锚的事务因校验失败而回滚，**When** 事后检查，**Then** 系统没有为这次失败的建锚发起任何补数

---

### User Story 2 - 盘中建的锚，不会被写进一条假的收盘数据 (Priority: P1)

我在美股盘中（北京深夜）临时决定加一只锚。我不指望立刻拿到收盘数据 —— 但我要求系统**绝不**把此刻的盘中盘口当成某一场的收盘态写进库里，因为那种错行不会报错、也没法事后修。

**Why this priority**: 与 US1 同为 P1，因为它是**正确性**而非便利性。行情供应方只提供「当下」的期权快照，写入时要自己贴归属交易日的标签；盘中贴上收盘日标签就是一条看起来完全正常的错行，而期权快照按唯一键去重、错行一旦占位，当晚正确的行会被挡掉，形成永久缺口。

**Independent Test**: 在该市场连续竞价时段建一只全新的锚，核对：期权快照数据集内不存在任何归属于「尚未收盘的交易日」的记录；同时期权链与正股日线已补齐。

**Acceptance Scenarios**:

1. **Given** 某市场正处于连续竞价时段，**When** 我在该市场建一只新锚，**Then** 系统不写入任何期权快照记录
2. **Given** 同上，**When** 当晚常规采集轮跑完，**Then** 该标的的期权快照正常落库，没有任何被冷启动挡掉或污染的行
3. **Given** 某市场处于分段交易的休息段（如午休），**When** 我在该市场建锚，**Then** 判定与盘中相同，不写入期权快照
4. **Given** 同上，**When** 我在建锚后立刻查看，**Then** 期权链与正股日线**已经**补齐（这两类不受盘中判据约束）

### User Story 3 - 尚未支持的市场，是「没做」不是「坏了」 (Priority: P2)

我给一只港股标的建了锚。港股期权采集目前还没开通。我要能一眼分清「系统跳过了因为还没支持」和「系统坏了」。

**Why this priority**: 港股锚在 045 起就已合法（估值台账与雷达都支持），只是不触发期权采集。冷启动路径若对未支持市场静默无反应，就与「消息丢了 / 补数挂了」不可区分；若报错，则每建一只港股锚都是一次假红。

**Independent Test**: 建一只港股锚，核对：对行情供应方的请求数为 0、无错误状态、且留有一条可判读的记录说明为何未动作。

**Acceptance Scenarios**:

1. **Given** 港股期权采集尚未开通，**When** 我建一只港股锚，**Then** 冷启动显式无操作、零对外请求、不产生错误
2. **Given** 同上，**When** 我事后排查，**Then** 能从记录中判定「跳过是因为该市场未开通期权采集」，而不是猜

### Edge Cases

- **同一只锚被删除后重新创建** → 视作一次新的首建，重新走冷启动；已存在的数据由幂等保证不重复、不冲突。
- **冷启动请求被重复投递**（同一次建锚触发出两次补数）→ 第二次起手即判定数据已具备，零对外请求。
- **短时间内连续建多只同市场的锚** → 各自触发、各自执行，**无合流机制**。若后一只在前一轮尚未跑完时创建，它的 job 起手复判会发现数据已具备 ⇒ 零外呼；若在前一轮跑完之后才创建，则确实需要真跑一轮 —— 那不是浪费。
- **冷启动因瞬时故障失败** → 有限次退避重试；耗尽后升级为需人工介入，不静默丢弃。**配额耗尽不算失败**，不消耗重试次数。
- **冷启动发起时，常规采集轮恰好已经采过该交易日** → 同上，零对外请求。
- **交易日历缺该市场的行** → 无法定位目标交易日；此时**不猜日期**，放弃本次冷启动并升级为需人工介入的记录（猜错会落一批归属日标错的脏行，比不补更难发现且要人工回删）。
- **标的在行情底座里还没有记录**（标的清单尚未轮到它）→ 先补齐记录，再纳入本次补数。
- **锚的标的标识不可解析出市场** → 显式跳过，不猜市场。
- **补数过程中行情供应方配额耗尽** → 顺延，不记为失败，不破坏已落数据。
- **冷启动本身失败** → 建锚已成功的事实不受影响，不回滚锚；其他锚的冷启动不受牵连。
- **冷启动与常规采集轮时间重叠** → 两者对供应方的调用串行，不并发争抢配额。
- **目标交易日之后是周末** → 归属口径判定必须区分「已进入下一个交易日的盘前」与「只是跨到了非交易日」，两者对未平仓量的归属日结论不同。

## Requirements _(mandatory)_

### Functional Requirements

**触发**

- **FR-001**: 锚**首次创建**成功后，系统 MUST 自动发起一次冷启动补数，MUST NOT 要求任何人工触发。
- **FR-002**: 冷启动 MUST 覆盖锚创建的**全部**入口（本人在 App 内建锚、经导入通道由模型建锚），MUST NOT 只覆盖其中之一。
- **FR-003**: 对**既有**锚的任何更新（估值刷新 / 复审 / 水位调整 / 人工位改动）MUST NOT 触发冷启动。
- **FR-004**: 冷启动的发起 MUST 与建锚同时成立或同时不成立 —— 建锚回滚时 MUST NOT 留下已发起的补数。
- **FR-005**: 冷启动 MUST 异步执行，MUST NOT 延长建锚请求本身的响应时间。

**目标交易日**

- **FR-006**: 冷启动补的目标交易日 MUST 是**该锚所属市场**的「最近一个已收盘交易日」，MUST NOT 取宿主所在地或任何其他市场的「今天」。
- **FR-007**: 系统 MUST 通过查交易日历确定该日，MUST NOT 由时区换算推导（时区换算在周末会算出一个不存在的交易日）。
- **FR-008**: 冷启动 MUST NOT 补比目标交易日更早的任何交易日 —— 只有紧邻的上一场能从当下数据原样补回。
- **FR-009**: 无法定位目标交易日时，系统 MUST 放弃本次冷启动并升级为需人工介入的记录，MUST NOT 猜测日期、MUST NOT 落任何数据行。

**盘中判据与分档**

- **FR-010**: 该市场处于连续竞价时段时，系统 MUST NOT 写入任何按交易日归属的期权快照。
- **FR-011**: 分段交易市场的休息段（如午休）MUST 判定为「不在连续竞价时段」，但**同样** MUST NOT 写入期权快照（该场尚未收盘）。
- **FR-012**: 期权链与正股日线的补齐 MUST NOT 受盘中判据约束（前者是与交易日无关的静态属性，后者有可指定日期的历史来源）。
- **FR-012a**: 正股日线的补齐 MUST 复用常规增量路径**及其自带的回看窗**，MUST NOT 为冷启动另设目标日参数 —— 回看窗会把近期缺口一并补上，多一条与常规路径不同的分支只会多一处可漂的判据。验收门是「目标交易日那一根已落」。
- **FR-013**: 盘中未做的部分 MUST 由当晚常规采集轮补齐，系统 MUST NOT 为此另设第二套补偿机制。
- **FR-014**: 冷启动写入的期权快照，其「归属交易日」与「未平仓量归属日」两个口径 MUST 与常规采集轮 / 既有盘前兜底路径在**同一时刻**下取值一致，MUST NOT 出现同一交易日两种口径并存。

**幂等与资源**

- **FR-015**: 冷启动 MUST 幂等 —— 重复发起 MUST NOT 产生重复或冲突数据。
- **FR-015a**: 冷启动写入的行情数据，其幂等键 MUST 是**标的 + 交易日**（合约级则为合约 + 交易日），**MUST NOT** 含锚或用户维度 —— 行情是跨锚、跨用户**共享的标的级事实**，不属于任何一只锚。
- **FR-016**: 冷启动起手 MUST 先判定目标数据是否已具备，已具备时 MUST 零对外请求。
- **FR-016a**: 该复判的判据 MUST 是「**该标的在目标交易日的数据**是否已具备」，**MUST NOT** 是「这只锚是否冷启动过」。二者今天等价（一个标的至多一只锚），**一旦锚按用户区分就不再等价**：同一标的的 N 只锚会各自判「没做过」，把同一份共享数据重复拉 N 遍。
- **FR-017**: 冷启动对行情供应方的调用 MUST 与常规采集轮串行，MUST NOT 并发争抢调用配额。
- **FR-018**: 供应方配额耗尽时 MUST 顺延，MUST NOT 记为失败、MUST NOT 破坏已落数据。
- **FR-019**: 冷启动失败 MUST NOT 影响建锚已成功的事实，MUST NOT 阻塞其他锚的冷启动。
- **FR-019a**: 冷启动失败后 MUST 有限次自动重试并在重试间退避；重试次数耗尽 MUST 升级为需人工介入的记录，MUST NOT 静默丢弃。
- **FR-019b**: 「供应方配额耗尽」MUST NOT 消耗重试次数 —— 它是**顺延**不是失败（见 FR-018），把两者混同会让真故障在几次限频之后被静默放弃。
- **FR-019c**: 系统 MUST NOT 为「短时间内多次建锚」实现任何合流 / 去重机制 —— 每次建锚各自触发、各自执行。当前建锚入口是单只 by-ticker 接口（一次调用 = 一只锚 = 一条消息），批量路径不存在；FR-016 的起手复判已使排队中的后续请求自然收敛为零外呼。**将来真出现批量入口，收敛 MUST 做在消息形态上（一条消息带多只锚），MUST NOT 在消费侧加去重。**

**市场参数化**

- **FR-020**: 市场归属 MUST 从锚的标的标识解析得出，系统 MUST NOT 假定任何默认市场。
- **FR-021**: 标的标识不可解析出市场时 MUST 显式跳过，MUST NOT 猜市场。
- **FR-022**: 尚未登记交易时段的市场 MUST 显式跳过并留下可判读记录，MUST NOT 套用其他市场的时段（美股与 A 股的盘中时窗零重叠，静默套用的后果是一次都不触发且不报错）。
- **FR-023**: 尚未开通期权采集的市场（当前含港股）MUST 显式无操作、零对外请求，MUST NOT 报错、MUST NOT 静默。
- **FR-024**: 「哪些市场支持哪些补数内容」MUST 是一处显式登记，MUST NOT 散落在多个判断分支里。

**标的前置**

- **FR-025**: 标的在行情底座尚无记录时，冷启动 MUST 先补齐该记录再纳入本次补数，MUST NOT 因此整体失败。

**可观测**

- **FR-026**: 系统 MUST 为每只锚保留其**最近一次**冷启动的结局记录（发生时刻 / 结局 / 跳过或失败的原因），且该记录 MUST 独立于应用日志可查 —— 应用进程挂掉时日志一起没了，而「这只锚的冷启动到底跑过没有」正是那时第一个要问的问题。
- **FR-026a**: 该记录的身份 MUST 是**锚本身**（一只锚一行），MUST NOT 以标的标识为身份 —— 否则锚按用户区分后，同一标的的多只锚会**撞同一行、互相覆盖结局**，而每只锚的冷启动结局本就可能不同（先建的那只是「已补齐」，后建的那只是「已具备零外呼」）。
- **FR-027**: 该记录 MUST 能区分下列结局：已补齐 / 盘中跳过 / 数据已具备零外呼 / 市场未开通期权采集 / 市场未登记交易时段 / 标的标识不可解析 / 日历缺行 / 重试耗尽失败 / **采集已执行但目标日快照仍未落库**。MUST NOT 把「没做」与「做了但失败」折叠成同一个值。
- **FR-027a**: 采集执行完毕后，系统 MUST 复判「目标交易日的期权快照是否真的在库」，并据此区分「已补齐」与「做了但没补上」；MUST NOT 仅凭采集调用已返回就记为已补齐。该复判 MUST 与起手复判使用同一判据（标的 + 交易日），MUST NOT 另立口径；判据范围 MUST 只看期权快照（正股日线可重拉、且其依赖边为软依赖，不参与结局判定）。这一档 MUST NOT 触发重试（期权链在前一相已执行完毕，重试只会重复取得同一空工作集），MUST 升级为需人工介入的记录。
- **FR-028**: 该记录 MUST NOT 复用逐维度的采集运行记录 —— 那张表被逐维度的报表解析与维度计数断言消费，塞非维度行会污染两者。

### Key Entities

- **锚**：某个标的的估值结论台账。以 `市场:代码` 形式的标的标识为业务唯一键；本片只关心它的**首次创建**这一个事件，不改它的任何字段。
- **目标交易日**：该锚所属市场最近一个已收盘的交易日，是本次冷启动要补的**唯一**一天。
- **期权链**：某标的的合约集（到期日阶梯 + 各合约静态属性）。与交易日无关。
- **期权快照**：某合约在某个交易日的盘口 / 希腊字母 / 未平仓量。**按交易日归属**，且供应方只提供「当下」的一份 —— 这是本片全部设计约束的来源。
- **正股日线**：标的的日频收盘数据，是锚的收盘价投影与雷达距 W% 的上游。
- **市场交易时段登记**：市场 → 该市场连续竞价时段（含分段）的显式登记表，未登记即视为不支持。
- **冷启动运行记录**：**以锚为身份**（一只锚一行，非以标的为身份 —— 见 FR-026a），记其最近一次冷启动的发生时刻、结局与原因。是 FR-026/027 的载体，也是「未支持」与「故障」唯一可事后区分的地方。**不是**逐维度采集运行记录的一部分（FR-028）。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 在市场休市时段建一只全新的锚，**30 分钟内**该标的具备目标交易日的期权链、期权快照与正股日线（当前基线：最坏需等约 60 小时 —— 周五盘后建锚要到下周二凌晨的采集轮）。
- **SC-002**: 盘中建的锚，其期权快照数据集内归属于「尚未收盘的交易日」的记录数 = **0**（100%，无例外）。
- **SC-003**: 同一只锚的冷启动重复触发 N 次，产生的期权快照记录数与触发 1 次**完全相同**；第 2 次起对行情供应方的请求数 = **0**。
- **SC-004**: 冷启动运行期间，对行情供应方的并发调用数**不超过**常规采集轮单独运行时的水平。
- **SC-005**: 未开通期权采集的市场建锚，冷启动的对外请求数 = **0**，且冷启动运行记录里该锚一行的结局为「市场未开通期权采集」—— 能据此区分「未支持」与「故障」，**无需翻应用日志**。
- **SC-006**: 冷启动写入的快照，经既有的期权快照完整性核对**零告警**，且其归属口径与同一时刻的常规路径判定**逐字相同**。
- **SC-007**: 冷启动的任何失败形态下，建锚成功率不变（= 100% 不受影响），且其他锚的冷启动不受牵连。
- **SC-008**: 引入本片后，常规采集轮的运行时长与请求数**零变化**（冷启动是叠加路径，不改既有轮次的行为）。
- **SC-009**: FR-027 列出的九种结局，在冷启动运行记录里各有唯一对应取值，**零折叠**（可由一条按结局分组的查询逐项验证）。
- **SC-010**: 单次瞬时的供应方故障（如一次网络抖动）**不会**导致该锚的冷启动最终失败 —— 退避重试后仍能在同一个休市窗口内补齐。

### Out of Scope（显式排除，避免后续 analyze 当缺口补）

- **标的层面的隐含波动率读数**：它与期权快照不同 —— 其历史序列在供应方侧保留三年滑动窗，漏采可事后回填，**不构成永久缺口**；且当晚常规轮即可补。故本片**不**纳入冷启动，SC / FR 均不覆盖它。
  - 🚨 **订正（2026-09-03）**：「保留三年**滑动窗**」的措辞不准 —— 实测底是**固定数据纪元**（2023-06-26/27，相隔 24 天未移动；见 046 FR-024 的订正注记）。⇒ 本条的**结论方向不但不变、还被加强**：固定纪元比滑动窗更「可事后回填」，「不构成永久缺口」因而更成立。
- **港股期权的采集面**：本片只做「按市场参数化 + 显式登记」的结构位，不开通港股期权的链 / 快照采集。
- **补数结果的任何前端呈现**：既有屏（雷达 / 详情 / 选约表 / 链报表）读到真值即可，本片零 UI 改动。
- **人工触发冷启动的入口**（CLI / 端点）：本片只做建锚自动触发。

## Assumptions

- **行情供应方不提供任意历史交易日的期权快照** —— 只提供「当下」的一份。这是本片形状的根本约束：所谓「补前一个交易日」实际是「在该场收盘后、下一场开盘前，取当下的一份并正确标注它属于哪一场」。任何「回到 N 天前重采」的做法都不成立。
- **期权在收盘后至下一场开盘前基本无成交**，故休市时段取到的盘口仍代表该场收盘态。既有的常规采集轮与盘前兜底路径都建立在同一前提上，本片沿用而非新引入。
- **建锚是低频动作**（单人使用，个位数/天），故冷启动即使跑一轮完整工作集也不构成配额压力；换来的是不必给采集侧的工作集选择开第二个口子。
- **交易日历由既有机制维护**，本片只读不写；日历缺行属于本片必须显式处理的失败态而非本片要修的问题。
- **当前仅美股开通期权采集**；港股锚合法但不触发期权采集。本片只留结构位，港股采集面另片。
- **锚当前不区分用户**（一个标的至多一只锚）。本片**不实现**多用户，但两处判据按「将来会区分」来定：行情数据的幂等键取标的 + 交易日（FR-015a）、复判判据取标的而非锚（FR-016a）、运行记录以锚为身份（FR-026a）。这三条今天与「按锚判」等价、零额外成本，**一旦区分用户就不再等价** —— 那时按锚判会把同一份共享行情重复拉 N 遍，运行记录会互相覆盖。
- **留痕靠一张独立的冷启动运行记录表**（clarify 已定，取代了 specify 阶段「纯日志」那个默认）。判据是：跳过类结局**没有数据行可当痕**，而日志会滚掉且随进程一起消失 —— 044 的日历心跳表正是为同一形态的静默降级而建。⚠️ 这张表**只记结局**，不是待办队列：盘中未做的部分仍由当晚常规轮补齐（FR-013），记录不驱动任何重做。
- 上述 **30 分钟门槛**（SC-001）是按现有工作集规模（十余只锚、一轮完整链发现约 4-5 分钟）留的余量，非硬性能预算；真实门槛是「远早于下一个交易日凌晨」。
