# Feature Specification: 收租候选窗由「码数预算」决定 —— 取代会空、会超批量的价格比例窗

**Feature Branch**: `077-optionsdesk-rent-window-budget`
**Created**: 2026-09-07
**Status**: Draft

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 新建锚的首日就能看到该看到的收租腿 (Priority: P1)

维护者新建一只锚，当天打开收租视角。他期望看到的是「按我的估值口径筛出来的、能收到租金的腿」。今天他可能看到的是一张少了腿的表，或者干脆是空表 —— 而少掉的那些腿其实完全满足他自己设的全部判据，只是被一道与判据无关的窗口边界挡在了外面。

**Why this priority**: 这是本片全部三个缺陷里影响面最大、也最贴近「屏上少了本该有的东西」的一条。2026-09-07 实测：美股 908 条合格腿里 **159 条（17.5%）**被挡、港股约 325 条里 **30 条**被挡。且被挡不产生任何可观测信号 —— 表照常渲染、无横幅、无日志，与「今天确实只有这么多腿」不可区分。

**Independent Test**: 取一只锚，分别在「设了候选窗」与「只按收租判据筛、不设窗」两条路上算候选集，比较差集。差集非空即缺陷成立；本片交付后该差集应为空（或仅剩因预算裁剪而被明确记录的部分）。

**Acceptance Scenarios**:

1. **Given** 一只愿买价明显低于市价的锚（估值/市价比落在 0.5–0.85），且其链上存在满足全部收租判据的腿，**When** 在零 Δ 面（新锚首日）请求收租候选，**Then** 这些腿全部出现在候选集里
2. **Given** 同一只锚，**When** 在正常 Δ 面请求收租候选，**Then** 结果与零 Δ 面同源 —— 不因走了哪条候选面而少腿
3. **Given** 一只锚的合格腿数超过供应方单批上限，**When** 请求收租候选，**Then** 保留的是**离锚定轴最近**的那一批，被裁掉的是最远的，且裁剪这件事有记录

---

### User Story 2 - 合约多的标的不再因为「问得太多」而整张表失去实时 (Priority: P2)

维护者打开一只合约数量很大的美股锚（链上认沽上千张）。今天在新锚首日这种场景下，系统一次要问的合约数会超过供应方单批允许的数量，于是**整张表退回收盘档** —— 屏上显示的是昨天的价，而不是此刻的盘口。

**Why this priority**: 影响的锚数比 US1 少（2026-09-07 实测 3 只：`us:ULTA` 470 码 · `us:REGN` 463 · `us:GOOGL` 416，上限 399），但**后果更重**（整表失去实时，而不是少几条腿）。且它是**现存**缺陷，不是本片引入的。

**Independent Test**: 对链最大的几只锚，在零 Δ 面下计算「本次要问多少个合约码」，与单批上限比较。今天有超限的；本片交付后应结构上不可能超限。

**Acceptance Scenarios**:

1. **Given** 一只链上认沽数量远超单批上限的锚，**When** 在零 Δ 面请求收租候选，**Then** 请求的合约码数不超过单批上限，且表呈实时档而非收盘档
2. **Given** 同一只锚，**When** 候选面被预算裁剪，**Then** 表上仍呈实时档，MUST NOT 因为「问不完」而整表降级

---

### User Story 3 - 真的没有合格腿时，空态仍然如实为空 (Priority: P3)

维护者给一只票定了远低于市价的估值（比如市价 167 而他认为只值 86）。收租意味着「以我的愿买价接货」，那么在他的价位上根本不存在既能收到租金、又不违背估值的认沽。此时他期望看到的是一句清楚的「没有腿满足判据」，而不是一张凭空多出来的表。

**Why this priority**: 这是本片的**反向护栏** —— 放宽窗口后 MUST NOT 把「本就该空」变成「凑出几条」。2026-09-07 实测：美股 24 只、港股 3 只在当前窗口下收租候选恒空，其中**美股 19 只 + 港股 3 只在完全不设窗时可用腿仍为 0** ⇒ 那些空态是正确答案，不是缺陷。

**Independent Test**: 取一只完全不设窗时可用腿为 0 的锚，本片交付后其收租候选集仍为空，且空态文案与「因供数失败而空」可区分。

**Acceptance Scenarios**:

1. **Given** 一只锚在不设任何候选窗时收租可用腿为 0，**When** 请求收租候选，**Then** 结果为空，且呈现为「没有腿满足判据」而非错误或降级
2. **Given** 同一只锚，**When** 维护者查看空态，**Then** 能看到是哪一道判据把腿筛掉的（门槛统计）

---

### Edge Cases

- 锚定轴退化（愿买价 ≥ 市价）时，候选集与退化前逐值相同 —— 本片 MUST NOT 顺手改变这一支的行为
- 链上在成色上界之下**一档都没有**（上界低于最低行权价）⇒ 语义过滤即为空，预算裁剪无对象，走 US3 的空态
- 合格腿数**恰好等于**单批上限 ⇒ 不裁剪（闭区间）
- 距离相同的两条腿撞在裁剪边界上 ⇒ 需要一条确定性的并列处置，否则同一批数据两次请求可能返回不同集合

## Requirements _(mandatory)_

- **FR-001**: 收租候选窗 MUST 由两段构成且顺序固定：① 语义过滤（认沽 ∧ 标准合约 ∧ 未软下架 ∧ 期限落在收租召回段 ∧ 行权价不超过成色上界）② 在 ① 的结果上按「离锚定轴距离」升序保留至预算上限
- **FR-002**: 预算上限 MUST 取供应方单批允许的合约码数上限；窗口大小 MUST NOT 有第二个来源
- **FR-003**: 系统 MUST NOT 在收租候选生成中使用「市价的固定比例」作为行权价下界
- **FR-004**: ① 非空时候选集 MUST 非空 —— 该性质 MUST 可由窗口定义直接论证，MUST NOT 依赖任何标的的估值与市价之比
- **FR-005**: 候选集大小 MUST 恒不超过预算上限 —— 同上，MUST 由定义直接论证
- **FR-006**: 零 Δ 面（新锚首日 / 供应方整批缺 greeks）与非零 Δ 面 MUST 共用同一套窗口形态；两条路径的差别 MUST 只在「候选面从哪来」，不在「窗口怎么算」
- **FR-007**: 发生预算裁剪时 MUST 留下可查记录（至少含标的、意图、裁剪前后码数）
- **FR-008**: 并列距离的裁剪 MUST 有确定性处置，同一批输入两次求解结果逐值相同
- **FR-009**: 建仓视角与全腿视角的响应 MUST 逐值零变化
- **FR-010**: 美股与港股 MUST 走同一套窗口形态；市场差异 MUST 只落在既有的 per-market 参数上，MUST NOT 为某一市另写一条分支
- **FR-011**: 本片 MUST NOT 重新标定任何既有的比例参数；沿用的旧值 MUST 在落值处标明「未随本片重新标定」
- **FR-012**: 本片 MUST 显式 supersede 071 SC-004（美股锚响应逐值相同）并写明理由 —— 美股收租候选集会变，那正是本片要修的
- **FR-013**: 「候选恒空是正确答案」这一情形 MUST 在文档中写清判据与识别方法，避免后续被当作缺陷重复排查

## Success Criteria _(mandatory)_

- **SC-001**: 对当前全部锚，「按收租判据筛出的合格腿」与「实际进入候选集的腿」之间的差集为空，或差集中每一条都能归因到预算裁剪且有记录
- **SC-002**: 对当前全部锚，收租候选请求的合约码数**无一超过**单批上限
- **SC-003**: 「① 非空 ⇒ 候选非空」与「候选 ≤ 预算」两条性质各有一条断言，且断言不依赖任何具体标的的数据
- **SC-004**: 建仓与全腿视角在本片前后**逐值相同，零例外**
- **SC-005**: 零 Δ 面与非零 Δ 面在同一批底层数据下产出同一个候选集
- **SC-006**: 每条 `state_branches` 各有至少一条自动化断言，且每条能通过定向变异证明其会红
- **SC-007**: 当前实测为「不设窗时可用腿为 0」的锚，本片后候选集仍为空 —— 零例外

真缺陷那 5 只：`us:ORCL` 18 条 · `us:GOOGL` 17 · `us:CRCL` 14 · `us:SMCI` 4 · `us:NFLX` 1。其估值/市价比落在 **0.505–0.813**，属正常区间，非边角案例。

### §4 缺陷三：单批上限已被违反

现行零 Δ 面窗口码数（认沽 ∧ 标准 ∧ 未软下架 ∧ 期限 `[1,365]`）：

| 市场 | 锚数 | 最大码数 | **超上限锚数** |
| ---- | ---- | -------- | -------------- |
| 美股 | 109  | **470**  | **3**          |
| 港股 | 22   | 207      | 0              |

超限三只：`us:ULTA` 470 · `us:REGN` 463 · `us:GOOGL` 416（上限 399）。超限后果不是报错而是**整表回落收盘档** ⇒ 这三只在零 Δ 面拿不到实时。`us:GOOGL` **同时**命中 §3 与 §4。

### §5 为什么不能只把下界改锚锚定轴（PoC 结论）

| 约束                 | 现行「市价 × 比例」 | PoC「锚定轴 × 比例」                      |
| -------------------- | ------------------- | ----------------------------------------- |
| 候选非空可由定义论证 | ❌ 依赖估值/市价比  | ✅ 由构造成立（实测美股 24→0 · 港股 3→0） |
| 候选 ≤ 预算          | ❌ 已破 3 只        | ❌ **恶化到 5 只，最大码数 470 → 700**    |

⇒ 超上限的后果就是回落收盘档 = 换一种方式失去实时 ⇒ **治一半、恶化另一半**，故本片不取该形态。

### §6 触发频率（用于定优先级）

| 观测                                      | 窗口                               | 结果     |
| ----------------------------------------- | ---------------------------------- | -------- |
| 某标的整面零可读 Δ（零 Δ 面触发的代理量） | 近 30 天 · 1447 个「标的×session」 | **0 次** |
| 候选面呈零 Δ 形态                         | 近 7 天 prod 日志                  | **0 次** |
| 窗口超上限回落                            | 近 7 天 prod 日志                  | **0 次** |

⇒ 零 Δ 面实际**只在新锚首日**走。⚠️ **射程边界**：同窗口内收租候选请求总计仅 18 次（该路径由人打开选约表触发），故上述三个 0 里有一部分是**样本少**，MUST NOT 读成「结构上不会发生」。

## Assumptions

- 「离锚定轴距离」以行权价与锚定轴之差的绝对值度量。选它而非「离市价距离」，是因为收租的成色上界本就锚在该轴上 —— 用市价度量会在估值远低于市价时把最该保留的腿判为最远
- 预算上限沿用供应方单批合约码数上限，不为本片另设一个更小的值
- 期限段、成色上界、权利金门槛、相对价差上界等既有判据**取值不动**，本片只改「候选窗怎么算」
- 零 Δ 面触发条件不变（本片不改「何时判定为零 Δ 面」，只改「判定之后用哪个窗」）

## Out of Scope

- **不重新标定任何比例参数**：2026-09-07 的取证是单次拍照（港股一个 tick、美股一个 session），不足以标定。取值该定多少需多日样本 + 预算约束一起算，另行排期
- **不改分页策略**：实时路径「主批恒 1」是既有裁决，本片沿用
- **不改建仓与全腿视角**：两者不设行权价上界，本片对其零影响（SC-004 钉住）
- **不改零 Δ 面的判定条件**
- **不处理供应方单批上限本身的变化**：上限值来自供应方契约，本片只消费不重定义
