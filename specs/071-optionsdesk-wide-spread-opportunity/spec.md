# Feature Specification: 宽价差机会标 — 收租点差闸的机会逃生舱

**Feature Branch**: `071-optionsdesk-wide-spread-opportunity`
**Created**: 2026-08-31
**Status**: Clarified（2026-08-31；四项决断经 2026-08-31 全量重扫定案，见文末标定实测）
**里程碑**: [ADR-0068](../../docs/adr/0068-realtime-narrow-recall-two-stage.md) 实施序列的 **P5 片**（补片；P1 = 067 / P2 = 068 / P3 = 069 / P4 = 070 均已 ship）。收口 issue #298。

## 背景

2026-08-29 实时窄召回设计对焦定过一条「价差双向」决策：离线保留 `rel ≤ 0.35` 闸、实时新增「宽价差机会」标（`rel > 0.35 ∧ abs_spread ≥ 阈值 ∧ bid 年化 ≥ 档 ⇒ 进候选并带标，打标不删`）。该决策在 068 / 069 两次 specify 之间**掉队**——算法位置在召回第二段打标（068 的地盘），排期表却写在 P3（069），ADR-0068 起草时两边都没认领，此后既无实现也无否决记录（issue #298 的全部取证）。

现状：`rel > 0.35` 的收租腿被 `passesRelativeSpreadMax` 挡在意图 Tab 外、只在全腿 Tab 可达，该行为已被 `get-legs.usecase.spec.ts` 固化成断言。070 之后离线收租已接同一条清链 / 行军管道，⇒ 这批腿**同时**缺席离线与实时两档的 fwd 阶梯。

## Clarifications

### Session 2026-08-31

- Q: 落地还是否决？ → A: **落地**。2026-08-31 全量重扫（dev 库 `2026-08-28` 收盘、109 只 us 锚、判据直调仓内 rules 入口）证实这是**真机会而非噪声**：`us:PCG K=16.5 DTE 35` bid 年化 **39.4%** / OI 301、`us:TTD K=13 DTE 35` 年化 **32.3%** / OI 122——砸 bid 即达档、持仓量厚，今天在意图 Tab 上完全不可见。
- Q: 两个阈值（`abs_spread` 下限 / `bid 年化` 档）各取多少？ → A: **单闸**，`abs_spread` 那道**删除**。实测年化闸一上，`abs_spread` 闸在 `$0.30` 之前一条都不筛（合格池最小绝对价差落在 `[$0.20, $0.30)`）——两个旋钮实际坍缩成一个；加一个当前不绑定、又标不出谷底的参数违反本仓「MUST NOT 靠分布拍一个中间值」的纪律。年化档取 **收租 good 档界（15%）**，为 `leg-tier.rules.ts` 既有档表的**引用**，零新数值。
- Q: 落点——召回层放行，还是只在表达层标而不放行？ → A: **召回层放行 + 打标**。只标不放行等于把腿留在全腿 Tab，而全腿 Tab 不进 fwd 阶梯 ⇒ 那 5 个缺失推荐档一个也回不来，标本身没有行动价值。
- Q: 带标的宽价差档参不参与凸包 / 行军？ → A: **正常参与，无特判**。实测边际（φ=good 生产配置）**+5 推荐 / −0 丢失 / 2 停点位移**：宽价差腿 bid 被压低 ⇒ 结构上落在凸包之下，劣质者被凹陷支配自动弹掉，不会污染既有推荐。给它开豁免反而要新写一条只作用于某类腿的几何特判。
- Q: 两档口径——照 08-29 原决策「只实时」，还是两档一律？ → A: **两档一律**。08-29 定该条时 070 尚未存在；070 已把离线收租接上同一条清链 / 行军管道，价值主张写的就是「计划 / 执行同口径」。只在实时放行会让两档给出**不同的推荐档**，把 070 刚收敛掉的分叉重新打开。
- Q: 建仓视角一起放行吗？ → A: **本片排除**。建仓面补测：候选本就 2762 条（不缺腿）、捡漏池 1476 条里过周化 good 档（2%）的仅 **24 条**，且样本以 OI 个位数的名义报价为主（`us:AVGO K=375` bid 8 / ask 24 / OI 6）；建仓不跑行军（069 FR-019 / ADR-0068 勘误）⇒ 放行只增行不增判决。建仓口径 MUST 等实盘反馈，🚫 MUST NOT 靠本片的收租分布顺手推一个。
- Q: 用户把点差上界收窄时，机会支还放行吗？ → A: **让位**（2026-08-31 impl 期修订：初版写的是「不随控件动」，被 T009 IT ⑤ 臂当场撞红）。拖动价差上界往紧里调是一句明确的话「我只要窄市场」；机会支若照样放行，这个控件就对一类腿失效了，而**表照样渲染得出来**。判据取「用户值**不比系统默认值严**」而非「有没有被覆盖」—— 后者会让「显式填一个与默认值相同的数」与「压根没动过」给出不同的成员集，而两种都解释得通。放宽 / 不限时机会支照常作用但恒无效果（主支已放行）。
- Q: 本片 UI 走不走 mockup-first？ → A: **免 mockup**（068 / 070 先例）。呈现增量为既有选约表行上的一个微标，无新屏 / 新布局 / 库选型；UI 规格由 plan 的 UI 段承载。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 宽市场里的厚租金不再被一刀切掉 (Priority: P1)

owner 打开一只锚的收租视角。市场报价很宽（买卖价差超过中间价的 35%）但**买价**本身已经足够厚——按买价卖出即可达到「好档」年化。这条腿现在出现在收租候选里，行上带**宽价差机会**标，买卖价同时可见；它照常参与 fwd 阶梯，可以成为该 K 的推荐停点。

**Why this priority**: 这是本片的全部价值——把「宽价差 ⇒ 一律出局」这条一刀切换成「宽价差 ∧ 砸 bid 仍达档 ⇒ 带标放行」。实测它在 318 条 K 梯上救回 5 个推荐档且零回归。

**Independent Test**: 构造一条 `rel > 上界 ∧ bid 年化 ≥ 15%` 的收租腿，断言：① 它在收租候选里；② 行上带宽价差机会标；③ 它进 fwd 阶梯并可当选推荐停点；④ 同 K 一条 `rel > 上界 ∧ bid 年化 < 15%` 的腿仍然出局。

**Acceptance Scenarios**:

1. **Given** 收租视角某腿 `rel > 点差上界` 且 `bid 年化 ≥ 15%`，**When** 检索，**Then** 该腿进候选、带宽价差机会标，且**不**计入「被流动性门槛挡下」的数
2. **Given** 同视角某腿 `rel > 点差上界` 且 `bid 年化 < 15%`，**When** 检索，**Then** 该腿维持出局（逐字沿既有语义），仍在全腿 Tab 可见
3. **Given** 某腿缺 bid 或缺 ask（相对价差算不出），**When** 检索，**Then** 维持既有 fail-closed 出局——机会支 MUST NOT 接管（「不知道」不是「宽」）
4. **Given** 带标腿与常规腿同在一条 K 梯，**When** 跑清链与行军，**Then** 带标腿无特判无豁免，劣质者照常被凹陷 / 绝对支配弹出
5. **Given** 用户把点差上界覆盖到**更严**的值，**When** 检索，**Then** 机会支让位，该腿出局——用户的值绝对生效
6. **Given** 用户把点差上界显式填成**与系统默认相同**的值，**When** 检索，**Then** 机会支照常放行——同一个上界不因「手填过」而给出两种成员集

### User Story 2 - 两档同口径：晚上看到的机会，盘中还在 (Priority: P2)

owner 晚间在离线档收租视角看到一条带宽价差机会标的推荐档；次日盘中打开实时档同一只锚，该机会仍按**同一条判据**评估——两档不会一个放行一个不放行。

**Why this priority**: 070 的价值主张是「计划 / 执行同口径」。机会支若只落一档，两档会在同一只锚上给出不同的推荐停点，而那正是 070 刚收敛掉的分叉。

**Independent Test**: 同一批腿分别经离线装配与实时窄召回第二段判腿，断言两路的候选成员集与机会标逐腿一致（差异只允许来自输入报价值本身）。

**Acceptance Scenarios**:

1. **Given** 同一批腿值，**When** 分别走离线档与实时档判腿，**Then** 机会支判定逐腿相同——判据恰好一处，无档位分支
2. **Given** 实时窄召回第二段，**When** 判腿，**Then** 机会标与带内 / 带外标各自独立共存（两者描述的是两件事：怎么进来的 vs 落不落 Δ 带）

---

### User Story 3 - 既有行为零回归 (Priority: P3)

不满足机会支的一切腿、建仓视角、全腿视角、交叉报价护栏、六维检索条件的控件与三态——与本片之前逐值相同。

**Why this priority**: 本片动的是全仓唯一的成员判定处；爆炸半径必须钉死在「收租 ∧ 点差维度 ∧ 年化达档」这一格里。

**Independent Test**: 机会支恒判 false 的输入面（建仓 / 全腿 / 年化不达档 / 缺报价）跑全量对照，逐值不变。

**Acceptance Scenarios**:

1. **Given** 建仓视角任意腿，**When** 检索，**Then** 候选成员与计数与本片之前逐值相同
2. **Given** 全腿视角，**When** 检索，**Then** 该视角本就不设点差上界，响应逐值不变
3. **Given** 交叉 / 锁定报价腿，**When** 检索，**Then** 护栏前置判定与两档处置（实时剔 / 离线降标）逐字不变

### Edge Cases

- `bid` 缺失 ⇒ 年化无定义 ⇒ 机会支不成立（🚫 MUST NOT 拿 0 顶 bid 算费率）
- `K − bid ≤ 0`（权利金吃掉整个行权价）⇒ 费率无定义 ⇒ 机会支不成立
- 机会腿当选推荐停点且同时被绝对支配标为「疑似陈旧报价」⇒ 两个标各自成立、不互相压制（问的是两件事）
- 机会腿的 OI 不过停点闸 ⇒ 沿凸包回退，与常规腿同一条路径
- 用户把点差上界覆盖到「不限」⇒ 主支不产生排除 ⇒ 机会支恒不触发（该腿本就进得来），但标的判定仍成立 ⇒ 标 MUST 以「本会被主支挡下」为判据而非以「实际被挡下」为判据，否则同一条腿的标会随控件闪烁

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 相对价差维度 MUST 成为「主支 ∨ 机会支」的**一个**维度——主支 = 既有 `rel ≤ 上界`，机会支 = `bid 年化 ≥ 收租 good 档界`；🚫 MUST NOT 新增第七个检索维度（不加控件、不进三态清单）。
- **FR-001a**: 机会支 MUST 在用户把该维度收窄到**严于系统默认上界**时让位——用户值绝对生效；判据 MUST 为「用户值 ≥ 系统默认上界」，🚫 MUST NOT 写成「该维度有没有被覆盖」。
- **FR-002**: 机会支的档界 MUST 为 `leg-tier.rules.ts` 年化档表的**引用**（`good`）；🚫 MUST NOT 新写任何数值字面量，🚫 MUST NOT 复用行军 φ 的可配置旋钮（召回成员集 MUST NOT 随 server 配置变）。
- **FR-003**: 机会支 MUST 只作用**收租**视角；建仓与全腿视角判据逐字不变。
- **FR-004**: 机会支 MUST 在相对价差可算时才成立——缺 bid / 缺 ask ⇒ 维持 fail-closed 出局；`bid` 缺失或费率无定义 ⇒ 机会支不成立。
- **FR-005**: 经机会支放行的腿 MUST 带**宽价差机会标**，标随候选集从召回层一路上浮到契约面；🚫 MUST NOT 在下游任何一层重算（重算即第二个判定点）。
- **FR-006**: 标的判据 MUST 为「主支不过 ∧ 机会支成立」——与该维度**实际**是否产生排除无关（用户把上界放到不限时标不得消失）。
- **FR-007**: 放行腿 MUST NOT 计入「被流动性门槛挡下」的两个数（051 FR-006a）——它已经不是被挡下的腿；计数与成员判定 MUST 同源产出。
- **FR-008**: 放行腿 MUST 照常进 fwd 阶梯并参与凸包 / tick-共线 / 行军；🚫 MUST NOT 为其新增几何特判、豁免或新审计类目（13 类枚举零改动）。
- **FR-009**: 离线档与实时档 MUST 共用同一机会支——判据恰好一处，🚫 MUST NOT 按档位分支。
- **FR-010**: 客户端 MUST 在收租视角行上呈现宽价差机会标，并使该行的买卖价可读（标的行动语义是「按买价卖出仍达档，但市场很宽」）；🚫 MUST NOT 呈现为劝阻式告警——它是机会标不是风险标。
- **FR-011**: 机会标与 068 的带内 / 带外标 MUST 各自独立——两者可同时出现在一行上，语义不互相覆盖。

### Key Entities

- **机会支**: 相对价差维度的第二条通过路径；输入 = 行权价 / bid / DTE，输出 = 布尔。与主支 OR 合成该维度的成员判据。
- **宽价差机会标**: 腿级呈现语义——「这条腿是从机会支进来的」。恒由召回层产出，下游只消费。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 判据单点可数：机会支谓词全仓恰好一处定义，非测试调用方恰为召回层的维度判定处（`rg` 可数）；年化档界字面量在 `leg-tier.rules.ts` 之外零新增（`check-optionsdesk-rule-constants` 通过）。
- **SC-002**: 零回归：建仓 / 全腿两视角与「年化不达档」的收租腿，本片前后逐值相同的机器判据通过。
- **SC-003**（2026-08-31 实装后回放已兑现）: 机会面兑现：2026-08-28 数据面回放中，收租候选自 852 增至 **930**（其中带机会标 **78**），K 梯推荐停点自 70 增至 **75**（**+5 / −0**）；建仓候选 **2762 逐值不变**。
- **SC-004**: 两档同口径：同一批腿值经离线装配与实时窄召回第二段，候选成员集与机会标逐腿一致。
- **SC-005**: 标可解释：带机会标的行在契约面同时给得出 bid / ask 与相对价差，使「为什么它在这里」可从屏幕反推。
